## 本章任务
**第 1 章标题**：品类边界：decision model 与 LLM 结构化输出、专训分类器、规则引擎的三角分工

**本章唯一要回答的问题**：decision model 这个品类到底划在哪、它的硬约束是什么、哪些需求应该直接被排除。

### 必须覆盖的 8 条要点

1. **三原语语义差异与业务映射**：`Choice`（选项集选一，上限 255，返回全选项概率分布 + `confidence`）、`Score`（有序档位打分，可落在两档之间）、`Noul`（命题为真概率 0–1，无独立 confidence 字段）。**要写清：各自对应什么业务问法、各自拿不到什么**（例如 Choice 拿不到"程度"、Noul 拿不到选项间比较）。官方 docs 有 primitives 页。

2. **非生成式机制与 RLCD 训练目标的后果**：一次前向并行输出、不生成 token；训练优化"校准概率"而非"人类偏好文字"。**要解释为什么它不能写报告、也不该被要求解释理由**——这是选型者最容易误判的地方（很多人会问"它为什么不告诉我为什么这么判"）。

3. **边界一（vs 传统专训分类器）**：不是替代，是「**零样本可换标签**」这一维度的补位。Cloudflare 发布 Clef 时的对照表里，BERT 系 Laya 在 CLINC150 上 macro-F1 仅 3.19，而 Jev 89.27——**这恰恰证明"零样本"与"专训小模型"根本不在同一条性能曲线上，不可横向比**。要讲清：什么时候该训分类器（数据充足、标签稳定）、什么时候该用 decision model（标签会变、冷启动、长尾类别）。

4. **边界二（vs LLM + structured output）**：差异在**延迟/成本/类型安全**，不在精度。关键数据：Vals AI 实测「向 LLM 索要概率会使成本上升 29%–101%」——**这是选型时最容易被算错的一笔账**（很多人只比单价，没算"让 LLM 输出概率"的额外成本）。

5. **边界三（vs 规则引擎）**：官方自我定位「**smart if-statement**」，只替代"手写逻辑太脆"的分支判断，周边确定性校验必须留在代码里。要给出**什么算"太脆"**的判据（例如：规则条目爆炸、自然语言输入、需要容忍表述变体），以及**什么绝不该交给它**（金额计算、权限判定、合规硬门槛）。

6. **不可协商的硬约束清单及其成因**：
   - 不公开架构、**不对客户数据微调 / 不做 LoRA / 全账户共享同一份权重**（即它是靠 prompt 塑形的通用模型，不是可定制分类器）
   - **仅文本输入**（音频视频不支持）
   - 英语为主，**CJK"能处理但不等同"**
   - 64k/请求 · 32k/问题；加 `TypeSafe-Danger-Zone-Long-Context` 头可到 262k（更慢更不准）
   - **$0.042/Mtok 输入，输出免费**
   请核实这些数字与官方 docs 一致（版本 1.14）。

7. **硬约束的排除效应（本章最重要的输出）**：需要领域定制权重的场景、需要图像/音视频输入的场景、需要 CJK 母语级语义判断的场景——**这三类需求应判定为「出局」而非「调优后可用」**。还要写出一条隐含代价：**共享权重意味着全行业共用一套失败模式，你的 badcase 不会因你反馈而改善**。

8. **成本与延迟的真实结构**：输出免费意味着"多问几个问题几乎不涨价"，输入按 token 计意味着"state 越长越贵"。**这一不对称直接决定 schema 与 state 的设计取向**——但要克制，只讲结构性含义，具体 schema 设计规则留给第 6 章。
