# 2026-11-02：PDF 管理能力收进可搬动的 skill

这份记录保存本次取舍与替代范围，是本项目约定，不是 MinerU 能力的来源证明。

当前决定：通用操作只保留 `pdf-manager`，论文库不再提供脚本入口或兼容层；下文的兼容安排是本日较早的方案，已被替代。独立实验与历史证据按原貌保留。

## 为什么迁移

旧 `mineru-pdf-convert` 只是入口，转换、下载和元数据脚本实际位于论文库 `_scripts/`。脚本又从自身位置推导资料根目录，并与索引、arXiv 命名及本库 Git 策略绑定。直接复制转换脚本不能得到独立使用的 skill。此次把通用实现、必要 API 参考和格式样本集中到 `pdf-manager`，资料目录由输入或 `--root` 决定；旧调用保留兼容入口。

## 已定取舍

用户需要下载、改名、Markdown 转换和 MinerU 已有提图方式，目的是以后深度调研时能直接读取好用的 MD。沿用同名 `pdf/` 与 `md/`、平铺 `assets/` 和相对引用；分类保持 `fig / chart / table / eq / img`。正文取 MinerU 的 Markdown，结构化结果只提供资源关联和命名所需信息。表格文本和裁图各有用途，因此返回的内容图即使没有被 MD 引用也保留。

用户明确不需要文献搜索、页码或区域映射、图片清单及关联数据库。原来的命名与同名 PDF 已可用于回查，不把更严格的定位功能设为完成条件。V1 作为现有主要依据；V2 仅在实际存在且字段可识别时补足归属，避免用无路径公式条目整体推断孤立图片类型。

命名保留 `<来源编号及版本>.<类型>.<简称>` 的可读性，但不把类型做成封闭枚举。脚本提取来源标题与完整摘要，Agent 根据摘要判断类型、简称和关键词，再由脚本执行命名；没有可靠编号不造编号，没有来源摘要不填 AI 概括。摘要无法直接获取时，先按现名转换再读取。索引是可选能力，单篇操作不依赖它。

转换只采用 MinerU v4 精准解析，默认 `vlm`；轻量接口仅返回 Markdown，对本次完整资产流程没有必要。接口约定以用户提供的官方摘录及在线接口文档核对，ZIP 内部字段则依据真实样本与对应版本源码，分别保留依据。

## 替代范围

现有论文库切换通用工具入口，既有 PDF、MD、资产和索引名称保留；本次不做全库重新命名。旧 `_scripts/` 保留兼容调用，本库 Git 忽略与追踪策略仍在项目侧维护。重命名维护本篇内部关系及已有索引行，不默认扫描整个研究仓重写外部引用。

当前操作说明在 [论文库 AGENTS](../resources/papers/AGENTS.md)，可复用工作流在 [pdf-manager](../.agents/skills/pdf-manager/SKILL.md)。本记录说明为什么采用这些选择，不复制当前命令清单；实际验证范围由本次实现交付报告陈述。

## 同日追加：VPN 网络排查与端到端验证完成

用户追问失败是否来自 VPN，并要求稳定的处理方式。只读检查发现系统代理为本地 `127.0.0.1:7892`，有运行中的隧道适配器，MinerU API、CDN、arXiv 的系统 DNS 均返回 `198.18.0.x`。关闭 Python 显式代理仍经过该 DNS／隧道路径，因而此前所谓直接连接并不能排除 VPN 影响。

通过 HTTPS DNS 获得实时 CDN 地址后，保持 VPN 开启并保留原域名的 SNI、Host 和证书校验，来自两组解析结果的四个地址全部返回 HTTP 200。由此将故障定位到本机接管后的域名访问链路；不把这一观测扩展成对所有 VPN 或某条尚未确认的分流规则的结论。

脚本增加仅限 MinerU 结果 CDN 的动态 DNS 回退，没有改变用户网络设置、关闭证书校验或固定 CDN IP。沿用原批次成功取得 ZIP，生成 Zep Markdown 和 8 张 table 资产，`check` 报告完整。随后对同一个已完成结果独立下载、解包三次，均成功：每次 981,049 字节、8 张资产，解析器标记为 `mineru-cloud 3.4.4`。这些重取不提交新的解析任务。

新增 6 项离线测试覆盖正常路径、限定域名的回退、HTTP 拒绝、DNS 查询边界及地址过滤、有限地址重试，以及 TLS SNI／证书校验／HTTP Host 保持原域名；相关 MinerU 模块共 23 项测试通过。此前的端到端阻塞已解除；这次验证证明工具流程和产物完整性，不声称逐项视觉核验过论文内容。
