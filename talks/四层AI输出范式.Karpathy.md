# Karpathy 四层AI输出范式（库森转述版）
> 核心思想：不要只让AI输出纯文字，逐层升级输出载体，提升信息传递效率；底层用 **80% ASD‑STE100** 受控写作约束文字质量

## 第一级：写作（基础层）
让AI按 ASD‑STE100 风格写解释。

ASD‑STE100 是一套写作规范，最早用在航空维修手册上。手册里一句话有歧义，飞机就可能出事故，所以规则很严。

主要规则有这几条：
1. 词典只有大约 900 个词，一个词只有一个意思。
2. 一条指令最多 20 个词，一句描述最多 25 个词。
3. 一段只讲一件事。
4. 用主动语态，说清楚谁做了什么。

AI写解释，常见问题是句子长、重点靠后、同一个东西换着叫。这几条规则正好管这些问题。

Karpathy 说 AI 熟悉这套规范。你在提示词里写上 ASD‑STE100，AI 就会照着写。全套规则太严，所以他会要求“做到 80% 的 ASD‑STE100”。

### 方案A：动态提取规则（提示词）
```
随机抽样过去一周内我与你互动工作的10个会话记录。将ASD-STE100规则应用到助手响应中，分析哪些规则会提升清晰度、减少困惑并改善对话，然后将这些规则记录到我的用户级 AGENTS.md中
```

### 方案B：静态全局规则（AGENTS.md 可直接粘贴）
```
当你解释代码、计划、错误或变更时，用大约 80% ASD-STE100 风格写作
1. 每句一个事实或一条指令。指令最多 20 个词，描述最多 25 个词。
2. 使用主动语态，说明谁做了什么。
3. 同一事物每次用相同的词，术语定义一次后精确复用。
4. 先给答案，再给细节。
5. 步骤放进编号列表，每段一个主题，最多 6 句。
6. 用我使用的语言回答，其他语言也保持句子简短。
7. 流程或结构超过 3 个部分时，加一张 ASCII 图。
8. 我说“用 HTML 解释”时，转成单文件交互式 HTML 页面。
```

## 第二级：图表（可视化层）
别让它写，让它画。这一点现在比以前更明显，模型画流程图、架构图、对比表，基本一次就能出能用的。

用法很简单。问“有哪几种方案”，就让它出表格。问“这个流程怎么走”，就让它出流程图。问“这几个模块什么关系”，就让它出架构图。

## 第三级：网页（交互层）
让它输出“HTML格式”。图表是静态的，网页可以动，可以点，可以折叠，还能放一个滑块让你自己拖参数看变化。前端又刚好是这两年模型进步最快的方向之一。

我觉得网页最适合拿来做展示，比如信息卡片。

直接说：`把刚才的内容整理成一个单文件 HTML，用信息卡片布局`，浏览器打开就行。

> 示例场景：把 Transformer 论文做成交互网页，每张卡片点进去都能动手试。

## 第四级：讲解视频（动态演示层）
这是 Karpathy 最看好的。给任意主题现做一支量身定制的讲解视频，提示词：`为 X 创建一个 3b1b 风格的视频解释`。

3b1b 就是那个讲线性代数、微积分特别出名的数学频道，动画是用代码画的，而写代码正好是模型的强项。

Opus 5.5 发布后，几天里就冒出一千五百多条它做的视频，不少是微积分、Transformer 这类原理讲解，公式一边推，图形一边动。

当初学这些的时候要是有这种视频，真的会轻松太多。
而且是为你一个人做的。卡在哪个知识点，就为那个点现做一支。

配音可以用微软的 edge-tts，本地就能跑，就是有点播音腔，自己学习完全够用。

## Karpathy 的两个核心判断
1. 模型越来越强，基础的活它自己就干完了，人的工作会上升到监督和理解。
> 写代码的人最有体会，AI一分钟能改两千行，真正花时间的变成了看懂它改了什么。

2. AI 正好能帮你解决这件事。现在可以让它做大型、定制、用完就扔的软件，比如一个网页，一个讲解视频。
> 以前谁会为了看懂一次改动专门写个网页，现在成本几乎为零。
> 这个思路：AI帮你改完一大块代码，已经没有精力看 diff 了，不如让它出一个网页，用图把改动前后的结构画出来，这样会快很多。
