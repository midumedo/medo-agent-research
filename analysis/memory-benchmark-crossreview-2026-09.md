# 记忆横评：谁在什么协议下报了多少分

> 调研时间 2026-09-21。本文回答一个问题：**记忆框架与基准的公开横评数字，在什么条件下可以互相比较，哪些只是一家之言。**
> 与 [Memory 工程选择](memory-engineering-selection.md) 的分工是：那份判断"值得深拆什么"，本文提供"分数为何不能直接拿来排序"的依据。两者都不把榜单当结论。
>
> **证据分级**（全文沿用）：
> 【一手】已在本地固定版本的论文正文中核对（PDF 已入库，见 [论文库](../sources/papers/README.md)）；
> 【自报】厂商博客/官网/文档，未经第三方复现；
> 【第三方】非当事方的独立审计或学术评测，但本身未必同行评审；
> 【未核实】本轮未能定位到一手来源，不作为结论使用。

---

## 一、先看结论

1. **跨来源的分数基本不可比。** 同一系统在同一基准上的公开数字可以差 30 以上：Zep 的 LoCoMo 在两年里先后出现过 84%、58.44%、75.14%、94.7% 四个数。差异主要来自 harness（回答模型、judge、题集、检索预算），不是来自系统。
   一个需要小心对待的例子：EverMemOS 自报 LoCoMo 92.32%，其仓库 issue #73（2026-02-05，非团队成员）报告只跑到 38.38%——但该复现只跑了 10 段对话中的 1 段，且模型、嵌入与重排模型都与论文配置不同。它可以证明"复现存在差距"，**不能**当作与 92.32% 对等的比较数字。
2. **真正有对照价值的横评不到五份**，而且它们的结论往往和厂商榜单相反：MemoryAgentBench 与 AMA-Bench 都报告 **长上下文基线的平均分高于被测的商用记忆系统**；2607.16848 报告 Graphiti 的领先在控制检索预算后消失。
3. **"记忆系统 vs 长上下文"在论文里没有厂商博客里那么一边倒。** Mem0 自家论文（2504.19413v1）Table 2 里 Full-context 是 72.90%，高于 Mem0 的 66.88%【一手】。厂商后来的 92.5% 换了算法、读者与评分口径【自报】。
4. **规模基准远未饱和。** BEAM 论文自身报告的最好平均成绩是 0.359（Llama + LIGHT @500K）【一手】，而厂商在同一名称下报 64.1%（BEAM-1M）【自报】。两者不可能是在说同一件事，引用前必须回到各自定义。
5. **老名单正在失效。** 2025-12 的综述 2512.13564 的框架表（其 Table 9）以 MemGPT/Mem0/Zep/LangMem/Cognee 为中心；2026-08 首次发榜的 AML 榜单前列则是 MemoraX、InvMem、ReFind、ActiveMemoryIndex 等陌生名字【第三方】。名气排序与当前前沿之间已经出现明显的时间差。
6. **因此本文的产出不是"最佳框架"，而是一张带日期与协议列的对照表**，加上一份按"机制代表性"而非分数选出的深拆候选。

**读这张表的三条提示：**

- **LoCoMo 的"1,540 题"已找到出处，但不是论文给的。** 论文全集是 7,512 题【一手】；而厂商普遍引用的 1,540 来自社区常用的 LoCoMo10 数据文件：EverMemOS 的 benchmark adapter 显示该文件含 1,986 题，排除对抗类 category 5 的 446 题后正好 1,540（282 多跳 + 321 时间 + 96 开放域 + 841 单跳）【一手，`sources/repos/EverOS` 的 `benchmarks/adapters/locomo.py`】。同一仓库注释里还出现过 2,432 这个数，实际数据文件口径未验证。**结论：报 LoCoMo 分数时必须说明用的是全集、LoCoMo10 全集还是去对抗类子集**——三者不可互换。
- **"LongMemEval-S / -M"不是论文的命名。** 论文 v2 的上下文列写 115K 与 1.5M【一手】；S/M 分档来自第三方 harness（如 agentos-bench）【自报】。同一缩写在不同 harness 里可能指不同题集。
- **venue 一列只写 API 明确给出的信息**，没有就留空。多数记忆基准目前只有 arXiv，尚未有正式发表记录，这是判断可信度时要考虑的背景。

## 三、有对照价值的横评（一手）

这五份是本文唯一建议直接引用的横评：它们在同一篇论文内、用同一协议测了多个系统。

### 3.1 MemoryAgentBench（2507.05257v4，Table 3）

四能力：准确检索 / 测试时学习 / 长程理解 / 选择性遗忘。被评系统约 23 条（长上下文 6、RAG 类 10、商用记忆 3、agentic 4）。

| 系统 | EventQA | FC-SH | FC-MH | 总均分 |
|---|---|---|---|---|
| GPT-5-mini(400K) 长上下文 | 78.2 | 78.0 | 28.0 | **60.6** |
| GPT-4o-mini(128K) 长上下文 | 59.0 | 45.0 | 5.0 | 42.2 |
| Zep | 42.5 | 7.0 | 3.0 | 24.0 |
| Mem0 | 37.5 | 18.0 | 2.0 | 21.1 |
| Cognee | 26.8 | 28.0 | 3.0 | 20.6 |

**读法**：这不是"Mem0 只有 21 分"，而是"在增量注入 + 冲突消解协议下，抽取式记忆系统与长上下文基线的差距主要出现在 FC-MH（多跳冲突）"。它对教材的价值是给出一个**记忆系统整体输给长上下文的可复现场景**，而不是给出排名。

### 3.2 AMA-Bench（2602.22769v4，Table 4 / Table 5）

| 类别 | 系统 | 均分 |
|---|---|---|
| 长上下文基线 | GPT-5.2 | **0.7226** |
| 长上下文基线（同主干） | Qwen3-32B | 0.5181 |
| 被测记忆系统最优 | EMem | 0.4610 |
| 论文提出 | AMA-Agent | **0.5722** |

论文的核心机制解释是：agent 轨迹是机器生成的（状态转移、JSON、代码），而压缩与相似度检索是为自然语言设计的；把正确证据直接喂给记忆系统时效果尚可，经过构建流水线后显著下降【一手，§4】。注意这里的**对照系是同主干的长上下文 0.5181**，AMA-Agent 的 0.5722 高于它——所以准确说法是"多数既有记忆系统不如长上下文，作者提出的因果图方法反超了同主干长上下文"。

### 3.3 2606.06448：十个系统的代价分布（本地库，Qwen3-32B，LongMemEval n=300）

| 系统 | 准确率 | 端到端能量 | 每答对一题 |
|---|---|---|---|
| BM25 | 47.0 | 582 kJ | 4,128 J |
| GraphRAG | 46.0 | 2,082 kJ | 15,084 J |
| HippoRAG v2 | 44.3 | 1,339 kJ | 10,079 J |
| A-Mem | 42.7 | 14,864 kJ | 116,116 J |
| embedRAG | 39.8 | 495 kJ | 4,144 J |
| SimpleMem | 36.0 | 5,481 kJ | 50,749 J |
| Mem0 | 32.0 | 4,878 kJ | 50,813 J |
| Letta | 27.7 | 15,429 kJ | 185,873 J |
| MIRIX | 20.0 | 8,678 kJ | 144,629 J |

**最有价值的一点不是排名**：LLM 中介型系统的能耗主体在 **construction（构建）**，对用户不可见；跨系统"每答对一题"的能耗差达 47 倍【一手，§4.2】。任何只看准确率的横评都会漏掉这一维。论文自己也声明"无法做到完全对等比较"，并承认 judge 未具名、本地/远程用了不同 backbone【一手，§3.1】。

### 3.4 2607.16848：控制检索预算后领先消失（本地库）

PAIM 上 Graphiti 原生档 8.04（L3 8.24），但消耗 **2,596,250 字符**；在公平锚点 B≈30K 下关掉 episode、只用知识图时掉到 **5.27**，落到末位【一手，§6.2】。PTr 上同样的架构优势没有消失。结论是同一个系统在不同语料上的胜负可以由"喂了多少原文"决定。

### 3.5 BEAM（2510.27246v2）

论文自身报告的最高平均成绩 0.359（Llama + LIGHT @500K）、最高单项 0.828（Abstention），10M 档相对长上下文有 +155.7% / +107.3% 的提升【一手】。**这些数字与厂商口径的"BEAM-1M 64.1%"不在同一量级**；在搞清两者指标定义之前，不应把任意一个当行业水位。

## 五、为什么不可比：一份变量清单

引用任何一个分数之前，至少要看这七项是否齐备。缺一项，就只能当"某家在某种条件下跑出来的数"，不能进对照表。

| 变量 | 为什么关键 | 实例 |
|---|---|---|
| 回答（reader）模型 | 换 backbone 可移动 10 点以上 | Mastra 94.87（GPT-5-mini）vs 84.23（GPT-4o） |
| judge 模型与提示 | judge 本身有约 63% 的假阳性率 | LoCoMo 标准 judge 审计【第三方】 |
| 题集与子集 | 全集 7,512 与常用 1,540 子集不是一回事 | LoCoMo【一手 vs 未核实】 |
| 检索预算 / top-k | 控制预算后领先可整体消失 | Graphiti 8.04 → 5.27【一手】 |
| 摄入粒度 | 整篇 episode 与 6K 块是两种信息量 | Graphiti 2.6M 字符【一手】 |
| 是否含对抗类题 | 剔除对抗类可移动 20 点以上 | Mem0 重算 Zep 58.44%【自报】 |
| 成本与延迟 | 准确率相同时能耗可差 47 倍 | 2606.06448【一手】 |

## 六、时间差：老名单与新前沿

用户担心"新项目被老项目挡住"，这个担心在本轮数据里得到确认。

- **综述名单滞后于工程前沿。** 2512.13564（2025-12）的框架表以 MemGPT、Mem0、Memobase、MIRIX、MemoryOS、MemOS、Zep、LangMem、Cognee 为主体【一手，其 Table 9】；它没有收录 2026 年上半年出现的 Agent Zero、MemMachine、HyperMem、Chronos、MRAgent、Oracle 等，也无法预见 AML 榜单。
- **2026 年首次上传 arXiv 的记忆工作**（编号与日期已用官方 API 核验）形成一个明确的第二波：AtomMem 2601.08323（2026-01-13）、SimpleMem 2601.02553（2026-01-05）、TiMem 2601.02845（2026-01-06）、AgeMem 2601.01885（2026-01-05）、EverMemOS 2601.02163（2026-01-05）、Chronos 2603.16862（2026-03-17）、MemMachine 2604.04853（2026-04-06）、HyperMem 2604.08256（2026-04-09）、VikingMem 2605.29640（2026-05-28）、MRAgent 2606.06036（2026-06-04）、MemCon 2607.13591（2026-07-15）、Oracle 2607.13157（2026-07-14）、Agent Zero 2608.29606（2026-08-30）、HiPS 2608.25329（2026-08-26）、Dual-Layer 2608.22215（2026-08-23）。
- **这条线的共同点不是分数更高，而是机制位移**：从"写入前抽取事实"转向"原样保存 + 检索时计算"（MemMachine、HyperMem）、"记忆是被重构的"（MRAgent）、"把管理本身学出来"（AtomMem、AgeMem、MemCon、HiPS）。这与第三节里"抽取式系统在冲突消解上失分"的一手观察是互相印证的。
- **AML（Agent Memory Leaderboard）2026-08-12 首次发榜**【第三方】：接口隔离到 Add/Search、统一 judge 与 reader、公布每例运行 JSON；学术榜首位 InvMem 45.06，商业榜首位 MemoraX 58.0。它本身就是"分数不可比"这一问题的产物，值得作为评测协议对象单独跟踪（尚无独立 arXiv 评测论文）。
- **但 AML 前列不是任何知名系统，而且它们的共同点是"不建结构"。** 学术榜第一 InvMem 的仓库自述是"一个面向服务器部署的朴素 RAG 基线"——细粒度消息块 + Dense/BM25 的 RRF 融合 + 同会话邻接补全，不抽取、不建图、不改写。第二 ReFind（arXiv 2608.12888）保留原文、用一个 GPT-4o-mini planner 在检索时迭代决定查什么，同样不建结构【一手，两个仓库已读，见 [AML 开源榜深拆](../deepdive/aml-open-track/index.md)】。这与第三节的观察一致：在"证据能否被找回"这一目标下，抽取式结构目前并未表现出优势。需要克制的限定是——AML 把 Answer 与 Eval 收归平台，本质只测召回，抽取式系统的收益（读得更少、当前认识更清晰）在这套七维里覆盖不足。
