## 本轮过程中产生、但未进正文的判断

这些是调研途中形成的观察，尚不足以写进结论，先留在这里以免丢失。

1. **"抽取-更新"与"原样保存"之争正在成为 2026 年的主轴。** MemMachine（原样存、检索时抽取）、ReFind（只留原文 + 模型控制搜索）、HyperMem（超图分层）与 SimpleMem（写入即压缩）分别站在这条轴的不同位置。若后续只挑一个分歧来讲，这条比"向量 vs 图"更有解释力。
2. **AML 榜单把评测接口收敛到 Add/Search 两件事**，这本身是一个设计判断：它假定"记忆系统"就是一个可插拔的存取层，把回答生成留给平台。这个假定值得单独质疑——它会使"记忆参与推理"类方法（如 ReFind 的迭代搜索）处于不利位置。
3. **七维能力（A 事实召回 / B 组合推理 / C 时间事件推理 / D 记忆治理 / E 个性化 / G 上下文学习与执行 / H 安全隐私）中缺了 F 这一维**，且 D（治理）与 H（安全）在所有系统上都普遍偏低（约 18–37 分）。这可能说明"治理"目前还没有成熟的工程答案，而不只是各家没做。
4. **多篇 2026 工作把"何时抽取"当成可调参数**，而不是 pipeline 的固定第一步。这与 [Memory 工程选择](memory-engineering-selection.md) 里"保留材料还是提前理解"的张力是同一件事的两种表述，可以互相印证。
5. **memU 当前 README 已改写为"Personal memory, stored as Wiki"并强调核心逻辑仅 500 行、MemoryService 不发起模型调用**——这与我们此前记录的"三层记忆树 + 权重检索"是不同阶段的描述。凡引用 memU 机制，必须注明所读版本日期。
6. **EverMemOS 的 38.38% 复现来自仓库 issue #73（2026-02-05，非团队成员，单段对话、模型与嵌入均异于论文配置）**。它可以作为"存在复现差距"的一手线索，但不够格作为严谨对比证据——上一版横评稿把它写得太重，本轮已下调。
7. **商用系统的"记忆引擎"往往与自研模型绑定**（MemoryBear 配合 OpenBear/CodeBear），这会使它们的公开分数无法与第三方系统在同一回答模型下比较。引用这类数字时应把它当产品说明而非评测结果。
