# 项目结构研究：让拆解、分析与综合各有独立用途

> 2026-09-20。依据用户提出的六项结构疑问，对当前材料逐份审查，并核对少量一手文档实践与产品资料。这是项目结构研究，不是领域理论或模型行为实验。

## 判断

采用 `sources/` → `deepdive/` 与 `analysis/` → `domain/` → `output/` 的主要关系，取消独立条目层，把项目决定并入交流历史。Domain 按完整主题组织，当前研究草稿回到 Analysis；Deepdive 以 Memory、Context 与相关 Harness 机制为重心，按需链接背景。

这里保留一个层次的理由，是它提供了不同的理解或使用任务。目录数、文档数与摘要长度都不能代替这个判断。当前可执行设计见 [ARCHITECTURE](../ARCHITECTURE.md)，本篇解释诊断和取舍。

## 本地审查发现的实际问题

**维护 skill 的用途过宽，内容又高度重复。** [修改前技能](../archive/2026-09-20-before-focused-research/.workbuddy/skills/project-maintenance/SKILL.md) 把所有新建、修订和迁移文档纳入触发范围，正文主要重述归属、引用、纠错、备份和完工检查。AGENTS 又要求修改时先读它，于是多了一个分发规则的入口。移除它，把少量路由留在 AGENTS、维护约定留在 CONVENTIONS，已能满足本项目当前需要。没有触发轨迹或行为对照，不能把用户的体验扩写成“技能会降低模型智能”的研究结论。

**Notes 与 Dialogue 服务相近的历史恢复任务。** 三篇实际 Notes 是不设长度上限、研究架构、增加 Deepdive 的决定。它们值得保留，但并不需要根级的通用笔记容器。Dialogue 下的 `decisions/` 能让重要决定可单独查找，同时避免把“讨论、决定、当前规则”误排成三份都需同步的知识副本。

**TRADEOFFS 混有写作和证据规范。** 选材原则仍有独立用途，但应只负责后期成品如何选取和展开材料；事实力度、数字依据和来源身份由 STYLE 负责，文件归属由 CONVENTIONS 负责。历史选择不再在 TRADEOFFS 中叙述。

**Entries 只有预计用途，没有独立需求。** 上一版称它为“后期编译接口”，但尚无生成器或产物需要这套长期维护的结构。若只是把 Domain 再提炼一次，会增加条件丢失和更新不一致的机会。后期特定手册确需简明条目时，可在该 Output 中编辑；这不要求现在另设通用知识层。删除该层不能被宣称已经测得 token 节约。

**Domain 采用了研究表单式分类。** [旧入口](../archive/2026-09-20-before-focused-research/domain/index.md) 把定义、机制、分歧、对象表并列，但同一留存问题分别出现在概念、机制、竞争解释、主线、议程和产品分析中。它们不是一组已经连通的主题综合，目录位置却容易暗示“当前领域模型已具备”。

| 原材料 | 实际用途 | 本次去向 |
|---|---|---|
| `domain/foundations.md` | 工作定义、边界、观察维度 | [概念与边界草稿](concepts-and-boundaries.md) |
| `domain/mechanisms/context-retention.md` | 单项条件推演、构造反例与成本式 | [上下文留存分析](context-retention.md) |
| `domain/disputes.md` | 我方提出的竞争解释与检验条件 | 合入[研究议程](research-agenda.md) |
| `domain/systems.md` | 已知材料范围和候选对象 | 合入 [Deepdive 阅读入口](../deepdive/README.md#research-map) |
| `THESIS.md` | 与议程高度重叠的 H1/H2/H3 | 假设、竞争解释与检验在同一份议程维护 |

合并没有把检验条件删成一句假设：充分证据诊断对照、质量与资源两种比较口径、更新与删除边界、缓存和内容因素、负结果停止条件继续保留。完整旧稿在 [本轮快照](../archive/2026-09-20-before-focused-research/SNAPSHOT.md)。

**Deepdive 的“尊重整体”容易被理解成平均覆盖。** 旧规则允许沿运行、存储、错误处理不断展开，却缺少明确的主文选择边界。忠实描述不需要全栈普查；但“只讲 Memory”也不能只找同名目录，否则会跳过实际决定行为的调度、事务和权限。

## 外部材料支持什么

核对过的短摘录、跳转地址和访问日期在 [资料记录](../evidence/project/design-references-2026-09-20.md)。

- [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)说明技能可以根据描述隐式调用，正文按需加载；[AGENTS 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明项目指令的发现机制。它们支持精简当前路由设计，不证明某个技能实际触发过多少次，更不证明模型能力变化。
- [Diátaxis](https://diataxis.fr/)强调文档服务读者需要；其[使用说明](https://diataxis.fr/how-to-use-diataxis/)明确不把框架当空目录计划。[Explanation](https://diataxis.fr/explanation/)强调建立关系并保持范围。这支持判断每层的独立用途、让综合从内容中生长；本项目不照搬它的四类产品文档目录。
- [Nygard 的决策记录原文](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions)支持保留被替代决定及当时理由。它没有要求本项目采用完整 ADR 流程，或把每次修改变成一项正式决定。

这些都是产品说明或经验性文档设计资料。本次没有做模型注意力、读取成本或写作质量的受控评估；架构优劣仍需由实际研究使用来检验。

## 三个关键设计选择

**综合要增加关系，不能只增加压缩。** Analysis 围绕一个问题推理；Domain 把一组问题连成可连续理解的主题，说明它们怎样相互约束。它可以有未决争议，但不应该由待办清单、来源库存或零散结论组成。主题包的价值是统一解释的能力，不是文档更短。

**阅读聚焦要保住关键依赖。** 对源码，以相关信息和状态的实际路径为中心；对论文，以相关机制及证据成立条件为中心。背景若只帮助复查某个部件，可以链接；若决定理解是否正确，就在主文说明。正文不是摘要索引，附件不是隐藏限制的地方。

**降低入口负担，同时保留发现能力。** AGENTS 只提供行动边界和读取路由，README 提供现有材料导航。取消每轮加载 Domain 与 THESIS，避免初步假设被频繁重复成默认解释。索引指向材料，不再维护一份平行的结论清单；用户目标与本轮问题决定本次需读什么。

## 用具体案例检查边界

| 材料或动作 | 归属与理由 |
|---|---|
| 固定版本的仓库或论文转换文本 | Sources，供回查对象，不写入我方推论 |
| 追踪某 Agent 的工具输出到消息组装 | Deepdive，以对象内真实路径为组织中心 |
| 对象稿里指出一个预算不公平的问题 | 仍留 Deepdive，局部评价不需要跨目录 |
| 多个实验的预算差异是否解释效果排名 | Analysis，形成需要独立比较的问题 |
| 一个项目的一般网络服务器配置 | 通常略过；必要背景才附在该对象中 |
| 重试会导致已删除记忆再次写入 | Deepdive 主文，后台机制直接影响记忆行为 |
| 论文的通用优化器推导 | 按需背景；若该算法决定记忆更新，则相关部分回到主文 |
| 跨表示、检索、更新、调度解释持续任务的状态管理 | 有材料支持且关系讲通时成为 Domain 主题，不能只排链接 |
| 一组初步定义、工作假设和实验方案 | Analysis，不因长期有用就自动归 Domain |
| 为什么本轮取消 Entries | Dialogue 中的决定；诊断与替代方案在本篇；现行结构在 Architecture |
| 以后教材怎样选例子、展开公式 | TRADEOFFS；某次实际编排在 Output |
| 产品手册中的短操作条目 | 该 Output 直接组织，不倒逼通用条目层 |

这些是对职责的人工检查案例，不是新建的测试框架。遇到真实材料越界，应先判断是否需要调整范围或合并文章，不为了维持目录对称拆出更多文档。

## 暂不采用的选择与重新考虑的条件

不把 Dialogue 和研究分析全部混成笔记库：历史语境与可修订解释的读取需要仍不同。不把 Domain 当成任何“有用认识”的容器：会重新混入微观推演与过程管理。不把所有后台细节强制挪走：有些正是关键机制。不另建维护手册替代技能：会恢复同一份重复规则。

如果以后实际的多产物构建反复需要稳定中间结构，再按具体任务生成可追溯数据；如果主题稿仍只是在摘要分析，就回到问题研究，不勉强保留综合；如果旁支经常被所有读者共同读取，就考虑并回核心。改结构的依据是出现了真实摩擦，不是提前满足未来想象。
