# 一、怎么读这批 Survey

## 1. 典型章节骨架

这五篇都是综述，骨架高度相似，但每篇的重心不同。读的时候不必平均用力。

| 章节 | 读的时候抓什么 | 能否快扫 |
| :--- | :--- | :--- |
| **Abstract** | 作者用哪几个轴切分领域；贡献动词是 categorize、formalize、unify 还是 survey | 可快扫，但要抄下轴 |
| **Introduction** | 缺口句：existing surveys … overlook / remain fragmented；以及末尾的 contributions 列表 | 精读最后两段 |
| **Related Work / Positioning** | 作者把自己和谁区分开（尤其和 RAG、LLM memory、context engineering 的边界） | 可快扫，只抓区分句 |
| **Taxonomy / Framework** | 分类轴、每一类的定义句、分类图 | **精读** |
| **Per-category 展开** | 每类的定义 + 代表系统 + 一句 limitation | 按需查，不必顺读 |
| **Benchmarks & Evaluation** | 指标定义、表的列、benchmark 覆盖了哪些能力 | **精读表头** |
| **Open Problems** | 反复出现的那几个名词（consolidation、forgetting、trustworthiness…） | 精读小标题 |
| **Conclusion** | 作者最终立场，常与 Introduction 的缺口句呼应 | 快扫 |

## 2. 五篇的骨架差异

| 论文 | 主切分轴 | 骨架特征 |
| :--- | :--- | :--- |
| **MemMech** | sources / forms / operations | 早期三分法：memory writing、management、reading；forms 只分 textual 与 parametric |
| **Rethink** | 两种形式（parametric / contextual）× 六种操作 | 操作定义最细：consolidation、updating、indexing、forgetting、retrieval、condensation |
| **AgeMem** | forms / functions / dynamics | 先划边界（vs LLM memory、RAG、context engineering），再讲载体、功能、生命周期 |
| **AgentMem** | substrate / cognitive mechanism / subject | 载体与认知类型双轴，另有 user-centric vs agent-centric 的主体轴 |
| **AutoMem** | temporal scope / representational substrate / control policy | 形式化最强：write–manage–read 循环 + POMDP 类比 + 五类机制 |

## 3. 先看哪三处

如果只有二十分钟，按这个顺序看三处：

1. **Taxonomy 章的开头三段 + 分类图**。它决定全文坐标。例如 AgeMem 的 §3 先给出 token-level / parametric / latent 三种 forms，后面所有系统都往这三个格子里放。
2. **Evaluation 章的指标表或 benchmark 表的表头**。它决定"用什么衡量"。例如 AgentMem 的 Table 3 把指标分成 accuracy-based、similarity-based、LLM-as-a-judge 三排；AutoMem 的 Table 2 用 √ / - 标出 benchmark 是否支持 multi-session、agentic tasks、forgetting。
3. **Open Problems 的小标题**。它决定作者认为哪里没解决，也往往是这批论文互相引用最密集的地方。

## 4. 一条省力的阅读路线

- 先用 **AgeMem §2.3** 建立边界：agent memory 与 LLM memory、RAG、context engineering 各是什么。
- 再用 **AutoMem §3** 建立三维坐标：temporal scope、representational substrate、control policy。
- 然后用 **Rethink §2.4** 补齐操作词表：六个 operation 的定义都在这里。
- 需要查载体时翻 **AgentMem §3.1**（substrate）与 **AgeMem §3**（forms）。
- 需要查指标与 benchmark 时翻 **AgentMem §7** 的三张表与 **AutoMem §5**。
- **MemMech** 留作早期对照：它的 writing / management / reading 三分法后来被 Rethink 明确说成"misses some operations like indexing"（Rethink §1，L23 附近）。

# 二、术语

六组：基座概念 / 载体与计算 / 记忆操作 / 记忆类型 / 评测与指标 / 工程实现。组内按逻辑或字母顺序。

## A. 基座概念

### memory

- **释义**：系统跨时间保留、组织并在需要时取用信息的整体能力；在 agent 语境里指可被写入、维护、读取的状态，而不是单次输入。
- **原句**：> "Memory generally refers to a system’s ability to retain, organize, and exploit information over time." —— **AgentMem §2.2（L101）**
- **易混**：**memory vs context**。context 是本次调用窗口内的 token 序列；memory 是跨 step / session 仍存在的状态，可以被换出窗口再取回。

### agent memory

- **释义**：agent 在任务内与任务间形成、演化并检索的记忆系统；AgeMem 把它与 LLM 内部记忆、RAG、context engineering 三者明确分开。
- **原句**：> "agent memory governs what the agent knows, what it has experienced, and how these elements evolve over time." —— **AgeMem §2.3.3（L298）**
- **易混**：**agent memory vs LLM memory**。前者跨多轮、多任务、可演化；后者指 KV cache、长上下文处理机制或模型结构改动。

### LLM memory / LLM-internal memory

- **释义**：直接干预模型内部状态的记忆，例如管理 KV cache、设计长上下文机制、修改模型架构；AgeMem 把它排除在 agent memory 之外。
- **原句**：> "managing the transformer’s key–value (KV) cache, designing long-context processing mechanisms, or modifying model architectures" —— **AgeMem §2.3.1（L268）**
- **易混**：与 **agent memory** 的边界正是五篇冲突最集中的地方，见文末"用法冲突"第 1、2 条。

### context window

- **释义**：模型单次前向能读到的 token 上限；这批论文把它当作容量约束，而不是记忆本身。
- **原句**：> "Longer context enlarges working memory but does not provide persistent cross-session storage, structured knowledge organization, selective retrieval from months of history, or governance mechanisms like deletion and access control." —— **AutoMem §8（L397）**
- **易混**：**context window vs memory**。窗口变大只是扩大 working memory；它不提供跨 session 持久化、结构化组织、选择性检索或删除治理。

### stateless

- **释义**：LLM 每次调用不保留上一次的内部状态；agent 必须显式把状态写进 context 或外部存储，才能跨步延续。
- **原句**：> "Since LLMs are inherently stateless, working memory provides the mechanism through which such state is explicitly carried and updated across interaction steps." —— **AgentMem §3.2.2（L188）**
- **易混**：**stateless vs memoryless**。stateless 描述模型调用本身无状态；memoryless baseline 指系统没有接任何外部记忆模块。

### long-horizon

- **释义**：任务跨度长到单个 context window 装不下，需要跨多步、多 session 维持状态。
- **原句**：> "real utility in long-horizon, dynamic, and user-dependent settings such as agentic coding, deep research, and computer use" —— **AgentMem Abstract**
- **易混**：**long-horizon vs long-context**。前者是任务时间跨度；后者是单次输入长度。长上下文不自动带来 long-horizon 能力。

### trial / inside-trial / cross-trial

- **释义**：MemMech 用 trial 指一次完整任务尝试；inside-trial 是本次尝试内的短期信息，cross-trial 是跨尝试积累的经验。
- **原句**：> "In a narrow sense, the memory of the agent is only relevant to the historical information within the same trial." —— **MemMech §3.2（L157）**
- **易混**：**trial vs session**。trial 是一次任务试验，带成败；session 是一段对话或交互时段，不一定有任务边界。

### catastrophic forgetting

- **释义**：更新参数学新知识时覆盖旧知识，导致原有能力下降。
- **原句**：> "it also raises concerns about catastrophic forgetting, where LLMs may forget the original knowledge because of updating their parameters." —— **MemMech §5.2.2（L306）**
- **易混**：**catastrophic forgetting vs forgetting（operation）**。前者是训练或参数更新的副作用；后者是记忆系统主动抑制、删除条目的操作。

### continual learning

- **释义**：增量纳入新知识，同时抑制遗忘；在 agent memory 里常作为长期目标出现。
- **原句**：> "Continual Learning incrementally incorporates new knowledge while mitigating catastrophic forgetting." —— **Rethink §2.4.2（L287）**
- **易混**：**continual learning vs lifelong learning**。前者强调"学了新的、不忘旧的"；后者强调跨任务持续积累与迁移，常用 lifelong-learning benchmarks 来测。

### RAG

- **释义**：生成器外接一个非参数检索索引，在推理时取回文档片段再生成。
- **原句**：> "pairing a generator with a non-parametric retrieval index produces strong results on knowledge-intensive tasks" —— **AutoMem §4.2（L173）**
- **易混**：**RAG vs retrieval**。RAG 是"检索 + 生成"的完整管线；retrieval 只是取回条目这个操作。RAG 通常面向静态外部知识，不维护跨轮演化的记忆。

### context engineering

- **释义**：把 context window 当作受限计算资源来系统设计输入内容的方法论。
- **原句**：> "Context engineering is a systematic design methodology that treats the context window as a constrained computational resource." —— **AgeMem §2.3.3（L292）**
- **易混**：**context engineering vs agent memory**。前者管理"这次窗口里放什么"；后者管理"跨时间留下什么"。

### self-evolution / self-evolving

- **释义**：agent 把自己的执行经验写成记忆，再用这些记忆改变后续策略，形成闭环。
- **原句**：> "agent memory is treated as an integrated hierarchy whose operations, from selection and retention to consolidation and skill formation, can themselves be designed, optimized, and, increasingly, learned from the agent’s own interactions." —— **AgentMem §2.2（L103）**
- **易混**：**self-evolution vs continual learning**。前者强调记忆→策略的闭环；后者强调知识不遗忘地累积。

### grounding

- **释义**：把生成内容锚定到检索到的证据或记忆，使 claim 有来源支撑。
- **原句**：> "appending those snippets to the prompt as grounding context" —— **AgentMem §3.1.1（L128）**
- **易混**：**grounding vs retrieval**。retrieval 是把条目取回来；grounding 是生成时真的依据这些条目。取回了但没用上，不算 grounded。

## B. 载体与计算

### substrate

- **释义**：承载记忆的物理或表示层，例如文本、向量库、图、参数、隐状态。
- **原句**：> "Memory substrates serve as the essential mechanisms for retaining historical knowledge" —— **AgentMem §3.1（L113）**
- **易混**：**substrate vs form**。substrate 偏"存在哪里"；form 偏"以什么单位被表示"（token、参数、latent）。

### external memory

- **释义**：存放在模型参数或推理状态之外的记忆载体，可被检索、检查、编辑。
- **原句**：> "External memory refers to any memory substrate that stores the knowledge, information, and past experience outside the agent model’s parameter or state." —— **AgentMem §3.1.1（L119）**
- **易混**：**external vs non-parametric**。external 是位置描述；non-parametric 是"不写进权重"。外部记忆通常非参数，但非参数不一定在外部（例如 latent state）。

### internal memory

- **释义**：存放在模型架构内部的记忆，包括参数里的持久知识和推理时的工作状态。
- **原句**：> "Internal memory refers to the information stored directly within the model’s architecture, encompassing both the persistent knowledge embedded in its parameters (i.e., parametric memory) and the working states utilized during inference." —— **AgentMem §3.1.2（L140）**
- **易混**：**internal vs parametric**。parametric 只是 internal 的一个子集；KV cache 是 internal 但不是 parametric。

### parametric memory

- **释义**：知识被编码进模型参数，推理时通过前向计算隐式访问，不需要外部检索。
- **原句**：> "Parametric Memory refers to the knowledge implicitly stored within model internal parameters [21, 233, 289]." —— **Rethink §2.1（L78）**
- **易混**：**parametric vs latent**。parametric 存在权重里；latent 存在隐状态、激活或连续表示里，不一定改权重。

### contextual memory

- **释义**：模型参数之外的显式外部信息，可结构化（图、表、轨迹）或非结构化（文本、向量、音视频）。
- **原句**：> "Contextual Memory denotes explicit, external information that complements model parameters" —— **Rethink §2.1（L80）**
- **易混**：**contextual memory vs context window**。contextual memory 是外部存储的显式信息；context window 是本次输入的长度预算。

### non-parametric

- **释义**：不把记忆写进模型权重，而放在外部索引、数据库或可检索载体中。
- **原句**：> "Systems with parametric memory (fine-tuned weights) and nonparametric memory (external stores) show different failure profiles." —— **AutoMem §5.5（L281）**
- **易混**：**non-parametric vs external**。前者说"没写进参数"；后者说"放在模型之外"。两者常重合，但概念不同。

### token-level memory

- **释义**：记忆被表示为离散、可单独访问和修改的单元；token 在这里不限于文本，也包括视觉 token、音频帧。
- **原句**：> "Token-level memory stores information as persistent, discrete units that are externally accessible and inspectable." —— **AgeMem §3.1（L324）**
- **易混**：**token-level vs textual**。textual 只指自然语言文本；token-level 还包括视觉、音频等任何可离散读写的单元。

### latent memory

- **释义**：记忆隐式地存在于模型内部表示中，例如 KV cache、激活、hidden states、latent embeddings，而不是显式 token 或独立参数集。
- **原句**：> "Latent memory refers to memory that is carried implicitly in the model’s internal representations (e.g., KV cache, activations, hidden states, latent embeddings), rather than being stored as explicit, human-readable tokens or dedicated parameter sets." —— **AgeMem §3.3（L481）**
- **易混**：**latent vs parametric**。latent 是推理时的连续内部状态，可随交互更新；parametric 是训练后固化在权重里的知识。

### KV cache

- **释义**：Transformer 自回归解码时缓存的历史 key–value 对，避免重复计算；它是推理时状态，不是持久知识。
- **原句**：> "In transformer-based LLMs, the KV cache is a transient, inference-time memory that speeds up autoregressive decoding" —— **AgentMem §3.1.2（L146）**
- **易混**：**KV cache vs working memory**。KV cache 是 working memory 的一种实现载体；working memory 是更上位的功能概念。它的归类在五篇里不一致，见冲突节第 1 条。

### weight memory

- **释义**：把记忆直接写进参数，之后模型不检索外部 context 也能"想起"。
- **原句**：> "Weight memory is implemented by writing memory into parameters, so the model later recalls the information without retrieving external context." —— **AgentMem §3.1.2（L142）**
- **易混**：**weight memory vs parametric memory**。基本同义；weight memory 更强调"写入动作"，parametric memory 更强调"存在形式"。

### adapter / LoRA

- **释义**：在不改原模型权重的前提下，用额外的小参数集承载记忆；属于 external parametric memory。
- **原句**：> "External Parametric Memory: Memory stored in additional or auxiliary parameter sets, such as adapters, LoRA modules, or lightweight proxy models." —— **AgeMem §3.2（L440）**
- **易混**：**adapter / LoRA vs fine-tuning**。前者只训练附加参数；后者可以改原权重。两者都属于 parametric，但部署与遗忘特性不同。

### vector index

- **释义**：把记忆条目和查询编码到同一向量空间，用近似最近邻取回 top-k，再拼进 prompt。
- **原句**：> "Vector index is implemented by embedding memory items or queries into a shared vector space, running approximate nearest-neighbor search to fetch top-k items, and appending those snippets to the prompt as grounding context" —— **AgentMem §3.1.1（L128）**
- **易混**：**vector index vs knowledge graph**。前者按语义相似度取回；后者按显式关系遍历，能回答"谁导致谁"，但需要 schema。

### text-record memory

- **释义**：把长期记忆当作一组显式文本文档，用关键词或轻量字符串匹配检索，优先透明与可控。
- **原句**：> "Text-record memory treats an agent’s long-term memory as a set of explicit text documents rather than embeddings or graphs" —— **AgentMem §3.1.1（L130）**
- **易混**：**text-record vs token-level**。text-record 是存储格式（文档）；token-level 是表示粒度（离散单元）。文本记录也可以是 token-level 的。

### structural store

- **释义**：用显式 schema（关系表、图、树）存记忆，通过符号查询或遍历取回。
- **原句**：> "Structural store is implemented by storing memories in explicit schemas and retrieving them via symbolic queries or traversal" —— **AgentMem §3.1.1（L132）**
- **易混**：**structural store vs vector index**。前者靠 schema 与关系查询；后者靠 embedding 相似度。前者精确但需要预先设计结构。

### flat / planar / hierarchical memory

- **释义**：AgeMem 按 token 单元之间的拓扑把 token-level memory 分三级：1D 无拓扑、2D 单层结构、3D 多层带跨层链接。
- **原句**：> "Flat Memory (1D): No explicit inter-unit topology." / "Planar Memory (2D): A structured but single-layer organization within one plane" / "Hierarchical Memory (3D): Structured across multiple layers with inter-layer links" —— **AgeMem §3.1（L332–336）**
- **易混**：**hierarchical memory vs hierarchical store**。前者是 token 单元的组织拓扑（3D）；后者是 AgentMem 里的多存储单元架构，每个单元有自己的 schema。两者都叫 hierarchical，但切分对象不同。

## C. 记忆操作

### memory writing

- **释义**：把原始观察投影成真正写入存储的记忆内容，通常伴随筛选、压缩与结构化。
- **原句**：> "This operation aims to project the raw observations into the actually stored memory contents" —— **MemMech §3.4（L167）**
- **易混**：**writing vs storage**。writing 是"把什么写成记忆"的转换动作；storage 是"放在哪个载体"的工程选择。

### memory management

- **释义**：对已存记忆做再加工，例如抽象出高层概念、合并相似条目、遗忘无关内容。
- **原句**：> "Memory Management. This operation aims to process the stored memory information to make it more effective" —— **MemMech §3.4（L175）**
- **易混**：**management vs updating**。management 是上位操作，包含合并、摘要、遗忘；updating 专指用新知识改写旧条目。

### memory reading

- **释义**：从记忆中取出支撑下一步行动所需的信息。
- **原句**：> "Memory Reading. This operation aims to obtain important information from the memory to support the next agent action." —— **MemMech §3.4（L183）**
- **易混**：**reading vs retrieval**。reading 是 MemMech 的三分法用语，偏"取用"；retrieval 在 Rethink 里是六个原子操作之一，偏"定位并访问"。

### encoding

- **释义**：信息被转换成可存储的表示，并与后续检索路径建立关联的阶段。
- **原句**：> "Memory encoding governs how information is transformed into storable representations and linked for later retrieval." —— **Rethink §2.4.1（L106）**
- **易混**：**encoding vs consolidation**。encoding 是"变成可存的形式"；consolidation 是"把短时经验整合成持久记忆"。

### consolidation

- **释义**：把短时经验整合进持久记忆，使其成为可复用的长期表征。
- **原句**：> "It encodes interaction histories (e.g., dialogs, trajectories) into durable forms such as model parameters" —— **Rethink §2.4.1（L108）**
- **易混**：**consolidation vs summarization**。summarization 只压缩文本长度；consolidation 强调跨时间把多条经验整合成更稳定、更高层的记忆。AutoMem 也提醒：episode→semantic 的 consolidation 很少自动发生（§3.1，L115）。

### indexing

- **释义**：为记忆构造辅助访问码（实体、属性、内容表示等），让检索能沿索引路径走，而不只靠相似度。
- **原句**：> "constructs auxiliary codes ... that serve as access points to stored memory." —— **Rethink §2.4.1（L114）**
- **易混**：**indexing vs retrieval**。indexing 发生在写入/整理阶段，构造访问路径；retrieval 发生在读取阶段，使用这些路径。

### updating

- **释义**：用新知识重新激活并改写已有记忆表征，处理冲突或补充信息。
- **原句**：> "Updating [136] reactivates existing memory representations" —— **Rethink §2.4.2（L122）**
- **易混**：**updating vs refresh**。updating 改内容；refresh 只改条目的显著度与可访问性，不动核心内容（AgentMem §4.1.3，L296）。

### forgetting

- **释义**：有选择地抑制或删除过时、无关、有害的记忆内容，以腾出容量并降低干扰。
- **原句**：> "Forgetting [49, 285] is the ability to selectively suppress memory content" —— **Rethink §2.4.2（L132）**
- **易混**：**forgetting vs forgetting（training）**。这里的 forgetting 是主动操作；catastrophic forgetting 是参数更新的副作用。

### retrieval / retrieve

- **释义**：根据输入定位并访问相关记忆片段，供下游生成、grounding 或决策使用。
- **原句**：> "Retrieval is the process of identifying and accessing relevant information from memory in response to inputs" —— **Rethink §2.4.3（L142）**
- **易混**：**retrieval vs RAG**。retrieval 是单个操作；RAG 是把检索结果接进生成器的完整管线，且通常面向静态知识库。

### condensation

- **释义**：在推理时把取回的原始长记忆压成结构化、紧凑的 context，按压缩比 α 保留显著信息、丢弃冗余。
- **原句**：> "Memory Condensation is the inference-time process of transforming raw, retrieved long-term memories into a structured and compact context for the LLM." —— **Rethink §2.4.3（L188）**
- **易混**：**condensation vs consolidation**。Rethink 自己点明：consolidation 发生在记忆构建阶段，condensation / compression 发生在推理阶段。

### summarization

- **释义**：把细粒度交互记录压成更短、更抽象的表示，通常在任务完成后或周期性执行。
- **原句**：> "many agent systems perform summarization periodically or after task completion, consolidating interaction histories into semantic or hierarchical memory suitable for long-term storage" —— **AgentMem §4.1.4（L300）**
- **易混**：**summarization vs condensation**。两者都压缩；summarization 更偏"写进长期记忆"，condensation 更偏"为本次推理准备 context"。

### formation

- **释义**：把工具输出、推理轨迹、计划、反馈等产物筛选成记忆候选，而不是原样存下整段历史。
- **原句**：> "selectively transforms these artifacts into memory candidates, extracting information with potential future utility rather than storing the entire interaction history verbatim." —— **AgeMem §2.2（L207）**
- **易混**：**formation vs writing**。formation 是 AgeMem 生命周期算子 F；writing 是 MemMech 的三操作之一。两者都指"写入前的内容转换"，但 formation 更强调"候选筛选"。

### evolution

- **释义**：把新形成的候选整合进已有记忆库：合并冗余、消解冲突、丢弃低价值信息、重构以利检索。
- **原句**：> "which may consolidate redundant entries" / "resolve conflicts" / "discard low-utility information" / "restructure memory for eficient retrieval" —— **AgeMem §2.2（L221）**
- **易混**：**evolution vs updating**。evolution 是生命周期算子 E，涵盖合并、冲突消解、丢弃、重构；updating 只是其中"改写旧条目"的一类。

### reflection

- **释义**：任务失败后让 agent 写一段自然语言复盘，并在下一次尝试时把它前置到 prompt，作为经验使用。
- **原句**：> "after failing a task, have the agent write a natural language post-mortem, then prepend it to the prompt on the next attempt." —— **AutoMem §4.3（L189）**
- **易混**：**reflection vs summarization**。reflection 产出的是因果/策略性的自我批评；summarization 产出的是内容压缩。前者可能引入错误并自我强化（AutoMem §4.3，L195）。

### distillation

- **释义**：把历史轨迹转成可复用的方案、策略或技能，降低对原始轨迹回放的依赖。
- **原句**：> "Experience distillation and metacognitive control involve transforming historical trajectories into reusable schemes" —— **AgentMem §3.2.5（L228）**
- **易混**：**distillation vs summarization**。distillation 的目标是"可复用模式"；summarization 的目标是"更短的描述"。前者通常跨多条轨迹。

### unlearning

- **释义**：在参数记忆中定向移除特定知识，同时尽量保留无关知识。
- **原句**：> "Parametric memory unlearning enables selective forgetting by removing specific memory while retaining unrelated memory." —— **Rethink §2.4.2（L291）**
- **易混**：**unlearning vs deletion**。deletion 删的是外部存储条目；unlearning 删的是已经进入权重的知识，需要改参数。

## D. 记忆类型

### short-term memory

- **释义**：为即时使用而暂存的信息；在 LLM agent 里通常指 KV cache 或当前 context window。
- **原句**：> "Short-term Memory refers to the temporary storage of information for immediate use" —— **Rethink §2.2（L88）**
- **易混**：**short-term vs working**。short-term 偏"存多久"；working 偏"在当下被操作和更新"。两者常重叠，但 working 更强调主动控制。

### long-term memory

- **释义**：跨较长时间保留信息的认知系统，容量近乎不受限；在 agent 里通常落在外部存储或参数中。
- **原句**：> "Long-term Memory refers to a cognitive system with virtually unlimited capacity for storing information over extended periods of time" —— **Rethink §2.2（L86）**
- **易混**：**long-term vs external**。long-term 是时间尺度；external 是空间位置。长期记忆可以在参数里（internal），外部记忆也可以只服务单次任务。

### working memory

- **释义**：在单次 episode 内对 context 进行主动管理、操作和更新的机制集合，而不只是被动缓存。
- **原句**：> "Whatever fits inside the current context window constitutes the agent’s working memory." —— **AutoMem §3.1（L111）**
- **易混**：**working vs short-term**。AutoMem 用窗口来定义 working；AgeMem 则把它定义为"单 episode 内主动管理 context 的机制"（§4.3，L756）。前者偏容量，后者偏控制。

### sensory memory

- **释义**：对刚到达的感知信号（视觉、音频、触觉等）的短暂保留，尚未进入工作记忆。
- **原句**：> "Sensory memory refers to the temporary retention of incoming perceptual signals" —— **AgentMem §3.2.1（L170）**
- **易混**：**sensory vs working**。sensory 是原始感知的短留；working 是对已选中信息进行操纵的工作区。AgentMem 的表 1 用 "What is perceived" 对 "What is currently handled" 区分。

### episodic memory

- **释义**：按时间与环境情境存储具体事件、交互轨迹和反馈，支持跨 session 回看"发生了什么"。
- **原句**：> "Episodic memory refers to a form of long-term memory dedicated to the persistent storage of an agent’s interactive experiences across sessions." —— **AgentMem §3.2.3（L198）**
- **易混**：**episodic vs experiential**。episodic 是"具体事件记录"；experiential 是 AgeMem 的功能类，涵盖 case / strategy / skill 三层抽象。前者是内容类型，后者是抽象层级体系。

### semantic memory

- **释义**：存储抽象事实、一般概念和结构化知识，脱离具体情境，可跨任务复用。
- **原句**：> "Semantic memory refers to a form of long-term memory dedicated to the storage of abstract facts, general concepts, and structured knowledge." —— **AgentMem §3.2.4（L212）**
- **易混**：**semantic vs factual**。semantic 强调"去情境化的知识"；factual 强调"可陈述的事实"，包含用户事实与环境事实，未必已抽象。

### procedural memory

- **释义**：存储"怎么做"的操作技能、执行策略和自动化流程，可抽象成可复用动作模式。
- **原句**：> "Procedural memory refers to a form of long-term memory dedicated to how to perform tasks." —— **AgentMem §3.2.5（L224）**
- **易混**：**procedural vs skill-based**。procedural 是认知类型；skill-based 是 AgeMem 对 experiential memory 的第三层抽象，指可调用、可验证的执行单元。

### factual memory

- **释义**：存储并取回关于过去事件、用户特定信息、外部环境状态的显式陈述性事实。
- **原句**：> "Factual memory refers to the capacity of an agent to store and retrieve explicit, declarative facts about past events, user-specific information, and the state of the external environment." —— **AgeMem §4.1（L609）**
- **易混**：**factual vs semantic**。factual 是"可陈述的事实"这一范围；semantic 是"去情境化、可跨情境复用"的那部分知识。factual 可以很具体、很临时。

### experiential memory

- **释义**：把历史轨迹、蒸馏策略和交互结果编码成持久、可检索表征的机制。
- **原句**：> "Experiential memory encapsulates the mechanism by which agents encode historical trajectories, distilled strategies, and interaction outcomes into durable, retrievable representations." —— **AgeMem §4.2（L682）**
- **易混**：**experiential vs episodic**。experiential 是功能分类，按抽象层级分 case / strategy / skill；episodic 只是其中最低层"原始事件记录"的认知类型名。

### case-based memory

- **释义**：保存最少加工的原始事件记录，保留情境与结果的原始对齐，供直接回放或作为 in-context 示例。
- **原句**：> "Case-based memory stores minimally processed records of historical events, prioritizing fidelity to ensure that episodes can be replayed or reused as in-context exemplars." —— **AgeMem §4.2.1（L704）**
- **易混**：**case-based vs episodic**。case-based 是抽象层级（低抽象、高保真）；episodic 是内容类型（具体事件）。一个 case 往往由多条 episodic 记录组成。

### strategy-based memory

- **释义**：从轨迹中蒸馏出可迁移的推理模式、工作流和高层洞见，用来约束规划，而不是回放原始记录。
- **原句**：> "strategy-based memory extracts transferable knowledge of how to act, encompassing reusable reasoning patterns, task decompositions, insights, abstractions, and cross-situational workflows." —— **AgeMem §4.2.2（L714）**
- **易混**：**strategy-based vs skill-based**。strategy 是"怎么想/怎么规划"，不可直接执行；skill 是"能调用/能验证"的执行单元。

### skill-based memory

- **释义**：把抽象策略落成可调用、可验证、可组合的执行能力，例如代码片段、函数、API、MCP。
- **原句**：> "Skill memory captures an agent’s procedural capacity and operationalizes abstract strategy into verifiable actions." —— **AgeMem §4.2.3（L726）**
- **易混**：**skill-based vs procedural**。skill-based 是存储与调用形态；procedural 是认知功能类型。前者强调"可执行"，后者强调"会做"。

### user-centric memory

- **释义**：围绕特定用户的事实与偏好抽象，跨 session、跨领域演化，用于个性化对齐。
- **原句**：> "User-centric memory refers to an abstraction of user-specific facts and preferences" —— **AgentMem §3.3.1（L245）**
- **易混**：**user-centric vs agent-centric**。前者优化"这个用户的满意度"；后者优化"agent 自己在任务中的可复用经验"，不绑定某个用户。

### agent-centric memory

- **释义**：agent 从自身任务执行历史中积累的蒸馏知识、技能和任务先验，可跨任务、跨用户复用。
- **原句**：> "Agent-centric memory refers to distilled knowledge, skills, and operational task priors that an agent accumulates through its own history of task execution" —— **AgentMem §3.3.2（L261）**
- **易混**：**agent-centric vs experiential**。两者都来自 agent 自身经验；agent-centric 是"服务对象"轴，experiential 是"内容抽象层级"轴。一个 agent-centric 记忆可以是 case、strategy 或 skill。

## E. 评测与指标

### benchmark vs dataset

- **释义**：benchmark 是"任务 + 环境 + 协议 + 指标"的整体评测设置；dataset 只是其中被使用的数据集合。
- **原句**：> "we survey representative benchmarks and datasets that have been used (or could be used) to evaluate the memory, long-term, continual-learning, or long-context capabilities of LLM-based agents." —— **AgeMem §6.1（L1081）**
- **易混**：**benchmark vs dataset**。说"在 LoCoMo 上评测"通常指整套 benchmark；说"用某个 dataset 训练"只指数据。综述里两者常被混着列，读表时要看列名是 Name 还是 Data。

### direct / indirect evaluation

- **释义**：direct evaluation 把记忆模块当独立组件单独测；indirect evaluation 通过端到端 agent 任务间接测。
- **原句**：> "direct evaluation, which independently measures the capability of the memory module. (2) indirect evaluation, which evaluates the memory module via end-to-end agent tasks." —— **MemMech §6（L363）**
- **易混**：**direct vs indirect**。direct 归因更干净，但缺真实使用场景；indirect 更真实，但成绩可能被推理、工具、prompt 等其他因素稀释。

### ablation

- **释义**：去掉或替换某个组件后重跑，用性能差来归因该组件的贡献。
- **原句**：> "nearly all the memory-equipped agents can evaluate the effect of memory by ablation studies, comparing the performance between with/without memory modules." —— **MemMech §6.2.4（L451）**
- **易混**：**ablation vs baseline**。ablation 是"拿掉自己的一部分"；baseline 是"换一个对照系统"。两者都出现在结果表，但回答的问题不同。

### Recall@K

- **释义**：top-K 检索结果中覆盖了多少相关条目；衡量"该取回的有没有取回"。
- **原句**：> "Recall@K measures the fraction of relevant items that appear among the top-K retrieved results" —— **AgentMem §7.1（L461）**
- **易混**：**Recall@K vs Precision@K**。Recall 看"相关条目被覆盖的比例"；Precision 看"取回的 K 条里有多少相关"。记忆系统通常更怕漏（低 Recall），但取太多又会引入噪声。

### NDCG@K

- **释义**：按位置折损的排序质量指标，越相关的条目排得越靠前得分越高。
- **原句**：> "MAP and NDCG@K, on the other hand, also take into account the quality of the ranking and give systems that put relevant memories first a higher score" —— **AgentMem §7.1（L461）**
- **易混**：**NDCG@K vs Recall@K**。Recall 不关心顺序，只关心是否在 top-K 里；NDCG 关心相关条目排在第几位。

### MAP

- **释义**：Mean Average Precision，先算每个相关位置上的 precision 再平均，最后跨 query 平均。
- **原句**：> "Averages precision at ranks of relevant items, then averages across queries." —— **AgentMem Table 3（L455）**
- **易混**：**MAP vs NDCG**。两者都看排序；MAP 基于 precision 的算术平均，NDCG 用折损增益并归一到理想排序。

### F1

- **释义**：precision 与 recall 的调和平均，用来给部分正确的答案计分，而不是要求完全匹配。
- **原句**：> "F1 relaxes the exact-match criterion by giving credit for partial overlap at the token level." —— **AgentMem Table 3（L461）**
- **易混**：**F1 vs accuracy**。accuracy 要求整体答对；F1 在 token 级给部分重叠计分，适合答案有措辞差异的 QA。

### Pass@K

- **释义**：采样 K 次尝试中至少有一次正确的概率；衡量"多试几次能不能做对"。
- **原句**：> "Probability that at least one correct solution appears among K sampled attempts" —— **AgentMem Table 3（L455）**
- **易混**：**Pass@K vs Pass^k**。Pass@K 是"K 次里有一次成功"；Pass^k（τ-Bench 用）是"连续 k 次都成功"，后者更严，衡量稳定性而非上限。

### success rate

- **释义**：在环境定义的成功判定下，完成任务的交互任务比例。
- **原句**：> "Success rate refers to the proportion of tasks that agents can successfully solve." —— **MemMech §6.2.4（L449）**
- **易混**：**success rate vs accuracy**。success rate 用于交互/具身任务，由环境 checker 判定；accuracy 用于有标准答案的问答。

### LLM-as-a-judge

- **释义**：用较强的 LLM 按 rubric 给开放输出打分，替代无法穷举的参考答案。
- **原句**：> "LLM-as-a-judge metrics are used when ground truth answers, or references, are incomplete, when multiple responses are acceptable, or when evaluation requires a rubric that is hard to encode as string matching" —— **AgentMem §7.1（L465）**
- **易混**：**LLM-as-a-judge vs exact match**。前者覆盖开放输出，但受 judge 模型与 prompt 影响；后者可复现，但无法处理合理 paraphrase。

### faithfulness / groundedness

- **释义**：判断回答中的 claim 是否真的由检索到的 context 或记忆支撑，而不只是语言流畅。
- **原句**：> "Faithfulness or Groundedness uses a judge to verify that claims are supported by retrieved context or memory" —— **AgentMem §7.1（L465）**
- **易混**：**faithfulness vs factuality**。faithfulness 是"是否忠于给定证据"；factuality 是"是否符合世界事实"。一段忠于错误记忆的回答可以 faithful 但不 factual。

### staleness

- **释义**：记忆条目已经过时、与当前世界状态不符；它是长期运行系统的主要失效模式之一。
- **原句**：> "Agent memory evaluation must jointly assess memory quality and decision quality, along with concerns that classical IR ignores entirely: staleness, contradiction, forgetting quality, and governance compliance." —— **AutoMem §5.1（L237）**
- **易混**：**staleness vs drift**。staleness 是单条记录"过期"；drift 是系统整体随时间"偏移"，可以由反复压缩或 schema 变化造成。

### false memory rate

- **释义**：系统在存储、更新或使用中引入编造或错误记忆的比例。
- **原句**：> "False Memory Rate measures how often systems introduce fabricated or incorrect memories" —— **AgentMem §7.1（L461）**
- **易混**：**false memory vs hallucination**。false memory 特指记忆库里的错误条目；hallucination 可以发生在生成阶段，即使记忆库是对的。

### test-time learning

- **释义**：不改参数，仅靠把经验写进记忆来提升后续任务表现。
- **原句**：> "TTL denotes test-time learning, where agents improve later performance by accumulating experience in memory without parameter updates." —— **AgentMem §7.2.2（L493）**
- **易混**：**test-time learning vs fine-tuning**。前者在推理期积累记忆；后者改参数。前者是 memory 的核心卖点，后者属于 parametric 路线。

## F. 工程实现

### write path

- **释义**：一条交互进入长期记忆前要经过的处理链：过滤低信号、规范化、去重、优先级打分、打元数据。
- **原句**：> "filtering to reject low-signal records, canonicalization to normalize dates, names, and quantities, deduplication to merge overlapping entries, priority scoring to rank records by task relevance and novelty, and metadata tagging" —— **AutoMem §7.1（L341）**
- **易混**：**write path vs memory writing**。write path 是工程管线；memory writing 是认知操作。前者包含后者，还包含清洗与元数据。

### read path

- **释义**：一次检索请求实际经过的优化链：是否检索、先粗后精、token 预算、缓存。
- **原句**：> "Practical read-path optimizations include: two-stage retrieval (fast BM25 or metadata filter → slower cross-encoder reranker)" —— **AutoMem §7.2（L347）**
- **易混**：**read path vs retrieval**。retrieval 是取回动作；read path 是整个读取侧的系统设计，包含"要不要取"和"取回后怎么塞进预算"。

### two-stage retrieval

- **释义**：先用便宜的 BM25 或元数据过滤召回，再用较慢的 cross-encoder 精排，兼顾延迟与精度。
- **原句**：> "two-stage retrieval (fast BM25 or metadata filter → slower cross-encoder reranker)" —— **AutoMem §7.2（L347）**
- **易混**：**two-stage retrieval vs hybrid retrieval**。two-stage 是"先粗后精"的级联；hybrid 是"同时用多种检索信号"再融合（AgeMem §5.3.3，L1055）。

### token budget

- **释义**：在固定 context 容量下，给记忆内容与当前任务内容分配 token 配额。
- **原句**：> "token budgeting that dynamically allocates context space between memory and current task" —— **AutoMem §7.2（L347）**
- **易混**：**token budget vs context window**。context window 是硬上限；token budget 是在上限内做的分配策略。

### eviction

- **释义**：容量满时按策略把某些记忆换出当前层或直接丢弃，例如按时间、重要性或访问频率。
- **原句**：> "each tier with different access patterns and eviction rules." —— **AutoMem §3.2（L137）**
- **易混**：**eviction vs forgetting**。eviction 是容量管理触发的置换；forgetting 可以是有意的语义删除。前者不一定因为"过时"，后者通常因为"不该再影响行为"。

### drift

- **释义**：记忆随时间偏离原始事实或当前世界状态；典型来源是反复摘要压缩与外部接口变化。
- **原句**：> "summarization drift. Each compression pass silently discards low-frequency details." —— **AutoMem §4.1（L163）**
- **易混**：**drift vs staleness**。staleness 是"这条记录旧了"；drift 是"系统整体在多次处理后偏了"。drift 可以在没有新事实的情况下发生。

### schema drift

- **释义**：外部 API 或数据结构改版后，记忆里存的使用模式失效；工具型 agent 的特有风险。
- **原句**：> "A practical hazard unique to this setting is schema drift: when an API updates its interface, stored usage patterns become invalid." —— **AutoMem §6.6（L323）**
- **易混**：**schema drift vs summarization drift**。前者由外部世界变化引起；后者由内部压缩过程引起。

### contradiction detection

- **释义**：发现新写入的事实与已有记忆冲突，并标记出来等待消解，而不是让两条并存的记录都被检索到。
- **原句**：> "contradiction detection (flag conflicts for resolution)" —— **AutoMem §7.3（L353）**
- **易混**：**contradiction vs staleness**。contradiction 是两条记录互相矛盾；staleness 是某条记录与当前世界不符。前者可以在两条都"曾经正确"时发生。

### observability

- **释义**：记录每次 write / read / update / delete 的时间、触发上下文与涉及记录，使记忆故障可复现、可归因。
- **原句**：> "every write, read, update, and delete should be recorded with timestamps, triggering context, and the records involved." —— **AutoMem §7.7（L383）**
- **易混**：**observability vs evaluation**。evaluation 在离线 benchmark 上打分；observability 在运行时留痕，用于定位"是检索错了、写入漏了，还是压缩丢了"。

### latency

- **释义**：一次记忆操作给端到端响应增加的时间；检索链路常是主要来源。
- **原句**：> "Retrieval pipelines can easily add 200–500ms." —— **AutoMem §7.4（L357）**
- **易混**：**latency vs cost**。latency 是响应延迟；cost 是 token、存储与计算开销。两者常一起权衡，但优化手段不同。

### routing

- **释义**：在多 agent 或多存储场景下，决定"哪个 agent 能读/写哪块记忆"的分配与访问规则。
- **原句**：> "routing describes a set of memory allocation and access rules." —— **AgentMem §4.2.2（L324）**
- **易混**：**routing vs retrieval**。routing 先决定"去哪个记忆源/哪个视图"；retrieval 再在选定范围内取条目。

### isolation

- **释义**：把不同 agent、角色或用户的记忆分开，防止并发写入造成污染、越权读取或隐私泄露。
- **原句**：> "memory isolation is very important because memory is read and written by multiple agents rather than updated in a single, sequential loop." —— **AgentMem §4.2.3（L334）**
- **易混**：**isolation vs access control**。isolation 是结构上的分离；access control 是在共享结构上限制谁能看什么。混合架构两者都用。

### provenance

- **释义**：记忆条目的来源与生成路径；多 agent 场景用来判断可信度、兼容性与冲突责任。
- **原句**：> "These operations must account for the provenance, reliability, and compatibility of memories generated by heterogeneous agents" —— **AgentMem §4.2（L308）**
- **易混**：**provenance vs metadata**。provenance 是"从哪来、经过谁"的溯源信息；metadata 是更广的标签集合，时间戳、任务 id 都算。

### MCP

- **释义**：Model Context Protocol，统一 agent 发现和调用工具与数据的开放协议；在记忆语境里也用于按需加载工具/技能。
- **原句**：> "the Model Context Protocol provides an open standard that unifies how agents discover and use tools and data" —— **AgeMem §4.2.3（L736）**
- **易混**：**MCP vs API**。API 是具体接口；MCP 是让 agent 以统一方式发现、描述、调用这些接口的协议层。

# 三、论文句法与套语

读这批综述最容易读反的不是单词，而是句子结构：长名词短语套叠、被动与名词化、比较结构、情态限定、否定与例外。下面 25 条按语用功能排列，每条给英文模板、它承担的作用、以及这批论文里的真实原句。

### 1. 定义句：X refers to …

- **模板**：`X refers to ...`
- **作用**：界定术语。后面通常跟"范围 + 组成 + 用途"，是抓定义的主句。
- **原句**：> "Semantic memory refers to a form of long-term memory dedicated to the storage of abstract facts, general concepts, and structured knowledge." —— **AgentMem §3.2.4（L212）**
- **读法**：`dedicated to` 后面才是作者真正想强调的功能；前面的 `a form of long-term memory` 只是归类。

### 2. 分类句：we categorize X into A and B

- **模板**：`We categorize X into A and B.`
- **作用**：提出本文的分类框架；这类句子通常出现在 Introduction 或 taxonomy 章开头。
- **原句**：> "we categorize memory into parametric and contextual types." —— **Rethink §1（L37）**
- **读法**：分类句之后，作者会用 `Based on ..., we further distinguish ...` 继续下钻；把两级分类一起记，才不会把子类当成同级。

### 3. 范围排除句：outside the scope of …

- **模板**：`These works ... should be considered outside the scope of X.`
- **作用**：界定范围，常用来把邻近领域排除出去。这是最容易被略过、但最影响理解作者立场的一类句子。
- **原句**：> "should be considered outside the scope of agent memory" —— **AgeMem §2.3.1（L268）**
- **读法**：看到 `outside the scope`、`more appropriately classified as`、`we do not consider`，要立刻记下"作者把谁排除了"。

### 4. 对照句：while

- **模板**：`A ... , while B ...`
- **作用**：并置两种机制，强调差异而不是优劣。
- **原句**：> "while contextual memory stores explicit external information" —— **Rethink §1（L37）**
- **读法**：`while` 两侧通常是对称成分；先找主语，再找动词，别被中间的长定语带偏。

### 5. 对照句：Unlike A, which …, B …

- **模板**：`Unlike A, which ..., B ...`
- **作用**：用一个已知概念给新概念定位；`which` 从句解释 A，主句才是作者要讲的新对象。
- **原句**：> "Unlike memory consolidation, which summarizes information during memory construction" / "compression focuses on reducing memory at inference" —— **Rethink §2.4.3（L148）**
- **读法**：主句在逗号之后。很多人读到 `which` 从句就停了，结果只记住 A 的定义，没读到 B 的差异。

### 6. 对照句：In contrast, …

- **模板**：`In contrast, ...`
- **作用**：转向相反面；常用来指出"被低估/覆盖不足"的一类。
- **原句**：> "In contrast, operational abilities are much less uniformly defined." —— **AgentMem §7.2.1（L485）**
- **读法**：`In contrast` 后的句子往往是作者的隐含批评，比前面的正面陈述更值得记。

### 7. 让步句：Even within / Although

- **模板**：`Even within ..., X ...` 或 `Although ..., X ...`
- **作用**：先承认对方条件成立，再指出仍有限制；让步从句不是结论。
- **原句**：> "Even within a sufficiently large window, the LLM’s attention mechanism must distribute capacity across all tokens." —— **AutoMem §4.1（L169）**
- **读法**：让步从句里的内容通常不是作者主张；主句才是。"窗口够大"不等于"没有问题"。

### 8. 否定修正句：not X, but Y

- **模板**：`X should be Y—not Z, but Y.`
- **作用**：先排除一个常见误解，再给出作者要的答案；这种句式常出现在纠正性论述里。
- **原句**：> "should be supplemented—not replaced, but supplemented—with an external store that preserves raw records at full fidelity." —— **AutoMem §4.1（L167）**
- **读法**：破折号中间是否定项，破折号后是主张项。不要把 `not replaced` 读成"不需要外部存储"。

### 9. 强否定句：X is not Y

- **模板**：`X is not Y.`
- **作用**：直接切断两个常被等同的概念；短句，信息密度高。
- **原句**：> "Long context is not memory." —— **AutoMem §5.5（L273）**
- **读法**：这类短否定句通常是整节的论点句；后面会跟证据。先记住它，再读证据。

### 10. 可能性限定：may / may not

- **模板**：`X may ...` 或 `X may not ...`
- **作用**：表示"有可能但不保证"；不是事实断言，不能当成结论引用。
- **原句**：> "A memory system that achieves 5% higher accuracy but triples latency and storage cost may not be an improvement in practice." —— **AutoMem §5.5（L283）**
- **读法**：`may` 后面的内容通常是作者留有余地的判断；写笔记时要保留这个限定，不要升级成 `is`。

### 11. 频率限定：typically

- **模板**：`X typically denotes / is ...`
- **作用**：表示"多数情况下如此"，允许例外。
- **原句**：> "In LLM-based agents, it typically denotes the KV cache" / "or current context window" —— **Rethink §2.2（L88）**
- **读法**：`typically` 说明这是主流用法，不是定义的全部；遇到反例时不要认为作者自相矛盾。

### 12. 频率限定：often

- **模板**：`X is often ...`
- **作用**：比 `typically` 更弱，只表示高频出现。
- **原句**：> "the agent’s immediate input x is often a poor retrieval query." —— **AutoMem §4.2（L177）**
- **读法**：`often` 后面常跟一个反直觉观察；这类句子往往是该小节的动机。

### 13. 因果句：Since …, …

- **模板**：`Since A, B ...`
- **作用**：A 是原因或前提，B 是结果；B 才是作者要成立的结论。
- **原句**：> "Since LLMs are inherently stateless, working memory provides the mechanism through which such state is explicitly carried and updated across interaction steps." —— **AgentMem §3.2.2（L188）**
- **读法**：`Since` 从句是前提，不要在笔记里把它当成主要论点。

### 14. 因果句：Because …, …

- **模板**：`Because A, B ...`
- **作用**：与 `Since` 类似，但更直接地给出机制上的原因。
- **原句**：> "Because these units are explicit, token-level memory is typically transparent, easy to edit, and straightforward to interpret" —— **AgeMem §3.1（L326）**
- **读法**：`Because` 后面解释"为什么这种载体有这些性质"；性质列表才是可操作的结论。

### 15. 结果句：outperforms

- **模板**：`X consistently outperforms Y across ...`
- **作用**：报告主结果；`consistently`、`across` 限定结论的适用范围。
- **原句**：> "Across five long-horizon benchmarks, AgeMem consistently outperforms strong baselines" —— **AutoMem §4.5（L223）**
- **读法**：先看 `across` 后面是几个 benchmark；`consistently` 表示不是单点胜出。不要把"五个 benchmark 平均更好"读成"每个都更好"。

### 16. 结果句：from X to Y

- **模板**：`dropped ... from X to Y`
- **作用**：用一对数字给出退化的幅度；比形容词更有信息量。
- **原句**：> "swapping an active memory agent for a long-context-only baseline dropped task completion from over 80% to roughly 45% on interdependent multi-session tasks." —— **AutoMem §2.4（L101）**
- **读法**：`from` 是原系统，`to` 是替换后的系统；`swapping A for B` 的方向容易读反——是"把 A 换成 B"。

### 17. 局限句：However / caveat

- **模板**：`However, ...` 或 `Two caveats temper ...`
- **作用**：转折，指出前面结论的边界；综述里的局限句往往比结果句更值得记。
- **原句**：> "Two caveats temper this trend." —— **AgentMem §3.2.5（L230）**
- **读法**：`temper` 是"削弱、给……降温"，不是"支持"。后面通常跟两条限制。

### 18. 开放问题句：remains an open problem

- **模板**：`How to ... remains an open problem.`
- **作用**：标记领域缺口；这类句子常与 Open Problems 章互相呼应。
- **原句**：> "How to effectively evaluate the memory module remains an open problem" —— **MemMech §6（L363）**
- **读法**：`remains` 暗示前面已经有人尝试过；`open` 表示还没有公认解。不要读成"没人研究"。

### 19. 指表句：Table X summarizes …

- **模板**：`Table X summarizes / compares ...`
- **作用**：把正文的散点收进表格；提示读者"这里可以跳读"。
- **原句**：> "Table 3 summarizes metrics most commonly used in foundation agent memory evaluations." —— **AgentMem §7.1（L457）**
- **读法**：看到这句，先读表头和 caption，再决定要不要回读正文。

### 20. 指图句：Figure X summarizes …

- **模板**：`Figure X summarizes / illustrates ...`
- **作用**：给出全局结构；图通常承载正文没展开的分类关系。
- **原句**：> "Figure 6 summarizes these operations for both single- and multi-agent settings." —— **AgentMem §4（L277）**
- **读法**：图的 caption 常有正文没有的限定（例如"实线表示写、虚线表示读"），先读 caption。

### 21. 引用句：X et al. show that …

- **模板**：`X et al. [ref] show that ...`
- **作用**：把某个具体证据挂到作者论点上；`show`、`demonstrate`、`report` 的证据强度不同。
- **原句**：> "Xu et al. [Xu et al., 2024] show that retrieving a handful of highly relevant passages into a moderate-length context often beats both pure long-context and pure retrieval approaches" —— **AutoMem §7.4（L359）**
- **读法**：`show that` 后面是作者借用的结论；注意 `often`、`a handful` 这些限定，别把它读成普遍定律。

### 22. 长名词短语堆叠

- **模板**：`a unified view of X along three dimensions: A (...), B (...), and C (...).`
- **作用**：一个中心名词后接多层修饰；中文读者容易在第一个介词处断句，导致修饰关系错位。
- **原句**：> "a unified view of foundation agent memory along three dimensions: memory substrate (internal parametric state and external retrieval-augmented stores), cognitive mechanism (sensory, working, episodic, semantic, and procedural), and memory subject (user-centric personalization and agent-centric experience)." —— **AgentMem Abstract**
- **读法**：先抓中心词 `view`，再问 `of what`（foundation agent memory）、`along what`（three dimensions），最后才展开括号。括号里的并列项是三个轴，不是三个例子。

### 23. 被动句 + 名词化

- **模板**：`X is typically indexed at write time by associating ...`
- **作用**：把动作变成名词（indexing、association、compression），主语被省略；信息密度高，但施动者消失。
- **原句**：> "memory is typically indexed at write time by associating each entry with semantic embeddings and auxiliary metadata" —— **AgentMem §4.1.1（L288）**
- **读法**：遇到 `by -ing`，要还原"谁在做"；遇到 `-tion`、`-ing` 名词，要问"这一步实际改了什么"。

### 24. 递进句：Beyond X, …

- **模板**：`Beyond X, we ...`
- **作用**：表示"X 之外还有一层"，常用于从已有分类转向新贡献。
- **原句**：> "Beyond consolidation, we articulate a forward-looking perspective on emerging research frontiers" —— **AgeMem Abstract**
- **读法**：`Beyond` 不是"除了……以外不重要"，而是"在……之上继续"。前面的 X 仍是基础。

### 25. 转化句：turn X into Y

- **模板**：`X is what turns A into B.`
- **作用**：用"转变"来定义某物的价值；常出现在 Abstract 的第一段，是全文主张的浓缩。
- **原句**：> "Memory—the ability to persist, organize, and selectively recall information across interactions—is what turns a stateless text generator into a genuinely adaptive agent." —— **AutoMem Abstract（L21）**
- **读法**：`turns A into B` 里，A 是现状，B 是目标；破折号中间是对 Memory 的定义，不是插入语废料。

# 五、表格与实验读法

## 1. 先分清三类表

这五篇综述里的表，大多数不是实验结果表，而是"覆盖表 / 清单表 / 定义表"。读错表类型，会比读错数字更浪费时间。

| 类型 | 长什么样 | 怎么读 |
| :--- | :--- | :--- |
| **能力覆盖表** | 行列都是能力或 benchmark，格子里是 ✓ / ✗ / - | 只看"覆盖/不覆盖"，不要把勾当成分数 |
| **系统清单表** | 列是 System / Year / Category / Feature | 只看年份、类别、一句区分特征；不比较性能 |
| **指标定义表** | 列是 Metric / Description / Benchmark | 读 Description 的第一句；它才是机制定义 |
| **实验结果表** | 行列是 dataset × metric，格子里是数字 | 才需要看 baseline、加粗、方向 |

具体例子：AgentMem 的 Table 3 是指标定义表；Table 4 / Table 5 是能力覆盖表；AutoMem 的 Table 1 是系统清单表；AgeMem 的 Table 8 / Table 9 是覆盖表 + 框架清单。真正的 dataset × metric 结果表出现在它们引用的原始论文里，不在综述正文。

## 2. baseline 行看什么

- 先确认 baseline 是 **memoryless**、**long-context-only**，还是 **RAG-augmented**。三者回答的问题不同。
- `memoryless` 看"有没有记忆"的增益；`long-context-only` 看"记忆 vs 单纯加长窗口"；`RAG` 看"agent memory vs 经典检索"。
- 如果一张表只有 `w/o memory` 和 `w/ memory` 两行，它本质是 ablation，不是和别人比。

## 3. ablation 行看什么

- 看"去掉了哪个组件"：write policy、retrieval strategy、compression module 分别对应不同结论（AutoMem §5.4，L267）。
- 看去掉后是**整体退化**还是**只在某一类任务退化**。后者说明该组件有任务特异性。
- 看有没有 `w/o reflection`、`w/o skill library` 这类单组件行；它们比"整体去掉记忆"更能定位机制。

## 4. 主结果表先看哪几列

按这个顺序，不要从左上角逐格读：

1. **第一列**：系统名，先找到 `ours` 或本文系统。
2. **任务/数据集列**：确认是单 session 还是 multi-session，是 QA 还是 agentic task。
3. **指标列**：确认是 accuracy、F1、Recall@K、SR 还是 Pass@K。
4. **最后一两列**：efficiency / cost / latency；没有的话，结论只能算"效果"，不能算"可用"。
5. **caption**：图例、✓ 的含义、单位、是否平均。

## 5. 指标方向

- **越大越好**：accuracy、F1、Recall@K、Precision@K、MAP、NDCG@K、success rate、Pass@K、memory integrity。
- **越小越好**：latency、token consumption、storage growth、false memory rate、contradiction rate、staleness、privacy leakage rate。
- **方向不明**：perplexity 越低越好，但它只是生成质量的间接指标；distinct-n 越高越好，但太高也可能是散乱。
- 看到 `↑` / `↓` 要先在 caption 里确认是"指标方向"还是"相对提升/下降"。

## 6. 加粗数字的含义

- 常规约定：**加粗 = 该列最好**；下划线 = 第二好。但这五篇综述本身不报实验结果，真正的加粗出现在被引论文里。
- 读加粗前先看 caption 有没有写 `bold indicates best`；没写就不要假定。
- 如果一行全是加粗，通常表示"该行在多个数据集上都最好"，也可能只是排版；以 caption 为准。

## 7. 覆盖表里的符号陷阱

- `✓` 与 `√` 可能是同一个意思，也可能在图例里被分成"明确覆盖 / 部分覆盖"两级；必须读 caption，不能只看形状（AgentMem Table 4 的图例就区分了 "explicitly covered" 与 "partially or indirectly covered"）。
- `-` 不一定是 0，可能是"不适用 / 未报告"；`✗` 才是"明确不支持"。
- 同一张表里 `✓` 出现两次但语义不同，是综述排版常见问题；以 caption 为准，不要跨表类推。

## 8. 一张结果表的 30 秒检查单

1. 这是结果表还是覆盖表？
2. baseline 是 memoryless、long-context 还是 RAG？
3. 指标是越大越好还是越小越好？
4. 加粗有没有在图例里定义？
5. 有没有报 efficiency / cost？
6. 任务是不是 multi-session？单 session 的好成绩不能外推到长期记忆。

# 六、五篇之间的用法冲突

只登记观察到的事实与出处，不判断谁对，也不做调和。

## 1. KV cache 被放进三个不同的格子

- **Rethink** 把它称作 **external parametric memory**：> "storing past key–value pairs as external parametric memory" —— **Rethink §2.4.2（L263）**
- **AgeMem** 把它列进 **latent memory**：> "Latent memory refers to memory that is carried implicitly in the model’s internal representations (e.g., KV cache, activations, hidden states, latent embeddings)" —— **AgeMem §3.3（L481）**
- **AgentMem** 把它列进 **internal memory**：> "In transformer-based LLMs, the KV cache is a transient, inference-time memory" —— **AgentMem §3.1.2（L146）**

同一个对象，分别被归为 external parametric、latent、internal。

## 2. agent memory 的边界：AgeMem 排除，AgentMem 纳入

- **AgeMem**：> "should be considered outside the scope of agent memory" —— **AgeMem §2.3.1（L268）**；> "more appropriately classified as LLM memory rather than agent memory" —— **AgeMem §2.3.1（L272）**
- **AgentMem**：把 parametric memory 与 working states（含 KV cache）都纳入 internal memory —— **AgentMem §3.1.2（L140）**
- **Rethink**：把 KV cache 视为 short-term memory —— **Rethink §2.2（L88）**

AgeMem 划出边界，AgentMem 与 Rethink 又把边界内的东西收进来。

## 3. parametric 的范围不同

- **MemMech** 只把 fine-tuning 与 knowledge editing 视为 parametric 的实现 —— **MemMech §5.2.2（L308）**
- **AgeMem** 把 parametric 分成 **internal**（原权重）与 **external**（adapter、LoRA、proxy model）—— **AgeMem §3.2（L438–440）**
- **Rethink** 把参数内知识整体视为 parametric，并把 KV cache 称为 **external parametric** —— **Rethink §2.1（L78）；§2.4.2（L263）**

注意：AgeMem 的 "external parametric" 指 adapter；Rethink 的 "external parametric" 指 KV cache。同一个短语，指两个不同对象。

## 4. episodic / experiential 是否是顶层类型

- **Rethink** 把 episodic、semantic、procedural 并列为 long-term memory 的子类 —— **Rethink §2.2（L94–98）**
- **AgentMem** 也把 episodic / semantic / procedural 并列为五种 cognitive memory 之一 —— **AgentMem §3.2.3–3.2.5（L198–224）**
- **AgeMem** 的顶层功能分类是 **factual / experiential / working**；episodic 不作为顶层类，而是落在 factual 的 "past events" 与 experiential 的轨迹描述里 —— **AgeMem §4.1（L609）；§4.2（L682）；§4.2.1（L704）**
- **AutoMem** 用 working / episodic / semantic / procedural 作为 temporal scope 的四类，并说多数系统只实现其中两层 —— **AutoMem §3.1（L111–117，L123）**

顶层切法至少有三种：认知类型、功能类型、时间范围。

## 5. consolidation 放在哪个阶段

- **Rethink** 把 consolidation 放在 **Memory Encoding** 之下 —— **Rethink §2.4.1（L108）**
- **AgeMem** 把 consolidation 放在 **Memory Evolution** 之下 —— **AgeMem §5.2（L947）**
- **AutoMem** 把 episode→semantic 的 consolidation 描述为跨 temporal scope 的过渡，并说它"rarely automatic" —— **AutoMem §3.1（L115，L123）**

同一个词，分别属于 encoding、evolution、跨层过渡。

## 6. RAG 是"外部对照"还是"记忆机制之一"

- **AgeMem**：RAG 面向静态外部知识、单次任务调用，agent memory 则是多轮、多任务演化 —— **AgeMem §2.3.2（L278，L280）**
- **AutoMem**：把 "Retrieval-augmented memory stores" 直接列为五类核心机制之一，并把 RAG 作为该类的起点 —— **AutoMem §4.2（L171–173）**
- **Rethink**：把 RAG 与极长上下文并列，作为当前 agent 的主要依赖 —— **Rethink §2.5（L413）**

AgeMem 把 RAG 排除在 agent memory 之外；AutoMem 把它收进机制家族；Rethink 把它当作现状描述。

## 7. long prompt / long context 算不算 memory

- **MemMech**：> "the long prompts are usually regarded as the memory contents" —— **MemMech §6.2.3（L439）**
- **AgeMem** 把 context engineering 与 agent memory 分开：前者管理 context window 资源，后者管理跨时间认知状态 —— **AgeMem §2.3.3（L292，L298）**
- **AutoMem**：> "Long context is not memory." —— **AutoMem §5.5（L273）**

MemMech 把长 prompt 直接当记忆；AutoMem 明确否认；AgeMem 用边界划分把两者分开。

## 8. benchmark 与 dataset 的列法不一致

- **AgeMem** 在同一句里并列 "benchmarks and datasets"，Table 8 又把 "Memory/Lifelong-learning/Self-evolving-oriented Benchmarks" 与 "Other Related Benchmarks" 分块 —— **AgeMem §6.1（L1081，L1091）**
- **AgentMem** 把 benchmark 按 user-centric / agent-centric 分两张表，指标另设一张表 —— **AgentMem §7.2（L471，L489）**
- **AutoMem** 的 Table 1 把 "Benchmark" 当作系统清单里的一类条目，而不是独立评测协议 —— **AutoMem Table 1（L185）**

同一个词，有时指整套评测协议，有时只指数据集合，有时只是清单里的一个标签。

## 9. 重心：retrieval 还是 generation

- **AgeMem**：> "Historically, the dominant paradigm in agent memory research has centered on memory retrieval" / "attention has shifted toward memory generation" —— **AgeMem §7.1.1（L1129–1133）**
- **AgentMem**：单 agent 的五个核心操作仍是 storage & index、loading & retrieval、update & refresh、compression & summarization、forgetting & retention —— **AgentMem §4.1（L281，L284）**
- **AutoMem**：五类机制里 retrieval-augmented stores 只是其中一类，另有 context-resident compression、reflective、hierarchical、policy-learned —— **AutoMem §4（L157–231）**

AgeMem 宣告重心转向 generation；AgentMem 仍以 retrieval 为五操作之一；AutoMem 把 retrieval 降为五类机制之一。
