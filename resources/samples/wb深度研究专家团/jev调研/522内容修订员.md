## 必改（7 条，前 4 条必须改对）

**1｜2.1「偏差的方向」第 3 段：wrapper 的效应方向写反了。**

**2｜论点第 2 段 / 2.2 / 小结 1（共 3 处）："LegalBench 单题上下文更短"这条反证无来源，却是新论点的承重墙。**

**3｜2.5 表第 5 条：「拆成 20 个窄问题」治不了 context rot，且与对照表 #4/#6 冲突。**
现文：「同一个 50 页合同，若拆成 20 个各自独立的窄问题（…），**正是官方 workflow 的形状**」
官方失败模式 #5 的机制是「**unrelated material in the `state` costs you accuracy**」，解法是「retrieve and filter in code first」；而 per-question context 含**整个** state——拆 20 个问题不消除 context rot，反而放大，且 50 页 × 20 问会顶到 64k/32k 上限。改为：「拆窄问题不解决这一条——官方的解法是**先在代码里过滤 state、只送该问题需要的字段**（与对照表 #4『大 state 不可外推』、#6『长文档需自行分片』一致）。」

**4｜论点第 3 段 + 小结 1：60–76% 缺"有序任务"限定；可操作判据缺第三维。**
现文（论点）：「最终决策又系统性地只使用金标量程的 **60–76%**」

**5｜2.6 第一层末段："期望概率被抬高到 20% 以上"是口径错误。**
