# 研究报告格式规范（`_format-spec`）

> 适用：本报告第 1–7 章及最终合稿　·　制定日期 2026-11-01　·　制定人：谭溯源（课题研究员）
> **本文档只定义格式，不改动、不移动任何 `ch*.md` 文件。** 所有偏差只登记、不修复。

---

## 0　边界

三条，先说清楚，免得这份文件越权：

1. **只管"长什么样"，不管"说什么"。** 论点成立与否、证据强度、口径是否正确，归各章作者与审稿人。本文档只在"两章用了两种写法、读者会因此误读"的地方出手。
2. **不发明新规范。** 凡本文档给出的规则，都能在某章已落盘的文本里找到现成实例；凡找不到实例的，标「提案」并写明缺什么、由谁裁定。
3. **以"已经写得最好的那一章"为基准，不以"最多章在用的写法"为基准。** 多数只代表返工量小，不代表正确。这一条直接决定了下面为什么选第 4 章而不是第 1 章（半角空格、`1.` 编号那套写法其实更多章在用）。

## 1　基准章：第 4 章

### 1.1　为什么是第 4 章

四条理由，逐条给对照证据，不用形容词。

**（1）它是唯一有"可判定的来源类型体系"的一章。**
第 4 章在来源清单前写了一整段「来源标注规范（全报告通用，仅在本章首次出现处印一次，其余章只标不解释）」，给出轴 1 的 **9 个主分类闭集**与轴 2 的 **6 个受控括注用语**。这句话本身就宣示了它是全报告的标准出处。

其余章的类型列是**自由文本**：第 3 章 21 条来源用了 **15 个各不相同的自造标签**——「厂商一手文档」「厂商一手」「厂商一手（模型卡）」「大厂一手」「大厂一手（**反向证据**）」「平台一手文档」「平台一手」「主流媒体」「二手媒体（中文）」「社区索引」「社区技术站」「开源仓库」「技术博客」「第三方基准仓库」「竞品官网（一手）」（已逐条提取去重）。**互相不可比、无法机器校验，且同一强度用三种写法**（"厂商一手""厂商一手文档""厂商一手（模型卡）"）。第 1、6、7 章则完全没有类型列。

**（2）它是唯一把表题做成标题的一章。**
第 4 章用 `### 表 1　实名客户核对表（…）`、`### 表 2　落地形态归纳`。标题能进目录、能被锚点引用、能在正文写"见第 4 章表 1"直接跳过去。第 3 章用加粗行 `**表 1 · 七家厂商…**`（不进目录、无法锚定）；第 1、6、7 章的表**连表题都没有**。

**（3）它是唯一在章首用引用块声明"证据门槛"的一章。**
第 4 章开篇：「证据门槛：只收**有第三方可核验的规模证据或付费主体**的用法；无规模证据的 POC 归第 5 章。」这一句同时干完三件事：定了收录标准、定了排除项、定了与邻章的分工。第 6 章有同范式写法（「本章只回答一个问题……本章不评价厂商是否应当修改这些约束——那是第 7 章的范围」），可视为同一体例的第二个实例。第 1、3、7 章没有。

**（4）它的 H1 用全角空格分隔章号与标题。**
`# 第 4 章　已验证的生产落地`（U+3000，已核字节 `343 200 200`）。中文行文不用半角空格断词；`# 第 3 章 选型地图` 里的半角空格渲染出来是一个**西文词间空格**，读者会看到"第 3 章"与"选型地图"之间有一道比中文标点还宽的缝。第 4、6 章用全角，第 1、3、7 章用半角。

### 1.2　第 4 章不是全项最优：两项从第 3 章取

诚实说明——如果照抄第 4 章，会丢掉两样东西，而这两样第 3 章做得最好：

**（1）`〔待补〕` 制度。** 第 3 章是唯一成体系的：三档写法（`〔待补〕`／`〔待补：缺什么〕`／`〔条款待补〕`）、一条硬约束（"凡正文出现〔待补〕的句子，该句不得同时承载断言性结论"）、一个载体（章末「仍缺一手来源的论断清单」四列表：论断／位置／缺什么／处理），并记录了由此**连带降级的三处表述**。其余六章无此制度。

**（2）计数口径必须可反算。** 第 3 章「写作口径备注」#8／#11 是唯一成文的：凡给"X 个"必须给出含哪些、排除哪些、哪几家可核实；给不出口径就改不可反算表述（"多家""30 余个"）。并附一条判据：**「报数与点名不一致时，先怀疑集合搞错了，再怀疑数字错了。」**

→ **本规范 = 第 4 章为主体 + 第 3 章两项专项。** 这两项不是"另一种风格"，是第 3 章已经做完、其他章还没做的工作，属于**补齐**而非**选择**。

## 2　标题层级

| 级别 | 规范 | 备注 |
|---|---|---|
| H1 | `# 第 N 章　标题`（**全角空格 U+3000**，全章仅一处） | 不写"第 N 章："，不加书名号，标题后不加句号 |
| H2 | `## N.M 标题`（西文数字，M 从 1 连续，不跳号） | 见 2.1 |
| H3 | `### 表 N　表题` 或 `### 未编号小节标题` | H3 不参与编号，仅作表题或局部小节 |

### 2.1　H2 为什么统一成 `N.M`

现状三种写法并存：

| 写法 | 在用章 | 实例 |
|---|---|---|
| `## 1.`–`## 8.`（西文点号，无章号） | 第 1 章 | `## 3. 边界一：与传统专训分类器——不是替代，是补位` |
| `## 一、`–`## 七、`（中文数字顿号） | 第 3、4 章 | `## 二、34 个模型与开源成熟度的光谱` |
| `## 6.1`／`## 7.1`（带章号） | 第 6、7 章 | `## 6.3 约束二：概率分辨率` |

**取 `N.M`，三条理由：**

1. **只有它能被正文精确定位。** 现有正文已在用两种引用方式：`§2.2`／`§7.5`／`2.6.1`／`6.3`／`6.4`（可解析、可跳转）与 `第 4 章 §四`／`第五节表 2`（`§四` 与"第四节"同形易混，`第五节` 得先数到第五个）。前者能跳，后者只能猜。
2. **七章报告里 `## 一、` 会出现七次**，目录与锚点同名冲突。
3. **它已经在被引用最多的两章里用。** 第 2 章被引 5 次以上（`2.2`、`2.6.1`、`2.6.2`、`2.7`），第 6、7 章被引 2 次以上。改这两章的成本低于改其余五章。

**迁移成本与最低要求（重要）**：把第 1、3、4 章标题改号，会连带改动正文里的 `第 4 章 §四`、`第五节` 等引用。若合稿时间不足，**最低要求是只改正文引用写法**——一律写成 `§N.M`——标题编号可暂留。因为读者读的是正文里的"§几"，不是目录。此项见 D02／D03／D17，标**需改（不阻塞交付）**。

### 2.2　章首结构（建议模板，非强制）

```
# 第 N 章　标题

> 本章只回答一个问题：……
> 证据门槛／与邻章的分界：……

## 论点
（三到五句，给出本章的判断，不是本章的目录）

## N.1 ……
## N.M 小结
```

现状对照：第 4 章（`## 论点` + 引用块）✓；第 6 章（两个引用块 + `## 论点`）✓；第 1 章用 `## 本章论点`（仅称谓不同，可接受）；第 3 章用 `## 论点：你要决策的不是"选哪一家"`（标题里带答案，可接受）；**第 7 章没有论点节**，论点写在无标题首段（D26）。

## 3　表格

1. **表题位置：表上方一行，作为 H3**，格式 `### 表 N　表题（括注）`。括注内至少写一项：口径／采集日期／样本范围。
2. **表号：章内连续，从 `表 1` 起**，不加章号前缀（全报告目前共 6 张表，加前缀反而难引）。
3. **引用写全**：章内写 `表 1`；跨章写 `第 4 章表 1`。**禁止 `第五节表 2` 这种"章节号＋表号"直接拼接**（D13）。
4. **表格前必须空一行**（Markdown 硬要求，D28）。
5. **单元格内不换行、不用 `<br>`**；需要多条时用 `；` 或 `·`。
6. **数字带单位、带口径**（见 §6）；**无法核实的单元格写 `无一手数据，不参与比较`，不写 `—`、不写"未知"、不留空**——留空会被读成"零"或"未测"，两者都不是事实。第 3 章表 2 的 pplx-decider 延迟栏已按此处理，可作范例。
7. **不在两张表里重复列同一指标。** 第 3 章表 1／表 2 的分工写法可作范例：表 1 只列产品身份（谁、何时、底座、许可、是否兼容），采购维度（价格、延迟、上下文、模态、辖区）统一交表 2，并在表下用一句话声明分工。**重复列同一指标的两张表，迟早会给出两个不同的数。**
8. **表题里可以写结论**（第 4 章表 1 的括注写"9 家 → 有效 5 家 / 未复核 2 家 / 不计入 1 家 / 证伪 1 家"），但结论里的数字必须能被表体逐行数出来。

现状：第 4 章 2 张表全合规；第 3 章 2 张表有题但题不是标题（D11）；第 1 章 1 张、第 6 章 3 张、第 7 章 2 张**无表题**（D03／D21／D27）。

## 4　正文引用

1. **形式：`[锚文本](URL)` 行内链接。** 锚文本用来源的可读名，**不裸写 URL、不用脚注、不用编号引用（`[1]`）**。
   - 锚文本优先取该来源在本报告来源清单里的标题简称：`[Cloudflare 博客]`、`[Vals AI 评测]`、`[官方 models 页]`、`[发布博客]`、`[Laya 模型卡]`、`[Vercel 指南]`、`[Primitives 总览]`。
   - 同一段内多次引用同一来源，**只链第一次**。
2. **一手/二手的措辞必须进正文**，不能只写在来源清单里。凡引二手，正文须出现"据转述""据报道""据二手口径"，并说明为什么没读到原文——第 4 章「该页本次受 Cloudflare 保护无法直接抓取，本章读到的是他人对它的转述（二手·转述），不是原文」是标准写法。
3. **厂商说法必须署名**：`Cloudflare 称`／`官方称`／`OpenAI 称`／`Bevel 自称`。本文自己的推断写"本文认为""本文估算"。**三者不得共用同一句式**——把"Cloudflare 称"写成无主语的陈述句，就是把厂商说法洗成本文结论。
4. **arXiv 引用**：正文首现写 `arXiv:XXXX.XXXXXvN` **并给链接**（`/abs/` 或 `/html/` 皆可，但同一篇全报告统一一种）。**只写 ID 不给链接视为不合格**（D25）。
5. **禁止**：编造 URL；用搜索站/聚合站落地页冒充原始来源；用 SEO 抢注域名（`aijev.app`、`usejevai.com`、`thejevai.com`、`jevai.pro`、`jev-ai.pro`、`jevai.dev`）作任何证据。
6. **百度百科类**可作线索、不可作依据。若用，须单列「线索（未采信为依据）」并写明它只用于确定检索方向——第 3 章已如此处理，可直接照抄该写法。
7. **接口端点不是来源**：`https://api.typesafe.ai/v1/systemone` 出现在第 3、4 章正文（请求示例），**不入来源清单、不入全局参考文献编号**。

## 5　来源清单字段

### 5.1　列结构（固定五列，顺序不变）

```
| # | 标题 | URL | 类型 | 一句话摘要 |
```

- **#**：章内从 1 起。
- **标题**：保留原标题语言，**不翻译**；arXiv 条目在标题后括注 `（arXiv:XXXX.XXXXXvN）`。
- **URL**：裸 URL，不加尖括号、不加链接语法。
- **类型**：见 5.2。
- **一句话摘要**：写**"这条来源能证明什么"**，不是"这条来源讲了什么"。凡有数字就写数字；凡有局限**同句写出**——第 3、4 章做到了（`（内部遥测不可复算；非 Jev 厂商）`、`（未直接复核，不计入成本型证据）`、`（页体受保护，本次未直接抓取）`），这是本报告证据纪律的主要载体，不能省。

### 5.2　类型 = 两轴（取自第 4 章，原文照录）

轴 1 主分类（**粗体**）+ 轴 2 括注（全角括号）。**把两者混成一个标签，会出现"客户本人署名却被归为二手"这类错位。**

| 主分类（轴 1） | 含义 |
|---|---|
| 一手·客户自有文档 | 客户自己写进产品文档、changelog、工程博客 |
| 一手·客户自述 | 客户本人在平台（评价卡、论坛）讲自己的使用 |
| 一手·厂商自述 | 厂商/竞品自己说（含官网、公告、遥测） |
| 一手·论文/预印本 | 学术来源，须附版本与同行评议状态 |
| 一手·平台数据 | 可复现抓取的接口数据（npm / GitHub / arXiv abs） |
| 二手·转述 | 我们没读到原文，靠他人转述 |
| 二手·社区/展示站 | 聚合站、展示站，非当事人也非媒体 |
| 二手·媒体/专栏 | 须标是否独立核实 |
| 本文推演 | 无公开实现证据 |

轴 2 括注**只用这六个用语**：可复现抓取 / 平台托管 / 页体受保护 / 内部遥测不可复算 / 无审计 / 利益相关。

### 5.3　一处措辞补充（**主理人裁定：采纳，但收窄为"子型"**）

「一手·平台数据」的示例只举了抓取型数据（npm / GitHub / arXiv abs），但实际使用中还需容纳**独立评测机构自测并公布结果**这一类（Vals AI、第三方基准仓库）。二者共同点是"平台方自己测、原始数据不可复算、但方法可复核"——与"内部遥测不可复算"的括注同性质。

**裁定：不改大类定义，改为在类下承认两个子型。** 理由是「平台数据」这一格承担着本报告最硬的那类证据（可复现抓取的接口数据），一旦把"第三方自测"写进定义，这一格就从"可复核的原始记录"漂移成"任何非厂商来源的测量"，而第 4 章的全部硬度都建立在前者上。子型写法既容得下 Vals，又不稀释原义。

固定写法（括注部分即子型，位置在类型栏内）：

| 子型 | 写法 | 适用 |
|---|---|---|
| 子型 a | `一手·平台数据`（可复现抓取） | npm / GitHub / arXiv abs 等可直接重抓的接口 |
| 子型 b | `一手·平台数据`（独立评测方自测；原始数据不可复算、方法可复核） | Vals AI、第三方基准仓库 |

`_refs.md` 已按此理解归类（R29 为子型 b，R30–R34 为子型 a），并在条目摘要里逐条注明来源性质。**编号不动，章内清单不动。**

### 5.4　章末必备的三个小节（按此顺序）

1. `## 本章来源清单`
2. `## 仍缺一手来源的论断清单`——四列：论断／位置／缺什么／处理
3. `## 写作口径备注`——给审稿与终校看的、**正文里读不出来的判断依据**

现状：**仅第 3 章三节齐全**；第 4 章有第 1 节；第 1、6、7 章三节皆无（第 7 章用 HTML 注释承担第 3 项，见 D29）。

## 6　数字、单位与计数

1. **每个数字三件套**：数值 + 单位/平台 + 日期。缺任一项即不合格。例：`GitHub star 34,729（10-31）`，不写 `3.4 万星`。
2. **平台必须点名**：GitHub star ≠ HuggingFace likes ≠ HF 月下载量。三者不得混称"星""热度""下载量"。
3. **比较前先确认"两个数是不是同一类量"**（上限 vs 实测；契约 vs 质量；厂商自称 vs 第三方测量），**再**谈是否同环境。第 3 章写作口径备注 #1 已成文，可直接引用。
4. **用"低于多数类基线"否证时，同句必须给随机基线**（第 3 章备注 #2）。
5. **计数必须可反算**：给"X 个"就给出含哪些、排除哪些；给不出口径就改不可反算表述（第 3 章备注 #8、#11）。
6. **百分比与百分点分开**：写 `+3.36 pp`，不写 `+3.36%`（第 7 章 §7.5 已如此处理）。
7. **币种不同不给单一百分比差。** 第 3 章来源 #21 写"€37 与 $42 币种不同、**名义低约 12%**"；第 4 章写"按 1 EUR ≈ 1.14 USD 估算，€37 约合 $42，**两者大致持平**——「名义低 12%」是币种不同造成的数字错觉"。**两处结论方向相反，必须统一**（D15）。
   规范取第 4 章写法，三步：**先给名义差 → 再给换算后的量级 → 最后说明"名义低 X% 是币种错觉"**，并且**不写"更便宜/更贵"**。

## 7　待补与不确定（取自第 3 章）

1. **三档写法**：`〔待补〕`（缺什么已知但未补）／`〔待补：具体缺什么〕`（能一句话说清）／`〔条款待补〕`（法律文本类）。
2. **硬约束**：带 `〔待补〕` 的句子**不得同时承载断言性结论**；结论依赖待补数字的，一律降为条件句。**否则待补标记只保护了数字，没保护推理。**
3. **载体**：章末「仍缺一手来源的论断清单」必须逐条列出，不许只在正文里散标。
4. **归因不可否证时写"原因不明"**，不写推测原因。
5. **宁可写「待补」，不要补写。**
