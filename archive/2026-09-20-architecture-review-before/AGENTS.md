# AGENTS.md

## 项目是什么

面向已了解 LLM 与 Agent 的进阶读者，写《Memory 与上下文工程》。

实质是：**构建一套 agent 领域的认知体系，再把它编译成不同形态的产物。**

认知层（`domain/`）是本体，教材与手册是它的投影。产物会过时、会重写、会换形态，认知层不会。所以**当前阶段只做认知层，产物是后期的事**。

卖点是判断力，不是信息量。

---

## 目录

| 目录 | 装什么 |
|---|---|
| `domain/` | **认知层 —— 一号资产**（坐标系 / 系统定位 / 分歧 / 机制库） |
| `sources/` | 别人写的：论文、第三方仓库、调研报告 |
| `analysis/` | 我们对外部系统的完整拆解 |
| `evidence/` | 支撑具体论断的原始摘录，与文档同名配对 |
| `dialogue/` | 交流记录：问了什么、怎么推演、否掉了什么 |
| `notes/` | 已拍板的决定 |
| `book/` | 教材 —— **后期产物** |
| `manual/` | 手册，多视图 —— **后期产物** |
| `archive/` | 会话快照 |

分水岭：**`sources/` 是外部世界，其余都是我们的产出。**

## AI 读到这里时

- 当前目标不是产出，是**积累认知**。`book/` `manual/` 是后期的事，现在别写。
- 判断优先于信息。能查到的东西不值得写进 `domain/`；值得写的是「为什么」和「什么时候会坏」。
- 拿不准放哪 → `CONVENTIONS.md`；拿不准该不该写 → `TRADEOFFS.md`。

## 产物：认知层的编译结果

| 产物 | 位置 | 回答什么 |
|---|---|---|
| 教材 | `book/` | 学的时候该按什么顺序 —— 一条路径 |
| 手册 | `manual/<视图>/` | 用的时候我在什么场景 —— 多个视图 |

两者互不为上下游，都从认知层直接编译。手册按使用场景分版（`claude-code/` `memory/` `harness/` `troubleshooting/`），每版内部逻辑不同，同一个知识点可以在多版出现。

**能不能到时候一把梭哈，取决于 `entries/` 能不能从 `domain/` 顺利提炼出来**——判据在 `project-maintenance` skill。注意别把「原子化」的要求压到 `domain/` 上，那会拆掉推理链，让人没法审查。

---

## 硬规矩（只有三条）

1. **主线未锁定。** THESIS.md 是假设不是目录。撞不上就改主线，不许硬套现实去迁就假设。
2. **先只读，要 action 时才改。** 默认不修改：先读清楚现状、确认要改的究竟是什么，再动手。
3. **`.workbuddy/memory/` 只放指针**（今天做了什么、产物在哪）。结论一律写进 `notes/` 或 `dialogue/`。

其余规则都在 `project-maintenance` skill 与 `CONVENTIONS.md`，动手时才读。**本文件每多一条，那三条被遵守的概率就降一分。**

## 开工前

要拆系统 → 先看 THESIS.md 的「已知最可疑的一段」，找能撞它的角度。**别拆没有撞击目标的系统**——那只会产出一份没有判断力的说明书。
