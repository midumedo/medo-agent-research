# 系统定位

各系统在我们的坐标系上处于什么位置。**这里是结论，证据在 `analysis/<系统>/`，两边不互相复制。**

| 系统 | 在地图上是什么 | 拆它要回答什么 |
|---|---|---|
| Claude Code | 上下文工程最密集的产品形态；**默认策略（自动压缩）恰好是它自己认为较差的那条** | 卸荷为什么无处安放 |
| Codex | 开源可读实现，用来验证对 Claude Code 的行为推断 | 推断与实现的落差在哪 |
| Tianshu | 极简 harness 路线的样本（薄壳） | 薄壳省下的钱来自哪 |
| mem0 / Zep / Letta / memgit | memory 层，与 harness 是另一种形状 | 「治理」在纯 memory 系统里长什么样 |
| OpenViking | 文件系统范式，反向量库隐喻 | 隐喻替换带来了什么新能力 |

只有 Claude Code 那一行的结论是撞过的，其余是待验证的定位——**别把它们当成已确认的认知。**
