写一本《Memory 与上下文工程》教材。

## 目录结构约定（2026-09-20 定，**已落地**）

- **切分依据是半衰期与读取频率，不是主题**。主线未锁定，按主题切目录 = 过早结构化
- **目录一律英文**；根级常驻文档全大写（AGENTS/THESIS/TRADEOFFS/STYLE/CONVENTIONS/BRIEF），
  内容文件小写 kebab-case。理由：Windows 非 ASCII 路径在脚本/工具链下会写坏文件名
- 根级目录：`domain/`（认知层·一号资产）· `sources/`（别人的）· `analysis/`（完整拆解）·
  `evidence/`（原始摘录，与文档同名配对）· `dialogue/`（交流记录：问了什么、推演过程、否掉了什么）·
  `notes/`（已拍板决定）· `archive/`（会话快照）· `book/` 与 `manual/`（**后期产物，现在不写**）
- **`README.md` = 人读入口（渐进披露：30秒 → 怎么逛 → 目录 → 目标边界 → 规则在哪）；
  `AGENTS.md` = AI 常驻指令。两者分工，不合并**
- **最重要的一条分界线：`sources/` 是外部世界，`analysis/` + `notes/` 是我们的产出**
- **不建空目录**；状态靠目录位置表达，不加 status 元数据字段
- md 配合：三段式（头来源 / 中正文 / 尾「拿去撞主线」）· 导航卡内嵌（nav.json 模式，
  **不建中央 INDEX.md**）· **引用单向**（book→analysis→sources；原料不反指章节）
- 源码：用户选**完整 clone 到 `sources/repos/`**。配套：锚定 commit sha、不 grep 全仓、
  已 .gitignore；**AI 默认读 `analysis/<系统>/` 下的锚点文件，深挖才进 repos/**
- **不用 `ref/`**——歧义（reference / git refs / refactor），且会把"我们的分析"污染成"参考资料"
- **维护规则已抽成 skill**：`.workbuddy/skills/project-maintenance/SKILL.md`（项目级）。
  装：先只读后改 / 改前判断改哪层 / 结构先改规则再动目录 / 不静默删除 / 认知层条目可编译三条 /
  命名 / 放文件判定测试。**动手时才加载，不进常驻文档**
- **不要在常驻文档里写论证过程**（用户 2026-09-20 明确否决：AGENTS.md 里那段"不设长度上限"的
  论证被要求删掉）。一个决定为什么这么定，写进 `notes/` 或 `dialogue/`；常驻文档只放结论与指针
- **常驻层不设长度上限**（2026-09-20 用户明确否决行数限制，见 `notes/decided-no-length-caps.md`）。
  理由：设了数字，注意力会漂到"怎么压到达标"而非"说清楚了没有"；且这是**指标替代**
  （拿可测的行数管不可测的注意力）。替代判据两条：① 删掉这段失去的是判断还是可查信息
  ② 有没有两组内容从不需要同时被读（有就拆，不是压）。**长不是问题，该拆没拆才是**
- `.workbuddy/memory/` 只放指针与"今天做了什么"，结论一律进 `notes/`，否则会被压缩掉

## 四个产物（2026-09-20 用户明确列出，已写进 AGENTS.md）

| 产物 | 位置 | 性质 | 消费方式 |
|---|---|---|---|
| 认知地图 | `domain/index.md` | 活状态，持续改 | 每拆完一个系统回来更新 |
| 系统拆解 | `analysis/` | 证据，写完即定 | 按需取 |
| 教材 | `book/`（未建） | 一次性消费，有路径 | 从头读到尾 |
| 手册 | `manual/<视图>/`（未建） | 反复消费，按查询 | 用时才查，按场景挑版本 |

依赖链：拆解 → 认知地图 → {教材, 手册}。**但教材与手册互不为上下游**——都直接从认知层
编译，是并列的编译目标：教材编译成**一条路径**（学的顺序），手册编译成**多个视图**（用的场景）。
把两者串起来，手册会继承教材的路径，而路径是它最不该有的东西

**教材 vs 手册（用户洞察，本书最锋利的一个区分）**：不是同一内容的两份排版，是两种知识组织方式
- 教材：顺序即知识，按因果组织，会**结构性过时**；用 `ch-01` 编号，编号本身就是信号
- 手册：打散路径、按查询重组，**局部可替换**；不编号，按问题索引组织
- **手册多版本，各版本内部逻辑不同**（用户 2026-09-20 明确要求）：`manual/claude-code/`（按配置
  调参动线）· `manual/memory/`（按"我要做哪个决策"）· `manual/harness/`（按搭建顺序）·
  **`manual/troubleshooting/`（症状反查，跨系统）**。划分依据是**读者当时在干什么**，不是知识主题。
  同一知识点会出现在多个版本里，但位置/详略/配什么决策卡都不同——**不是重复，别为去重而合并**
- **症状反查表不进任何产品专项**（用户纠正）：「压缩后静默丢失」「常驻层稀释」是**机制层**问题，
  不只存在于 Claude Code。用产品边界切机制层问题是错的——**症状不知道自己属于哪个产品**
- **术语：`claude-code` 指产品，`claude` 指模型**（用户纠正）。目录与文中指产品时必须写全称，
  两者失效模式完全不是一回事

## 认知层是本项目一号资产（2026-09-20，用户正名；**不要再叫「中间态」**）

用户：「我觉得叫中间态有点太不重视了，明明这玩意及其相关的，才是本项目的核心，
生成教材和手册只是产物罢了」

**项目实质重新定义**：**构建一套 agent 领域的认知体系，再把它编译成不同形态的产物。**
认知层（`domain/`）是本体，教材与手册是它的投影。产物会过时、会重写、会换形态，认知层不会。

已定名 **`domain/`**（DDD 领域层 = 核心、与基础设施无关的那层）。已从单文件拆成目录：
```
domain/
├── index.md        坐标系（三条轴：半衰期 / 载体 / **谁决定**）+ 导航
├── systems.md      各系统定位（结论；证据在 analysis/）
├── disputes.md     分歧与盲区
└── mechanisms/     机制库 —— **本层主体，待建**
```
**`mechanisms/` 才是大头**：每条机制一篇（是什么 / 解决什么 / 什么时候坏 / 数量级锚点 /
在哪些系统上被观察到）。教材与手册的绝大部分素材从这里出

**认知层分两层（用户 2026-09-20 指出，且说可以更多层）**：

| | 第一层 `domain/`（论述层） | 第二层 `entries/`（条目层，待建） |
|---|---|---|
| 谁读 | 人 + AI | 纯 AI |
| 目的 | 审查结论对不对 | 组装产物 |
| 形态 | 连贯论证，**带推理链** | 原子条目，按点拆 |
| 冗余 | 允许（铺垫是论证的一部分） | 不允许（每点一次） |
| 顺序 | 有意义（推导顺序） | 无意义（可任意重排） |

**关键**：链条不在条目里，**条目指向链条**（保留推导链指针），这样条目可自由组装又随时可回溯
**别把「原子化」压到 domain 层上**——会拆掉推理链，人没法审查结论对不对

## 中间态必须可编译（2026-09-20，用户点破的最重一击）

用户：「manual/ 不是该很后期吗，急着写干嘛？现在重点不是该在分析交流的中间态上吗……
难道交流完了，我还去自己手改吗？」

**核心判据：中间态的形状决定后期能不能一把梭哈**
- 中间态 = 连贯文章 → 后期编译 = **重写**，必须人手改
- 中间态 = 原子条目 → 后期编译 = **挑选 + 排序 + 补连接**，AI 可自动完成

三条配套：① 一条认知 = 一个条目（有小标题，摘出来就是一张卡）
② **标它回答什么问题，不标它属于第几章**（章节号随主线变而失效，问题不会；认领交给编译阶段，
这也是引用单向能成立的原因）③ 证据放 `evidence/`，正文只留论断，否则条目被撑成文章
**检验方法**：随机抽一条中间态问「它能直接放进手册吗」，需要重写句子 → 它是散文不是原子

**三层颗粒度**：`sources/`=外部材料全集（可能还没读）· `analysis/`=一次完整拆解推演 ·
`evidence/`=**已被引用**的那一小段（锚点+摘录，与 analysis 的重叠是引用式不是复制式）

**`dialogue/` vs `notes/`**：交流是过程（含死路），结论是结果（只含活路）。合并会让结论文件
被过程污染——想查"定了什么"却得先读完三轮推演。**死路有价值，但不该占着结论文件的位置**

## 文档两层：常驻与按需（2026-09-20，用户提出）

**默认只读，要 action 时才取**（用户借 agent 新范式指出：先只读，要 action 时再改）。
规则文档每轮都在场 → 注意力一直在分。这与"不设长度上限"同理：**问题不是文档多长，
是它是不是每轮都必须出现**

- **常驻（每轮读，只有三个）**：AGENTS.md + domain/index.md + THESIS.md
- **按需（动手时才读）**：TRADEOFFS / STYLE / CONVENTIONS / BRIEF / notes/
- **AGENTS.md 硬规矩从 8 条精简到 3 条**（主线未锁定 · 先只读后改 · memory 只放指针），
  其余搬进 CONVENTIONS.md 的「修改原则」节。**AGENTS.md 每多一条，那三条被遵守的概率就降一分**
- 修改原则（在 CONVENTIONS.md）：先只读 · 改前先判断改的是哪层（认知/赌注/证据/决定/规则）·
  **结构要变时先改规则再动目录**（顺序反了会留下永久不一致）· 不静默删除（标 `[已撞]` 保留原句）·
  **新规则默认进按需层，不进 AGENTS.md**
- 手册主力体例 = 条目 + 决策卡 + **症状反查表**（"看到现象 Y → 可能是 Z"）。
  教材按因果组织没法反查，而失效时人手里只有症状，没有原因
- **手册不是教材的摘要**——摘要保留路径，复习的人不需要再走一遍，他手里拿着一个具体问题
- TRADEOFFS 取舍准则**只管教材**；手册服从另一套（密度/可检索/可靠性，允许全是 L1 内容）

**THESIS vs UNDERSTANDING 分工**：THESIS = 赌注（待撞假设，窄而尖，撞不上就推翻）；
UNDERSTANDING = 地图（已确认认知，宽而平，只增不推翻）。**撞赢的假设从 THESIS 搬到 UNDERSTANDING**

## AI 时代教材的内容取舍原则（2026-09-20 确立）

- **总判据：AI 是生成器，教材训练判别器。** 生成类内容（代码/摘要/定义）塌成零成本；判别类内容随 AI 普及升值
- **判据升级：不是"能不能搜到"，是"读者能不能想到去问"** —— unknown unknowns 才是稀缺品
- 三类必写透：问题清单 / 失效模式与诊断信号 / 判别标准（品味）
- 三类必砍：术语定义与背景科普 / API 手册 / 完整代码实现
- 中间层的处理方式 = **精确检索锚点**（论文编号 + 一句话定位 + 检索式），给坐标不给内容
- 代码不一刀切：留 **minimal bad case 反例**、**真实数量级锚点**、**接口隐式行为**；伪代码价值反升
- 已 offered 待用户确认：把上述落成"取舍检查表"逐条过大纲
