# 《Memory 与上下文工程》写作准则 · 内容取舍

> 这份文件回答一个问题：**当检索成本趋近于零，什么东西还必须写进书里？**
> 它不是风格指南，是取舍依据。每写一节前过一遍「自检六问」，每定稿一节后过一遍。

---

## 一、总判据

**AI 是生成器，教材训练的是判别器。**

凡是"让 AI 生成"的内容（写一个实现、概括一篇论文、解释一个术语），成本正在塌向零。
凡是"让读者判别"的内容（这个方案会不会坏、坏的时候什么征兆、这一局该选哪个），随着 AI 普及反而升值——因为答案越廉价，筛答案的能力越贵。

所以取舍的分界线不是"难不难"，是**这一句话是在替读者做，还是在教读者判**。

---

## 二、判据的升级：从"能搜到"到"能问得出"

最初的想法是：能复制去搜到的东西，就不写。
这条是对的，但它不够——它是个必要非充分条件。

真正的追问是：**AI 只能回答被问出口的问题。**

读者不知道"chunk 边界会把一句关键约束切成两半"这个坑存在，他就永远不会去搜它。他搜不到，不是因为难，是因为不知道要搜。

> **教材卖的不是答案，是问题清单。**
> 一份"你应该担心哪些事"的清单，比三十页"事情是怎么回事"值钱。

这条推导出本教材最核心的一句自检：

> 把这一节删掉，读者失去的是**一条他本来会踩的坑**，还是**一段他随时能查到的信息**？

---

## 三、可搜性的三档（不要用同一个删法）

"搜得到"不能一刀切，必须分档：

| 档 | 状态 | 处置 |
|---|---|---|
| **L1** | 搜到了，答案就完整落在那一页 | **删**。教材不该为它占篇幅 |
| **L2** | 搜到了，但散在五处、互相矛盾、混着两年前的过时结论 | **不能删**。教材给的是**坐标加甄别提示**，不是内容本身 |
| **L3** | 搜不到，或搜到的全是在浅层打转 | **必须写透**。这是本书存在的理由 |

### L2 的具体体例：精确检索锚点

不要复述内容，给坐标。格式固定：

```
深挖坐标：[论文编号 / repo tag / 文档 §编号] — 一句话定位 — 注意：「XXXX年之前，还没有 prefix caching，
这个结论里的数字偏高 2–3 倍」
```

三个要素缺一不可：**编号（可直达）+ 一句话定位（值不值得点）+ 甄别提示（这份材料在哪个维度上过时或有偏）**。

第三要素是关键。没有甄别提示的参考文献，等于把甄别成本原样推回给读者——而那正是我们卖的东西。

> 本书的 `papers/nav.json` 已经是这套体例的雏形：每篇论文的「一句话定位 / 必须读的部分 / 可以跳过的部分 / 它的盲区」。书里的引用块应该就是这个结构的延续，而不是另起炉灶。

## 四、三档分类与判据

### A 档 · 砍（AI 一秒生成，写着只是占地方）

- 术语定义、背景科普（"什么是 RAG"、"Transformer 结构回顾"）
- API 参数表、SDK 用法、安装步骤
- 完整代码实现、样板、CRUD
- 单篇论文的内容摘要（→ 降为 L2 锚点）
- 数学推导的完整步骤（保留结论 + 直觉 + 那个反直觉的地方）
- 基准榜单的数字搬运（→ 降为数量级锚点）

**判据：一个熟练读者能用一句提示词还原它吗？能 → 砍。**

### B 档 · 压成锚点（有价值，但不值得展开）

- 论文贡献 → 编号 + 一句话 + 甄别提示
- 基准数字 → **数量级 + 来源 + 为什么这个数不能直接抄**
- 标准算法 → 伪代码骨架 + 关键参数的数量级
- 某个框架的用法 → 一行 "做到 X 的入口在哪" 的指针

**判据：读者需要知道它存在、知道去哪找、知道它什么时候不可信；但不需要你现在讲一遍。**

### C 档 · 写透（AI 给不了，这是地基）

四类，按稀缺度排序：

1. **问题清单**——unknown unknowns。这个领域里你应该担心的事，按领域组织成目录
2. **失效模式与诊断信号**——它通常以什么方式坏？坏掉时你在日志里看到什么？（AI 默认给成功路径，失败谱系是最稀缺的资源）
3. **取舍的依据与代价**——包括**什么时候不该用它**。AI 会给一个"通用最佳实践"的平庸答案，而真实答案依赖约束条件
4. **判别标准（品味）**——什么算好的上下文设计？这是判别器，不是生成器

顺带一个本书特有的第五类：**跨文献的分歧地图**。二十篇综述在一起时，A 说「就该压缩」、B 说「压缩毁掉一切」，这个分歧点不存在于任何单篇里，只存在于把它们放在一起的动作里。

## 五、代码怎么办（不要一刀切）

代码的角色不同，处置不同。

### 砍掉：可生成的那部分

实现、样板、标准 chunking 写法、通用的读写封装。
留一个**复现入口**就够——一行命令或一个 repo tag，而不是把代码搬进书页：

```
最小可跑入口：repo tag `ch04-rag-baseline`，`make demo` 直接起。书里不再贴代码。
```

### 留下：三种 AI 生成不出来的代码

| 形态 | 为什么 AI 给不了 | 本书的例子 |
|---|---|---|
| **minimal bad case 反例** | AI 倾向给出"正确版本"，给不出人实际会怎么错；而失效形态恰恰是最稀缺的东西 | 一段看似合理的上下文拼接，静默丢掉了第 3 轮的约束，agent 从此违反约定且**不报错** |
| **真实数量级锚点** | AI 会编出一个看着合理的数字。真实系统里的 chunk 是 512 还是 1024、压缩比几倍、命中率掉几个点，只有跑过才知道 | "生产环境里我们观察到 X，论文里报的 Y 是在 Z 条件下" |
| **接口的隐式行为** | SDK 的行为文档里没写、模型也不知道，只有踩过才有 | 某家的 prompt cache 到底怎么算命中：前缀必须逐字节相同，多一个空格就整段 miss |

### 反直觉结论：伪代码的价值上升了

- AI 能**可靠地**把伪代码变成实现。
- AI 不能可靠地把一段模糊意图变成正确的结构。

所以：

> **实现代码 → 交给 AI；结构伪代码与数据流图 → 留在书里。**

伪代码表达的是"意图的形状"，那是判别器的地盘。

## 六、替代代码块的核心体例：决策卡

砍掉代码块腾出的空间，不是留白，是换成**决策卡**。这是本书每段实操内容的基本单元。

模板：

```
场景：          遇到什么情况（要具体到读者能认出这就是他现在的处境）
候选：          通常有 3–5 个，列全
各自的失效模式： 注意是「以什么方式坏」，不是优点
选择依据：      什么条件下选哪一个（依赖读者的约束，不是通用最佳）
诊断信号：      你怎么知道自己选错了 —— 在日志/行为上看到什么
```

### 填好的一张（示例）

```
场景：  长对话跑到第 40 轮，上下文快撑不住了

候选：
  a 滑动窗口          丢掉最早 N 轮
  b 摘要压缩          把历史压成一段话
  c 结构化提取        按 schema 抽出字段
  d 外部化到文件      写到磁盘，用时召回
  e 换个更大的窗口    直接扩展

失效模式（不是优点）：
  a 丢掉第 3 轮定下的约束，agent 从此违反早期约定 —— 且完全不自知
  b 被丢掉的具体数字 / ID / 路径不可逆；摘要本身还会逐轮漂移放大
  c schema 没预料到的信息被系统性丢弃，这是静默的结构性损失
  d 召回失败时等价于「从没有过」，而且失败同样是静默的
  e 只是把悬崖推远了 20 轮，还额外付了成本和延迟

选择依据：先看任务里「不可重建的信息」有多少 ——
  约束多且不可重建 → 排除 a/b；信息能从外部重取 → 倾向 d；
  e 只是把悬崖推远二十轮，不改变问题的性质；
  窗口开多大、摘要压多短，是数量级问题，取决于具体任务 —— 本书不给通用值

诊断信号：agent 开始反复问同一个问题 / 引用了不存在的变量 / 突然改口推翻了它之前坚持的约定
```

注意这张卡里没有一个字是"怎么写实现"。全篇是判别信息。这就是我们在做的事情。

## 七、自检六问（每节必过）

1. **删除测试**：把这一节删掉，读者失去的是一条他本来会踩的坑，还是一段他随时能查到的信息？后者 → 删
2. **不问不知道**：这一节里有读者想不到要去问的东西吗？一个都没有 → 它大概率是 A 档
3. **失败密度**：这一节出现了几个具体的失效形态？一个都没有 → 多半是科普
4. **反面有没有写**：它讲了"怎么做"，讲没讲"什么时候不该这么做"？没讲 → 不完整
5. **代码审判**：留下的每段代码，属于「反例 / 数量级锚点 / 接口真相」中的哪一类？三者都不是 → 删，换成复现入口
6. **两年后测试**：两年后 AI 明显更强了，这一节还剩什么值钱的？答不上来 → 不该写

> 第 6 问是总闸门。前五问管省篇幅，第 6 问管地基选得够不够高。

## 八、剩下的护城河：路径本身

最后一件事，也是最难被 AI 复制的一件。

读者为什么不能直接去看那二十篇综述？因为读二十篇综述得到的是**二十个视角**，不是**一条路径**。

**顺序、强调、取舍本身就是知识。**

"先讲预算观再讲六段循环"、"把评测放进中间而不是附录"、"这一章故意不提某个框架"——这些决定合起来才是教材。AI 给的是切片，书给的是一条有人替你走过、替你排过雷的路径。

所以每个章节之间应该有**可感知的因果**：读者能回答"为什么下一个是这个"。答不出来，说明结构还没成形，加再多内容也只是堆叠。

## 九、这套规则的边界

诚实起见，三条：

1. **受众绑定**。本准则假设读者已了解 LLM 与 Agent。面对入门读者，"能不能想到去问"的答案完全不同——他们的 unknown unknowns 更多，某些定义类内容反而必须留。**换受众就要重估 A 档清单。**
2. **本准则只管教材，手册服从另一套准则。** 手册可以全是 L1 内容——它的价值是密度、可检索与可靠性，不服从「能搜到的就删」这条判据。**教材卖路径，手册卖查得到**，两者都做（见 AGENTS.md「四个产物」），但别用同一把尺子量。
   也别指望手册能从教材自动压缩出来：**手册不是教材的摘要**。摘要保留路径，而复习的人不需要再走一遍路径——他手里拿着一个具体问题。手册是**打散路径、按查询重组**的产物，主力体例是条目、决策卡，以及教材给不了的**症状反查表**（看到现象 Y → 可能是 Z）。
3. **动手性风险**。砍得太狠会让读者跟不上手。**保险丝**：每个实操章必须保留一个最小可跑入口（一行命令或 repo tag）。能不能跑起来，和要不要把代码印在书上，是两件事。

## 附：一句话版

> 不该写的东西：AI 能生成的。
> 该压缩的东西：AI 能找到但需要你告诉它靠不靠谱的。
> 该写透的东西：**你想不到要去问、AI 就永远给不了你的——问题清单、失效形态、取舍代价、判别标准，以及那条路径本身。**
