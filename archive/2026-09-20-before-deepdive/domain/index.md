# domain/ · 当前采用的领域解释

本项目研究：**Agent 如何在有限资源下，把过去的信息转化为未来可用、可更新、可追责的决策依据？**

这里保存我们当前采用的定义、机制解释和条件性判断。认知会过时，也会被反例推翻；值得长期保留的是证据、推理与修订的来由。教材和手册是后期产物，当前先把这些判断做扎实。

## 当前立足点

**Memory 跨决策步骤保留状态，Context 是本次调用实际可见的输入。** 任务内与跨任务都是研究范围；不能用“是否跨会话”排除长任务里的记忆问题。Harness 承载相关控制和运行过程，但本项目不覆盖它的全部工程。定义与边界见 [领域基础](foundations.md#context-memory-harness)。

**留在哪里、多久有效、多常使用、何时进入上下文，是不同问题。** 常驻项目指令可以很快过期，冷存的原始记录也可能长期有效。文字可以同时存于文件、索引与上下文中。不能从“热”“外部”“长期”一个标签直接推出工程选择。见 [独立描述维度](foundations.md#independent-dimensions)。

**先比较任务结果，再解释资源差异。** 减少主上下文 token 可能把成本转移给摘要、检索或子任务；保留更多内容也可能减少重读和错误。当前没有证据支持某种留存策略普遍最优。成本、质量与恢复能力的条件关系见 [上下文留存机制](mechanisms/context-retention.md)。

**论证可以被修订，来源不能替代验证。** 文档里的建议、接口的存在、清单的顺序，分别只能支持相应的有限事实。机制优势需要同条件比较，因果解释需要能区分替代解释的观察。本文档链接的论文片段已经核对本地转换文本；这不等于独立复现论文结果，也不等于核验当前产品。

## 如何使用这一层

每篇保留问题、依据、推理、边界和下一项关键观察。定义可以是工作约定，机制可以是待检验解释，但身份应当清楚。后续摘取结论时须保留条件、反例和来源；暂不建立另一套手工维护的条目层。

维护规则见 [内容归属](../CONVENTIONS.md) 与 [写作约定](../STYLE.md)。主线假设见 [THESIS.md](../THESIS.md)，它可以因这里的研究而改变。
