# 研究议程 · 用结果改变判断

> 2026-09-20。以下是可执行的研究设计，尚未报告任何模型实验结果。
> 对应 [THESIS.md](../THESIS.md)。先做能暴露机制与反例的小比较，再决定是否扩大样本。

## 第一优先：信息保留策略何时应该换

**决策问题**：一段长记录应该直接保留、摘要、外部保存后按需读取，还是组合？

先构造有确定任务约束的小型轨迹：早期给出一个后续必须保持的接口名、例外规则或数值；中间出现大量无关材料；后续任务分别需要原样字段、跨片段综合和此前未预料的细节。原文可访问与不可访问分别测试。构造案例只是机制探针，不是代表生产分布。

比较完整历史、保留原文的摘要、保留原文的按需读取、摘要加按需读取。固定过滤可作为容易诊断的对照；无记忆或仅当前问题作为任务是否真正依赖历史的检查。完整历史超出窗口时记为该条件下不可行，不偷偷截断后继续称为完整历史。

另设一个**只用于诊断的充分证据对照**：由任务设计者把完成任务所需的短而充分的正确材料直接放入本次输入，不计入策略成本排名。该条件仍失败时，先检查任务能力、工具和评判标准；它成功而某信息策略失败时，再追查选择、表示、恢复和使用。这不是现实策略，也不能借它给待测方案提供答案。

做两种互补比较：在同等质量要求下比较全路径开销；在固定可用资源下比较任务结果。不要同时强行固定策略本应改变的所有变量，导致比较失去意义。模型、工具、温度/采样设置、输入任务、截止规则和可见原文保持可解释；所有子调用均计入。

记录任务是否成功、关键约束是否违反、何时需要恢复、是否找到了正确原文、恢复后是否正确使用，以及全部输入/输出/缓存计数、工具成本与耗时。缺少可靠价格时只报 token 和时间，不能拿估价当账单。重试与失败都保留。

什么结果有价值：一个反例即可推翻“严格优于”；比较优势只在已测试条件内表述。若所有任务不依赖历史，则探针无效；若收益主要来自提示差异，先控制提示；若混合策略有收益但付出大量恢复操作，报告代价。随机结果需成对重复，报告分布与不确定性；样本量由观察到的方差与要区分的效果决定。

## 第二优先：更正、冲突和删除如何传到后续决策

**决策问题**：有版本与来源依赖的状态管理，比直接覆盖、重新构建能减少什么错误？

设置同一实体的初值、用户显式修正、低可信冲突、过期和删除，分别发生在写入前、摘要后、检索后。检查原文、摘要、检索索引和生成的派生事实是否继续带回旧值。先区分“撤出本次上下文”“停止检索”“删除持久记录”，不把三者统称遗忘。

比较简单覆盖、按任务重新构建、保留来源/版本关系的更新。固定冲突处理目标与权限，不允许一个方案偷偷获得额外正确答案。

观测旧值复活、正确值被覆盖、来源丢失、拒答是否恰当、删除是否在声明边界内完成。用一个编码任务与一个非编码的持续任务检查抽象；前者通过并不能证明后者成立。

如果简单方案同样可靠且更省，缩小版本机制的适用范围。如果源状态已经正确，但模型仍用错，要把问题归入使用或推理阶段，不能继续增加记忆组件来解释一切。

## 第三优先：把内容效果与缓存费用分开

**决策问题**：常驻内容何时有帮助，何时仅增加持有成本或干扰？

固定 token 规模改变换行，固定行数改变内容长度；分别加入相关、无关和矛盾信息，改变关键约束的位置。缓存前缀稳定性单独作为因素。不要用“超过某行数”预设质量悬崖。

分别记录约束遵循、任务结果、缓存命中范围和完整账单。新增相关信息即使增加输入也可能减少总成本；前缀稳定即使减少单价也不保证理解质量。

先核实实际 API 和客户端版本是否能观测所需计数；看不到的变量明确标为不可观测。没有测出拐点就是没有测出，不拟合出想要的数字。

## 实现与资料选择

系统只为问题提供观测窗口。先确认本地 checkout 是否有实际源码与可解析 commit，再选择可记录请求、轨迹和恢复行为的实现。若源码不完整，明确记录缺口；不能靠目录存在声称完成拆解。

产品特定的价格、thinking 留存、压缩触发和指令加载先补精确官方来源及版本；这些事实用于选择实验条件，不作为新理论的未检查前提。研究者应自行完成资料与实验，不把运行任务交还用户。

复现记录随对应分析保存，不先搭通用评测平台。记录运行标识、固定输入、模型/实现版本、策略差异、原始输出及判断依据；人工或自动评判都要能看到错误例。没有实际运行时，文档始终标“设计”，不填结果栏。

## 何时进入下一阶段

当问题已得到足够回答，或按事先说明的停止条件结束，就转向相邻机制或其他问题。结果可以改变选择，也可以支持继续采用简单方案、缩小适用范围，或确认在现有观测与资源内无法区分。最后一种要记录混杂因素、已投入范围及再次开启所需的新信息，不无限追加实验来追求正结果。

需要继续的正当理由是一个尚未解决且能影响选择的具体缺口。只增加背景资料而没有减少不确定性时，先重写问题；已经支持现有选择的负结果不属于这种情况。

当前不以论文数量、系统数量或目录填满作为里程碑。未来试做条目视图时，验收能否保留主张的条件和反例；未来编教材时，再评估读者能否迁移这些判断。
