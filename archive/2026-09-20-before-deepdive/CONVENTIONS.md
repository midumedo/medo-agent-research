# CONVENTIONS.md · 内容归属与维护边界

目录按**材料的职责与来源**分。时效、读取频率、证据强度是不同属性，不能用目录位置代替。设计理由见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 内容放在哪里

| 位置 | 职责 | 更新方式 |
|---|---|---|
| `domain/` | 当前采用的领域解释：定义、机制、条件、反例与未决问题 | 可纠错、可替换；重要变更留理由与旧版指针 |
| `analysis/` | 为具体问题进行的调查、系统拆解、跨材料比较、项目自审 | 可修订；区分来源所述、我方推断、实测结果 |
| `sources/` | 外部论文、代码和原始资料；转换工具与元数据不算外部证据 | 原件不改；引用定位到版本，转换件标明生成性质 |
| `evidence/` | 已用于论证的原文摘录、代码锚点、观测记录 | 已引用记录不覆盖；错误追加更正，重取形成新版本 |
| `dialogue/` | 交流中的问题、推演和被否掉的选择 | 历史保留，不冒充现行结论 |
| `notes/` | 项目决定及理由 | 新决定明确替代哪项旧决定 |
| `archive/` | 历史快照、旧稿与运行记录 | 用于追溯，不作为现行指令 |
| `.workbuddy/memory/` | 会话日期、做了什么、结果在哪 | 只存指针，不另存主线、术语或研究结论 |

`book/`、`manual/` 是后期产物，目前不建立。`entries/` 也不提前建立；需要时作为从认知层生成的派生视图，不成为第二套手工维护的结论源。

## 分文件与命名

内容回答不同问题、需要独立更新，或读者通常只需其中一段时，考虑拆分。完整论证不要为了原子化被拆散。主题可以用于目录内部导航；不要求全项目服从一种分类轴。

沿用 `domain/`、`analysis/` 等名称。新目录用小写英文与连字符；根级职责文档沿用大写，内容文档用小写 kebab-case。英文路径是兼容性约定，**不是 Windows 无法处理 Unicode 的事实判断**。不建空目录，不用行数上限替代内容判断。

## 引用与证据

正文用**显式相对链接 + 小节锚点**指向支撑材料。文件名配对只帮助归置，不代替链接；同一证据可被多篇论证引用，不按使用者复制。

关键外部证据要让读者找回来源身份、版本或获取日期、原文位置和必要摘录。动态网页留 URL 和访问日期；支撑强结论时保存所用片段或快照。源码引用记 commit 与路径。实验记录条件、输入、输出及执行方式。缺失字段写“缺失”，不能补猜。

原文和我方解释分开。来源声称 X，只能直接支撑“来源声称 X”；产品能力、比较优势和因果解释可能还需要实现或实验。不同文章转引同一来源，不算独立交叉验证。

依赖通常是产物 → 认知 → 分析 → 证据/来源；导航和修订记录可反向链接。不要在外部原文中写“应属于第几章”。影响检查通过搜索引用完成，暂不另建手工反向索引。

## 当前工作与历史

当前认知、主线和分析正文呈现最新判断。被否掉的长段论证留在历史版本，当前给必要的变更说明与链接。**保留历史，不让已撤回的主张继续占据现行入口。**

修改操作见 [project-maintenance](.workbuddy/skills/project-maintenance/SKILL.md)，表述约定见 [STYLE.md](STYLE.md)。目录规则只在这里维护。

## 现存材料的迁移边界

论文 PDF 是原件，解析 Markdown 是转换件；导航卡、阅读建议与我方调研迁入 `analysis/`。版本缺失时明确限制，不能把“本地有文件”写成“已核验为真”。

`sources/repos/` 中仓库只有在文件可读且 commit 可解析时，才算可用于源码审查。原始 checkout 不直接修改。项目目前没有根 Git 仓库；不能声称已被版本控制或已配置忽略规则。

历史目录中身份不明、可能与研究无关的文件不自动读取或批量迁移。归档和旧交流里的失效路径按当时语境保留，现行入口提供可用路径。
