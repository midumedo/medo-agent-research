# 研究对象与证据范围

系统和论文既可以是先去认识的对象，也可以成为检验具体解释的样本。当前优先选择可读的源码与论文，按对象自身结构建立认识；已有具体问题时，再按比较需要选择样本。**本表记录已有证据的边界和候选入口，不是当前产品能力表，也不表示这些对象已经完成深拆或同条件比较。** 探索方法见 [deepdive/](../deepdive/README.md)。

## 目前已有的材料

| 对象 | 本项目已有的材料 | 现在可以据此做什么 | 尚不能据此判断什么 |
|---|---|---|---|
| Claude Code | [上下文管理拆解](../analysis/claude-code/context-management-offload.md)与[上下文经济学拆解](../analysis/claude-code/context-economics-two-traps.md)；早期文章含待核实产品事实与过强推断 | 追踪项目如何形成旧假设，找出需要重新定位来源和验证的点 | 不能据文档顺序断定官方的策略排序；不能据建议行数推导性能悬崖；不能把价格比当策略实测收益 |
| 本地论文材料 | [已核对片段](../evidence/domain/reviewed-local-passages.md)，含控制策略与 Memory 范围定义 | 对照术语、发现原论证与本地来源的矛盾 | 不等于复现论文结果；也不证明论文覆盖所有产品或所有工程条件 |

论文的系统比较、官方文档、源码实现和本项目实验分别回答不同问题。论文报告了结果，不表示我们已经复现；源码存在分支，不表示它在当前版本和默认配置下会被执行；接口支持操作，也不表示用户通常能有效使用。

## 下一批候选如何选

以下候选来自项目已有名单。探索可以从“还不了解它怎样工作”开始：先确认对象身份、实际可读材料及版本，选择值得展开的范围；不必预先提出 THESIS 对应项或竞争解释。不同形态的对象可能帮助我们发现当前分类遗漏了什么，名称本身仍不作为能力证据。

| 候选 | 可从哪里开始认识 | 需要明确的材料与边界 |
|---|---|---|
| Codex | 从执行入口认识请求、工具调用与状态变化，再追踪历史保留和上下文组装 | 固定可用源码版本，标明入口与配置；静态路径、实际运行、模型或 API 行为分开 |
| Tianshu | 先确认具体项目，再按实际模块与执行关系认识其设计 | 核实项目身份和版本；不预先把“薄”或低成本当作已测出的性质 |
| mem0、Zep、Letta、memgit | 分别认识它们保存什么、如何写入和查询，再看是否实现更新、冲突与删除 | 各自定位材料与版本；不能因为常被归为 Memory 就假定结构或能力相同 |
| OpenViking | 核实对象身份，沿实际接口与数据组织方式理解保存、定位和读取 | 先查明实现，不把旧资料中的文件、层级等描述直接视为已核验事实 |
| 本地论文 | 重建作者的问题、概念、方法、实验设计与结论之间的关系 | 标明论文版本与已读范围，区分作者报告、本地文本核对和独立复现 |
| 简单文件检索或全文检索 | 认识简单实现如何组织原文、建立索引、处理查询与更新 | 用于后续比较时，另行控制原文、更新事件与预算，记录构建及检索成本 |
| 一个非编码的持续任务 | 认识任务中信息怎样产生、变化并影响后续行动 | 先明确任务和可观察状态；用于检验时再定义成功标准，避免直接推广编码工具结论 |

静态拆解可以在未运行系统时完成。应说明读到了哪些实现、哪些分支依赖配置、哪些行为仍需运行确认；commit 或其他版本定位缺失时如实记录。可复现轨迹能补充行为证据，但不作为开始阅读源码的前提。

## 对象探索何时暂停或收束

围绕本次选定范围，能够解释主要组成与关联、关键路径或论证，并让读者找到依据与剩余盲点，就可以收束。材料缺失或阅读继续扩大到无关范围时，也可以先暂停并记录限制。无需穷尽全部模块、复现全部实验，或产出适用于所有系统的结论；发现新结构、纠正理解和明确未知本身都是有效进展。

## 为问题检验选样时

具体问题已经形成后，比较样本应提供能区分解释的条件差异。只有“名字不同”而没有关键条件差异，不构成新的交叉验证；两篇文章转引同一文档，也不是两份独立证据。若补读一个系统无法帮助当前比较，应改变比较设计或结束这项检验；该系统仍可因理解其自身结构而值得探索。

可选的专题实验见 [研究议程](../analysis/research-agenda.md)；已经提出的解释见 [竞争解释](disputes.md)。两种选样方式可以互相启发，不要求先完成比较实验才能开展深拆。材料如何归属与引用见 [CONVENTIONS.md](../CONVENTIONS.md)。
