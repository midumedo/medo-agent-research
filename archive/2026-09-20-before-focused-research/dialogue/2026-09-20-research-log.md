## AI 时代教材的内容取舍方法论（讨论）

围绕"AI 能搜到的就该删吗"做了一轮深度讨论，产出可复用的取舍框架：

- 核心判据升级：**从"能搜得到"→"能问得出"**。AI 答不了没被问出的 unknown unknowns
- **生成器 vs 判别器**：AI 是生成器，教材训练判别器。生成类内容塌成零成本，判别类内容随 AI 普及升值
- 三类 AI 给不了的价值高地：问题清单（unknown unknowns）/ 失效模式与诊断信号 / 判别标准（品味）
- 代码不是一刀切删除，而是三分：
  - 砍（实现、样板、CRUD、标准 chunking）
  - 留三种不可生成的代码：**minimal bad case 反例**、**真实数量级锚点**、**接口隐式行为真相**
  - 伪代码价值反升 —— AI 能把伪代码可靠地变成实现，不能把模糊意图变成正确结构
- 体例提议：把"展开内容"变成"**精确检索锚点**"（论文编号 + 一句话定位 + 检索式）；替代代码块的核心单元是**决策卡**（场景 / 候选 / 失效模式 / 选择依据 / "你怎么知道自己错了"）
- 最后一个护城河：**认知路径本身**。顺序、强调、取舍就是知识；20 篇综述 ≠ 一条路径

已向用户提出下一步：把判据落成"取舍检查表"，逐条过一遍现有大纲。

## 产出：第一份真正的拆解（Claude Code）

`拆解/claude-code/上下文管理-卸荷优先于压缩.md`
资料来源：官方 costs / context 文档（一手）。

核心发现（判断，非搬运）：
1. **官方所有减负手段都不是"更好地压缩"，而是"别让它进来"** → 提出 **卸荷 vs 压缩** 的二分
2. **卸荷严格优于压缩**的三条硬理由：压缩本身是大请求（官方原话 "compacting a large context
   is itself a large request"）/ 压缩不可逆卸荷可逆 / 压缩是意图推断而卸荷是精确控制
3. **压缩被做成旋钮而非策略**（4 层粒度：自动 → /compact → 带焦点 → AGENTS.md 里
   `# Compact instructions`）→ 官方公开承认"什么值得留"不可判定。
   教科书级示范：不可判定就暴露控制点，别假装能自动化。代价是旋钮默认为空
4. **第 5 问答案**：把卸荷做成默认路径。现状结构性问题 = 默认行为（自动压缩）恰好是官方
   自己认为较差的策略，较好的策略要用户先跨配置门槛
5. **数量级锚点**：AGENTS.md ≤200 行 / 10000 行日志 →数百 token（Hook grep ERROR）/
   每轮重放全部历史 / MAX_THINKING_TOKENS=8000

**第二次撞主线**：**卸荷不属于六段循环的任何一段**（不是产生/召回/注入，甚至不完全是隔离）。
它是负向动作——核心不是"如何放入"而是"如何不放入"。
与昨天「治理缺失」同源：循环是按"信息如何流入"写的，现实却把大量工程量花在"如何不流入"。
初步推论：**骨架可能不是一条流水线（默认放行），而是围绕预算做准入/拒绝的守门机制（默认拒绝）**。
待 Codex 那侧交叉验证后再定。

## 产出：上下文经济学（用户追问反思 vs thinking 的成本）

`拆解/claude-code/上下文经济学-50倍价差与两处地雷.md`
来源：官方 pricing + extended-thinking + OpenAI reasoning 文档（均一手，2026-09-20）

价格（核心三角）：
| 模型 | input | output | cache read |
|---|---|---|---|
| Opus 5 | $5 | $25 | $0.50 |
| Sonnet 5 | $2 | $10 | $0.20 |
| Haiku 4.5 | $1 | $5 | $0.10 |
恒定比例：**output = 5×input；cache read = 0.1×input → thinking : cached-input = 50 : 1**

结论（用户结论对但推理路径反了）：
- thinking **算钱，按 output 计，计入 max_tokens**
- 但"输入划算"的真正理由不是它小，而是**它能命中缓存**
  —— 3000 token AGENTS.md × 50 轮：不缓存 $0.30 / 缓存 $0.03（差 10 倍）
  —— 一次 8000 token thinking = $0.08，比整场会话的缓存成本还贵 2.7 倍
- 反制：不能无限加输入（200 行稀释上限）+ thinking 有时省 tool calls
  → 比的是**整条路径总成本**，不是单价

**两处地雷（本次最有价值的发现）**：
1. **Opus 4.5/4.6+ 保留 thinking blocks 并按 input 反复计费**（Sonnet 4.5/Haiku 4.5 及更早剥离）
   → 链式反应：思考多 → 上下文涨得快 → 更早 auto-compact → 压缩=静默丢失
   → **追求更强推理，间接买到了更高失忆风险**
2. **thinking 与 cache 结构性冲突**：budget 被渲染进 prompt，改 budget_tokens 破 cache breakpoint；
   不能 pre-warm（budget 必须 < max_tokens）；官方要求持仓期内锁死 budget
   → "为了省钱动态调 thinking 预算"是自相矛盾的

**两家分歧**（思考以太typical curation）：能否"途中调推理强度且不破坏缓存"？
- Claude：做不到（预算在 prompt 里）
- OpenAI：可以（保持 request-level effort 不变，用 conversation-level configuration_update）
- 但双方共同不兼容自动压缩 → 说明是本质困难而非实现瑕疵

**第三次撞主线**：第一原理可能应从「预算」升级为「**负债**」——
预算是一次性容量约束，描述不出"进来后持续按轮计息"；负债观能自然推导前缀稳定性、
卸荷优于压缩、200 行限制。待 Codex 交叉验证。

## 四个任务定位（用户提出）+ 教材 vs 手册

用户列出四个任务：① 各 repos 拆解 ② 形成教材 ③ 形成手册 ④ 维护"对 agent 认知的中间态"（结合综述，需大量分析）

**用户最锋利的一句**："学过一遍了再去复习，肯定看手册不看教材" → 教材与手册必须分成两个产物

我的深化判断：
- **不是同一内容的两份排版，是两种知识组织方式**。教材顺序即知识（结构性过时），
  手册打散路径按查询重组（局部可替换）。教材用 `ch-01` 编号（编号即信号），手册不编号
- **手册不是教材的摘要**。摘要保留路径，而复习的人不需要再走一遍路径——他手里拿着一个具体问题
- 手册主力体例：条目 + 决策卡 + **症状反查表**。"看到现象 Y → 可能是 Z"——教材按因果组织
  没法反查，而失效的时候人手里只有症状没有原因。这是手册独有的、教材给不了的东西
- **手册可先于教材产出**：手册扁平可增量，写一条是一条；教材要等一条完整路径成形，
  否则退化成"按大纲扩写"。手册条目反过来是教材的素材池

任务④「认知中间态」的落点：新建 **`domain/index.md`**（常驻，≤150 行，超了拆目录）。
与 THESIS.md 的分工说死：**THESIS = 赌注（待撞假设，窄而尖，撞不上就推翻）；
