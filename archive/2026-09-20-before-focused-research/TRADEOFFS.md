# TRADEOFFS.md · 按决策价值取舍内容

> 主要用于后期 `output/book/` 与 `output/manual/`。研究阶段需要保留必要定义、事实与推导，不能用省篇幅原则提前删除证据。尤其不要以“能否直接进入教材”过滤对象深拆：先理解对象可以先于知道它最终有什么教学用途。

## 总判据

**保留能提高读者判断质量的内容，并给判断提供足够前提。**

这既可能是一条新问题、一个反例，也可能是常见概念的精确定义、一小段实现或已知实验结果。能搜索到不等于不值得出现；AI 能生成不等于无需验证。项目的价值不建立在“AI 永远做不了什么”上。

没有决策用途的罗列应删或降为阅读指针。有价值但易失效的产品细节需要版本和来源，可放专门材料或未来手册；机制解释则说明哪些结论依赖这些细节。

## 三种处理方式

| 处理 | 适合什么 | 判断依据 |
|---|---|---|
| 充分展开 | 因果推理、容易误判的比较、失效边界、反例、诊断方法 | 省掉推导会让人无法判断适用条件 |
| 简洁保留 | 工作定义、必要事实、关键代码或公式、版本差异 | 是理解或复现本段判断所需的前提 |
| 提供定位 | 完整 API 文档、安装流程、长篇外部推导、与当前问题无关的实现细节 | 读者知道为什么查、去哪查、查时注意什么即可 |

深挖链接写明来源身份、位置以及与当前判断的关系。没有真实依据时不要加貌似专业的过时警告或倍数。

## 工程内容怎样值得读

推荐一种策略时，说明任务条件、可选方案、付出的代价和选择改变的条件。诊断信号不是单一原因的证明：反复询问既可能来自记忆缺失，也可能来自来源冲突、工具读取失败或模型不确定。

反例有助于解释边界，但不要求每段故意制造反直觉。正常、朴素、可复现的结果同样有价值。负结果和简单基线应获得位置。

数字应能回到条件、单位、分母和来源。数量级锚点是证据压缩，不是把具体数字留着就天然可信。

## 代码与数学

当代码能暴露不可见的接口行为、表达最小反例、固定实验条件或使关键机制可复现时，保留必要部分。完整实现移到可定位的复现材料，但不能拿一个不存在的 repo tag 充当入口。

伪代码适合表达结构，真实代码适合检验行为；二者并无普遍高低。关键数学步骤若决定结论，不能只留一句直觉。公式的前提和未测量项必须可见。

## 教材与手册的不同用途

教材帮助读者建立可迁移的理解，按前提与因果组织。手册帮助读者在已有问题下定位行动，按场景、决策或症状组织；可以保留常用参数与重复出现的机制。

两者可以共享定义、例子、诊断表和决策比较，不靠禁止某种体例来划界。手册不是教材摘要，也不应丢掉条件；教材不是只讲原理的长评论，也需要验证入口。

两种产物都从认知层派生，但派生仍需要编辑、试读和来源检查。“可编译”意味着关系可追溯、内容可重组，不承诺自动生成就达到出版质量。

## 审稿时最有用的问题

- 读者面对什么具体选择，这段帮助他排除哪种误判？
- 需要哪些前提才能理解，有没有为了精简删掉必要事实？
- 依据能否回查，哪些句子只是我们的推断？
- 换一个任务、模型版本、资源约束或恢复条件，结论会怎样改变？
- 删除这段是否仍能完成推理；保留它是否只是重复？
- 技术变化后，哪些部分会失效，哪些判断方法仍可用？

不规定每篇的字数、反例个数或候选项个数。可测指标辅助审查，不能代替对真实内容的判断。
