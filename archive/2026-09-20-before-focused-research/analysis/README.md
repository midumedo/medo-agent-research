# analysis/ · 围绕问题的研究

这里保存围绕一个问题展开的解释、比较、综合、检验与项目审查。**组织中心是问题，不取决于用了几个系统、几篇论文或文章有多深。**

想先理解一个对象时，从 [deepdive/](../deepdive/README.md) 开始。深拆中的局部解释、质疑和比较可以留在对象稿；当一个问题需要单独持续研究时再进入本目录，不为几句评论拆文件。

## 与其他目录的关系

原件和转换文本在 [sources/](../sources/README.md)，对象解释在 Deepdive；本目录可直接引用它们或确切原文，不要求每项分析先完成全对象拆解。[Evidence](../evidence/domain/reviewed-local-passages.md) 中的片段与观测帮助追溯，不能用我方推论给自己充当独立证据。

当前可继续使用的定义、机制和判断在 [domain/](../domain/index.md) 组织；分析稿继续保留自己的研究来由，认知引用并吸收。项目下一步怎么做的决定在 [notes/](../notes/README.md)，讨论经过留 Dialogue。

现有两篇 Claude Code 文章以策略取舍和成本推理为中心，继续留在这里；文件名中出现产品名不会把它们自动归为 Deepdive。

## 做到什么程度

问题分析应说明当前回答、依据、推理、边界和仍未解决的部分。需要比较时认真处理替代解释与实验条件；描述结果时区分设计、作者报告和实际运行。

结果可以支持新方案，也可以支持保持现有选择，或说明在现有条件内无法区分。分析不等于必须有一个强结论，Deepdive 也不等于低一等的准备材料。

关键认识改变时同步引用它的当前文档。操作见 [维护 skill](../.workbuddy/skills/project-maintenance/SKILL.md)，职责细则见 [CONVENTIONS.md](../CONVENTIONS.md)。
