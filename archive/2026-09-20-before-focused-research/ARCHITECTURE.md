# ARCHITECTURE.md · 从理解对象到形成认知

> 2026-09-20 更新：正式加入对象驱动的深拆，研究与教材的结构均保持开放。
> 此次调整见 [设计决定](notes/2026-09-20-deepdive-and-research-roles.md)；此前的证据与纠错审查见 [审查报告](analysis/project-review-2026-09-20.md)。

## 一、项目做什么，当前缺什么

项目面向已了解 LLM 与 Agent 的进阶读者，研究 Agent、Context 与 Memory 的结构和运作，逐步形成能指导工程选择的认知体系。教材和多视图手册是后期产物。

当前仍在认识领域：有些对象的内部结构没有拆清，有些术语之间的关系没有想明白，教材顺序更未确定。因此研究既需要检验判断，也需要**在尚未知道该问什么时，先认真理解一些项目和论文**。

此前把“能否改变工程判断”设为所有研究的起点，过早要求探索拿出它尚未拥有的问题。修正这一点不降低证据要求：深拆可以暂不产生普适结论，但要把所理解的对象讲清楚，区分来源、推断、运行观察和未知。

认知层是核心资产，相关深拆、分析与证据共同支撑它。积累可靠的对象认识本身有价值，不必立刻证明能写成哪一章。

## 二、总体结构

采用以下职责结构。所有名称所指目录均位于根级；括号只表示研究工作在逻辑上并列。

```text
sources/
    ↓
deepdive/ ↔ analysis/       notes/：项目决定
    ↓          ↓
        domain/
           ↓
        entries/           后期提炼
           ↓
        output/            后期产物
          book/
          manual/<视图>/
```

这不是每份材料必须经过的流水线。问题分析可以直接读来源，深拆可以直接修订认知，领域认识也会反过来提出新的拆解和分析任务。`notes/` 记录本项目的选择，不是事实进入认知的审批层。

证据、交流和历史是配套材料：`evidence/` 支撑各层，`dialogue/` 保存讨论，`archive/` 保存旧版本。它们不用挤进这条主线。

这里的顺序表示知识怎样组织和使用，**不表示教材应该按这个顺序教，也不表示越往后越确定**。

## 三、两种同等正当的研究入口

| | 对象驱动：`deepdive/` | 问题驱动：`analysis/` |
|---|---|---|
| 出发点 | 想真正理解一个项目、论文或明确的对象 | 有一个现象、问题、假设或选择 |
| 组织中心 | 对象的真实结构与运行/论证过程 | 问题的证据、解释、对照与边界 |
| 可以包含 | 架构重建、代码路径、论文推导、实验解读、局部批评、未知 | 单系统诊断、跨系统比较、理论推演、实验设计、负结果、项目审查 |
| 无需预先具备 | 主线命中、成熟假设、教材章节、跨系统结论 | 完成过整个对象的深拆 |
| 合理成果 | 从看不懂到能解释，关键路径可追溯，知道哪些还不懂 | 得到回答、缩小范围、保留现有选择的依据，或明确无法区分 |

两者都需要思考。深拆不能退化为目录树和 README 的复述；分析也不因用了多个来源就自动可靠。

深拆中一句“这个实验没有控制检索预算”可以直接留在原稿。当它发展为“预算如何影响多个评测的可比性”，再形成独立分析。区别是文章围绕什么展开，不是有没有判断，也不是单篇/多篇、单系统/多系统。

两者可以反复交替。先拆项目发现不懂的现象，再围绕现象分析；分析遇到实现缺口，再回到对象路径深挖。无需等所有项目拆完才开始形成认知。

## 四、Deepdive 的忠实性与深度

“项目有什么就说什么”意味着尊重对象实际结构，保留重要但尚无法映射到当前框架的内容。不预设每个项目必须有六个阶段，也不因某部分与当前主线无关就提前判为没有研究价值。

对源码，先建立整体结构和关键运行路径，再按实际需要深入：入口、模块边界、调用与状态流转、配置、持久化、错误处理及验证依据。要区分文档承诺、源码实现、默认启用与实际运行结果。静态读码可以构成有效深拆，未运行就如实写明，不为完成感虚构轨迹。

对论文，重建问题、定义与假设、方法或推导、实验设置、作者结论与证据边界。论文报告有效，不等于本项目复现有效；发现论证跳步与实验缺口属于深拆本身。

“直接拆”也不要求逐行穷尽整个仓库。可以先做整体地图，再走通一条核心链路，然后按发现展开。范围要清楚：已理解哪些、哪些只是看到入口、哪些未覆盖。对象优先的具体工作方式放在 [deepdive/README.md](deepdive/README.md)，不规定所有对象使用同一目录或填同一张表。

项目重点仍是 Agent、Context 与 Memory。为理解一个对象，可以沿实际依赖扩展到运行循环、工具、调度、存储等部分；不需要预先证明每个模块最终都能进入教材。研究范围依对象和用户需求确定。

## 五、Analysis、Notes 与 Domain 各自负责什么

**Analysis 是一次研究如何回答问题。** 它保留材料选择、推演、比较、检验及未解之处。一个对象里的异常也能独立形成分析；来源只读到一部分时也可以形成有边界的局部分析。

**Notes 是项目怎样作决定。** 例如先拆哪些对象、采用什么维护方法、为何暂不制作教材。它可以引用分析，但“决定采用某方案”不是该方案普遍正确的证据。沿用现有复数名称，不再增加 `note/`。

**Domain 是我们当前怎样理解这个领域。** 它把对象认识和问题研究组织成可重复使用的定义、关系、机制、判断与盲区。它可含有依据的暂定解释，不等于事实认证区。既有框架只能帮助发现问题，不能成为深拆前必须填满的格子。

三者都可以很深入，区别在责任：研究问题、项目选择、当前领域解释。临时观察可以留在所属深拆或分析，讨论过程留 `dialogue/`，无需另建一个泛指笔记的容器。

拆解稿不会因为变成熟而搬进认知层。对象说明继续维护在原处，领域文章引用并重组它；同理，一份优秀分析不会因此消失。这保留了认识的来由，也避免每层手工复制同一份事实。

## 六、Sources 与 Evidence 如何支撑研究

`sources/` 保存别人写的东西及转换件；`deepdive/` 开始就是我们的理解。即便忠实转述，组织、选择和解释仍由我们负责，不能假装是原作者的声音。

`evidence/` 保存已引用的片段与原始观测，不是每份来源必经的摘抄阶段。正文可直接链接固定源码或论文小节；需要稳定摘录、运行输出或网页片段时再单独保存。

关键主张能找到来源身份、版本、位置和支撑内容。来源缺失或版本不明就说明限制。官方描述、代码分支、一次运行、受控比较支持的结论力度不同；重复转引同一个来源不构成交叉验证。

认知与研究都可纠错。关键依据改变时，复查引用它的深拆、分析和认知；旧版本可追溯，当前页面给当前答案。不因某份文档已经写完就停止修正。

## 七、Entries 与 Output 的地位

`entries/` 是**后期的编译接口**：把认知组织成能按不同目的选取和组装的单元。保留这一职责，但当前不急于确定 schema 或创建空目录。

条目必须携带主张、前提、适用条件、边界、依据和源版本，不能只摘一句强结论再指向长文。可组装不等于任意顺序都成立：定义、论证前提和适用限制的依赖仍需保留。

`domain/` 是维护认识的地方；`entries/` 的编辑纠错若涉及认识变化，应回到相应研究和认知中修正，再刷新条目。条目可以被人检查，不必把“只给 AI 读”变成禁令。

`output/` 统一容纳最终用途：
- `output/book/`：建立理解的学习路径。
- `output/manual/<视图>/`：按使用情境、决策、产品或症状查找。
- 其他产物在出现真实用途时再增加，不提前设计目录。

两种主要产物均从认知及其依据派生，互不为上下游。针对特定产品的操作细节可以回查深拆和来源，不必把每个参数都升级成领域理论。生成之后仍需要编辑、试读和事实检查；“编译”不承诺无需理解即可自动成书。

## 八、当前阶段怎样推进

当前以**先理解若干具体对象**为优先入口。可以从一个可读实现建立运行结构，再读一个持久记忆实现或相关论文，观察它们自然暴露哪些共同点与不同点。候选选择考虑未知程度、材料可读性、用户兴趣与结构差异，不要求预先拿得出反证目标。

研究议程中的已有对照实验保留为候选，不强迫下一步立刻执行。深拆发现新结构后，可以改问题、定义和主线；H1/H2/H3 也不享有优先被证明的权利。

深拆的阶段成果是：在声明范围内，能解释对象如何运行或怎样推出结论，关键关系可定位，盲区可见。分析的阶段成果是：问题得到足够回答，或有依据地停止。两种成果都不按文章数量、源码行数或目录填满验收。

具体目录归属只在 [CONVENTIONS.md](CONVENTIONS.md) 维护，操作见维护 skill。本次决定和对旧约束的替代见 [notes/](notes/README.md)。
