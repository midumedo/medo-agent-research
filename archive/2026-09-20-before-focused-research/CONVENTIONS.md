# CONVENTIONS.md · 内容归属与维护边界

目录按**材料的职责与来源**分。时效、读取频率、证据强度是不同属性，不能用目录位置代替。设计理由见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 主体结构

`sources/` 支撑研究，`deepdive/` 与 `analysis/` 是两种研究入口，`domain/` 组织当前认知，`entries/` 提供后期组装单元，`output/` 承载读者产物。`notes/` 记录项目决定，与这些目录同处根级，但不是每份知识必经的处理阶段。

| 位置 | 组织中心与职责 | 更新方式 |
|---|---|---|
| `sources/` | 外部原件、固定版本源码、论文与转换件；转换工具和元数据只是附属设施 | 原件不改；注明版本或缺口 |
| `deepdive/` | **一个对象**：忠实重建项目或论文的结构、运行/论证过程、局部解释与边界 | 可修订；保留对象版本、定位与覆盖范围 |
| `analysis/` | **一个问题**：解释现象、比较方案、检验假设、综合文献、审查项目 | 可修订；保留推理与比较条件 |
| `notes/` | **一个项目决定**：本项目采用什么、为什么、替代了什么选择 | 新决定指向被替代的旧决定 |
| `domain/` | **当前领域认识**：工作定义、关系、机制、判断、适用条件与未决问题 | 可纠错；重要变更留理由与旧版指针 |
| `entries/`（后期） | 从认知提炼的可组装单元，保留语义边界、依据与源版本 | 派生维护，不独立产生另一套研究结论 |
| `output/`（后期） | 面向用途的教材、手册及其他发布形式 | 依产物用途编辑与验收 |

后期产物采用 `output/book/`、`output/manual/<视图>/`，不再规划根级 `book/` 和 `manual/`。当前建立有说明内容的 `deepdive/` 入口；等实际提炼和制作时再建 `entries/`、`output/`。

## 配套目录

| 位置 | 职责 |
|---|---|
| `evidence/` | 被引用的原文片段、代码定位、原始观测；支撑任何研究或认知文档 |
| `dialogue/` | 交流中的问题、推演和否掉的选择；保留当时语境 |
| `archive/` | 历史快照、旧稿和原始会话记录；不作为当前指令 |
| `.workbuddy/memory/` | 日期、动作、产物指针；不另存研究结论或规则 |

来源正文可直接引用，不要求先复制进 `evidence/`。已引用的原始记录不覆盖，错误追加更正。历史讨论与项目决定也可以被更正，但不伪改当时的记录。

## Deepdive 与 Analysis 怎么判

按文章的组织中心判，不按篇幅、深浅、真假、完成度、单系统或多系统判。

- “这个仓库从接收请求到输出经历哪些步骤？状态在哪里改变？”进入 `deepdive/`。
- “这篇论文到底提出什么，它的实验支持到哪？”进入 `deepdive/`。
- “在这个仓库里，为什么某些更新没有进入后续上下文？”若围绕这一异常展开独立调查，进入 `analysis/`。
- “两个方案在什么条件下应该互换？”进入 `analysis/`。

深拆允许解释设计、发现矛盾、批评论文与作局部比较；这些不必被拆到另一目录。只有一个问题需要脱离对象叙述持续研究时，再独立成分析并互相引用。不为几句评论拆文件。

代码项目优先按 `deepdive/<项目>/` 组织，复杂时有对象入口及按真实子系统拆分的文章。单篇论文可用 `deepdive/papers/<编号或短名>.md`；需要代码、附录等多篇材料时再建对象子目录。首次有实际内容时才建这些对象位置，不提前堆占位文件。

## Notes 与认知的区别

沿用复数 `notes/`，不另建 `note/`。这里记录“本项目决定怎么做”；“记忆机制是什么、何时有效”属于领域认识，“为什么这次实验失败”属于分析。决定可以引用研究，但不能以“我们决定采用”证明一个外部事实。

尚未完成的观察放在所属深拆或分析中并注明缺口；无法归属的探索问题可以留在交流记录中，待明确后形成研究。不要把 `notes/` 变成临时想法、论文摘要和重要结论的共同堆放处。

## 研究怎样进入 Domain 与 Entries

对象拆清一部分后，可以提出分析问题，也可以直接修订某项领域定义；不要求先完成整个项目或通过全部假设。分析在回答具体问题，认知在维护此后会继续使用的解释。**两者职责不同，不代表从不确定区晋升到真理区。**

深拆和分析稿通常保留原位，认知另写综合后的解释并链接它们。只因原归类确实错误才迁移，不因“成熟”而逐级搬运。同一段事实不在每层复制维护。

未来条目至少保留主张/定义、前提与适用范围、边界或反例、源定位与版本。产物为特定系统补充细节时可以追溯深拆和原始来源，不必为每个 API 参数新造领域结论。新发现仍回写相应研究与认知，不只修改条目。

## 分文件与命名

内容回答不同问题、需要独立更新，或读者通常只需其中一段时，考虑拆分。完整论证和关键执行路径不要为了原子化被拆散。主题可用于目录内部导航，不要求全项目服从一种分类轴。

新目录用小写英文与连字符；根级职责文档沿用大写，内容文档用小写 kebab-case。英文路径是兼容性约定，不是 Windows 无法处理 Unicode 的事实判断。不用行数上限替代内容判断。

## 引用与版本

正文用**显式相对链接 + 小节锚点**指向支撑材料。命名配对只帮助归置，不代替链接；同一证据可被多篇引用。

源码说明记录 commit、路径和相关配置；静态可达路径、默认运行路径与实际观测分开。论文记录标识、所用版本或版本缺失、章节/图表位置；作者报告与本项目复现分开。动态网页留 URL 和访问日期，需要稳定依据时保存片段或快照。缺失信息不能补猜。

导航可双向，语义依赖要清楚。不要给外部原文安排教材章节，也不把深拆、分析、认知的排列顺序当作教材顺序。依赖变化通过搜索引用检查，暂不另建手工全局索引。

## 当前工作与历史

当前文档给当前认识；长段旧论证留在历史版本，当前说明变更理由与指针。维护操作见 [project-maintenance](.workbuddy/skills/project-maintenance/SKILL.md)，表述约定见 [STYLE.md](STYLE.md)。

现有两篇 Claude Code 文章围绕策略与成本问题，继续放 `analysis/`；不因旧称“拆解”就改装成完成过的源码深拆。综述阅读导航是阅读与比较入口，继续放 `analysis/surveys/`；以后对具体论文的完整深拆放新目录，二者互链。

`sources/repos/` 中只有实际源码可读、commit 可解析时，才算可用于源码审查。原始 checkout 不直接修改。根目录目前没有 Git 版本历史。身份不明、可能无关的私人文件不自动读取或批量迁移；历史原稿内部的旧路径按当时语境保留。
