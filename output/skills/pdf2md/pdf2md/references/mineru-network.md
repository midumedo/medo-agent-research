# MinerU：批次续取与网络诊断

按失败阶段继续处理，避免对已经完成的云端解析重新提交。

凭据、参数或服务端错误码需要核查时，使用 [MinerU 官方 API 文档](https://mineru.net/apiManage/docs)。

| 失败阶段 | 下一步 |
|---|---|
| 申请批次失败 | 核对凭据、请求参数和 API 返回；尚无可续取任务 |
| 已有批次，但上传失败 | 先确认哪些文件未上传；`--batch-id` 不补传文件，只对确需重做的项重新提交 |
| 查询中断或等待超时 | 用原 PDF、原文件名和已有批次继续查询 |
| 云端 `done`，ZIP 下载失败 | 续取已有批次，取得新结果地址；无需重新解析 |
| 云端 `failed` | 按 `err_msg` 修正原因后决定是否重提 |
| ZIP 无效或本地写入失败 | 检查响应内容、空间或文件冲突，不归因为云端解析失败 |

```text
python "<skill>/scripts/pdf2md.py" convert "a/pdf/原文件名.pdf" --batch-id "<批次>" --timeout 120
```

续取会重新查询并整包下载结果，不是字节级断点续传；完整本地转换件仍默认跳过。`--timeout` 只控制轮询等待，API、上传和下载另有连接或读取超时，因此总耗时可能更长。

## 脚本已有的连接回退

正常路径使用 `urllib`。只有结果 ZIP 的连接、TLS 或传输失败，且地址为 `https://cdn-mineru.openxlab.org.cn`、默认 443 端口时，才尝试通过 AliDNS 和 Cloudflare 查实时 IPv4，每家最多两个，去重后最多四次连接。

按 IP 连接仍用原域名做 TLS SNI、证书校验和 HTTP Host。此路径不使用应用代理，但可能仍经过系统路由或 VPN。HTTP 错误、重定向、无效 ZIP 不触发继续换地址；API 申请和文件上传不使用这条回退。

失败时保留阶段、错误类型或 HTTP 状态与批次编号。不要把“开着 VPN”直接当作原因，也不靠关闭证书校验、硬编码 IP 或重复提交任务处理连接故障。离线测试只验证这些分支，不证明服务当前可达。
