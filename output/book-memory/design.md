# Agent Memory：机制、实现与工程取舍

> 2026-09-21 · 专题教材设计提案。读者已了解 LLM、工具调用和 Agent；本稿确定阅读问题、章节关系与候选案例，没有开始编写全书。案例和比较均为设计，尚未运行。框架版本与研究结论继续由研究层核对，章节可随新证据调整。

## 这本书究竟帮助读者做什么

读者面对的困难并不是不知道有“短期、长期、情景、语义记忆”，而是看到大量都叫 Memory 的系统之后，仍不知道自己的问题是否需要它、应该比较什么、怎样判断多出来的结构是否值得。

这本书的中心问题是：**为了让一个 Agent 在后续任务中更好地使用过去经历，应保存和改变什么、如何再次使用、怎样知道这项投入值得。**

完成主干后，读者应该能做到四件事：辨认任务真正依赖哪些过去信息；搭出足够简单、能解释行为的记忆路径；沿错误定位保存、表示、读取、更新或使用中的原因；判断一个框架或论文方法带来的收益是否匹配自己的任务与维护成本。

Memory 在这里以可观察的外部记忆为主要实现范围，包含跨会话事实与经历，也包含长任务的工作记录及可复用经验。参数和隐态记忆保留概念位置，但其训练与部署条件不成为前面章节的必修前提。这是本书的选材约定，不是对整个研究领域下定义。

Context 在“怎样把记忆交给本次调用”时出现；Harness 在“谁触发读写、后台结果何时可见”时出现。一般工具调度、检查点执行语义、多 Agent 编排和通用安全门禁不另成主线。需要完整运行视角时，读者可以回查 [Agent 的持续运行](../../domain/agent-runtime/index.md)。

## 先拆开四种需求，再讨论共同机制

不同 Memory 项目经常回答不同问题。同一查询接口不代表可以直接比较，同一个综合得分也不保证测到了相同用途。

| 读者真正想要的能力 | 一个具体问题 | 最容易混淆的东西 |
|---|---|---|
| 记住当前仍然适用的背景 | 这个项目现在采用什么约束，用户此刻有哪些相关偏好？ | 原始聊天记录、当前采用值和长期偏好 |
| 找回过去发生过的事及依据 | 上次为什么放弃方案 A，当时用了哪个版本和数据？ | 当前答案与历史证据；事件时间与记录时间 |
| 继续一项尚未完成的工作 | 上次已经查清什么，还缺什么，下一步为何这样做？ | 任务进度与可长期复用的知识 |
| 从经历中减少重复探索 | 哪些做法在新任务里仍然有效，哪些旧经验已经不适用？ | 一次成功、稳定经验和可以直接执行的技能 |

公共文档检索可以支撑这四种任务，却不自动等于从经历形成记忆。比如论文正文是外部知识；“我们读过哪里、用什么条件得出什么判断、后来为何推翻”是持续研究产生的状态。RAG 的检索技术会被复用，无需先争论二者必须严格分家还是谁包含谁。

四种需求也不是四套必须独立部署的服务。一个文件就可能同时保存当前约束和进度；同一数据库可以承载事件和提炼结果。先用用途解释差异，再观察实际系统怎样组合，避免从分类学直接推导架构。

## 章节路线：八章主干，两条深入路线

主干先让读者有一个可比较的简单方案，再讨论复杂表示与自动化。阅读中不断更换的是具体限制，基本的问题始终是过去信息怎样帮助后续任务。

| 章 | 主问题与展开内容 | 应形成的判断 |
|---|---|---|
| **1. 你的 Agent 到底需要记住什么** | 从四种需求与真实失败进入；过去信息是否必要；重复读取、重新询问、全量历史与外部记忆各自的条件；建立任务结果、错误类型、延迟和成本的基本口径 | 识别需要保存的过去信息，区分记忆失败与模型已经知道却不会做；不因产品叫 Memory 就预设需要它 |
| **2. 一个足够好用的最小记忆系统** | 用原始事件、当前状态和可追溯来源组成第一条路径；文件或 SQLite、明确读取、简单搜索、人工或规则写入；展示跨会话恢复信息的完整实现 | 判断小文件、结构化字段和事件记录何时足够；说明每个信息副本存在的用途，而不是先装满数据库和服务 |
| **3. 怎样找回足够的正确材料** | 直接定位、全文与语义检索、时间及对象过滤、混合搜索；查询构造、读前预取和执行中补读；原文展开、证据组合与最终输入 | 分清“相关命中”和“足够支持本次任务”；精确名词、分散证据、时间问题各需要什么；何时追加向量、重排或多轮搜索 |
| **4. 什么值得写下来，写成什么样** | 原始记录、事实、画像、情景摘要、关系与经验；提取粒度、条件和出处；增量形成与查询时解释；压缩损失及原文恢复；人工、规则与模型写入 | 根据未来用途决定表示，而不是统一提取成事实条目；看清提前整理节省了什么、丢掉了什么，以及何时原文加索引更合适 |
| **5. 过去的信息怎样跟上变化** | 当前值和历史值、作用域、有效时间、否定与例外；更正、冲突、失效、删除；派生摘要和索引的更新；直接覆盖、保留版本、重建的选择 | 解释旧值为什么再次出现；区分真正冲突与范围不同；数据量小时能用简单重建，确有需要时再引入复杂时态结构 |
| **6. 一项工作很长时，怎样记住进展** | 工作记录、任务摘要、近期原文、检索入口、压缩后补读；目标、已证实结果、待定解释与下一步之间的区别；任务记录何时转为长期材料 | 区分“继续当前工作”和“学习长期经验”的保存需求；判断摘要、原文保留与按需恢复的组合；明确压缩后恢复不了什么 |
| **7. 记忆变多之后，复杂度花在哪里** | 写入与索引、读取与综合、更新与维护分别计成本；后台处理和可见性、重建、积累重复、遗忘和按需整理；查询复用、更新频率与成本摊销 | 判断重建是否比维护复杂依赖更省事；重写路径何时值得；异步处理是否只是转移代价；为自己的读写分布选择方案 |
| **8. 怎样选择框架，并验证它值得留下** | 按默认路径和可控部件拆解候选；与相同任务下的简单方案比较；版本、数据导入、读写控制、调试、导出和更换实现；论文协议与任务差距 | 给出一个有依据的选型以及改变选择的条件；分开方法价值、当前实现价值和本任务采用价值；保留简单方案作为真实可选结果 |
| **9. 当关系与时间真是难点时** | 条件深入：实体、关系、事件、时间及层次结构；图与关系表、结构化过滤和原文搜索的比较；关系抽取误差、变化传播和查询路径 | 判断关系是否真的承载问题中的约束；不用“多跳”一词直接推出需要知识图谱；识别结构本身的贡献和多读原文的贡献 |
| **10. 当任务反复出现时，怎样积累经验** | 条件深入：过去方案、失败原因、反思、范例、可复用步骤与技能；从回忆到行动；任务相似性、反馈质量、适用范围与退役 | 判断哪些经历值得归纳、哪些需要保留原样；区分记住教训和获得能力；检查错误经验和过度泛化，决定是否值得自动形成技能 |

前三章先读取未经复杂整理的过去记录，所以把检索放在自动提取之前。读者能先看到“读不回来”的具体原因，再评估加工表示是否解决了它。第五章则让记忆从静态资料库变成可以修正的持续状态，这也是很多简单检索演示没有暴露的问题。

第六章只研究任务内记忆。它不会展开所有 Context 优化，更不会把一个产品的全部压缩路径当作整本书中心。第七章讨论系统开销，但按记忆读写与变化来组织；通用后端部署只有在影响这些选择时才出现。

第八章集中收束选型，不意味着此前只能相信框架分数。第一章已给足比较口径；每章都沿用同一任务结果和错误样例，第八章再把组合方案与外部声明放在一起评估。第九、十章可以按读者需求先后阅读，其他主干不以学会图数据库或自动反思为前提。

这不是十次必做的组件升级。对于短历史、低查询量和少量明确字段，第二、三、五章的简单组合就可能是最终方案。读者跳过一个不匹配需求的复杂机制，也是学到了有效判断。

## 怎样把共同机制、条件机制和长尾研究分开

这里的“核心”指目标读者经常要作出的选择，不按论文数量、框架热度或流行术语确定。“条件深入”也不等于技术不成熟；它可能已经成熟，只是成立条件比较具体。

| 放在哪里 | 当前选择 | 进入或改变位置的理由 |
|---|---|---|
| 主干充分讲 | 原文与派生表示、简单持久化、任务相关读取、事实与事件、修正和时效、工作记录、完整成本与任务评估 | 无论框架如何包装，跨会话信息生效时都会遇到其中若干选择 |
| 有条件深入 | 关系与时态结构、层次摘要、查询规划、多轮记忆检索、经验与技能形成 | 需要解释具体任务结构怎样产生收益；满足条件时可成为项目重点，而非所有实现的升级方向 |
| 前沿专题按需读 | 学习式读写策略、参数编辑与持续训练、隐态记忆、具身或高频多模态记忆、大规模跨 Agent 协作记忆 | 当前读者若没有相应数据、训练资源或任务形态，难以把方法收益转成可检查的个人项目能力；保留方法概览和采用前提 |
| 暂不独立成章 | 企业级租户体系、合规认证、通用部署平台、所有框架的安装教程、全面产品史 | 与这本书当前要回答的个人工程问题距离较远；涉及具体记忆行为的必要条件就地解释 |

一个冷门方法可以有很高价值，只要它解决了普通方案解释不了的具体问题，或者提供了可以单独取用的机制。一个热门框架也可能在本任务里主要包装了已有能力。需要评估的是任务与方法的关系，而不是用“冷门”代替判断。

不把所有长尾方法统一贬为不实用。只有实验任务匹配而工程前提暂不可满足时，称为“当前难采用”；任务本来就不匹配时，称为“暂不相关”；材料不足时，保留“尚未判断”。这三种情况分别意味着工程投入、选题取舍和证据缺口。

## 框架应该成为哪些设计的样本

书中先给一张部件图，让读者认出系统实际提供什么，再挑有机制差异的对象深拆。不同层面的项目不能直接排成总榜。

| 对象形态 | 要追的实际路径 | 对照时最关键的问题 |
|---|---|---|
| 文件、结构化状态与简单搜索 | 谁写哪些记录，下一次按什么入口读取，如何更正 | 复杂框架相对它新增了哪项有效能力？ |
| 事实与画像记忆服务 | 输入怎样变成记录，是否真的执行更新，如何按对象与时间选择 | 提取是否丢掉条件；自动更新究竟存在于哪个版本与默认配置？ |
| 事件、关系与时态记忆 | 事件进入怎样的结构，冲突怎样处理，查询返回原文还是关系或答案 | 收益来自结构、提取、更强模型，还是更多原文和更大的读取预算？ |
| 记忆 SDK 与可编排组件 | 组件提供什么，调用时机和失败处理留给谁 | 少写了什么代码，还需要自己承担什么行为？ |
| Agent 或运行框架内置记忆 | 何时读写、谁持有工作状态、工具与记忆是否共同影响行为 | 换入的到底是记忆组件，还是整个 Agent 行为？ |
| 面向经验或学习的方法 | 使用什么反馈，怎样形成经验，怎样在新任务选择和应用 | 学会的东西能否迁移；收益是否依赖训练条件、执行器或额外反馈？ |

这些形态允许重叠。框架可同时提供事实存储、图检索和 Agent 接口；不能因为它被放进表中的一行就忽略其他路径。

具体对象名单随当前研究更新，暂不把品牌写成必修章名。Mem0、Letta 等对象存在显著版本演进，旧调查稿不能直接用作今日机制说明。正式写作时以固定版本与实际默认路径为准，区分“提供这个接口”“默认使用它”和“在任务中观察到收益”。本轮问题与选型研究见 [Memory 工程选择](../../analysis/memory-engineering-selection.md)。

重点拆解的对象需要提供新的比较信息：它是否暴露了不同表示、不同控制方式或不同代价，而不是又有一个名字。同类对象优先选择能清楚追踪行为的代表；第二个样本用于检验差异；只有品牌不同而机制相近时，不为数量而增加整章。

## 贯穿案例：一个持续研究项目怎样形成有用记忆

主案例是一名个人开发者用 Agent 持续研究、实现并修改一个小型文献检索工具。它包含确定性的字段、可回查的事件、开放研究判断与重复工作，容易观察多种记忆需要，又不需要建立企业后台。所有项目名、日期、偏好和实验记录均为构造数据。

案例将“外部资料”和“经历过这项研究的记忆”分开保存。候选库的文档、论文正文属于外部资料；选择目标、已做比较、失败结果、用户更正和当前进度属于研究过程产生的信息。任务端按时间释放新事件，待测系统事先看不到后面的提问或评分答案。

| 会话 | 新发生的事 | 后续需要记住什么 | 怎样检查 |
|---|---|---|---|
| 1. 建立项目 | 项目 Atlas 处理英文论文；用户要求保留原始出处，首版本地运行、只做段落搜索；用户通常偏好 Python，但此项目需要复用已有 TypeScript 页面 | 当前项目约束、个人偏好、项目局部例外 | 新会话提出实现建议时，能区分默认偏好和 Atlas 的具体要求 |
| 2. 留下可回查经历 | 对两个检索方案做一组明确配置的比较；方案 A 因精确缩写混淆失败；此次并未测试复杂关系查询 | 失败实例、数据和配置、选择理由、未覆盖范围 | 后来问“为什么没选 A”时，返回原来的原因与证据，不能编成普遍性能结论 |
| 3. 未完成任务继续 | 完成导入和基本搜索，发现 PDF 表格转换问题；下一步是定位转换损失，尚未证明需要换检索器 | 已完成、观测、猜测、未决问题与下一步 | 新会话继续时不重做已完成步骤，也不把转换假设写成已证实原因 |
| 4. 需求明确改变 | 用户允许远程批处理，但在线查询仍要低延迟；存量笔记仍写“全部在本地运行” | 新旧约束的范围和有效顺序 | 新方案允许远程离线处理，同时保留在线要求；旧记录仍能解释历史决策 |
| 5. 提出迟来的问题 | 用户询问比较时哪个样本暴露了 A 的问题，并要求复查原始片段；问题在形成摘要时未知 | 摘要未必保留的精确证据及原文入口 | 查到真实样本和条件；源记录不可达时明确缺口，而非从摘要猜原文 |
| 6. 引入新项目 | 项目 Boreal 使用另一套文本与约束；Atlas 的 TypeScript 例外不适用 | 哪些是全局偏好，哪些属于特定项目或数据 | 不把 Atlas 的局部规则带入 Boreal；仍能采用相关个人偏好 |
| 7. 更新事实和撤回推断 | 复查证明 A 的失败包含索引配置错误，修正配置后原问题消失；关系查询仍未测试 | 旧结论为何改变、当前判断、保留的未知 | 后续选型不再把已撤回结论当作禁用规则；历史问答仍能还原当时依据 |
| 8. 复用经验 | 在 Boreal 再做检索比较，数据不同但仍需检查索引配置、原文保留和缩写匹配 | 可以复用的检查步骤，以及不可直接搬用的参数和结论 | 减少可避免的重复探索，同时不照抄旧系统结论；若任务更换后无益，记录为经验不适用 |

这条案例同时包含“查到过去”“采用当前值”“继续未完成任务”和“复用方法”。它不靠几道回忆问答概括所有收益：字段与版本用明确预期检查，检索证据核对来源，任务继续检查实际进展，经验复用比较重复工作和结果。

第二章先用原始事件、当前项目文件和直接搜索完成它。第三章增大与问题无关的历史、改变提问措辞，检查读取；第四章增加提取与摘要，看哪些条件丢失；第五章重点使用更正和两个项目；第六章研究中断后的工作记录；第七章改变查询复用与更新频率；第八章把选中框架接到相同事件流；第九、十章分别增加真实关系问题和新任务复用。

不要通过不断增加干扰，专门制造简单方案必败的演示。保留小历史、少查询和直接读取足够的条件，连同复杂方案无明显收益的结果一起呈现。关系章节也不能仅把检索题包装成“多跳”：必须指出需要组合的关系及对应证据。

另设持续对话中的偏好与事实更正作为迁移案例。它有更强的隐含偏好与自然语言歧义，评分难度不同。主案例跑通并不自动支持陪伴、客服或具身场景；迁移案例需要独立说明任务与证据。

## 比较方法怎样嵌入章节，而不占据整本书

每次比较围绕当前设计选择展开，不要求所有章节套固定模板。必要时给可运行的短实现；如果代码只是重复 API 调用，机制图、数据变化和失败轨迹可能更有解释力。读者已有工程基础，不必用机械字数、习题数或章末格式制造教学感。

首次比较包括无历史对照、可行时的全量历史、文件或结构化状态加搜索，以及待测方案。无历史用于确认任务确实依赖过去；全量历史超出可行资源时如实记录，不把截断历史称作全量基线。已知充分证据可以单独用于定位模型能力问题，但不能伪装成正常检索方案参加排名。

记录任务质量、旧值误用、证据缺失、重复工作，以及完整写入、维护、读取、回答与失败重试的工作量。先比较实际默认行为，再通过有解释力的约束或消融调查原因。框架同名参数未必代表同等读取量，不能仅把 `top_k` 设成同一个数就声称公平。

个人项目尤其关心能否理解错误、调整写入、改掉记录和更换部件。这些不是企业安全门禁，也不要求专门平台；能看清一次记录如何形成和生效，就已经能减少大量盲调。运行依赖和维护复杂度描述为具体操作，不使用没有依据的“成熟度总分”。

有用的结论可以是“原始记录加词法搜索已足够”，也可以是“在这组变化频率与查询需求下，关系结构确实减少了遗漏”。后一结论必须交代成立条件；前一结论也不能推广成所有复杂记忆都无用。

## 与已有研究的关系及尚缺什么

[已有研究议程](../../analysis/research-agenda.md)中的留存、更正和成本问题可以直接支撑本书，但不把它的全部假设写成章节结论。[记忆生命周期综合](../../domain/agent-runtime/memory-lifecycle.md)提供初步关系解释；真正的 Memory 主题仍需要更多对象拆解与任务证据。

本地 [2606.06448](../../sources/papers/surveys/2606.06448.md) 的摘要与系统讨论按 construction、retrieval、generation 区分开销，提示第七章不能只计算回答时输入。这里引用的是作者研究的组织视角，本项目尚未复现其 profiling，不采用其中性能数字替任何当前框架排名。

本地 [2607.16848](../../sources/papers/surveys/2607.16848.md) 的 §8.1—8.2 讨论预算、检索方式、原文保留对科学文献问答比较的影响，并明确列出单次运行、近似预算控制等限制；部分内置综合系统并未使用统一回答模型。它支持“阅读协议后再理解排名”的教材安排，不能推出图记忆在动态对话、时态事件或持续行动中没有价值。两篇论文的具体摘录、混杂因素和部分报告不一致见 [比较边界核对](../../evidence/domain/memory-evaluation-passages-2026-09-21.md)。

[综述阅读入口](../../analysis/surveys/README.md)提供其他表示与操作的定位，现有元数据和转换正文并非全部完成版本、全文与实验复核。[历史调查稿](../../analysis/landscape/memory-landscape-2026-09.md)只用于发现候选和过去误判，不作为本书已核实的框架清单。

当前最有价值的写作准备是：完成一个可追踪的简单基线，深拆能增加机制差异的代表对象，围绕“更正怎样生效”和“保存怎样变成有效读取”形成比较。这会同时校准第一至第五章，也会决定图结构、自动提取和经验学习值得占多大篇幅。没有这些结果，先写完整产品排行榜或二十章前沿目录，只会把未知包装成确定结构。

本提案选择八章主干与两条深入路线，是当前的编辑判断。若对象研究显示某种条件机制普遍必要，就把它提升到主干；若某个主干问题用少量解释即可讲清，就合并相邻章节。教材顺序服务理解，研究主题保留其自身深度与范围。
