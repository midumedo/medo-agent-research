# AML 开源榜前列：两个"不建结构"的系统

> 对象深拆，2026-09-21。源码 `sources/repos/vanilla-rag-memory`（wenxiaof345-ctrl/vanilla-rag-memory，commit `31ab7bf9cfa3`，2026-08-11）与 `sources/repos/ReFind`（imlrz/ReFind，commit `a80175ca0eeb`，2026-08-14）。
> 两者分别是 Agent Memory Leaderboard（AML，2026-08-12 首次发榜）学术/开源榜的**第一名 InvMem 与第二名 Refind**。本轮从 AML 挑它，而不是挑更知名的系统，理由见最后一节。
> 状态区分：**代码确实存在** / **文档声称** / **默认启用** / **本项目未验证**。静态读码。

## 先说这个榜单本身

AML 把评测接口收敛到两个动作：

- `Add`：写入，同步，返回 200 表示已可查；
- `Search`：只返回**证据**，不生成答案——Answer 与 Eval 由平台统一做。

这个设计有明确的好处：把"记忆系统"和"回答模型"隔离，使不同系统能在同一回答模型与同一 judge 下比较，这正是 [记忆横评对照](../../analysis/memory-benchmark-crossreview-2026-09.md) 里反复指出的缺失变量。

但它也带来一个必须意识到的偏向：**它假定记忆系统就是一个可插拔的存取层。** 凡是把"记忆"和"推理"耦合在一起的方法（检索中迭代判断、让模型决定还查什么）在这个接口下会被削掉一部分能力。ReFind 的提交配置明确记录了这种妥协——它把论文里的第二阶段（LLM 回答）整个删掉了。

七维能力是 A 事实召回 / B 组合推理 / C 时间事件推理 / D 记忆治理 / E 个性化 / G 上下文学习与执行 / H 安全隐私（缺 F 维）。开源榜首 InvMem 总分 45.06。

## InvMem：一个自称"朴素"的 RAG 基线

仓库名 `vanilla-rag-memory`，README 自称"一个面向服务器部署的朴素 RAG 基线"，版本 `0.6.0`。**榜单第一名是一个刻意不做任何记忆工程的系统**，这件事本身就是本轮最有信息量的发现。

**写入。** `POST /add`，同步写 SQLite，持久化向量。相同 `request_id` 与相同内容重复提交幂等；同一 ID 配不同内容返回 409。不调模型，只做嵌入。

**检索。** 默认 `MEMORY_RETRIEVAL_MODE=hybrid`：Dense + BM25 用 RRF 融合（词法权重 0.5、RRF k=60）召回种子消息（默认 20 条），然后**对前 20 个种子各补充同一会话中前后相邻的消息**（`MEMORY_RESULT_WINDOW=1`），去重后补足 `top_k`。严格保持 user 与 session 隔离。

**冻结配置**：`BAAI/bge-small-en-v1.5`、Dense + BM25/RRF、词法权重 0.5、RRF k=60、窗口 1、种子 20。

**它自己在公开数据上的成绩**（README 明确声明不是官方成绩）：LoCoMo-Refined 1,382 道公开题上，Top-K=100 的 Evidence Recall 0.9277；用 `gpt-4o-mini` 生成与评分时 Judge Accuracy 76.92%（1,063/1,382）。

**机制含义。** 这个系统的全部"智能"是：**细粒度消息块 + 稠密与稀疏混合召回 + 同会话邻接补全**。不抽取、不建图、不改写、不治理。它在 AML 上拿第一，说明在这套协议与题集下，**把原文切小、召回够多、再补上上下文邻居**，比"先抽取成事实"更有效。

## ReFind：让模型控制搜索，而不是先建结构

ReFind 有论文（arXiv 2608.12888，《When Your Agent Opens the Chat App: Agent-Controlled Search over Raw Chat Logs Rivals Structured Memory》，中国科大 + Metastone），仓库是作者的参赛适配版。

**它保留的方法组件**（`docs/METHOD_CARD.md`）：

- 原始对话文本**保留原文**，不重写成生成的摘要；
- ReAct 式 planner 迭代地选择关键词搜索、查看结果、记下有用证据，并可按日期收窄；
- 检索粒度是对话块，BM25（`k1=1.2`、`b=0.75`）+ Porter 词干；
- 对话级与 session 级的 BM25 排名用 RRF（k=60）融合；
- 命中块向两侧各扩 2 个邻居块；
- 默认 planner 是 GPT-4o-mini，内部搜索深度 5，planner 预算 4 个动作。

**为适配榜单做的妥协**（仓库明确列出七条）：离线索引改为同步幂等的 SQLite 摄入；严格按 `user_id` 隔离；seen-chunk 过滤下沉到块级（因为平台可能把整份样本给同一个 `session_id`）；**删掉论文的第二阶段 LLM 回答**，只返回原始证据；`top_k` 当硬上限。

**Add 阶段不用模型，摄入是确定性的；唯一用到模型的地方是 Search 时的 planner。**

## 这两个系统合起来说明什么

它们排名前二，而它们的共同点不是"方法更先进"，而是**都不建结构**：

| | InvMem | ReFind |
|---|---|---|
| 存什么 | 细粒度消息原文 | 对话块原文 |
| 结构化 | 无（无图、无抽取、无改写） | 无（只有 BM25 索引与会话级聚合） |
| 智能在哪里 | 几乎没有：混合召回 + 邻接补全 | 检索时：模型迭代决定查什么 |
| 更新语义 | 只追加 | 只追加 |
| 用了模型 | 仅嵌入 | 仅 planner（Search 阶段） |

这个结果与 [记忆横评对照](../../analysis/memory-benchmark-crossreview-2026-09.md) 里的一手观察是一致的：MemoryAgentBench 与 AMA-Bench 都报告长上下文基线高于被测的商用记忆系统；2607.16848 报告控制检索预算后 Graphiti 的领先消失。**在"证据能否被找回来"这个评测目标下，抽取式结构目前并没有表现出优势，反而因为丢信息而吃亏。**

需要克制的是：这只在一个协议下成立。AML 把 Answer 与 Eval 收归平台，等于只测"召回"；抽取式系统的收益通常体现在"读得更少"（成本）与"当前认识更清晰"（一致性），这两项在 AML 的七维里只有 D（记忆治理）部分覆盖，而 D 在所有系统上都普遍偏低。

## 为什么从 AML 挑它，而不是挑更知名的系统

三个理由：

1. **有可读的源码。** InvMem 38 个文件、ReFind 24 个文件，能在一小时内读完并验证每一个说法。MemoraX（商业榜首）没有公开实现，读了也无法核对。
2. **机制立场鲜明。** 一个"完全不建结构"，一个"检索时把控制权交给模型"，分别占据了"保留原文 vs 提前理解"这道张力的两个极端，正好可以用来检验本项目反复讨论的那个问题。
3. **它们挑战了名单直觉。** 榜单前列不是 mem0、Zep、Letta，而是两个 2026 年才出现、几乎没有知名度的仓库——这直接印证了 [记忆横评对照](../../analysis/memory-benchmark-crossreview-2026-09.md) 第六节"老名单与新前沿"的判断。

## 覆盖缺口

1. AML 榜单本身的可信度：主办方为学术联盟（近 30 校），但**尚无独立的 arXiv 评测论文**，榜单数字只能按【第三方】处理。
2. InvMem 的 `docs/competition-contract.md` 未逐条读，官方评测数据（私有集）不可见。
3. ReFind 论文 2608.12888 未入库，本文的机制描述来自仓库的 METHOD_CARD，未与论文正文核对。
4. 两个系统都未运行，性能与召回数字均来自作者自述的公开数据回归实验。
