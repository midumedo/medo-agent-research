# deepdive/ · 围绕 Memory、Context 与 Harness 理解对象

这里深入拆解一个项目或一篇论文在本项目关注范围内的实际机制。无需先提出竞争假设、命中研究主线或选好教材章节。忠实是让证据决定解释，研究方向则明确聚焦信息与状态怎样影响 Agent 行为。

## 先理解整体，再沿相关路径深入

先建立足以定位机制的对象地图：它解决什么问题，相关状态在哪里，哪些部件参与关键行为。随后沿一次任务、一次写入或一次恢复走通真实路径；解释输入、状态变更、选择条件和最终进入模型的信息。对象可能有不同结构，不强行套统一循环。

Memory 的表示、写入、读取、更新、冲突、遗忘，Context 的选择、组装、压缩、卸载与恢复，以及 Harness 中改变这些行为的工具调度、任务切分、子 Agent 隔离、权限与恢复，都是可以深入的方向。它们是选取阅读路径的提示，不是每篇必须填完的模块表。

源码说明落到固定 commit、路径与相关配置。区分文档承诺、代码存在、默认启用和实际观测；静态拆解可以先完成，必要时再以最小运行检验关键理解。未读部分明确列为覆盖缺口，不写成不存在。

## 主文、必要背景与不展开的部分

| 发现的内容 | 放在哪里、展开到什么程度 |
|---|---|
| 一条消息如何经过筛选、摘要并进入下次模型请求 | 主文追踪完整的相关路径，解释状态、条件与失效点 |
| 一般 Web 路由、数据库连接池、序列化样板 | 主文只交代接口角色；有实际阅读价值的细节放补充材料，否则不展开 |
| 事务语义导致更新不可见，重试把已删除记录带回来 | 主文解释机制与影响；所需后台细节成为核心，而非因目录叫 backend 就略过 |
| 多 Agent 调度只涉及一般吞吐 | 通常不是主线；若隔离与回传决定上下文丢失或恢复，则转为核心 |
| 论文的记忆表示、更新算法、检索触发与基线差别 | 主文讲清方法、必要假设及支持到哪 |
| 通用优化器推导、完整训练脚手架和大段超参数清单 | 按理解需要简述并定位；较长但必要的解释可放补充材料 |
| 数据泄漏、未来信息可见、检索预算差异、更新时间与测试协议 | 若改变效果判断，主文明确给出限制，细节才另附 |

分层的目的，是让主文的一条机制解释连贯完整。关键前提、反例、负结果和会改变结论的实验限制必须在主文可见。补充材料负责独立的背景说明，不能用来藏起不利证据，也不必给每个外围模块新建文件。

内容规模需要时，可以采用如下组织；这些是路径示意，尚未创建：

```text
deepdive/<对象>/
  index.md                    对象版本、范围、整体地图与阅读路径
  <机制名>.md                 实际发现的关键路径与解释
  supporting/<背景名>.md      按需展开的必要旁支
```

简单对象一篇写清即可。主文链接旁支时说明“这个背景影响什么、何时需要读”；补充材料回指所支撑的机制。只读主文应能理解主张及其边界，复查实现或推导时再沿链接深入。

## 论文从相关机制和论证进入

先说明作者试图解决的信息或状态问题，再重建方法依赖的表示、操作与假设，以及实验实际比较了什么。公式和算法在决定机制时充分解释；普通研究步骤不为完整性平均分配篇幅。

区分作者声称、论文报告、我方推断与本项目复现。论文配套代码可在同一对象研究中核对，但两个版本分别记录，不假定天然对应。综述的分类也需要看范围与依据，不能直接当世界的真实结构。

若一项关键实验设计无法理解，就保留判断缺口；不能一面跳过它，一面转述效果排名。新发现超出现有框架但与信息行为有关时，可以扩展范围或改变框架。

以上是阅读入口与已知范围，不是产品能力表，不承诺按清单逐个完成。已有问题时，选能区分解释的条件；先探索对象时，选具有认识价值且材料可读的路径。

2026-09-21 起，当前优先 [Memory 工程选择](../analysis/memory-engineering-selection.md)提出的机制对照：简单原文与状态基线、Mem0 实际开源写读路径、当前 Letta 的模型主导记忆。已有[一手材料核对](../evidence/domain/memory-frameworks-core-2026-09-21.md)，仍不等于完整对象深拆；关系、时间和后台整理按具体问题选择后续对象。

本轮已完成的五个深拆把"谁决定存、取、弃"这个问题拆成了可对照的几种答案：抽取放在服务内（Mem0）、抽取交给调用方（memU）、检索时把控制权交给模型（ReFind）、完全不抽取只补上下文邻居（InvMem）、以及用激活值统一淘汰与排序（MemoryBear）。后续若要继续扩张名单，优先补"程序性记忆"与"多 Agent 共享"这两条尚无成熟实现的线，而不是再增加一个向量检索变体。

## 怎样接到其他工作

对象中的局部疑问和评论就地解释；需要持续单独追问时进入 [Analysis](../analysis/README.md)。多项认识开始需要统一解释时，再形成 [Domain 主题](../domain/index.md)。来源与运行记录可以直接引用，确有需要才保存在 Evidence。

当本次范围内的机制、路径和主要边界已讲清，就可以收束。遇到材料缺失或继续深入只扩展无关背景时，也可说明限制后暂停。不必穷尽整个代码库或完成所有实验，不按文件数量验收。文件与引用约定见 [CONVENTIONS.md](../CONVENTIONS.md)。
