**三条与 draft5 不同的结论**：

1. 硬推论「最晚加载最少量」在成本上无条件成立（`p<1` 的期望计算），故不需要省钱来辩护；
   真正的问题是缺的那一半代价不对称——缺约束时 agent 会发明约束且产物看起来合理。
   改写为「充分性是硬约束，最小化是目标函数」。
2. **draft5 唯一标为「已确认事实」的断言被一手来源推翻**：Claude Code 2.1.277 对
   `AGENTS.md` 的支持是 **fallback 而非 merge**（changelog 承重词是 `instead` 与 `no`），
   存在 `CLAUDE.md` 时静默跳过。且此写法违反本项目 STYLE.md 明文规定。
   → 分类学应按**角色**引用引导层，不按文件名。
3. `.etc` 梳理不完不是漏了，是缺坐标系：清单把「消费时点」与「生命周期状态」平铺了。
   补 6 根正交轴（消费时点／事实类型／执行点／可寻址性／生命周期／变更频率）后混乱消失。
   其中「变更频率」补的正是 draft5 自认缺的「维护程度、生命周期」。
