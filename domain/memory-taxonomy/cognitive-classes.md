# 经典记忆分类详解：感觉、工作、情景、语义、程序

> 2026-09-21 · [记忆有哪些分类法](index.md) 的支撑主题。
> 这一份讲**认知科学里那套最常见的分类**——短期/工作/长期，长期下的情景/语义/程序，以及陈述性/程序性、外显/内隐这两条交叉的轴——并把每一类映射到 LLM Agent 的实现上，说明哪些映射成立、哪些只是比喻。
> 认知科学概念按教科书通行的定义陈述（Baddeley 工作记忆模型、Tulving 的情景/语义之分、Miller 的容量讨论等），不把它们当作对 LLM 内部机制的断言。**类比是教学工具，不是机制证据。**

---

## 为什么从这套分类切入

对一个已经懂 LLM 和 Agent 的读者，"记忆"这个词最先唤起的就是这套分类：短期记忆、长期记忆、情景记忆、程序性记忆。从它切入有三个实际好处。

**词汇共通。** 论文和框架文档大量使用这套词（MemGPT 的 core/recall/archival 对应工作/情景/归档；LangMem 的 semantic/episodic/procedural 直接照搬；2602.06052 把 sensory 列为第五类）。不先把这些词讲清，读任何一篇都会把比喻当成机制。

**它能提示缺失的能力。** 大多数系统只实现了"语义记忆"（抽取的事实）与一部分"情景记忆"（原始日志），而**程序性记忆几乎没有成熟实现**。按这套分类检查一个系统，比看它的架构图更容易发现缺口。

**它能暴露类比的失效。** 人类的短期记忆容量有限且会衰减；LLM 的上下文窗口是"可容纳但注意力分布不均"。两者都叫"工作记忆"，行为规律却不同。把失效处讲清楚，比讲相似处更有价值。

代价是要随时提醒：**这套分类描述的是人，不是模型。** 下面每一节都在结尾给出"这个类比在哪里断掉"。

---

## 一、感觉记忆（sensory memory）

**定义。** 外界刺激在专门通道里保留极短时间（数百毫秒到数秒）的缓冲，未经注意就迅速消退。它是"进入"而不是"记住"。

**在 Agent 里的对应物。** 本轮工具返回的原始输出、刚读入的那一帧图像或音频、模型在当前调用里看到的全部输入。它还没被写成任何东西，也没有跨调用延续。

**容易被误用的地方。** 把工具输出缓冲讲成"感觉记忆"在教学上没什么收益——它更接近 [Context)(../../analysis/concepts-and-boundaries.md) 的入口，而不是 Memory 的一种。真正值得讲的反倒是它的一个特性：**感觉记忆容量大而持续时间极短，一旦被注意就转入工作记忆**。对应到 Agent，"哪些原始输出被保留下来进入下一次调用"是一个真实的工程决策（是否截断、是否摘要、是否落盘），而叫它感觉记忆并不增加理解。

**类比断在哪里。** 人的感觉记忆会无差别衰减；系统的原始输出不会自己消失，是代码决定丢弃。一个是生理限制，一个是工程选择。

## 二、短期记忆与工作记忆（short-term / working memory）

**定义。** 短期记忆指信息在数秒到数十秒内的保持；**工作记忆**更进一步，指在保持的同时进行操作（Baddeley 的模型把它拆成中央执行、语音回路、视觉空间模板，后来补入情景缓冲）。容量讨论从 Miller 的 7±2 到后续研究给出的 4±1，核心结论一致：**容量小且是瓶颈**。

**在 Agent 里的对应物。** 上下文窗口，以及窗口内的草稿、当前计划、正在累积的工具结果。它是"这次调用能看到的东西"。

**这是全篇最需要小心的一类**，因为三个常见说法都不准确：

| 常见说法 | 为什么不准确 |
|---|---|
| "上下文窗口就是工作记忆" | 工作记忆的关键不是容量而是**可操作**——能在保持的同时更新、抑制、重排。上下文窗口里的内容能被读到，但模型不能像中央执行那样主动改写它 |
| "128K 上下文等于超大的工作记忆" | 容量不是唯一约束。研究反复观察到**位置效应**：材料放在窗口中部时利用率下降（lost-in-the-middle）。可读长度不等于可用长度 |
| "上下文满了就压缩" | 压缩是**另一类记忆（语义/情景）的生成动作**，不是工作记忆的溢出处理。把两者混为一谈会掩盖"压缩丢了什么"这个问题 |

**可检查的问题。** 把一个关键事实分别放在窗口的开头、中部、末尾，看模型是否同样能用到它。这个检验比任何"上下文够不够大"的讨论都直接。

**类比断在哪里。** 人的工作记忆容量是硬约束且会随时间衰减；系统的上下文是**可读但注意力不均**，且可以通过检索把内容重新摆位。这导致两者在"如何补救"上完全不同：人靠复述与组块，系统靠重排与卸载。

## 三、情景记忆（episodic memory）

**定义。** Tulving 区分出的"记着某件发生在特定时间地点的个人经历"，特点是带有**心理时间旅行**——回忆时重新经历当时的情境，而不只是知道结论。

**在 Agent 里的对应物。** 原始对话记录、事件日志、工具调用轨迹、带时间戳与来源指针的任何不可变记录。

**实现要点。** 三类元数据决定它是不是真的情景记忆：**时间**（何时发生）、**来源**（从哪条对话或哪个工具得到）、**不可变性**（原文不改，更正以新记录追加）。缺了任何一项，它就在向语义记忆退化。

**最常见的误用：只存摘要却自称情景记忆。** 摘要是语义化的结果，它回答"发生了什么"但不回答"当时是谁说的、原话是什么、为什么那样判断"。教材里那个反复使用的例子——先记"优先阅读框架 A"，一周后改为"只借鉴 A 的写入机制"——只有保留两次原始表述才能回答"为什么曾考虑部署"。压成一条"重视 A"就同时答错了现在和过去。

**可检查的问题。** 问一次讨论中未经提前提炼的细节（精确措辞、当时的理由、被否决的方案）。检索式系统在这里要么答不出，要么答成概括。

**类比断在哪里。** 人的情景记忆会重构、会被后来信息污染；系统的原始日志不会自发改变，但**检索入口能不能到达它**是另一回事——保存了原文不等于能找回（这一点在 Hindsight 的 retain 目标过窄时已经观察到，见 [Memory 工程选择)(../../analysis/memory-engineering-selection.md)）。

## 四、语义记忆（semantic memory）

**定义。** 去情境化的事实、概念与知识：知道"巴黎是法国首都"，但不必记得是哪本书里看到的、什么时候知道的。

**在 Agent 里的对应物。** 抽取的原子事实、用户画像、知识库、任何"当前有效的认识"。Mem0 的 add 流水线、LangMem 的 semantic 类型、各类 profile 结构都属于这一层。

**它和情景记忆的关系是互补，不是升级。** 语义记忆让未来的读取变便宜（不必重读原文），代价是**写入时已经选过一次什么重要**。这正是 [Memory 工程选择)(../../analysis/memory-engineering-selection.md) 里"保留材料还是提前理解"的那道张力：两者不是新旧关系，而是赌注不同。

**最常见的误用：把语义层当成全部历史。** 抽取必然丢信息，而丢掉的是否重要取决于未来的问题。若未来问稳定偏好，事实集合很合适；若未来问当时的精确措辞，它必然不够。判断标准不是"抽取准不准"，而是"未来会问什么"。

**可检查的问题。** 事实更新后，旧值是否还会被检索到、并被当成当前事实使用。这是语义层最典型的失败：**它擅长记住，不擅长作废**。区分"当前成立"与"当时成立"是时态模型（如 Graphiti 的双时间）要解决的事。

**类比断在哪里。** 人的语义记忆来自大量经历的渐进抽象，且可以不确定、可修正；系统的语义层常由**一次性 LLM 抽取**生成，置信度不表达、来源不保留、错误不显形。

## 五、程序性记忆（procedural memory）

**定义。** "知道怎么做"的记忆：骑车、打字、按流程操作。特点是**难以言述**（很难把骑车步骤完整说出来）且通过练习逐渐形成，一旦形成不易遗忘。

**在 Agent 里有三种实现，差别极大**，混在一起谈会让人误以为它们是一回事：

| 形态 | 例子 | 获取方式 | 能否直接检视与修改 |
|---|---|---|---|
| 权重中的能力 | 基座模型的编码与工具使用能力、微调学到的风格 | 训练 | 不能，只能通过行为间接观察 |
| 可编辑的行为规则 | system prompt 中的约定、skill 文件、AGENTS.md | 人工或 Agent 自己写入 | 能，改了下次调用即生效 |
| 可执行产物 | 脚本、工具定义、MCP 服务器 | 生成并验证后保存 | 能，且可以被执行检验 |

**为什么它最容易被忽略又最贴近工程。** 学界把它点名为"价值最高、实现最少"的一层；而在工程里，真正让 Agent 少犯重复错误的往往不是多检索到一条事实，而是**把规则固化成行为**——例如"改完代码先跑测试"这条约定一旦进入常驻提示，就不再需要每次检索。LangMem 的 procedural 类型（Agent 根据反馈改写自己的 system prompt）是目前少见的显式实现。

**最常见的误用：把"存了一段操作说明"当成程序性记忆。** 一段能读出来、需要检索才会进入上下文的操作步骤，本质是**语义记忆**（它可被言述）。程序性记忆的判据是**不需要检索就表现出来**。这个区分看着吹毛求疵，但它决定了一个机制该放在哪一层实现：能被检索到的事实放在存储层，应该内化的行为放在常驻层。

**可检查的问题。** 在一个新任务里，Agent 是否无需任何检索就表现出该行为；把该规则从存储里删掉，行为是否仍然发生。若是，它已经是程序性的；若否，它只是被记住的事实。

**类比断在哪里。** 人的程序性记忆通过重复练习缓慢形成且难以言述；系统的"可编辑规则"是**显式写入、一次生效、可以瞬间删除**。这让系统的程序层比人的程序层灵活得多，也脆弱得多（一次误删就全部消失）。

## 六、两条容易混淆的轴

教学中最容易出错的地方，是把下面两组划分当成同一件事。

**陈述性 vs 程序性** 是顶层二分：能不能被"陈述"出来。
**情景 vs 语义** 是**陈述性内部的**再二分：记的是带情境的经历，还是去情境的事实。

所以正确的包含关系是：

```text
记忆
├── 陈述性（declarative，能说出来）
│   ├── 情景（episodic，带时间与情境）
│   └── 语义（semantic，去情境的事实）
└── 程序性（procedural，知道怎么做）
```

把"情景/语义/程序"并列成三类是一个常见但会丢掉结构的简化——它让人以为三者同级，从而忽略"程序性与陈述性是另一条更靠上的分界"。

**外显 vs 内隐** 是第三条轴，与前两条交叉：内隐记忆（启动、条件反射、程序性技能）不需要意识参与就能影响行为。它在 Agent 里的对应物是**检索不到但确实影响输出的东西**：训练得到的倾向、微调注入的偏好、常驻提示、甚至是同一前缀的 KV 复用。这类东西正好落在 [分类法主文](index.md#三处明确的归属冲突) 里提到的那场争论中心——2512.13564 先把缓存重写这类机制划出 agent memory，后来又把 KV 复用收进 latent memory 的 reuse 型。**"能不能被检索出来"是划分它们的可操作标准。**

## 七、另外两类值得知道

**前瞻记忆（prospective memory）。** 记着"将来要做的事"——下午三点开会、明天回复某人。它不是"记得过去"而是"记着将来"。在 Agent 里对应待办、计划、定时提醒与任务队列。**这一类在系统设计中常被漏掉**：绝大多数记忆框架只做"回顾型"检索（问了才找），不做"到点主动提起"。对 24/7 主动型 Agent，这一层的缺失比检索精度更致命。

**语义化（semanticization）。** 情景记忆随时间逐渐失去情境细节、转化为语义记忆的过程：你可能记得"我们去过海边"却不再记得是哪天、谁开的车。它直接对应 Agent 里的 consolidation 与摘要流水线——**把原始日志整合成稳定认识，本质就是在人工加速语义化**。这一点很有教学价值，因为它立刻引出一个工程问题：语义化是不可逆的，一旦转化就再也回不到当时的情境。哪些东西不该被语义化，是设计记忆系统时要显式回答的问题。

## 八、用这套分类读一个系统

拿到一个记忆框架，按下面的顺序问，比看它的架构图更快定位：

1. **它的"语义层"是什么**——抽取了什么、用什么提示抽取、抽取结果能否看到来源。
2. **它有没有真的情景层**——原文是否保留、带不带时间与来源、更正时是覆盖还是追加。
3. **它的程序层在哪里**——有没有可被 Agent 自己改写的行为规则，还是只有检索得到的操作说明。
4. **它的工作记忆边界在哪**——什么内容常驻、什么按需取、满的时候发生什么。
5. **它有没有前瞻层**——会不会在没人问的时候主动提起。
6. **它声称的能力属于哪一层，而实际实现了哪一层。**

最后一条最关键。把一个系统宣称的"记忆能力"拆到这五层上，常会发现它只做了其中两层——这不是缺陷，但决定了它能解决什么任务。
