# 记忆有哪些分类法，以及为什么它们互相矛盾

> 2026-09-21 · 主题综合。把"怎样给记忆分类"本身当成一个研究问题，而不是先选一套术语再往里填系统。
> 依据为本地已入库的六篇综述与一篇系统表征论文的**局部原文抽取**（[逐篇分类卡片](taxonomies-by-survey.md)），以及 [记忆横评对照](../../analysis/memory-benchmark-crossreview-2026-09.md) 中"分数为何不可比"的观察。
> 这不是对分类法的评选，也不给出统一标准；分类是工具，选择服务于要回答的问题。

---

## 一、为什么分类法值得单独成为主题

记忆领域的一个特殊困难是：**同一批系统，在不同人的分类里落到不同的格子，而且没有谁明显错了。** 这直接造成两个后果。

第一，**跨论文的结论无法直接拼接**。一篇说"RAG 是长期记忆的一种实现"，另一篇说"RAG 与 agent memory 概念相异"，同一句话在两者里的真值不同。读到"X 提升了长期记忆"时，若不知道作者用的是哪套边界，就无法判断它到底提升了什么。

第二，**评测数字的比较对象会错位**。[记忆横评对照](../../analysis/memory-benchmark-crossreview-2026-09.md) 里出现的"长上下文基线也算一种记忆系统"与"记忆系统是外挂模块"两种立场，正是不同分类法在评测里的投影：AMA-Bench 与 MemoryAgentBench 都把长上下文直接放入对照表，因为它们把长上下文算作记忆的一种实现；而只把外挂存储算作记忆的框架，则天然不会和长上下文同台比较。分类选择先于分数比较。

所以本主题要回答的不是"记忆有哪几类"，而是：**各家在切什么轴，他们把什么排除在外，以及这些分歧在什么条件下会改变结论。**

## 二、六家的主轴

| 论文 | 主轴 | 记忆的定义方式 | 把什么排除在外 |
|---|---|---|---|
| 2404.13501 (2024-04) | 来源 / 形式 / 操作 | 窄定义只含同一次 trial 内的历史信息（§3.2），宽定义扩展到跨 trial 与外部知识（§3.3） | 几乎不排除；RAG 式外部知识与参数化记忆都在宽定义内 |
| 2505.00675 (2025-05) | 表示 / 时间跨度 / 功能类型 / 操作 | 长期记忆"同时涵盖 contextual 与 parametric memory，并包含 RAG"（§2.2） | 基本不排除；把投毒风险列为安全问题而非边界 |
| 2512.13564 (2025-12) | 形式 / 功能 / 演化 | 把 agent memory system 形式化为随时间演化的状态 Mt（§2.2） | **明确排除**直接干预模型内部状态的机制——缓存重写、循环状态持久化，归为 LLM memory 而非 agent memory（§2.3.1）；RAG 被定为概念相异（§2.3.2） |
| 2602.06052 (2026-01) | 载体 / 认知机制 / 记忆主体 | "系统随时间保留、组织并利用信息的能力"（§2.2） | 不排除；向量库被直接称为 RAG 框架下外部记忆的主流实现（§3.1.1），KV cache 属内部记忆载体（§3.1.2） |
| 2603.07670 (2026-03) | 时间范围 / 表示载体 / 控制策略 | 记忆是 POMDP 中的 belief state，即交互历史的充分统计量（§2.2） | 不排除；长上下文、向量、参数都归为 substrate |
| 2606.06448 (2026-06) | 范式（+ 构建管线 / 可变性） | 按系统实现分成四范式（§2.2） | 不排除；长上下文就是范式之一 |

逐篇的类别取值、子类与原文位置见 [逐篇分类卡片](taxonomies-by-survey.md)。

**先看这张表里的两件事：**

- **"操作"这一维出现得越来越频繁。** 2404 是写—管—读；2505 拆成 Encoding（consolidation、indexing）／Evolving（updating、forgetting）／Adapting（retrieval、condensation）；2512 把 dynamics 提升为与 form、functions 并列的第三根支柱；2603 则把"谁决定存/取/弃"单独抽成 control policy。**分类的重心从"记忆是什么"移向"记忆被怎样操作"。** 这与工程现实一致：系统之间的差异大多不在存了什么，而在什么时候写、由谁决定、能否改写。
- **边界的宽度差别极大，而且不是随时间收敛的。** 2024 年的 2404.13501 用宽定义几乎什么都收；2025 年末的 2512.13564 反而是最严格的一家，明确把模型内部状态划走。宽严不等于新旧或深浅。

## 三、三处明确的归属冲突

这三处不是术语差异，而是"同一个东西算不算记忆"的实质分歧。引用任何分类结论前，必须先说明站在哪一边。

### 3.1 RAG 算不算记忆

- **算**：2505.00675 §2.2 把 RAG 写进长期记忆；2602.06052 §3.1.1 称向量库是"RAG 框架下外部记忆的主流实现"；2606.06448 §2.2 把 flat RAG 与 structure-augmented RAG 直接列为记忆范式。
- **不算**：2512.13564 §2.3.2 把 RAG 定位为静态外部知识范式，与"持久自演化基"的 agent memory 概念相异。

**这个分歧何时改变结论**：任何"记忆系统 vs RAG"的对照实验，都是站在第二家的立场上设计的；而任何"我们改进了 RAG 记忆"的说法，都是站在第一家的立场上说的。两种说法都不自相矛盾，但不能互相引用。

### 3.2 KV cache 与模型内部状态算不算记忆

- **算**：2602.06052 §3.1.2 把 KV cache 与 latent state 列为 internal memory 载体；2512.13564 自己 §3.3.2 也把 KV 复用列入 latent memory 的 reuse 型。
- **不算**：2512.13564 §2.3.1 明确说缓存重写、循环状态持久化"更适合归为 LLM memory 而非 agent memory"。

**注意这是同一篇论文内部的两处不一致**——它先在边界处把内部状态划走，后在形式分类里又把 KV 复用收进来。这提示一个更一般的问题：**"记忆"这个词在这一领域同时承担"能读到的内容"与"影响行为的任何状态残留"两种含义**，很多争论源于此，而不是源于事实分歧。本项目的相关工作把这类状态归入 Harness 与 Context 的处理范围（见 [Agent 的持续运行](../agent-runtime/index.md)），不在这里重复划分。

### 3.3 "external" 指什么

- 2602.06052 §3.1.1：**external = 模型参数与状态之外**（向量库、文本记录等）。
- 2512.13564 §3.2：**external parametric memory = 模型内的辅助参数**（LoRA、adapter 等）。

同一个词，一个指"模型外"，一个指"模型内但不是主权重"。读到 "external memory" 时必须回到该文的定义，否则会把向量存储和 LoRA 适配器当成同一层东西。

## 四、共通的轴与独有的轴

把六家叠起来看，有三根轴是稳定的，另外几根各自为政。

**稳定共有的：**

1. **表示/载体。** 六家全部以某种形式区分"以文本/结构化数据存放"与"编码进参数"。这条轴的分歧最小，也是工程上最有用的一条：它决定了能否直接检视、修改与删除一条记忆。
2. **认知功能类型。** working / episodic / semantic / procedural 这组划分在 2505、2602、2603、2512 中反复出现，且含义基本一致。它回答"这条记忆服务于什么"，与实现无关。
3. **操作与生命周期。** 六家都以各自术语覆盖了写入、整理、检索、更新、遗忘中的若干项；差别在是否把"遗忘"与"压缩"显式列为独立操作。

**各自独有的：**

| 独有轴 | 提出者 | 它补上了什么 |
|---|---|---|
| 来源（inside-trial / cross-trial / external knowledge） | 2404.13501 | 信息的出处，决定它能否被"重新获得" |
| 操作三态 + condensation | 2505.00675 | 把压缩当成一等操作 |
| functions（factual / experiential / working）+ dynamics | 2512.13564 | 把"记忆为什么存在"和"它如何演化"分开 |
| 记忆主体（user-centric / agent-centric）+ sensory | 2602.06052 | 记忆**为谁**服务，这是多 Agent 与个性化问题的入口 |
| 控制策略（heuristic / prompted self-control / learned） | 2603.07670 | 谁决定存、取、弃，直接对应 harness 的设计点 |
| 范式 + 构建管线 + 可变性 | 2606.06448 | 系统实现与代价结构，唯一可映射到能耗与延迟的分类 |

**这张表本身就是一条研究线索**：独有轴的不断出现，说明这个领域还没有稳定到可以只留一套术语；每一次新轴的出现，通常对应一类此前未被描述的系统（多 Agent、可学习管理、成本敏感）。

## 五、怎样选用一套分类法

不给统一标准，给判断条件。选轴之前先问要回答什么问题：

| 要回答的问题 | 该选用哪些轴 | 不该被哪些轴干扰 |
|---|---|---|
| 这条记忆错了，能不能改、改了谁会看到 | 表示/载体 + 可变性 | 认知类型不决定可改性 |
| 换一个更强的基座模型能不能补上记忆 | 表示/载体（区分上下文内与外挂）+ 控制策略 | 功能类型会把"上下文里的材料"和"外部存储"混在一起 |
| 多 Agent 共享会不会污染彼此的状态 | 记忆主体（user/agent-centric）+ 作用域 | 只有"长期/短期"不够，它不表达归属 |
| 写入成本是否会在使用期摊平 | 范式 + 构建管线 + 可变性 | 功能分类完全不涉及代价 |
| 该不该把 RAG 当成记忆的一部分来讲 | 先声明边界（见 §3.1），再选轴 | 不能默认两家立场可以混用 |

一个反复出现的误用是：**拿"长期/短期"当主分类轴**。它在所有六家里都不是主轴，而且它把两个不同问题压成了一个：信息保存多久（时间跨度）与信息以什么形式保存（载体）。一个每天重建的向量索引和一个持久的文件，在"长期"这一格里没有区别，但在可否审计、可否回滚、写入代价上完全不同。

## 六、本主题的限制

- 上述分类均来自**局部原文抽取**，不是对六篇论文的全文复核；每篇的具体类别取值与原文位置见 [逐篇分类卡片](taxonomies-by-survey.md)，引用前回到该处。
- 分类法描述的是**作者如何组织材料**，不能直接当作世界的真实结构。两家分类冲突不构成"其中一家错了"的证据。
- 本主题没有覆盖 2026 年新出现的机制（如把管理策略学出来的做法）。若它们形成新的稳定轴，应回到本文第二节的表格更新，而不是为新系统单设一格。
- 本主题不涉及"哪类记忆更有价值"的判断，那属于 [Memory 工程选择](../../analysis/memory-engineering-selection.md)。
