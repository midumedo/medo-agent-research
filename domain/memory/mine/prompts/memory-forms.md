# 背景
Agent memory 正在成形为一个研究领域，它的结构性核心是一个计算问题：一个以 LLM 为中心的 agent，行为由前向计算决定，过去要影响未来，必须经由某种持续存在、可被读取的状态——这种状态在计算上可以放在哪里？位置屈指可数，但放在哪里，决定了它是什么性质的记忆、以什么代价被写入和读取。载体因此是任何记忆设计的第一分岔，也是这个领域分歧真正所在的轴线。

我正在搭建 agent memory 的对比式研究框架——系统分类与深入理解，不提出新方法。本篇是地基：把载体问题论证清楚。它是一份自足的参考资料，后续所有章节默认这里的判断成立，其中的判断会向下传播。

# 分类框架
三个载体，统一定义轴：记忆状态要影响行为，必须接入前向计算——接入点在哪里，决定它是什么载体。

- **token**：状态存放在符号空间——以离散符号序列存在于模型之外，读取时作为输入进入计算。
- **parametric**：状态存放在参数空间——记忆即权重的一部分，读取内在于前向计算本身。
- **latent**：状态存放在表征空间——以连续向量形式存在于模型之外，读取时注入计算的中间层。

定义只做指称锚定，是起点不是结论。可检视性、读写成本、持久性等性质是位置的推论，由文章推导，不预设进定义。三个是位置不是互斥的格子，一个系统的记忆可同时分布在多处——承认即可，本文的分析单位是载体本身。正因为会并存，每种载体从哪里开始到哪里结束，才更需要划清。

# 任务
写一篇自足的深度参考文章。主体是三个载体各自的深度刻画：定义从何而来、什么算什么不算、状态存放在哪里、读写如何发生、各自的性质与代价。三个载体同等深度。KV cache需要专门说明，多载体的项目也可作为补充进行说明。

# 要求
这份文档的产出会向下传播进整个研究框架。四条要求都由这个事实推出，每条同时点名它要纠正的默认写法：

**详尽**：文档是拿来查的，不是拿来读的——没写进来的区分，就是后续研究会掉进去的洞。覆盖优先于篇幅与流畅，边缘的、别扭的、不流行的案例同样处理，宁可臃肿不可略过。默认行为是写到“一篇合理文章”的长度就收笔，这里的标准是穷尽。

**准确**：每句话会被当作事实地基使用。机制必须按机制写：状态在哪里、经过什么计算、产生什么效果——默认用类比、“本质上”、“相当于”来解释，这里禁用；术语首次出现即定义。

**无偏**：落进文档的任何判断，都会变成我后续研究的预设。训练里带着的领域默认倾向（谁是主流、什么更有前景）会经措辞、篇幅、框架选择无声渗出——只做描述性陈述，评价要么不给，要么显式标注为开放问题。一个具体风险：我之后主研 token 级 memory，这是路线选择不是优劣判断，本篇不能写成“token 是正确选择”的事后论证。有争议处保留多方立场或标注无共识。

**第一性原理**：这篇文章的框架会成为我后续所有章节的骨架，骨架必须推导出来，不能继承。对这个领域的知识来自文献，默认会复述综述的框架与判断——论证起点只能是“状态可以放在哪里”这个计算问题，每一步给出依据；文献只作证据与对照，某结论被文献说过不构成它成立的理由。

# 范围
- 载体间的转化与混合：承认存在，不作为主要研究对象。划边界时允许精炼点明转化关系（token 内容经训练进入参数，就不再是 token form），但不展开机制、不设专章、不梳理转化路径。
- 记忆生命周期（写入、维护、调用、更新、淘汰）等其他分类属其他研究，只在区分载体必需时最小限度触及。
