## §1 引言：冻结的前提
### 1.1 冻结
Agent memory 研究的全部前提可以压缩为一个事实：**基座模型在部署之后参数冻结**。预训练结束，参数 θ 不再随使用而改变，模型以只读函数的形式提供服务。
这一冻结并非技术必然，而是经济必然。单次梯度更新的开销是单次前向传播的数个数量级；若每次会话都触发训练，服务的成本结构无法成立。于是学习成本被一次性摊销到预训练阶段，此后模型作为固定函数运行。
冻结制造了一道结构性裂缝：**模型的知识存量在部署时刻成为常量，而世界的信息增量持续产生**。Agent memory 的研究问题即在于：如何让一个常量的函数，应对一个增量的世界。
一个值得记录的历史细节：在 agent 范式之前，“记忆”并未构成独立研究对象——训练本身即记忆，每一步梯度下降都是一次写入，模型的知识即其训练轨迹的凝固。冻结之后，记忆才第一次从训练中剥离，成为需要独立设计的系统组件。这是 agent memory 作为研究领域的诞生时刻。
### 1.2 判据：什么构成记忆
考虑一次普通的前向计算：模型在该次计算中“包含”了全部输入 token——但这是**当下**，不是记忆。本章采用的判据是：
> **定义（记忆判据）**。设信息 i 在时刻 t₁ 的计算 C₁ 中产生或出现。若存在机制，使 i（或其变换）在 t₂ > t₁ 的另一次计算 C₂ 中影响计算结果，则称该机制实现了对 i 的记忆。
使信息成为记忆的，不是它被存储，而是它**能够跨越计算边界存活**。由此，任何记忆系统必然包含两个功能组件：**持久化介质**（信息在两次计算之间的存身之处）与**重注入机制**（信息重新进入后续计算的通道）。
### 1.3 记忆系统的算子分解
无论载体为何，一个完整的记忆系统可分解为五种算子：写入 W（经验→存储项）、存储 S（维护记忆的物理存在）、读取 R（推理时选择并注入）、更新 U（修改或合并）、遗忘 F（淘汰）。
本章的核心论点是：**三类载体是这五种算子在三个不同物理位置上的实例化；位置的不同导致算子的实现方式、成本结构与失败模式产生根本性分野。**注意，五算子是分析工具而非分类——本章不使用它对任何记忆内容或功能做分类。

## §2 三个物理位置
### 2.1 前向计算的信息解剖
设冻结模型 M(θ)，输入序列 x = (x₁, …, xₙ)。前向计算中，与信息相关的物理存在只有三处：
1. **输入序列 x**——信息进入计算之前；
2. **模型权重 θ**——计算赖以进行的通道，冻结条件下为常量；
3. **中间激活**（各层 K/V 张量、hidden states）——信息在计算中流动时的瞬时状态。
需排除两个看似候选的位置。其一是**输出**：输出位于计算出口，要再次影响计算，必须作为后续输入进入序列（自回归的当下延续），或被写成文本保存（后者已落入 token 载体的写入来源）。其二是**梯度通道**：反向传播本来是信息写入权重的通道，冻结恰恰意味着该通道被关闭——parametric memory 的本质，正是有代价地重新打开这条被冻结关闭的通道（§4.3）。
### 2.2 穷尽性命题
> **命题（载体的穷尽性）**。在基座冻结的前提下，任何使信息跨计算存活的机制，其记忆载体必居三者之一：**token**（使输入持久）、**parametric**（使通道持久）、**latent**（使中间态持久）。
这不是分类学惯例，而是关于计算结构的事实推论。三类载体因此不是同一问题的三种解法候选，而是三个不同的问题（§7.3 论证）。
### 2.3 归类判据：以读取时刻为准
本章采用的归类纪律需要先行确立，因为它贯穿所有后续判例：
> **判据**。混合系统的归类，以**读取时刻**信息所处的载体为准，而非写入时使用的技术。
理由：载体分类的对象是“记忆如何生效”，而非“记忆如何被制造”。写入技术可以在任何载体间借用，但生效位置由计算结构唯一决定。判例集见 §6.2。

## §3 token 载体
### 3.1 定义与机制
> **定义（token 记忆）**。模型 M(θ) 冻结；维护外部记忆库 D（符号集合）；每次推理执行检索 r(q, D) → S ⊆ D，将 S 序列化后与查询拼接，模型计算 M(θ; q, S)。信息影响计算的唯一通道是输入 token 序列。
结构上，token 记忆是一个**围绕冻结模型外围的信息检索与注入系统**——模型本身完全不知晓记忆的存在，记忆对模型而言只是上下文的一部分。
五算子的实例化形态：写入是文本生成（无梯度）；存储是任意外部介质；读取是“检索 + 拼接”的显式动作，受上下文窗口与 token 成本的注入预算约束；更新与遗忘是文本级操作。全部算子均以 API 调用完成，全程不触碰模型内部。
### 3.2 设计自由度：token 内部分化的必然性与悬置
token 的写入在物理上只有一条约束：**可序列化为文本**。文本操作没有形态限制——可以存原文、存摘要、存结构化事实、存图、存树、存任何构造物。这与其他两类载体形成鲜明对照：parametric 的写入形状由优化动力学决定，latent 的写入形状由张量几何决定，而 **token 的写入形状完全由设计者决定**。
由此得到一个载体级推论：**token 载体的设计自由度最大，因此其内部必然产生分化，且分化是多维的。**
正因如此，本章对 token 内部的组织方式保持克制——直觉在讨论这些分化时极易把三件不同的事混为一谈：
- **存储引擎**：向量库、图数据库、关系库——工程介质的选择；
- **信息压缩度**：原文、原子事实、摘要——写入路径的有损变换档位；
- **组织拓扑**：平坦、树、图——条目间的关联结构。
三者正交：同一份原子事实可以放进向量库也可以放进图库；图拓扑下组织的既可以是原文也可以是摘要；“图”一词更是同时跨越了引擎（图数据库）、拓扑（图结构）与检索算法（图遍历）三个层面。对这三根子轴的分别分析——它们各自的谱系、取舍与组合方式——是后续章节的任务。本章只确立载体级事实：**写入自由度最大意味着设计空间全开放；这既解释了 token 何以成为工程主流（无物理门槛），也解释了为什么对它的内部分类必须推迟到专门章节（过早分类会在混淆的轴上锁死框架）。**
### 3.3 成本结构与性质
**成本结构：写便宜，读贵，且反复付费。** 写入是一次性的 LLM 调用或零成本的被动记录；但每次生效都占据上下文窗口、付出推理成本。同一记忆被使用一千次，就支付一千次注入成本。token 是**订阅制**的记忆。
由“载体是通用文本”派生全部工程性质：**模型解耦**（记忆库与模型可独立更换，记忆资产独立于模型存续）、**可回读**（人类可直接阅读每一条记忆——可审计、可版本管理的基础）、**可迁移**（换基座模型后记忆保留）。这是 token 在工程落地中占绝对多数（§8.1）的根本原因——不是因为效果最优，而是因为它是三类中唯一**可运营**的。
### 3.4 失败的可见性
token 的失败集中而可见：读取端召回失败、注入噪声挤占注意力、新旧记忆冲突未消解、写入端抽取丢失信息。可见性本身是资产：错误可定位到具体条目与具体检索决策——可归因，可修复。
它与 RAG 的概念关系（“检索自身经历”与“检索外部知识”的边界究竟落在哪里）是一个需要独立处理的问题，见辨析章；本章 §6.2 判例表中仅保留其在载体轴上的定位。

## §4 parametric 载体
### 4.1 定义与机制
> **定义（parametric 记忆）**。通过梯度更新 θ → θ′ 将信息写入权重；读取无显式操作，查询 q 直接进入 M(θ′)，信息以模型行为的方式涌现。
parametric 与 token 最深刻的差异发生在**读取端**：token 有一个显式的、可观测的读取动作，parametric 没有。一条事实被写入权重后，不存在任何操作叫“读取这条事实”——它弥散在数百万权重的调制之中，由整个网络的协作计算重构出来。
### 4.2 与预训练的关系，及写入的机制基础
层级关系须先澄清：**预训练知识本身就是 parametric 记忆**——冻结的基座即是一个巨型参数记忆库。Agent 语境下的 parametric memory 特指**预训练之上的增量写入**。
写入的机制基础来自一个关键发现：Transformer 的 FFN 层在功能上近似 key-value memory——中间神经元匹配输入模式（key），输出向量近似指向词汇空间的语义分布。事实性知识大量存储于 FFN 中间层。这一发现是知识编辑方向的支点：知识既然有近似定位，就有近似的定向修改。
### 4.3 写入通道：重开被冻结关闭的梯度
冻结关闭了梯度通道；parametric memory 的写入，本质是**有代价地重开它**。按写入的空间范围与精度，存在一个从粗到细的连续谱：全参数更新（写入整个通道，代价是与存量知识全面相互干扰）；低秩增量（将写入约束在冻结主干之外的 ΔW = BA 上——写入便宜、可插拔、可关闭）；定向修改（借 §4.2 的定位结果，对特定投影做手术式修改——精度最高，但牵连效应与顺序编辑的叠加退化是新引入的问题）。**注意：这个“粗细谱”本身也是后续章节的候选讨论对象，此处仅作为写入通道的物理描述，不构成对 parametric 内部技术路线的分类承诺。**
### 4.4 成本结构与性质
**成本结构与 token 完全对称反转：写贵，读免费。** 写入是离线训练（GPU 时、数据管线、回归评测）；读取即普通推理，零额外开销——写入成本被无限次读取摊薄。parametric 是**买断制**的记忆，适合高频复用、低频变化的知识。
性质由“信息弥散于权重”派生：
- **无地址性**→**不可定向删除**（不存在“删掉这条事实”的操作，只有重训或等待遗忘）；
- **不可回读**（无法从 θ′ 读出写入过什么——审计与合规在记忆级别上不可能）；
- **时间无表示通道**（见 §7.1：权重是纯函数参数，一次前向没有“现在”的概念；梯度更新虽有时间顺序，但收敛后顺序效应湮灭为不可读的动力学痕迹）。
### 4.5 记忆与推理的不可分离性
读取端没有操作，意味着**不存在“使用记忆”的可辨识时刻**。token 记忆的使用有明确边界（检索发生、注入发生、模型开始阅读）；latent 的使用也有边界（张量拼接发生在哪一步是确定的）。parametric 没有——写入权重的事实与模型固有能力之间的边界，在计算图中不存在任何对应物。
由此产生一个构成性的（而非工程性的）后果：**parametric 记忆的贡献无法与模型能力的贡献相分离**。当模型答对一个问题，没有任何手段区分“因为它记得”与“因为它会推理”。这向下投射为 parametric 评测的根本困难——只能通过编辑前后的行为差异间接测量，无法像 token 那样测量“检索质量”这个独立环节；向上投射为一个概念问题：当记忆与能力不可分，“记忆”在 parametric 载体中还剩多少独立内容。
### 4.6 失败模式
灾难性遗忘（写入损伤存量）；编辑的牵连效应（定向修改波及无关推理、或改了事实而关联推理不跟随）；顺序编辑的叠加退化（每次编辑污染上次编辑的效果）。所有这些失败都是**不可见的**——湮没在权重深处，无法归因到任何可指认的位置。

## §5 latent 载体
### 5.1 KV cache 的机制回顾
自回归生成中，第 t 个 token 依赖全部前文；若每步重算前文各层的 K/V 投影，总计算量为平方级重复。KV cache 的工程解法：每层的 K/V 只算一次、存下复用。KV cache 因此是推理系统的标准组件——**本职是计算优化，算完即弃**。
latent memory 的核心洞察是换一个视角看这批张量：**KV cache 里存的，是模型对前文的处理结果**——每一层的 K/V 编码了前文 token 在该层注意力下的角色。丢弃它们，下次就要重新计算“理解”；保留它们，就是保留“理解”本身。
### 5.2 定义与注入点
> **定义（latent 记忆）**。将前向计算的中间产物以张量形式持久化，并在后续前向计算中直接注入复用，跳过“从 token 重新计算”的环节。
注入点恰好覆盖前向计算的三个阶段：KV 张量拼接（attention 层入口，主流形态）、hidden states 拼接（层间）、连续向量作为前缀嵌入（embedding 层，即 soft tokens / continuous prefix）。这是 latent 作为“第三位置”的完整性佐证——三种注入点分别对应计算流程的三处间隙。
与 token 的根本区别：**token 让模型重新理解一遍文字；latent 直接保存并复用模型上次理解的结果。**
### 5.3 记忆临界点
KV cache 何时成为记忆？会话内，它是当前上下文的注意力缓存，请求结束即销毁——此时它是**计算状态**，是推理引擎的优化对象。跨请求持久化并复用时，“上一次的计算结果”存活到了下一次计算——按 §1.2 判据，**这一刻它升格为记忆**。
> **判据**：会话内缓存是系统优化；跨请求可复用的持久化 KV 才是记忆。
工程形态上，这一临界点已由推理引擎跨过（前缀缓存、跨请求 KV 复用，及其产品化形态），也有从压缩、生成到定点操作的多条深化路线——这些同属 latent 内部的设计分化，按本章纪律悬置至后续讨论。
### 5.4 存储成本：算例
fp16 下每 token 的 KV 体积为 2 × n_layers × n_kv_heads × d_head × 2 字节：
- Llama-2-7B（MHA，hidden 4096，32 层）：≈ **512 KB / token**；
- Llama-3-8B（GQA，8 个 KV 头）：≈ **128 KB / token** → 100K token 对话 ≈ **12.8 GB**。
对照：同一 100K token 的文本本体约 0.4 MB——同一内容的 token 形态与 latent 形态相差 3–4 个数量级。
latent 的成本结构由此清晰：**写即计算（缓存是预填充的副产品），读近乎免费（张量拼接），存储极重**——为“保存”本身持续付费，三类载体中独一份。
### 5.5 性质
**不可回读**（张量对人不可读，且从 KV 解码出文本属于重新生成而非保真回读）；**版本绑定**（绑定特定权重与推理配置——量化方案、位置编码实现、模型版本任一改变即作废，且权重的任何更新都使其失效——这与 parametric 更新构成结构性冲突）；**坐标可寻址**（KV 按（层，头，位置）组织，可在指定坐标上做定点操作——这种精细度在 token 与 parametric 处均无对应物）。失败不可见：一个被压缩失真的记忆，没有页面可翻开来检查它错成了什么样子。

## §6 边界与判例
### 6.1 裸上下文窗口：token 内容跑在 latent 载体上
一个收拢全局的观察：**裸上下文窗口本身，就是 token 形态的内容跑在 latent 载体上的实现**。每轮输入的 token 序列，进入模型后立即被转写为 KV cache（latent 形态）参与计算。token 记忆与 latent 记忆因此面对**同一个物理对象的两个侧面**：前者问“往窗口里注入什么内容”（内容侧），后者问“如何持久化、压缩、复用窗口的计算态”（载体侧）。token 记忆的读取成本中，隐含着 latent 载体的预填充计算成本——两类载体在成本上共享一个交汇点。
### 6.2 判例表
按 §2.3 判据（读取时刻为准）：
| 系统 | 写入技术 | 读取时刻载体 | 归类 | 判例意义 |
|---|---|---|---|---|
| token 记忆系统（Mem0、Letta 等） | LLM 抽取 | token 注入 | **token** | 标准形态 |
| 系统内嵌的向量索引 | embedding 化 | **从不进入前向计算** | **不是 latent** | latent 要求“以激活形态进入计算”；仅用于检索匹配的向量不满足——这是 latent 定义的精确化 |
| WISE 类（LoRA 银行 + 路由） | LoRA 追加 + router | 进入某个参数化实例生效 | **parametric** | 虽模仿外部存储的追加结构，生效位置在权重 |
| MemGen 类 | RL + LoRA | 以 latent token 的 KV 形态进入计算 | **latent** | 写入动用 parametric 技术、读取在激活空间——读取时刻为准 |
| 为用户语料预填充后跨会话复用的 KV | 一次预填充 | 张量拼接 | **latent** | latent 最纯粹的产品化形态 |
| RAG（外部静态语料） | 无写入 | token 注入 | token 载体形态 | 载体轴**无法**区分它与 token 记忆——二者的区分落在“检索对象的来源”上，属其他轴的管辖；此判例标定本轴判别力的边界 |
最后一行值得强调：**载体轴的判别力是有边界的**——它能回答“记忆如何生效”，不能回答“什么算记忆、算谁的记忆”。后一类问题是辨析章的对象。

## §7 载体的对比
### 7.1 总表（经审计）
上版总表经逐行审计后有两处修正：原“信息保真”一行缺乏参照系（保真相对什么而言？token 相对原文是转写、parametric 是行为化、latent 是确定性中间态——三者不在同一参照系上不可比），已并入“回读与可审计”一行，以“记忆→内容”的回读方向为准；原“时间语义”一行将“token 天然携带时间戳”误写为载体属性（时间在 token 中是**可表示的**，表示与否是设计选择），修正为“时间的可表示性”。另新增三行：记忆与计算的关系、与模型的解耦度、设计自由度（后两行由原“迁移性”“组织谱系”的散落内容收拢并提升）。
| 维度 | token | parametric | latent |
|---|---|---|---|
| 物理位置 | 输入序列（离散符号） | 模型权重 | 激活空间（连续张量） |
| 写入通道 | 文本操作（无梯度） | 重开被冻结关闭的梯度通道 | 前向计算的副产品 |
| 读取 | 显式：检索 + 拼接 | 隐式：与推理无边界 | 张量拼接（近零开销） |

| **成本位置** | **读端（订阅制）** | **写端（买断制）** | **存端（为保存持续付费）** |
| 信息形态 | 离散、可回读 | 弥散、无地址 | 连续、坐标可寻址 |
| 回读与可审计 | 可回读、人可读 | 不可回读 | 不可回读 |
| 时间的可表示性 | 有通道（设计选择） | 无通道（顺序效应湮灭） | 仅序列位置，无事件时间 |

| 编辑的物理形态 | 文本操作 | 需动权重（牵连） | 张量定点操作 |
| 遗忘的物理形态 | 介质销毁（可定向） | 不可定向，只能被覆盖 | 预算淘汰 |
| 失败可见性 | 可归因到条目 | 湮没于权重 | 湮没于张量 |
| **设计自由度** | **无物理约束，组织空间全开放** | **受优化动力学约束** | **受张量几何约束** |
| 代表 | Mem0、Letta、Zep | WISE、知识编辑谱系 | 前缀缓存谱系、MemGen |
表中三处需要正文补强。
**记忆与计算的关系**（新行）是本表最深的一行。token 的记忆在计算之外——读取后模型仍要从 token 重新理解；latent 的记忆在计算之内——记忆本身就是计算状态；parametric 的记忆与计算**无边界**——不存在“正在使用记忆”的可辨识时刻（§4.5）。这一行同时决定了三者的评测形态：token 可测检索质量这个独立环节，latent 可测压缩与复用的系统指标，parametric 只能测编辑前后的行为差异。
**设计自由度**（新行）回答了本章与后续章节的接口问题：parametric 与 latent 的内部主要是工程问题（在物理约束下把写入/存储做好），而 token 的内部是**设计问题**（组织空间全开放，选择空间巨大）——这就是为什么后续章节注定长在 token 里：不只是占比问题，而是唯有它拥有需要专门分析框架的设计空间（§3.2）。
**与模型的解耦度**（新行）统摄了原表的“迁移性”并更深一层：token 记忆的宿主是外部介质，模型存亡不影响记忆资产；parametric 记忆与模型是同一物；latent 记忆虽可存于任何张量存储，但其**有效性**系于特定权重版本——权重一变，存下的张量即成为不可用的“孤儿”。
### 7.2 三种经济学
表中分量最重的一行仍是成本位置。**每一个记忆设计决策，本质都是在选择把成本放在哪里**：token 放读端（其内部一切设计——压缩、组织——都在与“每次读取付费”搏斗）；parametric 放写端（写入必须批量、离线、充分评测）；latent 放存端（其内部设计——淘汰、压缩——都在与“保存持续烧钱”搏斗）。这根成本透镜将在后续章节继续使用：token 内部的各种分化，骨子里仍是读写成本的再分配。
### 7.3 不可通约性
三类载体表面都在解决“让 agent 记住”，实际分属三个学科：token 的核心问题是表示、写入、检索、更新——信息检索与数据库工程的问题；parametric 的核心问题是不破坏存量地写入增量——持续学习与知识编辑的问题；latent 的核心问题是压缩与复用计算状态——推理引擎与系统的问题。评测协议互不可通约（多轮对话召回 vs 编辑三指标 vs 压缩比与长程检索）；失败归因互不可通约（同一现象“答错了”，在 token 处归因于检索，在 parametric 处归因于训练动力学，在 latent 处归因于张量几何）；工程栈完全分离（检索生态 / 训练管线 / serving 引擎）。
三类载体不是同一问题的三种解法，而是**三个问题恰好共用了“记忆”这个名字**。强行统一对比，等价于把数据库索引算法、神经网络训练方法与操作系统虚拟内存放进同一张实验表。

## §8 范围与取材
### 8.1 分类实在性的证据
**主证据：学科结构。**三个载体各自继承了完整的母学科。token 背后是信息检索与数据库传统——数十年的检索研究、向量检索产业与 RAG 生态的全部积累；parametric 背后是持续学习与知识编辑传统——灾难性遗忘自联结主义时期起即是核心议题，知识编辑近年发展出独立的评测体系（zsRE、CounterFact、KnowEdit、Lifelong-M 一脉）；latent 背后是推理系统社区——serving 基础设施与 KV cache 管理的工程文献。三个文献宇宙各有自己的会议、基准与综述谱系，**彼此引用稀薄**。这个结构本身比任何论文计数都更硬地支撑 §7.3：它们不是同一个领域的三个分支，而是三个领域在“记忆”名义下的相遇。
**辅证据：数量分布。**一份收录 199 篇 agent memory 论文的分类仓库（截至 2026 年 8 月）给出：token 约 72%，latent 约 16%，parametric 约 12%。单一来源、社区维护，应作方向性参考。工程侧信号同向：可直接部署的记忆产品几乎清一色为 token 方案；latent 的工程化集中于推理引擎侧（其主流形态按 §5.3 判据严格说属“系统优化”）；parametric 的落地集中于特定场景的权重交付，尚无通用 agent 记忆产品形态。
两路证据指向同一结论：载体轴上的研究能量与工程现实高度偏向 token。
### 8.2 门槛与最优的诚实区分
token 的多数地位有相当部分源于门槛：复用成熟检索栈、可回读、易调试、可运营。多数不等于最优，聚焦不等于神化——parametric 的“读免费”与 latent 的“近零读取开销”在各自适用场景中是 token 无法企及的结构优势。本章对 token 的选择是可通约性与工程现实性的选择，不是性能优越性的判断。
### 8.3 声明
本研究的对比分析聚焦 **token 载体**。parametric 与 latent 在本章作为分类学对照出现，此后不再展开——理由不在其不重要（二者各自是完整的活跃学科），而在于深入的对比需要可通约的技术栈、评测协议与失败归因方式，而三类载体之间不存在这种可通约性（§7.3）。聚焦不是兴趣的偏狭，而是对“对比需要共同度量衡”这一方法论要求的服从。
本章同时为后续章节留下接口：token 内部的分化是必然的、多维的，且至少包含存储引擎、信息压缩度、组织拓扑等彼此正交的子轴（§3.2）；parametric 内部的写入精度谱与 latent 内部的持久化路线，同为各自载体的内部分化问题。对这些子轴的分别建立分析框架，是后续章节的任务；本章的使命只有一件事——把“载体”这根轴立直。

# 载体：Agent Memory 的第一分岔
## 引言：从计算结构到载体问题
一个以 LLM 为核心的 agent，其行为由前向计算决定。若将一次调用视为状态转移，则下一步输出取决于三类输入：模型权重 θ、当前输入 x、以及某种从前一步延续下来的状态 s。**过去要影响未来，必须经由 s——而 s 在计算上只有有限的几个位置可以安放**：作为输入流中的离散符号重新进入（token），作为权重本身被隐式携带（parametric），或作为持续存在的连续张量在激活管线中被注入（latent）。载体因此是任何记忆设计的第一分岔。
这个三分法并非约定俗成，而可以从两条正交轴推出。第一条轴是**表征形式**：离散符号序列，或连续实值向量。第二条轴是**读取方式**：隐式读取——状态即权重，无需单独的读取步骤，每一次前向传播都全部读取；或显式读取——状态作为独立张量存在，需要一次单独的注入操作才能参与计算。两条轴的组合至多给出四个格子：离散加显式，连续加隐式，连续加显式，以及离散加隐式。第四个格子是空的：离散结构一旦折叠进权重并被隐式读取，其在计算上就表现为连续权重的效应，不再保有离散性；任何在权重中保留离散码本（如 codebook）的方案，读取时仍需一次显式查表，故归入显式一侧。**所以计算上存在的载体恰好是三个**——这不是分类学的偏好，而是由前向计算的结构决定的。
本文的分析单位是载体本身，而非载体上的具体系统。三者是位置，不是互斥的格子：一个系统的记忆可以同时分布在多处；正因如此，每种载体从哪里开始、到哪里结束才更需要划清。载体间的转化与混合存在，但不是本文的对象——只在划界必需时以一句话点明（例如：token 内容经训练进入权重之后，就不再是 token 形态）。记忆的写入、维护、调用、淘汰属另一章，本文只在区分载体所必需的最小限度内触及读写代价。
---
## 判定框架：四个维度
对每种载体，本文沿四个维度刻画，所有性质判断都从这四条推出：
1. **状态存放位置**：s 物理上处于模型之外、权重之中，还是激活管线中的独立张量。
2. **读取路径**：s 以何种机制进入一次前向计算——经嵌入层重新编码，还是作为连续张量直接注入，还是根本无需读取步骤。
3. **写入路径**：s 以何种机制被生成或修改——字符串操作、一次前向编码，还是梯度更新。
4. **可检视性**：能否直接读取 s 的内容并做有语义的编辑。
其中**读取路径是首要判据**：状态如何进入计算，决定了它在计算上是什么。表征形式与存放位置是次要判据，用于进一步划界。下文对 KV cache 的处理将依赖这条判据。
---
## Token 载体
### 定义来源与计算定位
Token 载体指记忆以离散符号序列存在、读取时作为输入的一部分参与计算的形态。这个定义直接来源于 LLM 的输入接口：模型能"看见"的一切都必须先变成 token。因此凡是在模型之外持久化、在调用时以文本形式拼回 prompt 的状态——对话历史、用户画像、检索到的文档片段、结构化的笔记——都属于这一类。它是当前生产系统的主导形态：一项对 199 篇 agent memory 论文的清点显示，约 72% 落在 token-level 这一格。这一分布是工程约束的产物，不是优劣的裁决——本文的任务是把它的代价与好处并列摆开。
### 状态存放
存放位置在模型之外的任意持久存储：文件系统、关系数据库、向量库、图数据库。状态与模型解耦——换一个底层模型，记忆层不需要动。这是三个载体中唯一一个存放与计算完全分离的形态。
### 读取机制
读取是一次**完整的重新编码**。被检索的文本被拼入 prompt，经 tokenizer 离散化，经 embedding 层映射为向量，再经注意力与前馈层逐层变换。关键性质是：每次读取都要为整段被检索内容支付一遍前向成本。注意力在 prefill 阶段对序列长度是二次的，在解码阶段每生成一个 token 对保留前缀是线性的。除此之外，读取还受模型的长上下文行为约束：不相关内容会稀释注意力，经验上检索精度比召回率对下游任务影响更大。
### 写入与检视
写入发生在模型之外，是字符串层面的追加或编辑，由 agent 自身（生成待存文本）或外部系统执行。模型不参与写入计算。写入成本低，且发生在推理路径之外。**可检视性是完全的**：每一个字节都是人类可读的，可以在字符串粒度上精确编辑、删除、审计；这也是 token 载体在合规（如被遗忘权）与回滚上被生产系统广泛采用的原因。
### 性质与代价
性质与代价是一体两面，此处并列陈述，不做取舍：
- **读写成本不对称**：写便宜、存便宜、读昂贵。读取成本随被检索量线性（解码）或二次增长，且每次调用都要重付。与之相对，parametric 读零边际成本。
- **容量双约束**：外部存储容量在原则上无界，但读取时受上下文窗口约束；记忆的可用规模由读取侧而非存储侧决定。
- **透明与可移植**：可检视、可编辑、模型无关。这是 parametric 与 latent 都不具备的性质。
- **语义保真但计算失真**：token 保留了原始语义（可逐字还原），但每次读取都经过模型当前的重新编码，长上下文中存在位置偏置与干扰。
### 边界判定
什么算：任何以离散符号持久化、读取时经 tokenizer 进入 prompt 的状态，无论其外部组织是扁平、图结构还是层级。什么不算：一旦内容经训练折叠进权重，它就不再以 token 形态存在——读取路径变了，性质随之改变。介于其间的软提示与记忆 token，将在 latent 一节与 KV cache 一节专门处理。
---
## Parametric 载体
### 定义来源与计算定位
Parametric 载体指记忆编码在模型权重中、通过训练写入、前向传播时隐式读取的形态。这个定义的来源是对预训练模型行为的观察：模型在无任何外部提示的情况下能回忆大量事实性知识，说明这些知识必然存在于权重中；知识编辑研究通过因果追踪进一步定位了事实回忆的中层 MLP 位置。在计算上，parametric 记忆的特征是**没有单独的读取步骤**：θ 进入每一次前向传播，无论相关与否，全部被读取。
### 状态存放
存放位置就是权重张量本身，或附加的适配器模块（LoRA 等）。权重是所有请求共享的：一条 parametric 记忆对每一次调用、每一个用户都生效。这与 token（每请求独立拼装）和 latent（通常按请求或按会话持有）在存放粒度上根本不同。
### 读取机制
读取是隐式且无选择性的。不存在"取出某条记忆"的操作——梯度训练把知识分布式地编织进整个网络，每次前向传播都携带全部权重。这意味着：parametric 记忆的读取带宽极高（无需检索、无需重新编码），但没有寻址能力；其读取成本已摊销进权重本身。
### 写入机制
写入通过梯度更新完成：预训练、微调、LoRA 适配、或定位式知识编辑。ROME 将中层 MLP 视为一个键值记忆，通过定位后编辑插入新的 关联；MEMIT 将其扩展到跨多层编辑一批事实。写入的代价结构是：计算昂贵（需训练信号与算力）、且存在干扰——顺序编辑会退化，大规模编辑研究观察到 ROME/MEMIT 在数百次顺序编辑后精度显著下降，甚至出现"致残编辑"使模型整体失效；模块化方案（如 WISE 的独立记忆模块）能避免灾难性遗忘，但在上万次更新后仍会退化到编辑前水平。LoRA 作为受限 parametric 写入的工程折中，近年也被作为模块化记忆机制系统研究。
### 可检视性
**本质上不可直接检视**。权重是高维实数，知识在其中分布式叠加；只能通过行为探针间接观察。这带来两个直接后果：无法审计模型"知道"什么，也无法精确删除某条知识——被遗忘权在 parametric 形态下没有字符串级的对应操作。
### 性质与代价
- **读写成本不对称**：读零边际、写昂贵——与 token 恰好相反。
- **作用范围全局**：一条 parametric 记忆影响所有调用，无需按需检索；代价是无法按用户或会话隔离（多租户下需每用户独立权重副本）。
- **不可审计、不可精确撤销**：只能整体回滚到某个 checkpoint，不能定点删除。
- **写入脆弱性**：存在灾难性遗忘与编辑间的相互干扰，长序列写入的可持续性是当前研究的开放问题。
### 边界判定与一个有争议的点
什么算：任何经梯度进入权重、并经前向传播隐式生效的知识或倾向——预训练知识、微调技能、LoRA 适配、编辑后的事实。什么不算：软提示虽由梯度训练，但读取是显式的（作为向量注入输入），故不算 parametric（见 latent 一节）。
值得标注的**无共识点**：parametric 与 contextual（token）的边界在部分证据下显得模糊。有研究发现，长上下文训练会把梯度压力从前馈层（parametric 知识的常被定位的位置）转移到注意力模块，从而提高推理时对上下文的依赖、削弱 parametric 知识的鲁棒性。这提示两种载体在功能上竞争同一角色；但就计算载体而言，两者的读取路径仍然不同，边界在载体层面依然清晰。另有一些综述将 parametric 与 contextual 并列为两种记忆并定义原子操作，其划界方式与本文一致。

## Latent 载体
### 定义来源与计算定位
Latent 载体指记忆以连续向量状态存在、按需参与计算的形态。它的定义来自 Transformer 架构的中间表示：隐状态、注意力的 K/V 投影、以及各种被训练出来的压缩向量。它骑在 parametric 与 token 之间——**表征是连续的（像 parametric），但存储是显式的、可定位可替换的（像 token）**。按本文的两轴判定：连续表征加显式读取。
### 状态存放
存放位置是模型激活管线内或紧邻其外的显式张量：KV cache 条目、软提示向量、记忆 token 的嵌入、递归状态（如状态空间模型的隐藏状态 h）。这些张量可以被序列化、复制、搬移、整体替换——这是它与 parametric（存储即权重、不可分离）的关键差别。但张量与生成它的模型架构绑定：一组 KV 条目只对产生它的那一组权重和位置编码有意义，换模型即失效。
### 读取机制
读取是**显式注入但跳过重新编码**。连续向量直接进入前向计算的激活流：KV 条目被拼接到注意力缓存中参与注意力计算；软提示向量作为前缀嵌入进入输入序列；记忆 token 的嵌入被前置于当前上下文。与 token 读取的区别在于省去了 tokenizer 与嵌入层的重新编码；与 parametric 读取的区别在于仍需要一次单独的注入操作（不是每次前向都自动携带）。这是 latent 读取代价结构的来源：比 token 便宜（不重编码），比 parametric 贵（需要注入机制与状态搬运）。
### 写入机制
写入是一次编码：用模型自身（或训练出的编码器/压缩器）把一段 token 序列映射为向量。代表性路径有三类：**复用**（把一次前向产生的 KV cache 存下来重载，如 Memorizing Transformers、LONGMEM）；**变换**（对 KV cache 做剪枝或压缩，如 SnapKV、H2O、PyramidKV）；**生成**（训练模块把上下文压缩成少量记忆向量，如 gist tokens、AutoCompressor、Titans）。近期的 MemGen 与 NextMem 进一步把 latent 记忆做成生成式的：一个触发器监测推理状态决定何时调用，一个编织器把当前状态合成为一串 latent token 注入推理流。写入代价介于 token（字符串追加）与 parametric（梯度更新）之间：需一次前向或一次训练好的压缩，但无需梯度。
### 可检视性
**部分可检视**。张量是显式存在的，可以看到数值、可以整体替换，但没有离散语义：单个维度不对应可读的内容，对向量做局部编辑的语义效果不可预测。这与 token（完全可检视）和 parametric（完全不可检视）都不同——latent 处在一个尴尬的中间：可搬运但不可读。
### 性质与代价
- **读写成本中等**：读便宜（免重编码），写中等（一次编码）。是三者中读写最均衡的形态。
- **信息密度高但有损**：一段 K 个 latent 向量可以代表远长于 K 的 token 序列，压缩比可观；代价是损失不可逆，无法从向量还原原文。
- **架构绑定**：latent 状态对产生它的权重与位置编码有依赖，跨模型迁移不存在直接机制。
- **可搬运不可审计**：可以序列化与替换（合规上有回滚的可能），但无法检查内容或做有语义的删除。
- **访问门槛**：所有 latent 技术都要求触及模型内部状态（`past_key_values`、`inputs_embeds` 等），托管 API 不暴露这些接口，因此 latent 记忆目前只在自托管权重上可行。
### 边界判定
什么算：任何以连续向量显式存储、读取时直接注入激活流的状态——KV cache、软提示、记忆 token 嵌入、递归状态、压缩向量。什么不算：经梯度进入权重并隐式读取的不是 latent（是 parametric）；以离散符号存储并经嵌入层读取的不是 latent（是 token）。介于其间的情况——KV cache 的 token 对应结构、RMT 的记忆 token、MLA 的压缩表示——正是下一节专门处理的对象。

## 三载体对照
| 维度 | Token | Parametric | Latent |
|---|---|---|---|
| 表征形式 | 离散符号 | 连续权重 | 连续向量 |
| 存放位置 | 模型外（外部存储） | 权重本身 | 显式张量（激活管线内或紧邻） |
| 读取路径 | 经 tokenizer/embedding 重新编码，拼入 prompt | 无单独读取，每次前向隐式全量读取 | 显式注入激活流，跳过重编码 |
| 写入路径 | 模型外的字符串操作 | 梯度更新（微调/LoRA/编辑） | 一次编码或压缩 |
| 可检视性 | 完全（可读可编辑） | 无（仅行为探针） | 部分（可搬运不可读） |
| 读取代价 | 高（重编码 + 注意力） | 零边际 | 低（免重编码） |
| 写入代价 | 低 | 高（且脆弱，存在干扰） | 中 |
| 作用范围 | 按请求组装 | 全局（所有调用） | 按请求或会话注入 |
| 模型绑定 | 无（模型无关） | 即模型本身 | 绑定架构与权重 |
| 容量约束 | 存储无界、读取受上下文窗口限制 | 参数量与干扰 | 压缩比（有损） |
| 合规可操作性 | 完全（可删除/审计/回滚） | 极弱 | 部分（可整体替换，不可定点删除） |

## KV Cache：latent 与 token 之间的边界案例
KV cache 是锐化 latent/token 边界的最佳案例，因为它在两条轴上都骑在中间。本节从计算结构出发逐项拆解，然后给出判定。
### 计算结构
自回归解码中，每个注意力层为每个已见 token 保存其隐藏状态的 key 与 value 投影；每生成一个 token，新 query 与缓存中全部 K/V 做注意力。每 token 的逻辑缓存大小为 2 × KV 头数 × 头维度 × 字节数；以 Qwen3-8B（36 层 GQA、8 个 KV 头、head_dim 128、bf16）为例，每 token 约 144 KiB，32K 上下文约 4.5 GiB，八个并发等长序列约 36 GiB——缓存可与参数量本身同量级，且随生成线性增长。KV cache 的设计动机是用记忆换计算：把 O(n²) 的重复投影变成一次计算加 O(n) 的重用。
### 为何骑在边界上
把 KV cache 放到本文的四维判定上，可以看到它同时在两侧都有强证据：
- **表征是连续的**：K/V 是实值向量，属于 parametric/latent 一侧的表征形式。
- **存储是显式的、可定位可替换的**：缓存是独立于权重的张量，可以序列化、重载、在多条请求间共享前缀——属于 latent/token 一侧的存储方式。持续缓存（persistent KV cache）研究正是利用这一点做跨请求重用。
- **来源是 token**：缓存由 token 经模型投影生成，token 是它的输入侧。
- **索引结构与 token 一一对应**：KV 条目与 token 位置保持逐元素对应，隐私研究正是利用这一点从缓存中逐 token 重建输入。这是纯 latent 向量（软提示、记忆 token）不具备的性质——后者没有 token 粒度的索引。
- **读取是连续注入**：缓存条目作为张量直接参与注意力计算，不经重新 token 化——latent 的读取路径。
### 判定
按本文的首要判据——**读取路径**——KV cache 应归入 latent 载体：它以连续张量显式存储、读取时直接注入激活流、跳过重新编码，满足 latent 的全部计算条件。已有综述也把 KV 复用/压缩/生成列为 latent 记忆的三个子类。
但它的 token 对应索引给了它一项纯 latent 向量不具备的能力：**可以在 token 粒度上编辑 latent 内容**。H2O 按"重击者"逐 token 驱逐，SnapKV 按头投票逐 token 保留，PyramidKV 分层分配 token 预算——这些方法操作的是连续向量，但决策粒度是 token。这是 latent 内容、token 索引的混合体，也是它成为最佳边界案例的原因：它同时展示了 latent 读取的经济性与 token 索引的可编辑性，两条性质在此交汇。
两个反向的参照物进一步锐化边界。**MLA（DeepSeek-V2 的多头潜注意力）**把 KV 压缩成更小的潜表示再存取，把缓存进一步推向纯 latent——索引与 token 的对应被压缩打破。**RMT（Recurrent Memory Transformer）**则做法相反：把记忆做成加在输入/输出序列上的特殊记忆 token——名义上是 token 位置，实际传递的是连续向量嵌入，跨段递归。RMT 是"latent 内容、token 位置"的另一个实例，与 KV cache 互为镜像。软提示同样如此：由梯度训练（parametric 式写入），作为连续向量前缀注入（latent 式读取），既非典型 parametric 亦非典型 token。
需要标注的**无共识点**：不同综述对 KV cache 的归属划法不一。有的将其纳入 latent 工作记忆；有的把模型内部的缓存管理整体划给"LLM memory"、排除在"agent memory"之外。本文按读取路径归入 latent，并把上述分歧如实记录——领域尚未收敛，本文不替读者收敛。
---
## 结语：载体作为第一分岔
三种载体由前向计算的结构唯一确定：离散符号经显式读取、连续权重经隐式读取、连续张量经显式注入。它们各自的读写代价、可检视性、作用范围与容量约束，全部从这四条维度推出，且互为镜像——token 写廉读昂，parametric 写昂读廉，latent 居中；token 完全可检视，parametric 完全不可检视，latent 可搬运不可读。不存在一种载体在所有维度上占优，因此任何"某载体是正确选择"的判断都是本文要避免的事后论证——本文后续章节的主研对象选在 token 级，是路线选择，不是优劣裁决。
载体之间会转化、会并存、会在边界案例上纠缠——KV cache、软提示、记忆 token 这些骑在边界上的对象本身就是证据。但作为分析框架的地基，本文坚持以读取路径为首要判据、以表征形式与存放位置为次要判据，把每一处边界的两侧证据都摆开。后续所有章节默认此处的判断成立；有争议处已如实标注，不替读者收敛。

## §0 方法论前言：第一性立场与边界声明
### 0.1 为什么从"冻结"出发——以及为什么这是有条件的
本分析的出发点是一个工程现状：主流 agent 部署中的基座模型在服务运行期间参数保持冻结。这是当前服务化 LLM 的默认形态，但**不是物理定律，甚至不是长期稳定的经济必然**。当前的反例至少有三类：端侧部署中的 on-device 个性化微调已产品化；test-time training（TTT）研究方向明确探索推理时的参数更新，并已扩展到 foundation models；推理时 LoRA 热切换与 adapter 路由在 serving 层已有实践。若这些路线规模化，本框架的地基条件随之松动。
因此本框架的正确认识论地位是：**条件框架**——在"基座冻结、计算=单次前向、载体以读取时刻生效位置为准"三重条件下成立的结构性推论。附录 A 逐一列出了每个强断言所依赖的定义选择。
### 0.2 记忆研究的三条前史——避免领域诞生神话
agent memory 并非在冻结之后凭空诞生。它至少继承了三条成熟研究传统，这些传统的存在直接约束本框架的历史叙事：
**外部记忆带的传统**（2014–）：Neural Turing Machines、Memory Networks、Differentiable Neural Computer 等工作明确将外部可寻址存储作为独立于主网络的组件训练。这是 agent memory 最直接的技术先驱。
**认知架构的传统**（1970s–）：ACT-R 的 declarative memory（chunk + 激活扩散）与 procedural memory（production rule）的区分，Soar 的工作记忆与长时记忆分层，是 agent memory 概念词汇的直接来源。Shunyu Liu 等 2025 年 12 月的综述《Memory in the Age of AI Agents》明确承认这种继承。
**对话系统的传统**（1990s–）：对话状态追踪、belief state tracking、user modeling 本质上是跨轮持久化的工作记忆研究。
本框架不宣称"agent memory 是全新领域"，而承认它是这三条传统在 LLM agent 语境下的汇流。
### 0.3 粒度声明与判据边界
本分析显式定义"计算"为**单次前向传播**。这一选择的后果必须正面承认：按此粒度，**会话内跨轮 KV 复用已满足记忆判据**（第一轮信息影响第二轮计算）。这与工程直觉中"会话内状态不是记忆"的直觉冲突。本框架的处理是承认这是判据的自然结论，而不是通过"会话豁免"补丁强行收回。跨请求复用的"记忆临界点"因此是一个**产品层裁量**而非本体层跃迁。
本分析同时承认：**载体轴的判别力是有边界的**。它回答"记忆如何生效"，不回答"什么算记忆、算谁的记忆、用于什么目的"。后两类问题需要其他维度（来源、功能、主体性），本框架刻意不做覆盖。

## §1 判据与算子分解
### 1.1 记忆判据及其超集问题
**定义（记忆判据）**。设信息 i 在时刻 t₁ 的计算 C₁ 中产生或出现。若存在机制，使 i（或其变换）在 t₂ > t₁ 的另一次计算 C₂ 中影响计算结果，则称该机制实现了对 i 的记忆。
按此功能性判据判出的集合是**缓存的严格超集**：任何持久化状态（硬盘文件、数据库、缓存）都满足。要收窄到有研究意义的"记忆"，需要**三个附加判据**，本版显式声明（原稿将其隐含于判例中）：
1. **载体判据**：信息必须以某种形态进入前向计算（排除仅用于匹配的向量索引，见 §6.2）；
2. **作用判据**：影响的必须是模型的计算结果而非系统行为（排除路由层的外部决策）；
3. **来源判据**（本框架选择不施加）：信息是否必须来自 agent 自身经验，是一个独立维度，本框架不在载体轴上处理。
### 1.2 算子分解及其边界
一个完整的记忆系统可分解为五种算子：**写入 W**（经验→存储项）、**存储 S**（维护记忆的物理存在）、**读取 R**（推理时选择并注入）、**更新 U**（修改或合并）、**遗忘 F**（淘汰）。
必须立即防御的两点：
- **五算子非必然分解**。遗忘 F 可视为更新 U 的特例（U∅ 形式），"存储 S"更接近介质属性而非操作。本框架保留五算子是因为它在数据库与认知架构传统中已被广泛使用，但它**不是第一性推论**，而是分析工具——本章不使用它做任何分类承诺。
- **算子本身可跨载体借用**。写入技术可以在任何载体间迁移（判例表中 MemGen 写入用 parametric 技术但读取在 latent），这正是 §2.3 归类判据必要性的来源。
### 1.3 主体性维度：本框架刻意缺席的一根轴
同一套机制，可以是"用户记忆"（关于用户的事实）、"agent 自我记忆"（关于 agent 自身行为的记录）或"共享记忆"（多 agent 共同维护的状态）。多智能体系统中的 governed shared memory 是一个独立且活跃的研究方向，涉及作用域隔离、时间正确性、溯源追踪等分布式系统议题。
本框架在载体轴上**不区分**主体性，因为主体性不影响信息进入前向计算的位置。但这是一个刻意且需要声明的缺席——载体轴能回答"记忆如何生效"，不能回答"这是谁的记忆、为谁服务"。

## §2 三类载体的结构性论证
### 2.1 前向计算的信息解剖
设冻结模型 M(θ)，输入序列 x = (x₁, …, xₙ)。单次前向中与信息相关的物理存在只有三处：
1. **输入序列 x**——信息进入计算之前；
2. **模型权重 θ**——计算赖以进行的通道，冻结条件下为常量；
3. **中间激活**（K/V 张量、hidden states）——信息在计算中流动的瞬时状态。
需排除两个候选位置。**输出**位于计算出口，要再次影响计算必须作为后续输入进入（这落入 token 载体的写入来源）或被外部系统记录（同样落入 token）。**梯度通道**在冻结条件下关闭——parametric memory 的本质是有代价地重开它（§4.3）。
### 2.2 穷尽性的认识论地位
> **命题（载体穷尽性）**。在基座冻结、计算=单次前向、载体以读取时刻生效位置为准的三重条件下，任何使信息跨计算存活的机制，其记忆载体必居三者之一：**token**（使输入持久）、**parametric**（使通道持久）、**latent**（使中间态持久）。
**认识论修正**：这不是"事实推论"，而是**框架内定理**——其有效性由三重定义选择的强度决定。本框架承认以下两个偏差必须正视：
**路由/编排层的归并**。决定调用哪个模型、哪个 LoRA、哪个工具的信息（路由器权重、路由规则）不进入任何单次前向，但显著影响最终结果。本框架将其强行归并进 token（因为路由规则以文本/代码形态存储），但这暴露了**分类粒度选择对结果的塑造作用**——一个更细的分类可能将"路由/编排"列为第四种载体。本框架选择不这样做，理由是它影响的是系统行为而非单次计算，但这必须声明为**定义选择而非物理必然**。
**token 作为杂物间的风险**。工具、技能库、可执行程序（Voyager 式技能库）、环境状态、sandbox 代码——这些都被归入 token 类，因为它们以文本形态被"读取"。这造成 token 内部的**分化显著性高于其他载体**，部分原因是**分类粒度选择使然**，而非 token 天然拥有更大的设计空间（详见 §3.2 的诚实处理）。
### 2.3 归类判据：以读取时刻为准
> **判据**。混合系统的归类，以**读取时刻**信息所处的载体为准，而非写入时使用的技术。
这一判据的理由是**归类纪律**（防止同一系统按写入技术被重复计数），而非存在性声明。载体分类的对象是"记忆如何生效"，写入技术可以在任何载体间借用。本判据的判例效果见 §6.2。
### 2.4 完整性与混合的张力
三载体框架在文献中已被广泛采用（Shichun Liu 等综述、TeleAI-UAGI 综述、yyyujintang 综述均按 Form 分为 token-level / parametric / latent），说明该分类在当前社区中具有**描述性有效性**。但需注意：文献中同样大量存在**混合系统**（RAG+微调、KV 预填充+parametric 更新、LoRA 银行+token 路由），说明三类在工程上可组合。穷尽性不排斥混合，但**穷尽性不是互斥性的证明**——同一条信息可以同时在 token 与 latent 中有副本（上下文及其 KV），也可以同时进入 parametric（被微调吸收）与 token（被记录为文本）。本框架的归类判据（读取时刻）处理了这一多重性，但其代价是承认：**同一信息可以在不同时刻以不同载体生效**。

## §3 token 载体
### 3.1 定义与机制
> **定义（token 记忆）**。模型 M(θ) 冻结；维护外部记忆库 D（符号集合）；每次推理执行检索 r(q, D) → S ⊆ D，将 S 序列化后与查询拼接，模型计算 M(θ; q, S)。信息影响计算的唯一通道是输入 token 序列。
五算子的实例化：写入是文本生成（无梯度）；存储是任意外部介质；读取是"检索 + 拼接"的显式动作；更新与遗忘是文本级操作。全部算子均以 API 调用完成，不触碰模型内部。
### 3.2 token 内部分化：载体属性 vs 分类粒度
**原稿宣称**："token 的设计自由度最大，因此其内部必然产生分化。"
**本版修正**：该断言有**两个来源**，必须拆开：
1. **物理来源**（真实存在）：token 的写入形状由设计者决定，parametric 的写入形状由优化动力学决定，latent 的写入形状由张量几何决定。这一不对称是真实的。
2. **分类来源**（需诚实承认）：本框架将工具、技能、程序、环境状态、路由规则等全部归入 token，**人为扩大了 token 内部的异质性**。若 parametric 类同样细分为"预训练知识 / 微调增量 / adapter / LoRA / 编辑"等子轴，其分化程度未必更小。
**诚实表述**：token 的设计自由度**相对于当前工程实践最显著**，部分原因是其无物理写入门槛，部分原因是分类粒度选择使其成为杂物间。**两种来源的相对贡献无法分离**，本框架对此不做定量判断。
token 内部**至少**存在以下分化维度，且彼此不正交（原稿宣称正交性是理想化）：
| 维度 | 取值谱系 | 与其他维度的耦合 |
|---|---|---|
| 存储引擎 | 向量库、图数据库、关系库 | 与拓扑在工程上强耦合 |
| 信息压缩度 | 原文、原子事实、摘要 | 独立 |
| 组织拓扑 | 平坦、树、图 | 引擎耦合 |
| **陈述性 vs 程序性** | 事实描述 / 可执行代码、技能 | **本维度跨拓扑存在，且读取形态有质差** |
**程序性记忆是本版新增的关键分化维度**，原稿完全遗漏。Voyager 的技能库、AutoManual、AWM 等工作已将其发展为一个完整子方向。其与陈述性内容的差异不在存储形态（都是文本），而在**读取后的处理方式**：陈述性内容被"理解"，程序性内容被"执行"。这暴露了原稿 §7.1 表中"token 读取后仍需理解"这一行对程序性内容不成立——程序性 token 读取后可能触发工具调用而非语义理解。
### 3.3 成本结构与性质
**成本结构：写便宜，读贵，且反复付费。** token 是**订阅制**的记忆，每次生效都占据上下文窗口、付出推理成本。
**对称性修正**：原稿将"订阅制"绝对化。实际上 prefix caching、跨请求 KV 复用、摘要缓存等机制**已在工程上摊薄 token 的读成本**——特别是当注入内容是重复出现的前缀时。本框架在 §6.1 中自己承认了这一点，与 §3.3 的绝对化表述构成轻微不一致，本版统一为：**token 的读成本是逐次付费的，但其边际成本可通过缓存机制部分摊薄**。
性质由"载体是通用文本"派生：
- **模型解耦**：记忆库与模型可独立更换；
- **可回读**：人类可直接阅读，是可审计、可版本管理的基础；
- **可迁移**：换基座模型后记忆保留。
**"唯一可运营"的修正**：原稿称 token 是三类中"唯一可运营的"。**本版降格为**"当前运营生态最成熟"。反例：跨请求 KV 预填充复用（§6.2 判定为 latent 最纯粹的产品化形态）已是生产部署的现实形态；on-device 个性化 parametric 更新已产品化。"唯一"过强。
### 3.4 失败的可见性
token 的失败集中而可见：读取端召回失败、注入噪声、新旧冲突未消解、写入端信息丢失。可见性本身是资产——错误可定位到具体条目与具体检索决策。
**补充失败模式**（原稿遗漏）：**注入攻击面**。token 记忆是外部可控文本进入前向的直接通道，记忆投毒、prompt injection 通过记忆注入是 token 载体特有的安全攻击面。其他载体无此暴露面。

## §4 parametric 载体
### 4.1 定义与机制
> **定义（parametric 记忆）**。通过梯度更新 θ → θ′ 将信息写入权重；读取无显式操作，查询 q 直接进入 M(θ′)，信息以模型行为的方式涌现。
parametric 与 token 最深刻的差异在**读取端**：token 有一个显式的、可观测的读取动作，parametric 没有——事实弥散于数百万权重的调制中，由整个网络的协作计算重构。
### 4.2 与预训练的关系，及定位发现的争议状态
**层级关系**：预训练知识本身就是 parametric 记忆——冻结基座即是巨型参数记忆库。Agent 语境下的 parametric memory 特指预训练之上的**增量写入**。
**定位发现的机制基础与争议**：Geva et al. 2021 提出 Transformer FFN 层在功能上近似 key-value memory，中间神经元匹配输入模式，输出向量近似指向词汇语义分布。**这一发现是知识编辑方向的支点**。但必须诚实承认其争议状态：Hase et al. 2023 的实验表明，**因果追踪所得的定位结论与编辑有效性之间缺乏稳定对应**——定位结果不能预测哪个 MLP 层是最佳编辑位置。
**本版关键修正：与"无地址性"的内部矛盾的解决**。原稿 §4.4 声称"无地址性→不可定向删除"，而 §4.2 又引用定位发现作为定向编辑的支点——两者不能同时以最强形式成立。**本版的统一表述**：parametric 记忆的地址性是一个**程度谱**，而非二元属性：
- **因果定位的相对性**：causal tracing 等方法可在统计意义上定位事实的关键神经元，但定位的因果性是**相对于干预方式的**（denoising ≠ counterfactual editing）；
- **编辑定向的可能性**：ROME、MEMIT 等方法已实现单事实定向编辑，其有效性在 CounterFact 等基准上可测，但**定向是近似的、有牵连效应的、随编辑次数退化的**；
- **删除的不可定向性**：与编辑不同，**删除**（将事实从权重中抹除而不影响其他）的定向性显著弱于编辑——不存在"删掉这条事实"的操作，只有覆盖或重训。
**修正后的准确表述**：parametric 载体在**写入方向**具有近似可定位性（支撑知识编辑），在**删除方向**接近不可定向（删除远难于编辑）。
### 4.3 写入通道：重开被冻结关闭的梯度
冻结关闭梯度通道；parametric memory 的写入是有代价地重开它。按写入的空间范围与精度，存在从粗到细的连续谱：全参数更新（写入整个通道，代价是与存量全面干扰）；低秩增量（ΔW = BA，写入便宜、可插拔）；定向编辑（借定位结果对特定投影做手术式修改——精度最高，但牵连效应与顺序编辑叠加退化是新引入的问题）。
持续学习与灾难性遗忘是一个**完整的母学科**，有数十年的研究积淀与 2024-2025 年的活跃文献。本框架将其作为 parametric 内部的工程问题悬置。
### 4.4 成本结构与"买断制"的适用域
**成本结构与 token 对称反转：写贵，读免费。** parametric 是**买断制**的记忆。
**适用域修正**：原稿的"买断制"暗示一次性支付后永久免费。**本版指出其适用域**：该表述仅对**静态知识、低频变化、高频读取**的场景成立。agent memory 的核心场景恰恰是**持续经验积累**——此时顺序编辑的叠加退化（§4.6）使得成本并非一次性，而是**随编辑次数超线性增长**。"买断制"的绝对化程度需降为"对静态知识适用、对持续增量场景受限"。
### 4.5 记忆与能力的不可分离性——及其对预训练知识地位的张力
parametric 记忆没有可辨识的使用时刻，其贡献无法与模型固有能力分离——**答对时无法区分"因为它记得"与"因为它会推理"**。
**必须正面处理的张力**：原稿 §4.2 声称"预训练知识本身就是 parametric 记忆"，而 §4.5 声称"记忆与能力不可分瓦解 parametric 记忆的独立地位"。若不可分离性成立，它**同样瓦解预训练知识作为'记忆'的地位**——因为预训练知识与能力同样不可分离。
**本版的解决方案**：承认两者均部分成立。parametric 记忆的"记忆"地位是一个**程度问题而非本体问题**：行为上可辨识的记忆效应（某事实被写入后行为改变）是可测的；但记忆与推理的**概念边界**在权重层面不存在。这一张力不是缺陷，而是 parametric 载体的本质特征——它同时解释了为何 parametric memory 在概念上有尴尬地位（何为记忆、何为能力），以及在工程上为何有真实效果（编辑改变行为可测）。
### 4.6 失败模式
灾难性遗忘（写入损伤存量）、编辑牵连效应（改了事实但关联推理不跟随）、顺序编辑叠加退化（每次编辑污染上次编辑）。**所有失败均不可见**——湮没于权重深处，无法归因。

## §5 latent 载体
### 5.1 KV cache 的机制回顾
自回归生成中，第 t 个 token 依赖全部前文；KV cache 的工程解法是每层 K/V 只算一次、存下复用。**本职是计算优化，算完即弃**。
latent memory 的核心洞察是换视角：**KV cache 里存的是模型对前文的处理结果**——每一层的 K/V 编码了前文 token 在该层注意力下的角色。保留它们，就是保留"理解"本身。
### 5.2 定义与注入点
> **定义（latent 记忆）**。将前向计算的中间产物以张量形式持久化，并在后续前向计算中直接注入复用，跳过"从 token 重新计算"的环节。
注入点覆盖前向计算的三个阶段：KV 张量拼接（attention 层入口）、hidden states 拼接（层间）、连续向量作为前缀嵌入（embedding 层，即 soft tokens / continuous prefix）。这与 token 的根本区别是：**token 让模型重新理解一遍文字；latent 直接保存并复用模型上次理解的结果**。
### 5.3 记忆临界点：工程裁量而非本体跃迁
**原稿叙事**：会话内 KV 是"计算状态"，跨请求持久化并复用时"升格为记忆"。
**本版修正**：按 §0.3 粒度声明（计算=单次前向），**会话内跨轮 KV 复用已满足记忆判据**。会话边界是产品层裁量，不是本体层跃迁。工程形态上，推理引擎的跨请求 KV 复用、前缀缓存已被广泛部署。本框架承认这一点，而不是通过"会话豁免"收回判据的自然结论。生产部署中的挑战是系统层的：FlashAttention 不写 attention scores 导致部分压缩方法难以工程化。
### 5.4 存储成本：算例的形态对称性
fp16 下每 token 的 KV 体积为 2 × n_layers × n_kv_heads × d_head × 2 字节：
| 模型 | 配置 | 体积/token | 100K token 总量 |
|---|---|---|---|
| Llama-2-7B | MHA，32 层，hidden 4096 | ≈ 512 KB | ≈ 51 GB |
| Llama-3-8B | GQA，8 个 KV 头 | ≈ 128 KB | ≈ 12.8 GB |
| Llama-3-8B + 8×压缩 | 量化+低秩 | ≈ 16 KB | ≈ 1.6 GB |
同一 100K token 的文本本体约 0.4 MB——**未压缩形态相差约 4.5 个数量级，8× 压缩后缩至约 3.6 个数量级**。
**本版关键修正：形态选取的对称性**。原稿在存储成本侧使用最不利形态（未压缩 fp16），在读取成本侧使用最有利形态（"近零"）。**本版对称化**：
- **存储侧的诚实性**：PyramidKV、PyramidInfer 等方法可将 KV cache 压缩至 12% 甚至 0.7% 而维持相当性能；KIVI 等量化方法可将存储降 8× 以上。**"存极重"仅在未压缩形态下绝对成立**。
- **读取侧的诚实性**："读近零"精确说是"免重新理解"，但**注意力交互本身有计算成本**，与 token 注入同级——§6.1 自己承认了这一点。latent 的真实读取优势不是"近零"而是"免 prefill"，对长上下文场景优势显著，对短上下文不显著。
### 5.5 性质：时间维度的对称宽容
**不可回读**：张量对人不可读，从 KV 解码文本属于重新生成而非保真回读。**版本绑定**：绑定特定权重与推理配置（量化方案、位置编码实现、模型版本任一改变即作废）。**坐标可寻址**：KV 按（层，头，位置）组织，可做定点操作——这在 token 与 parametric 处无对应物。
**时间表示的双重标准修正**：原稿对 token 获得系统层宽容（"时间戳是设计选择，可由系统写入文本"），对 latent 只检视张量内在属性（"仅序列位置，无事件时间"）。**本版对称化**：latent 存储同样可以由系统层附带时间元数据并按序拼接——如果对 token 宽容，对 latent 也应宽容。修正后的表述：**三类载体在时间表示上均无内在通道，均需系统层设计**。parametric 在顺序效应湮灭上确有特殊性（梯度更新收敛后顺序不可读），但这是程度差异而非有无差异。
**补充失败模式**（原稿遗漏）：**分布偏移**——跨会话 KV 拼接引入位置编码错位、注意力分布失配，是 latent 最现实的失败模式之一。

## §6 边界与判例
### 6.1 裸上下文窗口：token 内容跑在 latent 载体上
**裸上下文窗口本身，就是 token 形态的内容跑在 latent 载体上的实现**。每轮输入的 token 序列，进入模型后立即被转写为 KV cache（latent 形态）参与计算。token 记忆与 latent 记忆是**同一物理对象的两个侧面**：前者问"往窗口里注入什么内容"（内容侧），后者问"如何持久化、压缩、复用窗口的计算态"（载体侧）。
这一观察削弱了 §7.2 "三种经济学"的正交对立：**token 的读成本隐含 latent 载体的 prefill 计算成本**，两类载体在成本上共享一个交汇点。成本并非三分。
### 6.2 判例表
按 §2.3 判据（读取时刻为准）：
| 系统 | 写入技术 | 读取时刻载体 | 归类 | 判例意义 |
|---|---|---|---|---|
| Mem0、Letta（MemGPT）、Zep | LLM 抽取 | token 注入 | **token** | 标准形态 |
| 系统内嵌的向量索引 | embedding 化 | **从不进入前向计算** | **不是 latent** | latent 要求"以激活形态进入计算"；仅用于检索匹配的向量不满足——此为显式化补丁 §1.1 |
| WISE 类（LoRA 银行 + 路由） | LoRA 追加 + router | 进入某个参数化实例生效 | **parametric** | 写入模仿外部存储，生效位置在权重 |
| MemGen 类 | RL + LoRA | 以 latent token 的 KV 形态进入计算 | **latent** | 写入动用 parametric 技术、读取在激活空间 |
| 为用户语料预填充后跨会话复用的 KV | 一次预填充 | 张量拼接 | **latent** | latent 最纯粹的产品化形态 |
| RAG（外部静态语料） | 无写入 | token 注入 | **token 载体形态** | **载体轴无法区分它与 token 记忆**——区分落在"来源是否为 agent 经验"上，属其他轴；此判例标定本轴判别力边界 |
| Voyager 技能库 | 代码生成 | token 注入后**触发工具执行** | **token（程序性）** | 引入程序性子轴：读取后不是被理解而是被执行 |
最后一行揭示原稿遗漏的关键分化维度（§3.2）。

## §7 载体的对比
### 7.1 总表（经二次审计）
| 维度 | token | parametric | latent |
|---|---|---|---|
| 物理位置 | 输入序列（离散符号） | 模型权重 | 激活空间（连续张量） |
| 写入通道 | 文本操作（无梯度） | 重开梯度通道 | 前向计算的副产品 |
| 读取 | 显式：检索 + 拼接 | 隐式：与推理无边界 | 张量拼接（免 prefill） |
| 记忆与计算的关系 | 外置：读取后仍需理解（陈述性）/ 执行（程序性） | 无界：使用时刻不可辨识 | 内置：读取即计算态 |
| 成本位置 | 读端（可部分摊薄） | 写端（持续写入时超线性） | 存端（压缩后缩小但仍重） |
| 信息形态 | 离散、可回读 | 弥散、**近似可定位** | 连续、坐标可寻址 |
| 地址性 | 天然可寻址 | **写入方向近似可定位；删除方向近不可定向** | 坐标可寻址 |
| 回读与可审计 | 可回读、人可读 | 不可回读 | 不可回读 |
| 时间的可表示性 | **无内在通道，系统层设计** | 顺序效应湮灭（程度特殊） | **无内在通道，系统层设计** |
| 与模型的解耦度 | 解耦：记忆宿主在外部 | 同一：记忆即模型本体 | 版本绑定：有效性系于特定权重 |
| 编辑的物理形态 | 文本操作 | 需动权重（牵连） | 张量定点操作 |
| 遗忘的物理形态 | 介质销毁（可定向） | 不可定向，只能被覆盖 | 预算淘汰 |
| 失败可见性 | 可归因到条目 | 湮没于权重 | 湮没于张量 |
| **攻击面** | **注入攻击面（外部可控文本直接进入）** | 无此暴露面 | 无此暴露面 |
| **主体性** | **可承载单用户/单 agent/共享记忆** | 绑定单一模型实例 | 可承载共享记忆（工程实践） |
| **设计自由度** | **相对于当前工程实践最显著**（部分源于分类粒度） | 受优化动力学约束 | 受张量几何约束 |
### 7.2 三种经济学（修正版）
**每一个记忆设计决策，本质都是在选择把成本放在哪里**：token 放读端（内部设计在与"逐次付费"搏斗，但 prefix cache 可部分摊薄）；parametric 放写端（静态知识买断制、持续增量场景成本超线性）；latent 放存端（压缩后仍重，但免 prefill 的读取优势显著）。
**修正**：三种经济学**并非严格正交**（§6.1 揭示 token 与 latent 在成本上交汇）。但作为透镜仍有价值：token 内部的分化，骨子里仍是读写成本的再分配。
### 7.3 可通约性：从绝对到相对
**原稿断言**："三类载体不是同一问题的三种解法，而是三个问题恰好共用了'记忆'这个名字"，并以"数据库索引、训练方法、虚拟内存不该同框"作类比。
**本版修正**：绝对化的不可通约不成立，且有明显的反证：
- **混合系统常态存在**（RAG+微调、KV 复用+parametric 更新、LoRA 银行+token 路由），说明三类在工程上**可组合**——不可通约至多成立于评测协议层，不成立于问题本体层；
- **端到端度量可能**：任务性能、总拥有成本、每比特有效记忆的延迟、记忆投毒鲁棒性，都是载体无关的共同度量衡。"不存在可通约性"应降格为"**当前缺乏通用协议**"；
- **修辞类比的反噬**：learned index 与 KV cache 管理恰恰在系统社区被统一研究，说明跨学科融合在发生。
**修正后表述**：三类载体在**当前评测协议与工程栈上高度分离**，形成三个不同的母学科传统（信息检索 / 持续学习 / 推理系统），但**在问题本体上有部分共同度量衡**，且混合是常态。原稿的绝对化版本承担了为"§8.3 此后不再展开 parametric 与 latent"提供豁免的功能——本版将聚焦理由改为诚实的实用主义（生态、占比、作者选择），删除护城河功能。

## §8 范围与取材
### 8.1 分类实在性的证据与选择偏倚
**主证据：学科结构**。三载体各自继承完整母学科——token 背后是信息检索与数据库传统；parametric 背后是持续学习与知识编辑传统（灾难性遗忘自联结主义时期起即是核心议题，知识编辑发展出 zsRE、CounterFact、KnowEdit、Lifelong-M 一脉）；latent 背后是推理系统社区。**三个文献宇宙各有自己的会议、基准与综述谱系，彼此引用稀薄**。
**循环风险声明**：学科边界作为本体论证据存在循环——**先按载体分学科，再用学科分离证明载体是根本轴**。且收录本身有选择偏倚：持续学习与知识编辑社区未必自我认同为"agent memory"，parametric 占比可能被系统性低估。
**辅证据：数量分布**。一份收录 199 篇 agent memory 论文的分类仓库（截至 2026 年 8 月）给出：token 约 72%，latent 约 16%，parametric 约 12%。单一来源、社区维护，应作方向性参考。**Shichun Liu 等的 Agent-Memory-Paper-List 综述采用同样的三形态分类**，说明该分类在当前社区具有描述性有效性。工程侧信号同向：可直接部署的记忆产品几乎清一色为 token 方案。
### 8.2 门槛与最优的诚实区分
token 的多数地位有相当部分源于门槛（复用成熟检索栈、可回读、易调试）。**多数不等于最优**——parametric 的"读免费"与 latent 的"免 prefill"在各自适用场景中是 token 无法企及的结构优势。本框架对 token 的选择是**可通约性与工程现实性的选择，不是性能优越性的判断**。
### 8.3 聚焦声明的诚实化
本研究的对比分析聚焦 **token 载体**。parametric 与 latent 在本章作为分类学对照出现，此后不再展开。
**聚焦理由（本版修正）**：原稿以"不可通约性"为聚焦提供方法论护城河。本版删除该功能，改为**诚实的实用主义**：(a) 当前 token 占研究能量与工程落地的绝对多数（§8.1）；(b) token 内部的分化维度最多且最需要专门分析框架；(c) 作者的选择与本书篇幅约束。三者中无一是结构必然性。
本章为后续章节留下接口：token 内部的分化至少包含存储引擎、信息压缩度、组织拓扑、**陈述性 vs 程序性**等子轴；parametric 内部的写入精度谱与 latent 内部的持久化路线，同为各自载体的内部分化问题。

## §0 方法论前言：立场与边界
### 0.1 冻结作为条件前提
本分析的出发点是一个工程现状：主流 agent 部署中的基座模型在服务运行期间参数保持冻结。这是当前服务化 LLM 的默认形态，但**不是物理定律，甚至不是长期稳定的经济必然**。当前至少存在三类松动迹象：端侧部署中的 on-device 个性化微调已产品化；test-time training 研究方向明确探索推理时参数更新，并已扩展至线性层以外（Sun et al., 2024）；推理时 LoRA 热切换与 adapter 路由在 serving 层已有工程实践。
因此本框架的认识论地位是**条件框架**：在“基座冻结、计算 = 单次前向、载体以读取时刻生效位置为准”三重条件下成立的结构性推论。三重条件中任何一条的松动都对应框架的明确修正方向（附录 A 逐条列出）。同时须澄清一个常被夸大的成本论证：同一 batch 上前向 + 反向 + 优化器更新的开销约为前向 FLOPs 的三倍量级，“单次更新比单次前向贵数个数量级”在算子层面不成立——真正阻止部署期更新的是系统层成本（评测、灰度、回滚、多租户一致性），而非单步计算。
### 0.2 三条前史
agent memory 并非在冻结之后凭空诞生，至少继承三条成熟传统。**外部记忆带传统**（Graves et al., 2014, NTM；Weston et al., 2015, Memory Networks；Graves et al., 2016, DNC）：外部可寻址存储作为独立于主网络的组件被训练，是本领域最直接的技术先驱。**认知架构传统**（ACT-R 的 declarative/procedural memory 区分，Soar 的工作记忆与长时记忆分层）：agent memory 的概念词汇直接来源于此，近期的领域综述亦明确承认这一继承（Liu et al., 2025）。**对话系统传统**（对话状态追踪、belief state tracking、user modeling）：本质上是跨轮持久化工作记忆的先行研究。本框架将 agent memory 定位为三条传统在 LLM agent 语境下的汇流，而非新领域的诞生时刻。
### 0.3 粒度声明
本分析显式定义“计算”为**单次前向传播**。该选择的直接后果是：**会话内跨轮 KV 复用已满足 §1.1 的记忆判据**（第一轮信息影响第二轮计算）。“会话内状态不是记忆”的工程直觉，在此粒度下不成立。本框架接受这一结论而非引入会话豁免条款；跨请求复用与请求内复用的差异因此是**产品层裁量**（存储预算与复用半径的经营决策），不是本体层跃迁。
本分析同时承认**载体轴判别力的边界**：它回答“记忆如何生效”，不回答“什么算记忆、算谁的记忆、用于什么目的”。后三类问题属其他维度（来源、功能、主体性），本框架不在载体轴上处理，其接口见附录 B。

## §1 记忆判据与本章边界
### 1.1 记忆判据及其附加条件
> **定义（记忆判据）**。设信息 i 在时刻 t₁ 的计算 C₁ 中产生或出现。若存在机制，使 i（或其变换）在 t₂ > t₁ 的另一次计算 C₂ 中影响计算结果，则称该机制实现了对 i 的记忆。
该功能性判据判出的集合是**缓存的严格超集**：任何持久化状态（文件、数据库、缓存）都满足。要收窄到有研究意义的“记忆”，需追加两个附加判据：
1. **载体判据**：信息必须以某种形态进入前向计算（仅用于检索匹配、从不进入前向的向量索引不满足，见 §6.2 判例）；
2. **作用判据**：影响的必须是模型的计算结果而非系统行为（路由层的外部决策不算——这一归并是本框架的定义选择，见 §2.2）。
第三个候选判据——**来源判据**（信息是否来自 agent 自身经验）——本框架选择不施加：来源是独立维度，与载体轴正交，其处理见附录 B。
由此，任何记忆系统天然包含两个功能组件：**持久化介质**（信息在两次计算之间的存身之处）与**重注入机制**（信息重新进入后续计算的通道）。
### 1.2 载体轴与操作轴的解耦
记忆现象可分解为两组正交问题。**载体轴**：信息在哪里、以什么物理形态生效——其取值由计算结构决定（§2）。**操作轴**：信息的生命周期如何被管理——写入、维护、调用、更新、淘汰——其取值由设计选择决定。
两轴的正交性论证：任一载体上原则上可实现任一操作组合。但操作的**物理可行性**受载体约束——如 parametric 载体上“定向删除”近不可实现（§4.2），token 载体上一切操作退化为文本操作（§3.1）——这说明操作可行性是载体的结构属性，而操作设计是独立的研究问题。二者的区分是本章反复使用的分析杠杆。
本章纪律：**只立载体轴**。操作轴的分析框架（生命周期算子的分解、各载体上操作谱系的展开）属后续章节。两轴的可分离性同时是 §7.4 混合系统在概念上合法的原因：写入技术跨载体借用，正是操作在载体间迁移的表现，而归类不受其影响（§2.3）。

## §2 三类载体的结构性论证
### 2.1 前向计算的信息解剖
设冻结模型 M(θ)，输入序列 x = (x₁, …, xₙ)。单次前向中与信息相关的物理存在只有三处：
1. **输入序列 x**——信息进入计算之前；
2. **模型权重 θ**——计算赖以进行的通道，冻结条件下为常量；
3. **中间激活**（各层 K/V 张量、hidden states）——信息在计算中流动的瞬时状态。
两个看似候选的位置须排除。**输出**位于计算出口，要再次影响计算必须作为后续输入进入序列（自回归的当下延续），或被写成文本保存（后者已落入 token 载体的写入来源）。**梯度通道**是信息写入权重的原生通道，冻结意味着该通道被关闭——parametric 载体的全部写入，本质是有代价地重开它（§4.3）。
### 2.2 穷尽性命题及其前提
> **命题（载体穷尽性）**。在基座冻结、计算 = 单次前向、载体以读取时刻生效位置为准的三重条件下，任何使信息跨计算存活的机制，其记忆载体必居三者之一：**token**（使输入持久）、**parametric**（使通道持久）、**latent**（使中间态持久）。
这不是经验发现，而是**框架内定理**——其有效性由三重定义选择的强度决定，且有两个已知代价须正面陈述：
**路由/编排层的归并**。决定调用哪个模型、哪个 adapter、哪个工具的信息（路由器、编排规则）不进入任何单次前向，但显著影响最终结果。本框架按作用判据将其归并为系统行为而非记忆，并因路由规则多以文本/代码形态存储而在技术形态上将其划入 token——这暴露了**分类粒度选择对结果的塑造**：一个更细的分类可将“编排层”列为第四种载体。本框架不这样做，理由是它影响系统行为而非单次计算，但该理由是定义选择而非物理必然。
**token 类的异质性负担**。工具、技能库、可执行程序、环境状态、编排规则均以文本形态被“读取”而归入 token 类。这使 token 内部的分化显著性高于另外两类——其中部分是物理属性（无写入门槛），部分是分类粒度的产物，两者贡献无法在当前证据下分离（§3.2）。
### 2.3 归类判据：以读取时刻为准
> **判据**。混合系统的归类，以**读取时刻**信息所处的载体为准，而非写入时使用的技术。
理由是归类纪律而非存在性声明：载体分类的对象是“记忆如何生效”；写入技术可在载体间借用（操作轴迁移），但生效位置由计算结构唯一决定。判例效果见 §6.2。
### 2.4 穷尽性不蕴含互斥性
三载体框架在近期领域综述中被广泛采用（Liu et al., 2025 等），具有当前社区内的描述性有效性。同时，同一条信息可以多载体并存：上下文 token 与其 KV cache 是自动的双重存在（§6.1），经验既可被记录为文本又可被微调吸收（§7.4）。读取时刻判据处理这一多重性的代价是承认：**同一信息可以在不同时刻以不同载体生效**。载体轴回答“每次生效时信息在哪里”，不承诺信息的唯一性。

## §3 token 载体
### 3.1 定义与机制
> **定义（token 记忆）**。模型 M(θ) 冻结；维护外部记忆库 D（符号集合）；每次推理执行检索 r(q, D) → S ⊆ D，将 S 序列化后与查询拼接，模型计算 M(θ; q, S)。信息影响计算的唯一通道是输入 token 序列。
结构上，token 记忆是一个**围绕冻结模型外围的信息检索与注入系统**——模型本身完全不知晓记忆的存在，记忆对模型而言只是上下文的一部分。全部生命周期操作以 API 调用完成，不触碰模型内部；这是三个载体中唯一与模型零耦合的形态。
### 3.2 内部分化：自由度的两个来源
token 的写入在物理上只有一条约束：**可序列化为文本**。文本操作没有形态限制——原文、摘要、原子事实、结构化记录、可执行代码、图与树的序列化，皆可。对照之下，parametric 的写入形状由优化动力学决定，latent 的写入形状由张量几何决定；token 的写入形状由设计者决定。
由此常被引出的断言“token 载体的设计自由度最大”，其成立依赖**两个可分离的来源**：
1. **物理来源**：无写入门槛、无形态限制，这是真实的载体属性；
2. **分类来源**：本框架将工具、技能、程序、环境状态、编排规则尽数归入 token，人为扩大了其内部异质性。
两者贡献无法分离，故正确表述是：**token 的设计自由度相对于当前工程实践最显著**。其内部至少存在以下分化维度，且彼此只是近似正交（图数据库的检索算法与图拓扑在工程上强耦合）：
| 维度 | 取值谱系 | 备注 |
|---|---|---|
| 存储引擎 | 向量库、图数据库、关系库 | 工程介质选择 |
| 信息压缩度 | 原文、原子事实、摘要 | 写入路径的有损变换档位 |
| 组织拓扑 | 平坦、树、图 | 条目间关联结构 |
| 内容功能 | 陈述性事实 / 程序性技能 | 读取后的处理方式有质差：被理解 vs 被执行 |
程序性内容（Voyager 技能库、Agent Workflow Memory、AutoManual 一脉）是常被遗漏的关键分化：同为文本，技能被读取后触发工具执行而非语义理解。**这些子轴的分别展开是后续章节的任务**；本章只确立载体级事实——token 的写入自由度最大意味着设计空间全开放，这既解释了 token 何以成为工程主流（无物理门槛），也解释了其内部分类必须推迟（过早分类会在混淆的轴上锁死框架）。
### 3.3 成本结构与性质
**成本结构：写便宜，读贵，逐次付费。** 写入是一次性 LLM 调用或零成本被动记录；每次生效占据上下文窗口、付出推理成本。token 是**订阅制**的记忆——且该订阅可被部分摊薄：注入内容为重复前缀时，跨请求 KV 复用与提示缓存（prompt caching，已为多家推理服务商产品化）可显著降低边际读成本。token 记忆的读成本结构因此精确表述为：**逐次计费，重复前缀可摊销**。
其余性质由“载体是通用文本”派生：**模型解耦**（记忆库与模型可独立更换，记忆资产独立于模型存续）；**可回读**（人类可直接阅读每一条记忆，是审计与版本管理的基础）；**可迁移**（换基座后记忆保留）。三者共同构成 token 当前运营生态最成熟的原因——同类比较中，跨请求 KV 预填充复用与 on-device 个性化微调均已产品化，故“唯一可运营”的表述过强；准确说法是**运营生态最成熟、运营门槛最低**。
### 3.4 失败的可见性与攻击面
token 的失败集中而可见：读取端召回失败、注入噪声挤占注意力、新旧记忆冲突未消解、写入端信息丢失。可见性本身是资产——错误可定位到具体条目与具体检索决策，可归因、可修复。
**token 特有的失败面：注入攻击**。token 记忆是外部可控文本进入前向的直接通道，记忆投毒与经记忆注入的 prompt injection 是该载体独有的攻击面【附录 B-6】。parametric 与 latent 不存在等价暴露（攻击面在训练与权重分发环节，不在推理注入环节）。该不对称在 §7.1 表中以独立行呈现。

## §4 parametric 载体（对照载体）
### 4.1 定义与机制
> **定义（parametric 记忆）**。通过梯度更新 θ → θ′ 将信息写入权重；读取无显式操作，查询 q 直接进入 M(θ′)，信息以模型行为的方式涌现。
parametric 与 token 最深刻的差异在**读取端**：token 有显式、可观测的读取动作；parametric 没有——一条事实被写入权重后，不存在任何操作叫“读取这条事实”，它弥散于数百万权重的调制之中，由整个网络协作重构出来。
### 4.2 与预训练的关系、地址性程度谱
**层级关系**：预训练知识本身就是 parametric 记忆——冻结基座即一个巨型参数记忆库。Agent 语境下的 parametric memory 特指预训练之上的**增量写入**。
**地址性是一个程度谱，且在写入与删除两个方向不对称**：
- **定位发现的证据与争议**。Geva et al.（2021）提出 Transformer FFN 层在功能上近似 key-value memory——中间神经元匹配输入模式，输出向量近似指向词汇语义分布；Dai et al.（2021）的知识神经元与 Meng et al.（2022, ROME）的因果追踪将这一方向推向事实级定位。但 Hase et al.（2023）的实验表明，**因果追踪的定位结论与编辑有效性之间缺乏稳定对应**——定位结果不能预测哪个 MLP 层是最佳编辑位置，且 denoising 干预与 counterfactual 编辑的因果结论互不一致。定位在统计意义上存在，其操作有效性无保证。
- **写入方向：近似可定位**。知识编辑方法（ROME、MEMIT 一脉）已实现单事实定向写入，在 CounterFact、zsRE、KnowEdit 等基准上可测；但定向是近似的、有牵连效应的、随编辑次数退化的。
- **删除方向：近不可定向**。与写入不对称，“从权重中抹除特定事实而不伤及其他”没有稳定操作子；只有覆盖或重训。灾难性遗忘自联结主义时期即是该载体的核心议题，知识编辑近年发展出独立的评测体系（zsRE、CounterFact、KnowEdit、Lifelong-M 一脉），是一个完整的活跃母学科。
### 4.3 写入通道：重开梯度
冻结关闭了梯度通道；parametric 的写入是有代价地重开它。按写入的空间范围与精度，存在从粗（全参数更新，与存量知识全面相互干扰）到细（低秩增量 ΔW = BA，可插拔可关闭；定向编辑，牵连效应与顺序叠加退化是新引入问题）的连续谱。该谱系的展开属 parametric 内部的设计问题，本框架作为对照载体仅记录其存在。
### 4.4 成本结构与“买断制”的适用域
**成本结构与 token 对称反转：写贵，读免费。** 写入是离线训练（GPU 时、数据管线、回归评测）；读取即普通推理，零额外开销，写入成本被读取次数摊薄。parametric 是**买断制**的记忆——但该表述仅对**静态知识、低频变化、高频读取**的场景成立。agent memory 的核心场景恰是持续经验积累，此时顺序编辑的叠加退化使成本随编辑次数超线性增长：买断制的正确表述是**对静态知识适用、对持续增量受限**。
### 4.5 记忆与能力的不可分离性
读取端没有操作，意味着不存在“使用记忆”的可辨识时刻。由此产生一个构成性后果：**parametric 记忆的贡献无法与模型固有能力相分离**——答对时没有任何手段区分“因为它记得”与“因为它会推理”。评测上只能测编辑前后的行为差异，不存在“检索质量”这样的独立环节。
这一不可分离性同时波及预训练知识的记忆地位：预训练知识与能力同样不可分离，故“预训练知识本身就是 parametric 记忆”与“parametric 记忆的记忆地位被不可分离性削弱”只能同时以弱化形式成立。本框架的统一表述：parametric 记忆的“记忆”地位是**程度问题而非本体问题**——行为上可辨识的记忆效应（写入后行为改变）可测，概念上记忆与推理的边界在权重层面不存在。这一张力是载体的本质特征而非表述缺陷：它同时解释了 parametric memory 的工程可验性（编辑改变行为）与概念尴尬性（何为记忆、何为能力）。
### 4.6 失败模式
灾难性遗忘（写入损伤存量）、编辑牵连效应（改了事实而关联推理不跟随）、顺序编辑叠加退化（每次编辑污染上次）。所有失败均不可见——湮没于权重深处，无法归因到任何可指认位置。

## §5 latent 载体（对照载体）
### 5.1 KV cache 的机制回顾
自回归生成中，第 t 个 token 依赖全部前文；若每步重算前文各层的 K/V 投影，总计算量为平方级重复。KV cache 的工程解法：每层 K/V 只算一次、存下复用。它因此是推理系统的标准组件——**本职是计算优化，算完即弃**。
latent memory 的核心洞察是换一个视角：**KV cache 里存的是模型对前文的处理结果**——每层 K/V 编码了前文 token 在该层注意力下的角色。丢弃它们，下次要重新计算“理解”；保留它们，就是保留“理解”本身。
### 5.2 定义与注入点
> **定义（latent 记忆）**。将前向计算的中间产物以张量形式持久化，并在后续前向计算中直接注入复用，跳过“从 token 重新计算”的环节。
注入点覆盖前向计算的三个阶段：KV 张量拼接（attention 层入口，主流形态）、hidden states 拼接（层间）、连续向量作为前缀嵌入（embedding 层，即 soft tokens / continuous prefix）。与 token 的根本区别：**token 让模型重新理解一遍文字；latent 直接保存并复用模型上次理解的结果**。
### 5.3 记忆临界点：工程裁量
按 §0.3 粒度（计算 = 单次前向），会话内跨轮 KV 复用已满足记忆判据。会话边界是产品层裁量而非本体层跃迁：请求级前缀缓存、跨请求 KV 复用已被推理引擎与 API 服务商广泛产品化，其区别只在存储预算与复用半径。生产部署的系统层挑战真实存在（如 FlashAttention 不物化 attention scores 使部分压缩方法难以工程化），其深化路线（压缩、生成、定点操作）属 latent 内部的设计分化，本框架作为对照载体仅记录其存在。
### 5.4 存储成本：形态对称的算例
fp16 下每 token 的 KV 体积为 2 × n_layers × n_kv_heads × d_head × 2 字节：
| 模型 | 配置 | 体积/token | 100K token 总量 |
|---|---|---|---|
| Llama-2-7B | MHA，32 层 | ≈ 512 KB | ≈ 51 GB |
| Llama-3-8B | GQA，8 KV 头 | ≈ 128 KB | ≈ 12.8 GB |
| Llama-3-8B + 8× 压缩 | 量化（如 2-bit 一脉）/ 逐层低秩（PyramidKV、PyramidInfer 一脉可达 12% 甚至更低） | ≈ 16 KB | ≈ 1.6 GB |
同一 100K token 的文本本体约 0.4 MB——未压缩形态相差约 4.5 个数量级，8× 压缩后缩至约 3.6 个数量级。须对称地陈述两端：**存储侧**，“存极重”仅在未压缩形态下绝对成立，压缩技术已在持续收窄量级差；**读取侧**，“读近零”精确说是“免重新 prefill”，注入后与查询的注意力交互成本与 token 注入同级（§6.1）。latent 的真实读取优势是**免 prefill**——对长上下文场景显著，对短上下文不显著。综合成本结构：**写即计算（prefill 副产品），读免 prefill，存重且持续**——三类载体中唯一为“保存”本身持续付费的形态。
### 5.5 性质
**不可回读**：张量对人不可读，从 KV 解码文本属于重新生成而非保真回读。**版本绑定**：绑定特定权重与推理配置（量化方案、位置编码实现、模型版本任一改变即作废）——与 parametric 更新构成结构性冲突。**坐标可寻址**：KV 按（层，头，位置）组织，可做定点张量操作——这种精细度在 token 与 parametric 处无对应物。
**时间维度的对称表述**：三类载体在事件时间表示上均无内在通道，均需系统层设计——token 的时间戳可由系统写入文本，latent 的时间元数据同样可由系统附带并按序拼接，二者处境对称。parametric 的特殊性是程度性的：梯度更新虽有时间顺序，但收敛后顺序效应湮灭为不可读的动力学痕迹，系统层补救手段也最少。
**缺席的失败模式补全**：跨会话 KV 拼接引入分布偏移（位置编码错位、注意力分布失配），是 latent 最现实的失败模式之一；压缩失真的记忆没有页面可翻开来检查它错成了什么样子。

## §6 边界与判例
### 6.1 裸上下文窗口：token 内容跑在 latent 载体上
**裸上下文窗口本身，就是 token 形态的内容跑在 latent 载体上的实现**：每轮输入的 token 序列进入模型后立即被转写为 KV cache（latent 形态）参与计算。token 记忆与 latent 记忆是**同一物理对象的两个侧面**——前者问“往窗口里注入什么内容”（内容侧），后者问“如何持久化、压缩、复用窗口的计算态”（载体侧）。两个推论：token 记忆的读成本隐含 latent 载体的 prefill 计算成本（成本轴上两载体交汇，非三分）；任何 token 注入自动获得一个 latent 副本（多载体并存的最小形态，见 §7.4）。
### 6.2 判例表
按 §2.3 判据（读取时刻为准）：
| 系统 | 写入技术 | 读取时刻载体 | 归类 | 判例意义 |
|---|---|---|---|---|
| Mem0、Letta（MemGPT）、Zep | LLM 抽取 | token 注入 | **token** | 标准形态 |
| 系统内嵌的向量索引 | embedding 化 | **从不进入前向计算** | **不是 latent** | latent 要求“以激活形态进入计算”；仅用于检索匹配的向量不满足——载体判据的精确化（§1.1） |
| WISE 类（LoRA 银行 + 路由） | LoRA 追加 + router | 进入某个参数化实例生效 | **parametric** | 虽模仿外部存储的追加结构，生效位置在权重 |
| MemGen 类 | RL + LoRA | 以 latent token 的 KV 形态进入计算 | **latent** | 写入动用 parametric 技术、读取在激活空间——读取时刻为准 |
| 为用户语料预填充后跨会话复用的 KV | 一次预填充 | 张量拼接 | **latent** | latent 最纯粹的产品化形态 |
| RAG（外部静态语料） | 无写入 | token 注入 | **token 载体形态** | 载体轴**无法**区分它与 token 记忆——区分落在“检索对象的来源”上，属来源轴；此判例标定本轴判别力的边界 |
| Voyager / AWM 类技能库 | 代码与工作流生成 | token 注入后触发工具执行 | **token（程序性）** | 引入内容功能分化：读取后不是被理解而是被执行（§3.2） |

## §7 载体的对比
### 7.1 总表
| 维度 | token | parametric | latent |
|---|---|---|---|
| 物理位置 | 输入序列（离散符号） | 模型权重 | 激活空间（连续张量） |
| 写入通道 | 文本操作（无梯度） | 重开被冻结关闭的梯度通道 | 前向计算的副产品 |
| 读取 | 显式：检索 + 拼接 | 隐式：与推理无边界 | 张量拼接（免 prefill） |
| 记忆与计算的关系 | 外置：读取后仍需理解（陈述性）/ 执行（程序性） | 无界：使用时刻不可辨识 | 内置：读取即计算态 |
| 成本位置 | 读端（逐次计费，重复前缀可摊销） | 写端（静态知识买断，持续增量超线性） | 存端（压缩收窄量级差，免 prefill 的读取优势对长上下文显著） |
| 信息形态 | 离散、可回读 | 弥散 | 连续、不可回读 |
| 地址性与定向操作 | 天然可寻址，文本操作可定向编辑/删除 | 写入方向近似可定位（有争议），删除方向近不可定向 | 坐标可寻址，可做定点张量操作 |
| 时间的事件表示 | 无内在通道，系统层设计 | 顺序效应湮灭，系统层补救最少 | 无内在通道，系统层设计 |
| 与模型的解耦度 | 解耦：记忆宿主在外部，独立存续 | 同一：记忆即模型本体 | 版本绑定：有效性系于特定权重与推理配置 |
| 失败可见性 | 可归因到条目 | 湮没于权重 | 湮没于张量 |
| 推理期攻击面 | 注入攻击面（外部可控文本直接进入前向） | 无此暴露面（风险在训练/分发环节） | 无此暴露面（风险在缓存污染环节） |
| 设计自由度 | 相对当前工程实践最显著（部分源于分类粒度） | 受优化动力学约束 | 受张量几何约束 |
| 代表 | Mem0、Letta、Zep | WISE、知识编辑谱系 | 前缀缓存谱系、MemGen |
三行需正文补强。**记忆与计算的关系**是最深一行：token 的记忆在计算之外，latent 的记忆在计算之内，parametric 的记忆与计算无边界。该行同时决定三者的评测形态——token 可测检索质量这个独立环节，latent 可测压缩与复用的系统指标，parametric 只能测编辑前后的行为差异。**地址性行**统摄了定向编辑与遗忘的物理基础：可归因失败、可定向删除、可版本管理这些工程性质，全部是地址性的下游。**设计自由度行**回答本章与后续章节的接口：parametric 与 latent 的内部主要是工程问题（在物理约束下把写入/存储做好），token 的内部是设计问题（组织空间全开放）——后续章节长在 token 里，既是占比问题，更是唯有它拥有需要专门分析框架的设计空间。
### 7.2 三种经济学
**每一个记忆设计决策，本质都是在选择把成本放在哪里**：token 放读端（其内部一切设计——压缩、组织——都在与逐次付费搏斗，缓存可部分摊销）；parametric 放写端（写入必须批量、离线、充分评测；持续增量场景成本超线性）；latent 放存端（其内部设计——淘汰、压缩——都在与保存持续烧钱搏斗，换取免 prefill 的读取优势）。三种经济学并非严格正交（§6.1 揭示 token 与 latent 在 prefill 成本上交汇），但作为透镜仍有价值：token 内部的各种分化，骨子里是读写成本的再分配。
### 7.3 可通约性
三类载体当前评测协议高度分离：多轮对话召回（token）vs 编辑三指标（parametric）vs 压缩比与长程检索（latent）；失败归因方式不同——同一现象“答错了”，在 token 处归因于检索，在 parametric 处归因于训练动力学，在 latent 处归因于张量几何；工程栈分离（检索生态 / 训练管线 / serving 引擎）。
但“三类之间不存在可通约性”的绝对表述不成立。**反证有二**：其一，混合系统是工程常态（§7.4），说明三类在系统层可组合；其二，端到端度量载体无关地存在——任务性能、总拥有成本、每比特有效记忆的延迟、记忆投毒鲁棒性。准确表述是：**三类载体当前缺乏通用评测协议与工程栈，形成三个母学科传统（信息检索 / 持续学习 / 推理系统），但在问题本体层存在部分共同度量衡**。“数据库索引、训练方法、虚拟内存不该同框”的类比亦须谨慎——learned index 与 KV cache 管理恰在系统社区被统一研究，跨学科融合正在发生。
### 7.4 混合形态：补充说明
载体框架不排斥混合；混合恰恰是部署常态。本节梳理两类混合形态，并由此给出纯 token 研究的边界条件。
**其一：技术借用（写入技术跨载体迁移）**。操作的物理实现与生效载体可以分属不同体系——MemGen 用 RL + LoRA（parametric 技术）生成 latent token，读取发生在激活空间；WISE 的 LoRA 银行模仿外部存储的追加结构，生效位置在权重；实践中亦常见“用 token 记忆生成语料再蒸馏入权重”的双段式（token 写入喂给 parametric 写入）。读取时刻判据使这类系统的归类不产生歧义——这正是 §1.2 两轴解耦的操作性收益：内容的管理可以在一处，生效可以在另一处。
**其二：副本同存（同一信息的多载体冗余）**。最小的混合是自动的：任何 token 注入即获得其 latent 副本（§6.1）。产品形态中可见三级冗余：会话日志（token）+ 定期微调摘要（parametric）+ 常驻前缀 KV（latent）。同一信息的内容视图与载体视图分离：内容层面的组织决策（操作轴）与各副本的生效位置（载体轴）是两组独立设计。
**对本研究的意义：纯 token 研究纲领的边界条件**。混合是常态，纯化是方法。聚焦单一载体不损失框架有效性——载体轴恰恰把混合解析清楚之后，才使单载体的独立研究成为可能。但纯 token 研究的结论须声明三条适用前提，它们同时是实验设计中的控制变量：
1. **冻结基座**：若 parametric 更新与 token 记忆并行存在，模型行为既被记忆注入又被权重改变，token 记忆的可归因优势（失败定位到条目）被稀释，评测信号混杂；
2. **单一生效通道**：token 记忆的优化目标函数假设“效果经由注入产生”；若部署中存在常驻前缀 KV（latent 副本固化了部分记忆），检索优化的反馈信号被污染；
3. **版本稳定**：token 记忆相对 parametric / latent 的核心优势是可迁移（模型更换后记忆保留）；该优势在基座升级时需主动验证迁移有效性，而非默认成立。
三条不是纯化研究的缺陷，而是其诚实声明：token 级记忆的优化设计在上述控制变量下推进，混合部署下的结论外推作为独立问题留在接口层（附录 B-7）。

## §8 范围与取材
### 8.1 分类实在性的证据与偏倚声明
**主证据：学科结构**。三载体各自继承完整母学科——token 背后是信息检索与数据库传统（数十年检索研究、向量检索产业与 RAG 生态的全部积累）；parametric 背后是持续学习与知识编辑传统（灾难性遗忘自联结主义时期起即是核心议题，知识编辑有独立评测体系）；latent 背后是推理系统社区。三个文献宇宙各有自己的会议、基准与综述谱系，彼此引用稀薄。
**偏倚声明**：该证据存在循环风险——先按载体分学科，再用学科分离证明载体是根本轴；且分类仓库的收录本身有选择偏倚（持续学习与知识编辑社区未必自我认同为“agent memory”，parametric 占比可能被系统性低估）。学科结构支撑的是“三个传统的分离是事实”，不直接支撑“分离在本体上是必然的”。
**辅证据：数量分布**。一份收录 199 篇 agent memory 论文的分类仓库（截至 2026 年 8 月）给出：token 约 72%，latent 约 16%，parametric 约 12%；近期领域综述采用同样的三形态分类，说明该分类具有当前社区内的描述性有效性。单一来源、社区维护，作方向性参考。工程侧信号同向：可直接部署的记忆产品几乎清一色为 token 方案；latent 的工程化集中于推理引擎侧；parametric 的落地集中于特定场景的权重交付。
### 8.2 门槛与最优的区分
token 的多数地位有相当部分源于门槛：复用成熟检索栈、可回读、易调试、运营生态成熟。**多数不等于最优**——parametric 的读免费与 latent 的免 prefill 在各自适用场景中是 token 无法企及的结构优势。对 token 的选择是可通约性与工程现实性的选择，不是性能优越性的判断。
### 8.3 聚焦声明
本研究的对比分析聚焦 **token 载体**。parametric 与 latent 在本章作为分类学对照出现——其载体级结构（物理位置、成本位置、地址性、解耦度、失败可见性）已在本章交付，其内部的设计分化（写入精度谱系、持久化路线）不属本研究。聚焦的理由是三重实用主义，无一为结构必然性：
1. **研究能量分布**（§8.1）：token 载体占据当前研究能量与工程落地的绝对多数，是问题最密集处；
2. **设计空间的存在性**（§3.2）：唯有 token 载体拥有需要专门分析框架的开放设计空间——parametric 与 latent 的内部主要是物理约束下的工程优化，token 的内部是组织学问题；
3. **控制变量的清晰度**（§7.4）：单载体研究使优化目标函数、评测信号、失败归因三个环节都免于跨载体混杂——注意力与精力分配的考虑，在此转化为方法论上可辩护的控制变量声明。
本章为后续章节留下接口（附录 B）：token 内部的分化至少包含存储引擎、信息压缩度、组织拓扑、陈述性/程序性内容功能等子轴；操作轴（生命周期算子分解）作为与载体正交的第二根分析轴整体移交；parametric 写入谱系与 latent 持久化路线作为各自载体的内部分化问题、混合部署下的结论外推问题，同在接口清单中。

# v4：Agent Memory 的载体：token、parametric、latent
## 0. 本文的地位、范围与用法
载体是 agent memory 的第一分岔。以 LLM 为行为核心的 agent，其行为由前向计算决定；过去要影响未来，必须经由某种跨计算存续、且能在读取时进入该计算的状态。对标准自回归 Transformer 的计算图做接口枚举，这样的位置只有三个：**符号空间、参数空间、表征空间**，本文依次称为 token、parametric、latent 载体。KV cache 是三位置之外的边界情形——单次序列处理内部自留的计算状态——单设一节处理。
本文是对比式研究框架的地基篇：只做载体问题的系统刻画，不提出方法，不给出载体优劣的规范判断。所有判断将向下传播，因此每处区分尽量写明裁定规则；有争议处保留多方立场并显式标注。记忆生命周期（写入策略、淘汰、治理）与载体间转化的机制梳理属其他章节，本文仅在划界必需时以最小限度触及。
**分析单位**：被追踪的那个 LLM 的前向计算。多模块 agent（检索器、视觉编码器、工具执行器）中其他模块持有的状态，只有当其最终以 token、参数或 latent 注入的形式进入该 LLM 的计算时，才在本框架中获得载体归属；模块自身的权重属于该模块的 parametric 状态，是否计入"agent 的记忆"取决于分析单位的选取（见 §8）。
近期综述将 agent memory 的形式切为 token-level、parametric、latent 三类，与本文的结论一致；但本文的论证顺序相反——先从计算图推导位置，再以文献作证据与对照。某结论被文献陈述过，不构成本文采用它的理由；本文只在其作为机制性证据处引用。

## 1. 计算图与位置推导
### 1.1 前向计算的解剖
先固定术语。**前向计算**指模型一次推理中从输入到输出分布的全部计算。**自回归**指逐个 token 生成、每步以已生成内容为条件。推理时的计算图可拆为四个部件：
- **输入接口**：输入是离散符号 ID 序列 x ∈ V^n（V 为**词表**，n 为序列长）；经**嵌入矩阵**（词表各行到向量的查找表）查表得 H⁰ ∈ ℝ^{n×d}（d 为**隐维**），并加入位置信息。这是符号世界进入连续计算的通道。
- **连续计算流**：对层 ℓ = 1..L，H^ℓ = Block^ℓ(H^{ℓ-1})。每层内部，**注意力**把隐状态投影为查询 Q、键 K、值 V 并做加权求和；**前馈网络**（FFN，每层中逐位置的两层矩阵变换）逐位置映射；**残差流**（跨层累加的表示通路）贯穿各层。
- **参数集 θ**：嵌入矩阵、各层 QKV 与输出投影矩阵、FFN 两矩阵、LayerNorm 参数。标准部署下推理期间不变。
- **输出接口**：H^L 经输出投影得词表上的分布，采样出离散符号。
### 1.2 持久状态的两个必要条件
称 s 为记忆状态，须同时满足：
1. **跨情景存续**：在两次独立的前向计算之间保持取值；
2. **因果有效**：s 的取值改变某次前向计算的输出分布。
### 1.3 接口枚举：为什么恰好三个位置
s 要影响输出，只能落在计算图上被读取的位置：
1. **输入接口之前的符号层**。s 必须可表示为（可扩展）词表中的离散符号序列，读取时作为输入进入计算 → **token 载体**。
2. **参数集 θ 内**。s 即参数取值，读取内在于每次前向计算 → **parametric 载体**。
3. **连续计算流内**。单次前向内的隐状态与 K/V 是易逝的；要满足条件 (i)，s 必须在计算之外以向量形式保存，并在读取时重新注入流中；注入点只能在嵌入输出之后、某层计算之中（软 token 位、逐层 K/V 位、中间隐状态位）→ **latent 载体**。
4. **采样与解码控制**（温度、停止规则、模型路由）：属编排配置。若其内容要作为记忆影响输出，最终仍须经过 1–3 之一进入计算；否则不在本框架范围内。
穷尽性依据：1–3 覆盖了计算图上全部"外部状态可接入"的接口；4 不构成新位置。由此得到三个载体，外加一个边界情形：单次序列处理内部自留的中间激活（KV cache 及层内记忆槽）——满足条件 (ii) 但默认不满足条件 (i)；一旦跨情景保存并再注入，即归 latent（§5）。
### 1.4 判定规则：状态本体 + 读取接口
**载体的判定不依赖存储介质的物理形式，而依赖两点：持久状态本体的数学形态，与读取时穿过计算图的接口。**
- 本体是符号序列、读取经过嵌入查表 → token。
- 本体是参数值（在计算中作为乘法权重参与运算）→ parametric。
- 本体是表征空间中的连续向量、读取时作为激活值注入嵌入之后的计算流 → latent。
同一段文本存进数据库是一份 token 记忆；把它训练进权重后，产生的是另一份 parametric 记忆——是两个不同的状态本体，不是同一记忆的两种存放方式（转化的最小声明见 §6.3）。
### 1.5 三个位置，不是三个互斥格子
一个系统的记忆可同时分布于多处（§6）。正因并存常见，每种载体从哪里开始、到哪里结束才需要显式划界——这是各载体小节的核心工作。

## 2. Token 载体
### 2.1 定义与来源
**定义**：记忆状态以离散符号序列的形式存在于模型之外；读取时作为输入序列的一部分进入前向计算，经嵌入查表与位置编码后，与普通输入 token 同等地参与注意力和 FFN 计算。
来源：位置 1 的直接推论。定义只做指称锚定；下述一切性质由位置推出，不预设。
### 2.2 什么算，什么不算
判例（依 §1.4 规则裁定）：
**算**：
- 检索增强（RAG）中被置入上下文的文档文本：本体是符号，读取经嵌入接口。注意：向量检索库中用于匹配的 embedding 是选取符号的访问结构，不是记忆内容本体；被取出并进入上下文的文本才是 token 记忆。
- 对话历史、消息日志、用户画像文本。
- 思维链 / 草稿纸文本：模型自产符号并跨步存续。
- 工具输出的序列化文本。
- 知识图谱、三元组表、结构化记录：存储为符号结构，读取时渲染为文本进入上下文；图结构是符号内容上的组织结构，不改变载体。
- 经验轨迹、成功/失败案例、工作流模板、few-shot 样例、摘要。
- 系统提示、指令模板。
- 以离散量化码表示的图像 token（若词表可扩展容纳）。
**不算**（归他类或界外）：
- 软提示向量：本体是连续向量，不经查表——latent（§4.2 专门论证）。
- KV cache：连续激活，见 §5。
- 只用于检索匹配、从不进入计算的 embedding 索引：访问结构，非记忆本体。
- 工具执行产生、从未序列化进上下文的环境侧效果：环境状态，界外（其影响最终要经由未来的输入符号才进入计算）。
- 以文件形式存放的技能代码：作为符号工件是 token 工件；其行为效果若只通过执行器发生而不进入 LLM 上下文，则对该 LLM 不构成记忆读取——边界情形，见 §2.7。
### 2.3 状态存放
存放介质任意：文件系统、关系数据库、向量库（存的是符号的索引）、图数据库。约束不在存储，而在读取通路：必须最终成为输入序列中的符号。
### 2.4 写入机制
写入 = 产生符号 + 存放。产生途径：模型自生成（一次前向计算后采样：草稿、反思、摘要、经验提炼）；环境与工具输出经序列化；模板化与结构化抽取（如从对话抽取三元组）；人或系统注入。写入不需要梯度运算；成本为生成计算与存储。
### 2.5 读取机制
读取 = 把符号置入输入窗口。此后与普通输入无差别：查表、位置编码、逐层注意力与 FFN。计算效果：输出分布以这些符号为条件。读取通路中不存在独立的"记忆读取器"——检索是决定哪些符号进入的写入侧选取机制，不是读取机制本身。
### 2.6 性质与代价（由位置推出）
- **读取成本**：每次读取消耗上下文窗口的位置额度；注意力计算量随读入长度与层数增长。同一份记忆反复读取即反复付费。
- **写入成本**：一次生成计算 + 存储；无训练。
- **持久性**：与模型完全解耦——换模型、换版本，符号工件原样可用（tokenizer 差异只影响切分）。
- **可检视性**：符号对人可读、对模型可读、可被任意第三方程序处理。
- **容量结构**：单次读取受窗口长度上限限制；存量无上限。压缩发生在写入时（摘要是有损写入），读取本身无损。
- **行为效果通路**：间接——效果依赖预训练赋予符号的语义，同一符号在不同模型上效果不同。
- **接口要求**：不要求接触模型内部（参数或中间层）——这是位置的结构性推论，与托管 API 的兼容性直接得出，不构成对载体优劣的评价。
### 2.7 边缘情形
- **多模态内容**：图像以连续 patch 嵌入进入计算（经视觉编码器），不经符号查表；持久工件是字节文件，向量由编码器每次重导出。对"LLM 单体"的分析单位，读取接口是连续的；对"含编码器的 agent 整体"，工件是符号字节。归属未决，见 §8。
- **存储-读取不对称**：符号存于图结构、读取渲染为线性文本——组织信息在读取时可能丢失，属访问设计而非载体问题。
- **程序性技能**（存为代码、由执行器运行）：效果不经由前向计算则不构成对该 LLM 的记忆；一旦代码或其输出进入上下文，则发生 token 读取。

## 3. Parametric 载体
### 3.1 定义与来源
**定义**：记忆状态即参数取值的一部分——存放在 θ 或附加于其上的参数模块中；读取内在于前向计算：权重参与每次矩阵乘法，不存在独立的读取动作。
来源：位置 2 的直接推论。
### 3.2 什么算，什么不算
**算**：
- 预训练从语料中写入的世界知识。
- 继续预训练 / SFT 写入的领域知识、人格、风格。
- 知识编辑的直接目标：ROME 对中层 FFN 第二矩阵做秩一更新以写入新的键值关联；MEMIT 把编辑分布到相邻多层。
- LoRA / 适配器形态的持久知识模块（**LoRA**：以低秩矩阵对 ΔW = BA 的参数增量形式存放，推理时合并或旁路计算）。
- 在线/测试时权重更新（如 Titans 把长程信息压缩进一个在线更新的 MLP 权重）——位置推导归 parametric；文献分类存在分歧，见 §8。
- 蒸馏内化（如 SELF-PARAM 用 KL 蒸馏把检索知识写入参数，使外部存储可弃）。
- 扩展词表新增的嵌入行。
**不算**：
- 软提示 / prefix 向量：本体是激活值，不是权重——latent（分界论证见 §4.2）。
- KV cache：激活。
- 检索器、编码器等旁模块的权重：对该 LLM 而言是机器；是否算 agent 记忆取决于分析单位（§0、§8）。
- 采样超参、路由配置：编排状态。
**分界细则（parametric vs latent 的决定性判例）**：LoRA 的持久本体是 B、A 两个矩阵，读取时作为线性映射的权重参与乘法 → parametric；prompt-tuned 软提示的持久本体是提示向量本身，读取时作为激活值注入嵌入层 → latent。判别标准即 §1.4：状态本体在读取时承担的角色是"乘法权重"还是"被注入的激活值"。
### 3.3 状态存放
**内部 parametric**：直接位于 θ。**外部 parametric**：附加模块（适配器、LoRA、旁路网络）的参数集，与主干预训练参数物理分离，可挂载/卸载，读取时以额外计算并入前向。
### 3.4 写入机制
写入 = 修改参数值，所有已知途径本身都是计算程序：梯度下降（预训练、继续预训练、SFT、RL）；闭式编辑（ROME 的秩一更新、MEMIT 的多层分布）；学习到的编辑器（MEND 训练小网络变换梯度以实现快速编辑）；在线更新（推理中对当前序列损失做梯度步）；蒸馏。写入成本结构：至少一次对目标内容的训练级计算；附带风险为干扰与遗忘——编辑文献以 specificity（不伤无关行为）与 generality（泛化到复述）度量编辑局部性。经验规律：数据重复对记忆化有超线性效应并伴随隐私风险，模型规模放大记忆容量。
### 3.5 读取机制与内部结构
读取无需动作：θ 在每次前向中必然参与。内部结构上，文献提供了机制级刻画：FFN 层呈现键值结构——第一矩阵的行与训练样例中的文本模式相关（键），第二矩阵的列诱导输出词表上的分布（值）；层输出是多个此类记忆的加权组合，经残差连接逐层精炼。ROME 的**因果追踪**（通过干预激活定位决定性计算的实验方法）把事实回忆定位于中层 FFN 在主语末 token 位置的计算，并据此实施定点编辑；对 FFN 键与值分别更新的消融显示两条通路的分工。要点：parametric 记忆并非均匀涂抹于权重——存在可定位的子结构；但定位本身是研究性问题，读取没有"按地址取"的操作语义。
### 3.6 性质与代价（由位置推出）
- **读取成本**：内部 parametric 为零边际（无论记住多少，计算图不变）；外部 parametric 为固定的额外矩阵乘法，与上下文长度无关、与记忆量线性相关（适配器数量、LoRA 秩）。
- **写入成本**：高；写入本身是计算密集程序。
- **持久性**：与模型版本绑定——换底座需重新内化；LoRA 增量在同架构底座间可迁移。
- **可检视性**：权重值不可直接人读；机制可解释性（键值结构定位、因果追踪、扰动诊断）能部分还原内容，读取本身是开放研究问题。
- **容量结构**：以参数计；分布式、叠加式存储（大量记忆共享权重），定量理论未建立；经验上随规模与数据重复增长。
- **保真**：有损（训练是压缩）；对重复数据可逐字复现，但不可按地址寻址。
- **行为效果通路**：直接——状态就是计算的基底，不存在符号解释环节。
### 3.7 边缘情形
- 每情景由上下文即时生成的"快权重"：若不跨情景存续，是 token 输入的函数而非持久状态；若以增量形式保存并在后续加载，归 parametric。
- 量化/压缩后的权重：存储形态改变，读取接口不变，仍归 parametric。
- MoE 专家权重：parametric；门控是输入依赖的计算，不构成独立记忆。

## 4. Latent 载体
### 4.1 定义与来源
**定义**：记忆状态以连续向量形式存在于模型之外（处于其表征空间的维度与分布内）；读取时注入前向计算的中间层——注入点在嵌入查表之后、输出投影之前的连续计算流上。
来源：位置 3 的直接推论。
### 4.2 什么算，什么不算（含软提示归属论证）
**算**：
- prompt tuning 产生的**软提示**：可训练的连续向量，置于输入序列前端、进入嵌入层输出位——模型冻结、只训向量。
- prefix tuning 的逐层 K/V 前缀：每层注意力的 K/V 序列上拼接训练向量，真实 token 的注意力可读取它们。
- gist token、AutoCompressor 摘要向量、ICAE 记忆嵌入、sentinel 隐状态：把长上下文压缩为少量向量存续复用。
- 跨情景保存并再注入的 KV 条目（Memorizing Transformers 的外部 KV 记忆 + KNN 检索、Memory3 的关键 KV 对、LONGMEM 的 SideNet 持久存储）——注意与 §5 的会话内 cache 区分。
- 压缩/变换后的 KV 工件（H2O 重击 token 保留、SnapKV 聚合、PyramidKV 层级预算、SirLLM、RazorAttention）作为被保留的工件。
- ElasticMem 的内容缓存：冻结编码器对 chunk 产生的末段隐状态，检索后作为软记忆 token 注入。
- LMI 从向量库检索并注入中间隐状态的稠密知识向量。
- MemGen 由 weaver 生成的隐 token 序列，其隐状态前置于推理机的当前隐状态。
- 连续思维链中跨步存续的隐状态部分。
**不算**：
- 离散 token。
- 检索匹配用、从不注入的 embedding：访问结构。
- 产生这些向量的编码器/生成器权重：机器的 parametric 状态（分析单位问题）。
- 单次前向内部的注意力输出、层间传递：易逝计算状态。
**软提示归属论证**（本框架内最常被误归的判例）：软提示常被称为"参数"（它们是可训练的）。按 §1.4 规则裁定：其持久本体是向量值，读取时作为激活值进入嵌入输出位，不经查表、不作为乘法权重参与计算——归 latent，不归 parametric。"可训练"是写入途径的属性，不是载体判据；载体判据是读取接口。文献中存在把连续向量 token 归入"token 级序列表示"的切法（按序列拓扑而非接口切）——两种切法在此判例上直接冲突；本文采用接口切法，并显式记录该分歧。
### 4.3 状态存放
向量形态：d 维（单点注入）或 d×层数（逐层注入）每条；存放于向量库或显存缓冲，检索键可另建（ElasticMem 用 chunk 末位隐状态做检索键、末段隐状态做内容缓存）。
### 4.4 写入机制
- **提取**：跑一次前向，取隐状态或 K/V（自源 latent——由模型自身计算产生，天然处于其表征分布内）。
- **训练编码器/压缩器**：训练一个模块把内容映射为注入向量（外源 latent——需与模型协同训练才被有效利用；gist、AutoCompressor 以"用向量复现长上下文延续"为目标训练）。
- **直接优化**：对向量本身做梯度下降（prompt tuning 即此）。
- **生成式**：训练生成器按当前状态产出记忆向量（MemGen 的 weaver）。
自源/外源之分影响读取效力：自源向量无需模型适配即可参与计算（Memorizing Transformers 直接拼接检索到的历史 K/V）；外源向量通常要求模型或注入器经过训练（软提示的生效依赖针对冻结模型的优化）。这是 latent 载体内部的结构差异，不影响载体归属。
### 4.5 读取机制：注入点枚举
- **嵌入层输出位**（软 token）：向量占据序列位置，从第 1 层起参与注意力。
- **逐层 K/V 位**（prefix 式 / KV 复用式）：向量拼接进每层注意力的 K/V 序列。
- **中间隐状态位**（加性注入）：不新增位置，在选定层对现有位置的隐状态做加和或变换（LMI 的逐 token 注入）。
- **记忆槽位**：每层附加固定槽，由专门注意力读写（LM² 的矩阵槽、M+ 的跨层池）——若槽值跨情景存续则属本载体；仅会话内存续则近 KV 情形。
### 4.6 性质与代价（由位置推出）
- **读取成本**：位置注入消耗序列位置、注意力开销与 token 同阶，但单位承载为 d 维连续向量；加性注入无位置消耗、有逐位置变换开销。两者均不经过符号生成。
- **写入成本**：一次前向提取（自源），或训练级投入（外源/直接优化）。
- **持久性**：向量绑定于产生它的模型的表征空间（维度、分布）；模型更替需重编码或迁移——跨模型迁移方法开放（§8）。
- **可检视性**：向量不可直接人读；探针可部分解码；解释性研究活跃但未解决。
- **容量结构**：单次读取受注入向量数限制；存量无上限；单位向量信息密度依赖训练，压缩比的经验报告限于特定设置，理论上界未建立。
- **保真**：自源复用可无损；压缩/生成式写入有损。
- **行为效果通路**：直接进入连续计算；外源向量的效力依赖模型与向量的协同适配——与 token 的免适配可读构成结构性差异（描述性陈述，非评价）。
### 4.7 边缘情形
- 检索键向量（如用末位隐状态做查询）：仅用于寻址，不进入计算，非记忆本体。
- 表征漂移：模型更新后，旧向量落入过时分布，与新的前向计算的兼容性问题开放（§8）。
- 会话内层内记忆槽：见 §5 的边界讨论。

## 5. KV Cache：专项说明
### 5.1 机制
自回归解码第 t 步，每层注意力需要对全部 j ≤ t 的位置做注意力，因而需要全部历史的。KV cache 保存已计算的，使每步只计算当前位置的 K、V 并对缓存条目做注意力，把每步重算从 O(t) 降为常数、整体从 O(n²) 降为 O(n)。规模：2 × 精度字节数 × 层数 × d_model × 序列长度 × batch；OPT-13B 每 token 约 800 KB、2048 token 约 1.6 GB。MQA/GQA/CLA 通过共享 K/V 头压缩体积；LRKV 等利用头间冗余做低秩化。
### 5.2 归属：三位置之外的边界情形
逐条对照：非 token——内容是连续向量，不经嵌入查表；非 parametric——是逐序列的激活，不是权重；与 latent 定义的前半句吻合（表征空间中的连续向量），后半句不吻合——它默认不被"注入"：它就是本次计算自身留存的状态。
结构定位：**KV cache 是"会话内自留的计算状态"——满足因果有效，默认不满足跨情景存续。**它是上下文中的 token 得以影响后续 token 的读取通路的中间形态：符号先被转为 K/V 条目，后续注意力从缓存中读取。会话内的 token 记忆，经由 KV cache 这个工作状态，实现其对未来的影响。
### 5.3 三种命运
- **默认**：序列处理结束即丢弃——会话内工作状态，不落入三载体中任何一格。
- **跨情景保存并再注入**（Memorizing Transformers 的外部 KV + KNN 检索、Memory3 的关键 KV 对、LONGMEM 的 SideNet 持久存储）：状态本体移到模型之外、读取经注入接口 → latent（复用型）。
- **压缩/变换后作为保留工件**（H2O、SnapKV、PyramidKV、SirLLM、RazorAttention）：若工件跨步或跨情景存续，为 latent（变换型）；若仅在会话内维持，仍是受管理的工作状态。
### 5.4 文献中的界定分歧（如实记录）
一种立场把 KV cache 管理、长上下文架构归为"LLM 内部记忆"，置于 agent memory 范围之外，同时承认用于保全任务内显著信息的 KV 压缩"在 agent 意义上起短期记忆作用"。另一种立场把注意力 KV cache 直接列为短期记忆的规范实例。分歧源于对"记忆"是否要求跨情景存续的定义选择。本文采用跨情景标准，同时单设本节以保住这个关键判例。

## 6. 多载体系统（补充）
### 6.1 并存的结构性原因
由 §2.6/§3.6/§4.6 的成本结构：token 读取消耗上下文但免训练、免内部访问；parametric 读取零边际但写入昂贵、不可按地址寻址、绑定模型版本；latent 读取紧凑但（外源时）需协同适配、绑定表征分布。没有任何位置在全部轴上同时占优——这是复合系统在位置间分工的推导依据，与对各载体前景的评价无关。
### 6.2 代表性组合（载体成分标注）
- **RAG + 领域微调**：token（检索文本）+ parametric（领域权重）。
- **WISE**：parametric（旁路编辑记忆与路由机制）+ 检索。
- **MemGen**：parametric（weaver/trigger 的 LoRA 模块）+ latent（生成的隐 token 序列工件）。
- **MemGPT**：token 单载体 + 复杂编排（分页管理）——作为"并存非必然"的对照。
- **ElasticMem / LMI**：latent（注入向量）+ parametric（编码/注入模块权重）。
- **Titans**：写入位于参数（在线更新的 MLP 权重）。位置推导归 parametric；有综述按"操作性记忆单元是推理期产生的 latent 向量"归 latent-generate——两判并存，见 §8。
### 6.3 载体间转化（最小声明，不展开）
- token → parametric：内容经训练写入权重后，持久状态本体已位于参数空间，归 parametric；原符号工件若仍保存，是并存的另一份记忆。
- parametric → token：从权重诱导出的文本是新生 token 工件，权重记忆本体仍在。
- latent ↔ token：向量经解码器可产符号，符号经编码器可产向量——产物是新本体。
- latent ↔ parametric：向量可被蒸馏进权重；权重可在线产出向量。
转化路径的机制、触发条件与保真度属后续章节。

1. **多模态输入的归属**：图像经视觉编码器以连续嵌入进入 LLM——对 LLM 单位，读取接口是连续的；对含编码器的 agent 整体，持久工件是字节文件。接口切法与工件切法给出不同归属，文献未统一。

5. **parametric 容量与定位的定量理论**：记忆化-重复-规模的经验规律已有，理论未建立。
6. **编排状态**（路由、模型选择、工具配置）是否计入 agent memory：取决于分析单位，文献分歧。

# v5：记忆的载体：token、parametric 与 latent
> **本文的性质与用法**。本文是 agent memory 对比研究框架的地基篇：论证“记忆状态在计算上可以放在哪里”，并对三个位置做同深度的机制刻画。本文的判断将向下传播为后续章节的默认前提，因此采用三条写作纪律：机制按机制写（状态在哪里、经过什么计算、产生什么效果），不用类比性表述替代机制；术语首次出现即定义；有争议处显式标注，不替读者收敛。本文按参考文档组织：§6 判例表与 §7 对照总表供直接查检，§7.5 汇集全部无共识点，§8 声明本文判别力的边界。

## §0 导言：载体问题
一个以 LLM 为计算核心的 agent，其行为由前向计算决定。若过去的行为与经验要影响未来的输出，相关信息必须经由某种**持续存在、可被读取的状态**进入后续计算——单次计算结束后，除了被持久化的状态，什么都不剩。
这个状态在计算上可以放在哪里，是一个可枚举的问题。位置的数量有限，而位置决定随后的一切：状态以什么物理形式存在、经过什么计算被写入、经过什么计算生效、受什么约束、以什么方式失败。载体因此是任何记忆设计的第一分岔——本文的任务是把这根轴立直：推导位置枚举的穷尽性，划定每个载体的起止边界，刻画三个载体各自的机制、性质与代价。
三个载体获得同等深度的处理。本文不提出新方法，不比较优劣，不为任何路线提供论证；领域内的数量分布与学科结构仅作为描述性证据呈现，并附带偏倚声明（§7.4）。本文的分析单位是载体本身，不是载体上的系统；三个位置不是互斥的格子——同一系统的记忆可同时分布在多处（§1.5），正因如此，每个载体从哪里开始、到哪里结束才需要划清，这是判例集（§6）的职能。

## §1 计算结构：状态位置的枚举
### 1.1 术语与前向计算的信息解剖
先固定术语。**LLM**：以 Transformer 解码器架构为基础的自回归序列模型，参数集合 θ（下称**权重**）在部署期默认数值不变（**冻结**——作为可松动的工作条件处理，见 §1.4）。**前向计算**：以 θ 与输入 token 序列 x = (x₁, …, xₙ) 为输入、输出词表分布的数值过程 f_θ(x)，分三段：x 经嵌入查表（查 θ 的嵌入矩阵）变为向量序列；向量序列经 N 个结构相同的层逐层变换，每层含**多头自注意力**（每个位置对各层产生的查询/键/值投影做匹配，键与值经各自投影矩阵从该位置表示算出）与**FFN**（前馈网络：中间神经元激活后经输出投影回加到表示流）；末层表示经输出投影得分布。计算各步产生的中间数值（键/值投影、注意力权重、隐藏状态）合称**激活**。
**请求**：推理系统对外暴露的一次完整计算调用，含两阶段——**prefill**（对全部输入 token 计算各层键/值投影并缓存）与**解码**（逐 token 生成：每步以已有缓存为条件计算下一分布并采样，直至终止）。**KV cache**：请求期间驻留的键/值张量集合，按（层，头，序列位置）索引。
信息在一次请求的计算中的物理位置有且只有三处：
1. **输入 token 序列**——离散符号，计算开始前存在于系统之外；
2. **权重 θ**——计算必经的数值通道；
3. **激活**——计算进行中产生与消耗的数值（prefill 产物在请求的解码期内持续驻留，是请求内持久的激活）。
两个看似的候选位置须排除。**输出**（采样所得 token）位于计算出口：它影响后续计算的方式只有两种——作为本请求内下一步解码的输入（自回归的请求内结构），或离开本请求、以符号形式重新进入后续请求的输入序列（落入位置 1）。输出不构成独立位置。**梯度通道**：训练期由输出损失计算 θ 的梯度并更新 θ；部署冻结期间该计算不发生，若发生（微调、测试时训练），信息经 θ 的数值修改持久化——那是位置 2 的写入机制，不是第四个位置。
### 1.2 计算事件的边界：请求
载体判定需要先固定“一次计算”的粒度。三个候选：单次前向、单次请求、会话。
**单次前向**过细：自回归解码中第 t 步的计算以第 t−1 步产生的 KV 与已生成 token 为条件——若以单次前向为判定单位，每个生成步都在“跨计算传递状态”，生成过程本身会被判为记忆系统。这把计算的内部实现误判为跨计算的状态保持。
**会话**过粗：会话是产品对请求的分组。把会话内跨轮传递排除在记忆之外需要一条特设豁免（“会话内状态不算记忆”）——但多轮对话中，前几轮内容在本轮请求重新进入输入，是真实跨请求传递的状态。
**请求**两侧干净：请求有系统提交与返回的明确边界；请求内的一切传递（自回归步间、请求内 KV）是本次计算的执行结构；跨请求的状态保持需要独立于单次请求的持久化介质与重注入机制——后者正是记忆问题的物理内容。
因此本文固定：**请求边界是“当下”与“过去”的分界，载体判定以请求为最小单位。**由此得到一个须直陈的推论（与部分工程直觉相反）：多轮对话中重新拼入的历史文本满足记忆判据，是 token 载体记忆的实例；“逐字的交互记录”与“加工过的记忆条目”的差异属于内容与操作的取值（后续轴），不影响载体判定。会话边界不影响判定。
### 1.3 记忆判据与前向判据
> **定义（跨请求记忆判据）**。设信息 i 出现于请求 R₁（作为输入、计算内容或输出）。若存在机制，使 i 或其变换在后续请求 R₂ 的前向计算中影响计算结果，则称该机制实现了对 i 的记忆。
由此，任何记忆机制必然包含两个组件：**持久化介质**（i 在请求间的存身之处）与**重注入机制**（i 进入 R₂ 的通道）。
该判据判出的集合很宽，须收窄。满足判据的状态包括两类额外对象：
- **控制面状态**：决定计算的组织而不进入计算内容——路由表（决定调用哪个模型/适配器）、采样参数（作用于分布输出之后）、编排规则。它们影响最终结果，但不进入任何前向计算的信息内容：改变的是“哪次计算、以何种方式发生”，而非“计算处理什么”。
- **执行面状态**：工具的可执行代码在外部运行器中的运行态、环境变量——由外部系统执行，不进入前向；其执行结果返回时以 token 进入（此时是数据）。
故追加收窄条款：
> **前向判据**。i 须经由前向计算的信息内容通道影响计算——作为输入 token、作为权重数值的效应、或作为注入的激活数值。控制面与执行面状态不是载体轴的对象。
（工具调用的完整链条因此分解为：工具描述文本进入前向——数据面，token；工具本体执行——执行面；执行结果返回并进入前向——数据面，token。链条两端是 token 载体，中间一段不在载体轴管辖内。）
### 1.4 位置枚举与穷尽性
i 跨请求影响 R₂ 的前向计算，必须出现在其三个信息位置之一：
| 位置 | 持久化形态 | 载体 |
|---|---|---|
| R₂ 的输入 token 序列 | 模型外符号序列，读取时经输入接口进入 | **token** |
| R₂ 所用权重（θ₂ ≠ θ₁，差异编码 i） | 权重数值 | **parametric** |
| R₂ 的中间激活（外部持久张量注入） | 模型外连续张量，读取时注入计算管线 | **latent** |
> **命题（载体穷尽性）**。任何使信息跨请求存活并影响 LLM 前向计算的机制，其记忆载体必居三者之一。
论证：前向计算的信息位置恰为三处（§1.1 解剖：输入、权重、中间激活），这是“以权重为参数、以符号序列为条件、以数值激活为过程”的计算结构的组成性事实，凡属此结构的模型皆然，不限 Transformer。跨请求的影响必须落位于三处之一，无第四位置；输出与梯度通道已在上文归并。
穷尽性的认识论地位须如实标注：它依赖两个前提——**架构前提**（LLM 中心系统；对不含此类计算的智能系统不适用）与**粒度前提**（请求边界，§1.2）。**冻结不是穷尽性的前提**：三位置对权重可变的系统同样穷尽；冻结影响的是 parametric 写入的成本结构（写入成为显式的、有代价的系统事件，§3.4），以及下文各性质推导的默认工作条件。冻结本身是部署主流而非必然：测试时训练（推理中更新参数）、端侧个性化微调、适配器热切换均已存在——它们不引入第四载体，只改变 parametric 的写入时序与成本（判例见 §6）。
### 1.5 定义锚定、归类判据与两轴解耦
三个载体的操作性定义（只锚定位置与通道，不预设任何性质；性质由后文从机制推导）：
> **token 载体**：记忆状态以离散符号序列存在于模型之外的介质；读取时作为输入的一部分进入前向计算。
> **parametric 载体**：记忆状态编码于权重数值之中；读取内在于前向计算，无需独立操作。
> **latent 载体**：记忆状态以连续张量存在于模型之外；读取时注入前向计算的中间环节。
三条配套纪律：
**归类判据（读取时刻为准）**。混合系统的载体归类，以读取时刻信息所处的位置为准，不以写入技术为准。理由：载体刻画的对象是“状态如何进入计算生效”；写入技术可跨载体迁移——梯度训练可产出外挂向量（软提示，§6），强化学习可产出注入用张量（生成式 latent 记忆，§6）——写入属操作范畴，生效位置由计算结构唯一决定。
**位置非互斥**。同一信息可在多个载体持有副本：注入的 token 文本与其被服务端持久化的 KV 副本；既被记录为文本又被微调吸收的经验。读取时刻判据承认同一信息可在不同请求以不同载体生效；多副本的管理属操作范畴。
**载体与操作的解耦（范围声明）**。记忆的生命周期管理（写入、更新、淘汰如何组织）与载体是两组问题：任一载体上可组织多种操作方案，但操作的**物理可行性与代价**受载体约束（条目级定向删除在 token 载体上是字符串操作，在 parametric 载体上无稳定算子，在 KV 形态的 latent 载体上可按位置区间执行）。本文只刻画载体与操作的物理基础；操作谱系的展开、各载体内部的设计分化（token 的存储介质/压缩档位/组织拓扑/内容功能，parametric 的写入谱系，latent 的持久化路线）全部属后续章节，本文仅在判例中登记其存在。

## §2 token 载体
### 2.1 定义来源
> **定义（token 载体）**。模型 M(θ) 冻结；外部介质维护符号集合 D；请求时执行选择 s(q, D) → S ⊆ D，将 S 序列化为文本并与查询组装为输入，模型计算 f_θ(组装输入)。记忆影响计算的唯一通道是输入 token 序列。
该定义来自模型的可观测输入接口：LLM 的输入协议是离散符号序列——一切被计算处理的信息必须先成为 token。凡以符号形态持久、以输入形态生效的状态自动落在这个位置，无需任何附加机制。接口的存在使 token 载体成为**零门槛位置**：任何能产出文本的系统（agent 自身、环境、外部应用）都能写入；任何持有权重的推理栈都能读取。这一点是纯结构性陈述，不涉及效果评价。
### 2.2 状态存放
模型外部任意持久介质：文件系统、关系数据库、向量数据库的文本字段、图数据库、代码仓库。物理上与模型部署完全分离。介质的选取是 token 内部的设计分化（登记，不展开）。
须立即划清一个边界：**向量数据库中存储的嵌入向量不是记忆载体**。它们用于检索匹配——查询向量与条目向量的相似度计算由独立的嵌入模型与索引结构完成，发生在 LLM 前向计算之外，从不进入前向；进入前向的是被检索出的文本。嵌入向量与索引结构是检索基础设施，不是任何载体上的记忆状态。此判例排除“向量库 = latent 记忆”的常见混淆。
### 2.3 读取机制
读取是一条完整计算链，逐步给出：
1. **选择**：依据当前查询从 D 选出 S。执行者可以是向量相似度检索、符号匹配（关键词、结构化查询、图遍历）或一次 LLM 调用。选择发生在目标前向之外（用 LLM 做选择时，那次调用是一次独立前向，模型在其中充当选择器而非记忆宿主）。
2. **序列化**：S 的条目转为字符串（模板、格式化、拼接）。
3. **组装**：与系统指令、查询、对话历史组装为完整输入。
4. **tokenization**：字符串 → token id 序列。子词切分（BPE 类算法按合并规则迭代切分）依赖字符串的局部上下文，拼接边界处的切分可能与条目单独编码时不同；token 数与字符数的比率随内容与 tokenizer 版本而变。
5. **嵌入查表**：id → 嵌入向量（查 θ 的嵌入矩阵；这是 token 读取与权重的唯一交互——冻结参数被当作查找表使用）。
6. **逐层前向**：注入内容与输入其余部分一起参与每层计算。注意力的交互项使 prefill 计算量随序列长度二次增长（注意力矩阵的二次项）；解码期每步对全部缓存键的注意力随注入量线性增长。注入内容经注意力影响查询位置的表示，进而影响输出分布。
读取的约束：
- **窗口预算**：注入量受模型上下文长度上限约束——硬约束。token 载体的可用容量由读取侧决定，存储侧原则上无界：容量双约束的不对称是 token 载体特有。
- **读取有效性的经验性质**：长上下文中注入内容的召回随位置与总量变化（中部位置召回偏弱、无关内容稀释相关注意力等经验观察）。这些是分布层面的经验规律，非确定性机制，登记为读取端的经验性质，不进入机制推导。
**读取成本结构**：每次生效重付第 4–6 步计算；同一记忆被读取一千次，支付一千次注入计算。摊销机制存在且物理上重要：当注入内容跨请求重复（固定系统前缀、固定记忆块），推理系统可缓存其 prefill 产物（KV 张量）并在后续请求复用——注意此摊销的实现：实际生效的是该前缀的 KV 副本，即 latent 载体形态（§4、§5）。**token 的读成本可以经把重复内容物化为 latent 副本而摊销**；多家推理服务商的前缀缓存/提示缓存产品即此机制（登记为工程事实）。两载体在此交汇（§7.2）。
### 2.4 写入机制
写入的物理动作是外部介质的字符串追加或修改。按内容来源分两种：**生成式写入**（内容由一次 LLM 调用产出——摘要、事实抽取、反思、归纳的规则；成本为一次推理调用，模型充当内容生产者，存储动作仍在外部）与**被动写入**（环境或系统直接记录——交互日志、工具输出存档、用户提供资料；零模型成本）。
写入形状的约束只有一条：可序列化为文本。数字、结构化记录、代码、图的序列化、多模态内容的文本描述皆可。这条约束的宽松程度与其他两载体形成结构性对照：parametric 的写入形状由优化动力学或求解目标决定（§3.4），latent 的写入形状由张量几何与生成机制决定（§4.4），token 的写入形状由设计者直接决定。须同时登记对称修正：现有分类把功能高度异质的内容（事实、技能、工具描述、环境记录、编排文本）尽数收入 token 类，token 内部异质性部分来自分类粒度的收纳选择而非载体物理——两种来源的贡献在当前证据下不可分离，此点不构成对任何载体价值的判断。
### 2.5 性质与代价（由机制推导）
- **写入成本低**：字符串操作或一次推理调用。
- **读取成本高且逐次付费**：注入、重编码、注意力；占窗口预算。重复前缀可经 latent 副本摊销（§2.3）。
- **存储成本近零**：文本介质驻留成本可忽略（对照 latent 的持续驻留成本，§4.5）。
- **完全可检视**：内容是人可读文本，可在任意粒度（字符、条目、字段）阅读、编辑、删除、比对。这是审计、版本管理、条目级合规操作（如按用户删除特定数据）的物理基础。
- **模型无关**：换用不同权重与 tokenizer 的模型后文本仍可注入——可注入性跨模型保持；注入后的语义效果稳定性是经验问题，不构成载体性质。记忆资产的存续不依赖模型版本。
- **生效范围逐请求组装**：注入什么、注入多少由每次请求的选择决定——与 parametric 的全局生效对照（§3.4）。
- **推理期攻击面**：注入内容直接进入前向计算的信息内容，外部可控文本可经记忆库进入计算（记忆投毒、经记忆通道的提示注入）。这是 token 载体在数据面的暴露；parametric 的对应暴露在训练与权重分发环节、latent 的在持久张量写入环节（对称登记，见 §4.5；防御方法不在本文范围）。
### 2.6 失败模式
选择失败（相关条目未被选中）、注入失败（噪声内容占预算、干扰注意力——注意力稀释为经验性质）、内容失败（过时、条目间冲突、抽取损失）。全部失败可定位到具体条目与具体决策：错误可见性高，修复可定向执行（改条目、改选择器、改注入预算）。

## §3 parametric 载体
### 3.1 定义来源
> **定义（parametric 载体）**。通过修改权重数值 θ → θ′ 使信息持久化；读取无独立操作——θ′ 在后续每次经此权重的前向计算中生效，信息以模型行为差异的方式出现。
定义来源是可直接验证的观察：无任何外部注入时，模型对大量事实与技能表现出稳定掌握；这些信息的影响通道只能是 θ——每次计算必经且持久的唯一内部数值。因此，任何对 θ 的信息性修改都是 parametric 写入，其效果自动传播至此后的一切计算。
层级澄清：部署前的预训练存量是 parametric 载体上已存在的记忆（写入过程不可观测、无审计记录）；agent 语境的 parametric 记忆研究通常指部署后的**增量写入**。存量与增量是时序区分，载体相同。此区分有一个开放问题式后果（见 §3.3）：预训练知识与模型能力的不可分离性，使“预训练存量是记忆”这一陈述本身依赖记忆概念的取值（§7.5-4）。
### 3.2 状态存放：编码方式与其证据
信息在 θ 中的编码是分布式的。机制层面的经验证据（作为证据登记，非推导起点）：
- **FFN 的键值结构**（Geva et al., 2021）：FFN 中间神经元在非线性激活后的取值可视为键——对该位置输入模式的匹配度；输出投影矩阵的对应列可视为值——被激活神经元的列向量加权累加进表示流。报告的观察：中间神经元的激活模式与训练语料中的可辨识模式对应，输出列与词汇分布相关；事实性关联的读取大量经由 FFN。
- **因果定位**（知识神经元，Dai et al., 2021；因果追踪，Meng et al., 2022）：对选定位置数值加噪并观测行为退化、再恢复并观测恢复的实验，报告事实回忆对中层 MLP 的依赖。知识编辑方法以此定位为支点。
- **争议登记（无共识）**：Hase et al.（2023）报告因果定位结论与编辑有效位置之间缺乏稳定对应，且不同干预方式（去噪式与反事实式）给出的关键位置不一致。准确表述：**定位是统计意义上的近似聚集，不是可依赖的精确地址。**
架构修正：**混合专家（MoE）**路由下，每个 token 的前向只激活被路由选中的专家 FFN 子集——parametric 读取是“输入条件化的子集读取”。路由由前向自身计算（无外部操作），读取仍无独立操作；但“每次计算携带全部权重”须修正为“每次计算携带路由选中的子集”。
### 3.3 读取机制
无独立读取操作。具体机制：查询 q 进入前向，其逐层表示与 θ 数值交互；若某信息编码于某些 FFN 神经元（其键匹配 q 的表示模式），对应值列被累加进表示流，最终影响输出分布。三个结构特征：
1. **无操作边界**。不存在“读取这条记忆”的可辨识计算步骤；信息生效与计算过程同一。推论一：不存在“使用记忆”的可观测时刻——单次行为中无法区分“因记忆而正确”与“因固有能力而正确”，记忆的贡献与模型计算的贡献在计算图上无对应分界。推论二（评测形态）：parametric 记忆只能通过写入前后的行为差异间接测量，不存在“检索质量”这类可独立测量的环节（对照 token，§2.6；latent，§4.7）。
2. **默认无选择开关**。全参数部署时全部数值参与每次计算；MoE 为路由条件化子集；适配器插拔提供部署级开关，粒度是模块（一个适配器的全部内容），非条目。不存在“本次请求不读某些记忆”的请求级选择——对照 token 的逐请求选择与 latent 的逐次注入。
3. **弥散编码**。一条信息的效应分布于大量数值的联合调制；行为探针（构造查询、观测输出）是唯一观测通道。
### 3.4 写入机制
写入的物理动作统一：**修改 θ 的数值**。按“如何决定新值”分两谱系：
1. **优化谱系（梯度）**。构造训练信号（目标函数与数据），反向传播迭代更新。按写入的空间范围与约束分：全参数更新（范围 = 全部 θ）；低秩增量（LoRA：冻结 W、训练 B ∈ R^{d×r} 与 A ∈ R^{r×d}，生效时以 W + BA 计算，写入被约束在低秩子空间，产物可独立存储与加载）；适配器模块（新增小参数块接入计算路径）。写入结果的形状由优化动力学决定——损失曲面、数据分布、初始化、训练顺序的联合作用；设计者指定目标与约束，不直接指定每个数值。
2. **编辑谱系（直接数值修改）**。先定位（因果追踪等近似方法），再求解约束修改（ROME：对选定层求最小范数扰动使该层对特定输入的输出满足目标关联，闭式解直接写入权重，Meng et al., 2022；MEMIT 扩展为跨层批量，Meng et al., 2023）。写入结果的形状由求解目标直接指定，受定位精度约束——定位误差表现为牵连效应（§3.7）。
边缘形态登记：权重算术（多个 θ 的线性组合）是两谱系之外的写入形态，见于模型合并实践；登记存在，不展开。
两谱系共享的结构后果：
- **生效全局性**：θ′ 对此后经此权重的所有请求生效——所有用户、所有会话共享。无法按请求或按用户隔离；多租户需要每租户独立权重实例或独立适配器实例，隔离的物理代价随租户数增长。
- **版本耦合**：记忆与模型是同一物理对象；增量的交付形态是“新版本权重”或可加载的适配器（判例见 §6：适配器文件在加载前是潜在状态，加载后生效——文件形态的物理外观不决定载体，生效机制决定）。
### 3.5 性质与代价
- **读取零边际**。准确内容：记忆生效不需要计算之外的任何额外步骤——若信息编码于 θ 并影响行为，其生效成本已包含在必经的前向计算之内。对照的精确表述：token 读取付注入加重编码加注意力；latent 读取付注入加注意力（免重编码）；parametric 读取无额外项。（MoE 下为路由子集的同一性质。）
- **写入昂贵**。优化谱系付数据构造、训练算力、回归评测（评测的目的是防止写入损伤存量行为）；编辑谱系付定位、求解、副作用检查。共同点：写入是低频、离线或批量事件，不能在推理路径上逐请求进行。
- **写入相互干扰（开放问题，无共识）**。增量对存量的干扰（灾难性遗忘，自联结主义时期起的持续议题）；编辑间干扰（顺序编辑叠加退化——有研究报告数百次顺序编辑后精度显著下降乃至模型整体失效；模块化路线（独立侧网络加路由）在万次级更新后仍报告退化，见 WISE 类工作）。持续写入的可持续性上限无共识（§7.5-3）。
- **不可检视**。数值不暴露内容，行为探针是唯一通道。推论：无法审计“模型记得什么”；条目级删除无稳定算子。
- **地址性是程度谱且方向不对称**。写入方向近似可定位（编辑技术存在、行为可测——但定位与编辑有效性的对应有争议，§3.2）；删除方向近不可定向（“抹除特定信息而不伤及其他”无稳定操作子；覆盖、重训、模块卸载是可用替代，各有代价）。
- **时间无表示通道**。θ 的数值不编码事件时间；梯度更新的先后顺序在收敛后表现为不可读的动力学痕迹，系统层的补救手段也最少（对照 §4.5、§7.1 的时间行）。
- **无独立存储**。记忆的驻留与模型运行同一物理对象——parametric 没有独立存储成本，也没有独立存储（版本耦合的另一面）。
### 3.6 失败模式
灾难性遗忘（写入损伤存量行为）；牵连效应（编辑改变目标之外的行为——修改事实 A 而关联推理不跟随、无关行为漂移）；顺序叠加退化。共同特征：**失败不可见**——数值中无条目、无页面，只能行为级回归观测；多写入事件的效应叠加使归因到具体写入困难。

## §4 latent 载体
### 4.1 定义来源
> **定义（latent 载体）**。将前向计算的产物（或专门模块合成的）张量持久化于模型之外；读取时作为连续数值注入前向计算的中间环节，跳过“从符号序列重新计算”的路径。
定义来源是计算结构的一个直接可能性：激活在请求内本就是跨解码步持久的数值状态（KV cache 是其标准形态）。把这类数值持久化到请求之外、并在后续请求注入计算，是第三个信息位置的实例化。载体身份由此确定：既不经符号接口（与 token 的区别），也不驻于每次计算必经的通道（与 parametric 的区别）——latent 状态是计算的选择性注入物。
历史登记：可微外部存储（NTM，Graves et al., 2014；Memory Networks，Weston et al., 2015；DNC，Graves et al., 2016——外置矩阵加软寻址读写，端到端训练）是 LLM 之前该载体位置的先例；认知架构传统（ACT-R 的陈述性/程序性记忆区分、Soar 的工作记忆分层）提供了概念词汇来源；对话状态追踪是跨轮持久状态的先行工程。本框架将 agent memory 定位为这些传统在 LLM 语境下的汇流，此定位为描述性陈述。
### 4.2 状态存放
模型外部的张量存储（显存/内存/磁盘上的实值数值），具备独立管理性：可序列化、复制、搬移、整体替换、删除。具体形态：**KV 条目**（每层每 KV 头每位置的 k、v 向量）；**压缩/聚合向量**（多位置信息合并为少量向量）；**记忆槽向量**（占序列离散槽位的连续向量，如记忆 token 的嵌入）；**循环状态**（循环网络/状态空间模型的隐藏状态 h——跨请求持久 h 的方案属此）。
### 4.3 读取机制：注入点与计算细节
读取需要触及推理管线的内部接口（KV 句柄、嵌入注入口、层间接口）。按注入点分三处，对应前向计算的三个阶段：
1. **注意力入口（KV 注入）**：持久 k/v 拼入当前请求的 KV cache，参与每步注意力的键值匹配。位置机制：旋转位置编码（RoPE——键在生成时已按其原位置旋转，注意力内积携带相对位置信息）下，跨请求拼接要求注入块的位置标注与当前序列协调：作为前缀续接，或对缓存键重新旋转重标注——重标注改变注意力模式。位置协调失败是跨请求复用的真实失配源（§4.7）。
2. **嵌入层（向量作为输入）**：连续向量作为输入序列位置的嵌入（替换或前置于查表输出）。这些位置的后续计算与 token 完全相同，区别仅在表示的来源（注入值 vs 查表值）。软提示、记忆 token 嵌入、摘要向量前缀属此。
3. **层间（隐藏状态注入）**：持久隐藏状态拼接到某层之后的计算流。工程化最少，登记存在。
**读取的计算成本（对称陈述）**：**免 prefill**——注入的 KV 不需对其源文本重付编码计算（token 载体每次注入都重付源文本的 prefill）；**保留注意力成本**——注入条目参与每步解码的注意力计算，量级与 token 注入的解码期相同。净效果：对长上下文、重复读取的内容显著节省；对短上下文、单次读取的内容不显著。
### 4.4 写入机制
写入的物理动作分三谱系：
1. **复用**：把某次请求已产生的 KV 持久化（源 = 该请求处理过的文本）。写入成本 = prefill 计算（那次请求本来要付，缓存是其副产品）。产物保真于“该模型对该文本的计算结果”。
2. **压缩**：对已有 KV 做张量操作。逐 token 剪枝（按注意力重要性分数驱逐——H2O 的累计注意力，Zhang et al., 2023；观察窗口投票——SnapKV，Li et al., 2024；层间预算分配——PyramidKV）；跨位置合并；量化（KIVI 等 2-bit 存储）。产物是原 KV 的有损变换。
3. **生成**：经训练的模块把 token 序列映射为记忆向量（gist 类，Mu et al., 2023；AutoCompressor 类软摘要向量，Chevalier et al., 2023；MemGen 类以强化学习训练生成器产出记忆槽向量）。写入成本 = 生成器的一次前向。产物形态由训练目标决定。
注意生成器自身的权重经梯度训练——parametric 写入发生在生成器上，而产物按读取时刻归 latent。写入技术与载体分离的又一实例（判例 §6）。
**写入形状的约束**：张量几何——维度由模型架构决定（层数、KV 头数、头维、位置数），数值内容由源计算或生成机制决定。设计者不能任意指定写入形状（对照 token 的任意文本与 parametric 的经优化塑造：三种载体的写入形状决定机制各不相同）。
### 4.5 性质与代价
- **存储重（算例，形态依赖）**。fp16 下每 token 的 KV 字节数 = 2（K 与 V）× 层数 × KV 头数 × 头维 × 2。Llama-3-8B 型配置（32 层、分组查询注意力 8 个 KV 头、头维 128）≈ 128 KB/token，100K token ≈ 12.8 GB；Llama-2-7B 型（多头注意力 32 头）≈ 512 KB/token，100K token ≈ 51 GB。对照：100K token 的文本 ≈ 0.4 MB——未压缩形态相差约 4–5 个数量级；压缩收窄量级差（有逐层预算分配与量化达到 10% 级保持率的报告，方向性证据），差距仍保持数个数量级。**为保存持续付费**：张量驻留显存/内存预算，成本随记忆量线性增长——三类载体中唯一“保存本身构成运营成本”的位置（token 存储付介质费用，近零；parametric 无独立存储）。
- **版本绑定**。张量数值只在生成它的权重数值与推理配置（位置编码方案、量化精度、架构切分、头数布局）下有效；任一改变即失配，且失配是静默的——无错误信号。推论：latent 记忆的寿命 ≤ 模型版本寿命；parametric 更新与既有 latent 记忆构成结构性冲突（更新权重使后者作废）；跨模型无迁移机制（不同 θ 的表示空间无对应关系）。
- **部分可检视**。张量显式存在：可复制、搬移、整体替换、删除——回滚在物理上直接。数值无符号语义：人不可读；探针解码是重建而非回读，重建与原文的对应无保证。局部数值编辑的语义效果不可预测。
- **索引可寻址（KV 形态特有）**。天然按（层，头，位置）组织且与 token 位置一一对应——可在 token 粒度做定点操作（逐条驱逐、保留、按区间删除）。压缩/生成形态失去该索引（向量与源位置无对应）。索引形式是 latent 内部的分化维度（§5.2 展开）。
- **生效范围按注入组织**。注入什么、注入多少由每次请求决定——与 token 同为逐请求可变；会话级/用户级 KV 持有是天然的作用域单元（对照 parametric 的全局生效）。
- **访问门槛**。读取要求触及内部接口；托管推理 API 通常只暴露文本输入——纯 API 部署下 latent 不可用。例外形态：服务商的上下文缓存功能（用户指定持久化前缀，后续请求复用其 KV——Gemini Context Caching、Anthropic Prompt Caching；引擎级前缀复用如 vLLM、SGLang 的基数树缓存）是服务商代理执行的 latent 注入，功能上开放了有限的 latent 载体访问。登记为工程事实。
- **推理期暴露面（开放问题）**。持久 KV 的写入端控制（缓存投毒：诱导系统持久化受控内容、后续复用波及其他请求）。暴露面在结构上存在，研究稀薄，实际严重性无共识（§7.5-6）。
### 4.6 失败模式
- **分布失配**：拼接来自不同上下文的 KV——位置编码错位、注意力分布漂移，当前请求在“不属于其语境的表征”上做注意力。
- **压缩失真**：剪枝、合并、量化的信息损失；被压缩的记忆无可翻开的页面，无法检视损失了什么。
- **版本失配**：权重或推理配置变更后旧张量静默失效。
- 失败可见性介于两者之间：低于 token（无可读条目）；高于 parametric（张量级可数值检测、可重建探针诊断——但诊断成本高且非保真）。

## §5 KV cache：内容与索引的分离
KV cache 获得专门处理，因为它同时具备两侧的强证据，是锐化 latent/token 边界的最佳案例。
### 5.1 机制回顾
自回归解码中，第 t 个 token 的计算以全部前文为条件：每层注意力以第 t 位为查询、对位置 1..t 的键值做匹配。不缓存则每步重算前文各层投影，计算量含大量重复；KV cache 使每层每个已处理位置的 k、v 只算一次并存驻，后续步直接复用。请求内它是解码的必要中间状态（计算内状态，§1.2）；请求结束默认销毁。每 token 的逻辑体积与存储算例见 §4.5。
### 5.2 双重结构
**内容在表征空间**：每条目是实值向量——该位置 token 的隐藏状态经该层键/值投影矩阵计算所得，编码该 token 在该层注意力中的角色。
**索引在符号空间**：条目按（层，头，位置）组织，与输入 token 序列一一对应；RoPE 下每个缓存键携带其原位置的旋转。索引的 token 对应性有两个可观测后果：
- **逐 token 定点操作可行**。驱逐、保留、检索的决策粒度是 token——H2O、SnapKV 等压缩方法操作的对象是连续向量，决策粒度是 token，机制上依赖索引对应。
- **逐 token 重建可行**。已有隐私方向工作演示从 KV cache 重建输入文本（利用位置对应与可训练探针）：索引对应性使 cache 携带可恢复的源序列信息（latent 记忆的合规暴露面，§5.5）。
### 5.3 判定与索引维度
按读取时刻判据：条目以张量注入激活管线、参与注意力计算，不经符号接口——**归 latent 载体**。token 级索引不改变读取路径的判定，但给予该形态一项纯连续内容所没有的能力：token 粒度的操作与合规定位（删除某用户的 KV 可按位置区间执行）。
由此得到一个框架级观察：**载体的三分覆盖“内容形式 × 读取路径”两个维度；索引形式是未被三分覆盖的第三维。**token 记忆天然符号索引（文本条目）；parametric 无索引（弥散）；latent 的索引随形态分岔。2×2 谱系：
| | 符号索引 | 无符号索引 |
|---|---|---|
| 符号内容 | token 记忆（文本条目） | ——（符号内容必有可定位条目） |
| 连续内容 | **KV cache**、记忆 token 槽位 | 软提示、压缩/生成向量 |
索引形式决定可定点操作的粒度（符号索引 → 条目/token 粒度可定位）；内容形式决定可检视性（符号内容 → 人可读）。KV cache 处于“连续内容 + 符号索引”格：可定位操作，不可读。
### 5.4 反向参照物
四个参照显示内容与索引两个维度独立变化，KV cache 是其中一格而非中心：
- **MLA**（DeepSeek-V2 的多头潜注意力）：cache 存每 token 的低维潜向量，推理时上投影重建键/值——索引仍 token 级，内容进一步压缩（k、v 不分别存储）。架构内的压缩推进，索引保持。
- **RMT**（Recurrent Memory Transformer，Bulatov et al., 2022）：序列末的记忆 token 槽位承载连续向量、跨段传递——连续内容 + 符号槽位，与 KV cache 同格的另一实现（读取经嵌入注入而非注意力拼接）。
- **软提示**：连续前缀向量，无符号索引——纯连续形态。
- **压缩/生成记忆**：k 个向量代表 n ≫ k 个 token——索引与源位置断裂。
### 5.5 记忆临界点与缓存同构
按请求边界判据：请求内 cache = 计算内状态；**跨请求持久并复用 = latent 记忆的实例**（前缀缓存、会话级 KV 持有、跨用户前缀共享）。
内容恒定的持久 cache（系统提示的 KV）满足记忆判据，其内容不随经验更新，与缓存的物理功能重合。准确表述：**记忆判据判出的是“跨请求可注入状态”的全集；其中内容静态的子集与缓存重合，内容动态的子集是通常语境的记忆。缓存与记忆的区分不在载体与读取（物理实现相同），而在内容演化与操作（后续轴）。**这是 latent 记忆与推理系统工程同源的机制原因：两者的差异是操作层的，不是载体层的。

## §6 判例总集
按读取时刻判据（§1.5）逐例判定。判定依据写入末列；本表兼作载体边界的完整登记。
| # | 对象 | 写入技术 | 读取时刻生效方式 | 归类 | 判定依据与意义 |
|---|---|---|---|---|---|
| 1 | 多轮对话历史（逐字记录重拼） | 被动记录 | 输入序列拼接 | **token** | 请求边界判据下即记忆；“逐字记录 vs 加工条目”是操作轴取值 |
| 2 | 系统提示（恒定文本持久保存） | 设计写入 | 输入序列拼接 | **token** | 内容静态：与缓存功能重合的形态（§5.5） |
| 3 | 记忆条目库（Mem0、Letta、Zep 类） | LLM 抽取 | 检索后注入 | **token** | 标准形态；条目组织（图/扁平/结构）是内部轴 |
| 4 | 技能库（Voyager、AWM、AutoManual 类） | 代码生成 | 描述与观察以 token 注入；代码本体被执行 | **token**（数据面部分）+ 执行面（代码本体） | 程序性内容登记：读取后可触发执行——内容功能分化，后续轴 |
| 5 | 向量库嵌入索引 | 嵌入化 | 不进入前向 | **非载体** | 检索匹配发生在前向之外（§2.2）——排除“向量库 = latent 记忆”的混淆 |
| 6 | 请求内 KV cache | prefill 副产品 | 请求内复用 | **非记忆**（计算内状态） | 请求边界判据（§1.2） |
| 7 | 跨请求前缀缓存 / 提示缓存 | prefill 副产品 | KV 张量拼接 | **latent** | 内容恒定子集 = 缓存重合；token 读成本的摊销通道（§2.3） |
| 8 | 会话级/用户级 KV 持有（Context Caching 类） | 一次 prefill | KV 张量拼接 | **latent** | 产品化形态；天然作用域单元 |
| 9 | 检索式 KV 记忆（Memorizing Transformers、LONGMEM） | 请求 KV 存库 | 相似度检索后拼接 | **latent** | 学术形态：检索发生在激活空间，索引是数值相似度 |
| 10 | 压缩 KV（H2O、SnapKV、PyramidKV、KIVI） | 张量操作 | 拼接 | **latent** | 有损变换；驱逐型方法保留 token 索引、合并型断裂 |
| 11 | 生成式 latent 记忆（gist、AutoCompressor、MemGen 类） | 训练模块生成 | 槽位向量注入 | **latent** | 写入动用 parametric 技术、读取在激活空间——读取时刻为准 |
| 12 | 软提示 / 前缀微调产物 | 梯度训练向量 | 嵌入层注入 | **latent** | 读取时刻判据的最清晰教学案例：梯度写入不使载体成为 parametric |
| 13 | RMT 记忆 token | 取隐藏状态 | 槽位嵌入注入 | **latent** | 连续内容 + 符号槽位（§5.4） |
| 14 | 适配器文件（未加载） | LoRA 训练 | 无（潜在状态） | **无生效**；加载后 **parametric** | 文件形态不决定载体：生效机制决定（§3.4） |
| 15 | 微调后部署 / 加载中的适配器 | 梯度 | 权重参与前向 | **parametric** | 标准形态 |
| 16 | LoRA 银行 + 路由（WISE 类） | 侧网络训练 | 权重实例生效 | **parametric** | 追加结构模仿外部存储，生效位置在权重；路由是控制面 |
| 17 | 知识编辑（ROME、MEMIT） | 定位 + 闭式修改 | 权重生效 | **parametric** | 定向写入（近似、有牵连，§3.2） |
| 18 | 测试时训练 / Titans 类在线记忆模块 | 推理中梯度更新模块权重 | 模块权重参与前向 | **parametric** | 冻结松动情形；**动态性不是载体判据，状态的物理类别才是**（与 #19 对照） |
| 19 | 跨请求持久的循环/SSM 隐藏状态 | 前向计算 | 初始状态注入 | **latent** | 与 #18 同属“在线记忆”功能、分居两载体 |
| 20 | NTM / DNC 外部存储矩阵 | 软写入 | 软寻址读取 | **latent** | LLM 之前该位置的先例（§4.1） |
| 21 | 离散码本（VQ 类） | 梯度训练码本 | 输入条件查表后注入 | **latent / token**（按注入物形态） | 查表注入是显式读取；写入技术不决定载体。同时解释“离散内容 + 隐式读取”组合为何空缺：离散结构折叠进 θ 后计算中表现为数值调制；保留离散查表则读取必为显式注入 |
| 22 | 路由表、编排规则、采样配置 | 系统设计 | 不进入前向内容 | **控制面**（非载体轴对象） | 前向判据排除（§1.3） |
| 23 | 工具运行态、环境状态本体 | — | 外部执行，不进入前向 | **执行面**（非载体轴对象） | 观察结果返回进入时是 token |
| 24 | RAG（外部静态语料） | 无 agent 写入 | 检索后 token 注入 | **token 载体形态** | **载体轴无法区分它与 token 记忆**——区分落在“检索对象的来源”上，属来源轴；此判例标定本轴判别力边界 |

## §7 三载体的对照
### 7.1 总表
| 维度 | token | parametric | latent |
|---|---|---|---|
| 物理位置 | 模型外符号介质 | 权重数值 | 模型外连续张量 |
| 内容形式 | 离散符号 | 连续数值（弥散） | 连续数值（结构化张量） |
| 写入机制 | 字符串操作（生成式或被动） | 梯度优化或定位编辑 | 前向产物复用 / 压缩 / 生成 |
| 写入形状的决定者 | 设计者 | 优化动力学 / 求解目标 | 源计算或生成机制（受张量几何约束） |
| 读取路径 | 输入接口：tokenization → 嵌入查表 → 逐层计算 | 无独立操作，内在于前向 | 显式注入：注意力入口 / 嵌入层 / 层间 |
| 读取成本 | 注入 + 重编码 + 注意力，逐次付费（重复前缀经 KV 副本可摊销） | 零边际（MoE：路由子集） | 注入 + 注意力，免 prefill |
| 存储成本 | 近零（介质费） | 无独立存储（与模型同一） | 持续驻留成本（未压缩下与同内容文本差 4–5 个数量级，压缩后收窄） |
| 生效范围 | 逐请求组装 | 全局（所有经此权重的请求；多租户需实例隔离） | 逐请求注入，可组织会话/用户作用域 |
| 可检视性 | 完全（人可读，任意粒度） | 无（行为探针唯一通道） | 部分（可搬运可替换，不可读） |
| 索引与地址性 | 符号条目，天然可寻址 | 弥散；写入方向近似可定位（有争议），删除方向近不可定向 | 坐标索引（KV：token 级；压缩/生成形态无符号索引） |
| 定向删除 | 字符串删除 | 无稳定算子（覆盖/重训/卸载） | KV 按位置区间可删；压缩形态不可定位 |
| 时间的事件表示 | 文本可写时间标记（设计选择） | 无通道，顺序效应湮灭 | 无内在通道（序列位置 ≠ 事件时间；系统层可附元数据，与 token 处境对称） |
| 与模型版本的关系 | 解耦（可注入性跨模型保持） | 同一（记忆即模型本体） | 绑定（权重或推理配置变即静默失效） |
| 推理期暴露面 | 注入面（外部可控文本直接进入前向） | 无（暴露在训练/权重分发环节） | 写入端（缓存投毒，开放问题） |
| 失败可见性 | 条目级可归因 | 行为级可测、写入级归因难 | 张量级可检测、语义级诊断难 |
| 评测形态 | 选择/注入质量可独立测量 | 写入前后行为差异 | 压缩比 / 复用收益 / 失配率 |
### 7.2 三行展开
**记忆与计算的关系**（表中第 5、16 行的底层结构）。token 的记忆在计算之外：读取后重复执行从符号到激活的计算（注入内容仍需经嵌入与逐层变换才生效）。latent 的记忆在计算之内：注入物本身就是计算状态，读取即生效。parametric 的记忆与计算无边界：不存在“正在使用记忆”的可辨识时刻。这一行决定三者的评测形态（表中末行）：token 可把“选对了没有”作为独立环节测量；latent 可测系统指标（复用收益、压缩损失、失配率）；parametric 只能测写入前后的行为差。
**成本位置与交汇**。每个载体把主要成本放在不同环节：token 放读端（逐次付费，内部设计与摊销机制围绕它）；parametric 放写端（低频、批量、须充分评测）；latent 放存端（持续驻留，内部设计围绕保存的预算）。三种经济学**不是正交的**：token 读成本的摊销机制物理上经 latent 副本实现（§2.3）；latent 复用形态的写入成本与一次必经 prefill 同一（写入即计算的副产品）；parametric 的读取成本与模型运行成本同一（无独立项）。成本轴上三者存在交汇点，交汇不消除位置差异——每次请求的生效机制仍然不同。
**索引与地址性**。三者的可定位操作粒度：token 为符号条目（字符/条目/字段）；KV 形态的 latent 为 token 位置（层、头、位置坐标）；parametric 近乎无（写入方向有近似定位）。可归因失败、可定向删除、可版本管理这些工程性质的物理基础全部在此行。
### 7.3 载体间的转化（最小点明）
转化存在，转化后载体身份改变（读取路径变）：token 内容经训练进入权重后，不再以 token 形态生效（成为 parametric）；文本 prefill 物化为 KV 后跨请求复用，生效形态转为 latent（前缀缓存即此）；从张量解码重建文本是 latent → token 的路径（非保真重建）；行为蒸馏产出语料是 parametric → token 的路径。转化的机制与组合方式不属本文；判例 #11、#14、#16 已显示写入技术与生效载体的可分离性。
### 7.4 描述性分布：证据与偏倚
**数量分布（辅证据）**。一份收录 199 篇 agent memory 论文的社区维护分类仓库（截至 2026 年 8 月）给出：token 约 72%，latent 约 16%，parametric 约 12%。单一来源、社区维护，作方向性参考。工程侧信号同向：可直接部署的记忆产品以 token 方案为主；latent 的工程化集中于推理引擎侧（其中内容恒定的部分按 §5.5 与缓存同构）；parametric 的落地集中于特定场景的权重交付。近期领域综述（Liu et al., 2025 等）采用同样的三形态分类，说明该分类在当前社区内具描述性有效性——此为描述性对照，不作为本文论证的依据。
**学科结构（主证据）**。三个载体各自继承完整的母学科：token 背后是信息检索与数据库传统；parametric 背后是持续学习与知识编辑传统（灾难性遗忘自联结主义时期起的议题，知识编辑有独立评测体系）；latent 背后是推理系统社区。三个文献宇宙各有会议、基准与综述谱系，彼此引用稀薄。
**偏倚声明**。其一，循环风险：先按载体分学科，再用学科分离佐证载体是根本轴。其二，收录偏倚：持续学习与知识编辑社区未必自我认同为“agent memory”，parametric 占比可能被系统性低估。其三，也是最重要的：**分布是描述不是评价**——多数地位与工程门槛（复用成熟检索栈、可检视、易调试）相关，不蕴含载体优劣；parametric 的读零边际与 latent 的免 prefill 在各自场景中是其他载体没有的结构属性（§7.1 已并列陈述）。
### 7.5 无共识点清单
1. **KV cache 系列的领域归属**：推理工程优化还是记忆研究——不同综述划法不一；本文按读取时刻归 latent（§5.3）并记录分歧。
2. **定位与编辑有效性的对应**：因果定位结论不能预测最佳编辑位置（Hase et al., 2023 对 ROME 谱系的检验）；定位的地位是统计近似（§3.2）。
3. **parametric 持续写入的可持续性**：顺序编辑退化的上限、模块化路线的万次级退化——开放。
4. **parametric 记忆中“记忆 vs 能力”的概念边界**：不可分离性（§3.3）同样适用于预训练存量，使“预训练知识是记忆”依赖概念取值——开放。
5. **长上下文与 parametric 知识的功能关系**：有证据方向报告长上下文训练把梯度压力从 FFN 转向注意力模块、增强上下文依赖——两载体在功能上竞争同一角色的可能，证据未收敛。
6. **latent 缓存投毒的实际严重性**：暴露面结构上存在、研究稀薄（§4.5）。
7. **跨请求 KV 拼接的失配治理**：位置编码协调与注意力分布漂移的系统性方案——开放。

## §0 方法论前言：立场与边界
### 0.1 冻结作为条件前提
本分析的出发点是一个工程现状：主流 agent 部署中的基座模型在服务运行期间参数保持冻结。这是当前服务化 LLM 的默认形态，但**不是物理定律，也不是长期稳定的经济必然**。当前至少存在三类松动迹象：端侧部署中的 on-device 个性化微调已产品化；test-time training 研究方向明确探索推理时参数更新，并已扩展至线性层以外（Sun et al., 2024）；推理时 LoRA 热切换与 adapter 路由在 serving 层已有工程实践。
同时须澄清一个常被夸大的成本论证：同一 batch 上前向加反向与优化器更新的开销约为前向 FLOPs 的三倍量级，“单次更新比单次前向贵数个数量级”在算子层面不成立。真正阻止部署期更新的是系统层成本——评测回归、灰度发布、回滚机制、多租户一致性——而非单步计算。
因此本框架的认识论地位是**条件框架**：在“基座冻结、计算 = 单次前向、载体以读取时刻生效位置为准”三重条件下成立的结构性推论。三重条件中任何一条的松动都对应框架的明确修正方向（附录 A 逐条列出）。
### 0.2 三条前史
agent memory 并非在冻结之后凭空诞生，至少继承三条成熟传统。**外部记忆带传统**（Graves et al., 2014, NTM；Weston et al., 2015, Memory Networks；Graves et al., 2016, DNC）：外部可寻址存储作为独立于主网络的组件被训练，是本领域最直接的技术先驱。**认知架构传统**（ACT-R 的 declarative/procedural memory 区分，Soar 的工作记忆与长时记忆分层）：agent memory 的概念词汇直接来源于此，近期领域综述亦明确承认这一继承（Liu et al., 2025）。**对话系统传统**（对话状态追踪、belief state tracking、user modeling）：本质上是跨轮持久化工作记忆的先行研究。本框架将 agent memory 定位为三条传统在 LLM agent 语境下的汇流，而非新领域的诞生时刻。
### 0.3 粒度声明
本分析显式定义“计算”为**单次前向传播**。该选择的直接后果是：**请求内乃至会话内的 KV 跨步、跨轮复用已满足 §1.1 的记忆判据**（先前前向的信息影响后续计算）。“请求内状态只是缓存、会话内状态不算记忆”的工程直觉，在此粒度下不作为本体判断成立。本框架接受这一结论而非引入豁免条款；请求级、会话级、跨会话的差异因此是**产品层裁量**（存储预算、复用半径与治理要求的经营决策），不是本体层跃迁（§5.3 给出该裁量在 KV 对象上的完整分析）。
本分析同时承认**载体轴判别力的边界**：它回答“记忆如何生效”，不回答“什么算记忆、算谁的记忆、用于什么目的”。后三类问题属其他维度（来源、功能、主体性），本框架不在载体轴上处理，其接口见附录 B。

## §1 记忆判据与本章边界
### 1.1 记忆判据及其附加条件
> **定义（记忆判据）**。设信息 i 在时刻 t₁ 的计算 C₁ 中产生或出现。若存在机制，使 i（或其变换）在 t₂ > t₁ 的另一次计算 C₂ 中影响计算结果，则称该机制实现了对 i 的记忆。
该功能性判据判出的集合是**缓存的严格超集**：任何持久化状态（文件、数据库、缓存）都满足。要收窄到有研究意义的“记忆”，需追加两个附加判据：
1. **载体判据**：信息必须以某种形态进入前向计算（仅用于检索匹配、从不进入前向的向量索引不满足，见 §6.2 判例）；
2. **作用判据**：影响的必须是模型的计算结果而非系统行为（路由层的外部决策不算——这一归并是本框架的定义选择，见 §2.2）。
第三个候选判据——**来源判据**（信息是否来自 agent 自身经验）——本框架选择不施加：来源是独立维度，与载体轴正交，其处理见附录 B-9。由此，任何记忆系统天然包含两个功能组件：**持久化介质**（信息在两次计算之间的存身之处）与**重注入机制**（信息重新进入后续计算的通道）。
### 1.2 载体轴与操作轴的解耦
记忆现象可分解为两组正交问题。**载体轴**：信息在哪里、以什么物理形态生效——其取值由计算结构决定（§2）。**操作轴**：信息的生命周期如何被管理——写入、维护、调用、更新、淘汰——其取值由设计选择决定。
两轴的正交性论证：任一载体上原则上可实现任一操作组合，但操作的**物理可行性**受载体约束——如 parametric 载体上“定向删除”近不可实现（§4.2），token 载体上一切操作退化为文本操作（§3.1）——这说明操作可行性是载体的结构属性，而操作设计是独立的研究问题。二者的区分是本章反复使用的分析杠杆。
本章纪律：**只立载体轴**。操作轴的分析框架（生命周期算子的分解、各载体上操作谱系的展开）属后续章节（附录 B-1）。两轴的可分离性同时是 §7.4 混合系统在概念上合法的原因：写入技术跨载体借用，正是操作在载体间迁移的表现，而归类不受其影响（§2.3）。
### 1.3 治理检测器：记忆的操作性校验
在计算判据之外，工程与安全实践提供了一个**独立的操作性检测器**：当系统实践要求某个持久状态被隔离、授权、按作用域管理、纳入威胁模型时，该状态已在事实上承担记忆的角色。共享推理环境中的前缀缓存使 KV 状态成为攻击面（跨请求侧信道、缓存投毒一脉的攻击研究），多租户部署以作用域隔离管理 KV 状态——“推理状态已进入安全边界”是这一判断的概括。
该检测器的认识论地位是**实践性的**：它不来自计算结构，而来自运维与安全工程对“什么需要治理”的判断。它与计算判据的吻合（KV 跨请求持久化既满足判据、又进入威胁模型）构成载体分类有效性的经验校验。其使用纪律是**单向的**：进入威胁模型的必是记忆性对象，但未进入的不必然不是——低敏感记忆无需隔离治理。检测器可作校验，不作定义。

## §2 三类载体的结构性论证
### 2.1 前向计算的信息解剖
设冻结模型 M(θ)，输入序列 x = (x₁, …, xₙ)。单次前向中与信息相关的物理存在只有三处：
1. **输入序列 x**——信息进入计算之前；
2. **模型权重 θ**——计算赖以进行的通道，冻结条件下为常量；
3. **中间激活**（各层 K/V 张量、hidden states）——信息在计算中流动的瞬时状态。
两个看似候选的位置须排除。**输出**位于计算出口，要再次影响计算必须作为后续输入进入序列（自回归的当下延续），或被写成文本保存（后者已落入 token 载体的写入来源）。**梯度通道**是信息写入权重的原生通道，冻结意味着该通道被关闭——parametric 载体的全部写入，本质是有代价地重开它（§4.3）。
### 2.2 穷尽性命题及其前提
> **命题（载体穷尽性）**。在基座冻结、计算 = 单次前向、载体以读取时刻生效位置为准的三重条件下，任何使信息跨计算存活的机制，其记忆载体必居三者之一：**token**（使输入持久）、**parametric**（使通道持久）、**latent**（使中间态持久）。
这不是经验发现，而是**框架内定理**——其有效性由三重定义选择的强度决定，且有两个已知代价须正面陈述：
**路由/编排层的归并**。决定调用哪个模型、哪个 adapter、哪个工具的信息（路由器、编排规则）不进入任何单次前向，但显著影响最终结果。本框架按作用判据将其归并为系统行为而非记忆，并因路由规则多以文本/代码形态存储而在技术形态上将其划入 token——这暴露了**分类粒度选择对结果的塑造**：一个更细的分类可将“编排层”列为第四种载体。本框架不这样做，理由是它影响系统行为而非单次计算，但该理由是定义选择而非物理必然。
**token 类的异质性负担**。工具、技能库、可执行程序、环境状态、编排规则均以文本形态被“读取”而归入 token 类。这使 token 内部的分化显著性高于另外两类——其中部分是物理属性（无写入门槛），部分是分类粒度的产物，两者贡献无法在当前证据下分离（§3.2）。
### 2.3 归类判据：以读取时刻为准，及一处判据分歧
> **判据**。混合系统的归类，以**读取时刻**信息所处的载体为准，而非写入时使用的技术。
理由是归类纪律而非存在性声明：载体分类的对象是“记忆如何生效”；写入技术可在载体间借用（操作轴迁移），但生效位置由计算结构唯一决定。
须显式指出：文献中实际并存两套归类判据。本框架的判据看**内容的生效位置**（读取时刻信息以何种形态进入前向）；另一套判据看**机制的位置**（实现存储与检索的组件是参数化的还是外部的）。两者在大多数系统上一致，在“机制与内容分属不同载体”的系统上分歧——典型即预训练阶段写入参数化检索头、知识内容留外部 token 库的 LMLM/HierMemLM 一脉：按机制位置归类为 parametric，按内容读取位置归类为 token。本框架采内容判据，理由是载体轴的对象是记忆内容如何生效，机制是实现而非内容；但判据选择必须显式，因为它直接改变统计结论（§8.1）。完整判例见 §6.2。
### 2.4 穷尽性不蕴含互斥性
三载体框架在近期领域综述中被广泛采用（Liu et al., 2025 等），具有当前社区内的描述性有效性。同时，同一条信息可以多载体并存：上下文 token 与其 KV cache 是自动的双重存在（§6.1），经验既可被记录为文本又可被微调吸收（§7.4）。读取时刻判据处理这一多重性的代价是承认：**同一信息可以在不同时刻以不同载体生效**。载体轴回答“每次生效时信息在哪里”，不承诺信息的唯一归属。

## §3 token 载体
### 3.1 定义与机制
> **定义（token 记忆）**。模型 M(θ) 冻结；维护外部记忆库 D（符号集合）；每次推理执行检索 r(q, D) → S ⊆ D，将 S 序列化后与查询拼接，模型计算 M(θ; q, S)。信息影响计算的唯一通道是输入 token 序列。
结构上，token 记忆是一个**围绕冻结模型外围的信息检索与注入系统**——模型本身完全不知晓记忆的存在，记忆对模型而言只是上下文的一部分。存储介质任选（文件、数据库、向量库中的原文）；全部生命周期操作以 API 调用完成，不触碰模型内部；这是三个载体中唯一与模型零耦合的形态。
### 3.2 内部分化：自由度的两个来源与多轴结构
token 的写入在物理上只有一条约束：**可序列化为文本**。文本操作没有形态限制——原文、摘要、原子事实、结构化记录、可执行代码、图与树的序列化，皆可。对照之下，parametric 的写入形状由优化动力学决定，latent 的写入形状由张量几何决定；token 的写入形状由设计者决定。
由此常被引出的断言“token 载体的设计自由度最大”，其成立依赖**两个可分离的来源**：其一为**物理来源**（无写入门槛、无形态限制，真实的载体属性）；其二为**分类来源**（本框架将工具、技能、程序、环境状态、编排规则尽数归入 token，人为扩大了其内部异质性）。两者贡献无法分离，故正确表述是：**token 的设计自由度相对于当前工程实践最显著**。
其内部至少存在以下分化维度，且彼此只是近似正交（图数据库的检索算法与图拓扑在工程上强耦合；文献中亦有按拓扑复杂度递增的单轴划分——平坦/单层结构化/分层——但该单轴将压缩度与内容功能混入拓扑维度，本框架将其降格为组织拓扑轴上的素材而非独立分类）：
| 维度 | 取值谱系 | 备注 |
|---|---|---|
| 存储引擎 | 向量库、图数据库、关系库、文件 | 工程介质选择 |
| 信息压缩度 | 原文、原子事实、摘要 | 写入路径的有损变换档位 |
| 组织拓扑 | 平坦、单层结构化（树/图）、多层分层 | 条目间关联结构 |
| 内容功能 | 陈述性事实 / 程序性技能 | 读取后的处理方式有质差：被理解 vs 被执行 |
程序性内容（Voyager 技能库、Agent Workflow Memory、AutoManual 一脉）是常被遗漏的关键分化：同为文本，技能被读取后触发工具执行而非语义理解。**这些子轴的分别展开是后续章节的任务**（附录 B-2 至 B-5）；本章只确立载体级事实——token 的写入自由度最大意味着设计空间全开放，这既解释了 token 何以成为工程主流（无物理门槛），也解释了其内部分类必须推迟（过早分类会在混淆的轴上锁死框架）。
### 3.3 成本结构、性质与结构性限制
**成本结构：写便宜，读贵，逐次付费。** 写入是一次性 LLM 调用（抽取、摘要、索引构建）或零成本被动记录——“符号追加 O(1)”仅对写入管线中最末的介质追加子步骤成立，不宜以之概括写入整体；每次生效占据上下文窗口、付出推理成本。token 是**订阅制**的记忆——且该订阅可被部分摊薄：注入内容为重复前缀时，跨请求 KV 复用与提示缓存（已为多家推理服务商产品化）可显著降低边际读成本。读成本结构的精确表述：**逐次计费，重复前缀可摊销**。
其余性质由“载体是通用文本”派生：**模型解耦**（记忆库与模型可独立更换，记忆资产独立于模型存续）；**可回读**（人类可直接阅读每一条记忆，是审计与版本管理的基础）；**可迁移**（换基座后记忆保留）。三者共同构成 token 当前**运营生态最成熟、运营门槛最低**的原因——同类比较中，跨请求 KV 预填充复用与端侧个性化微调均已产品化，“唯一可运营”的表述过强。
**结构性限制：外置内容的理解深度。** token 记忆的生效必须经过模型对注入文本的完整编码，注入内容与参数化知识在计算中的融合深度存在经验上限——内化型任务（风格保持、技能泛化、深度一致性）上，token 注入形态逊于参数化形态的系统证据已在文献中出现。该限制的准确表述是“注入通道的融合上限”而非“模型能力上限”；它是后续章节中压缩度与内容功能两根子轴的物理动机之一——压缩不足挤占上下文预算，压缩过度丢失融合所需的语境。
### 3.4 失败可见性与攻击面
token 的失败集中而可见：读取端召回失败、注入噪声挤占注意力、新旧记忆冲突未消解、写入端信息丢失、事实编辑的级联（依赖条目陈旧化、跨条目一致性）。可见性本身是资产——错误可定位到具体条目与具体检索决策，可归因、可修复。
**token 特有的失败面：注入攻击**。token 记忆是外部可控文本进入前向的直接通道，记忆投毒与经记忆注入的 prompt injection 是该载体独有的推理期攻击面（附录 B-6）。parametric 与 latent 不存在等价的推理期注入通道（后者的条件性攻击面见 §5.5）。该不对称在 §7.1 表中以独立行呈现。

## §4 parametric 载体（对照载体）
### 4.1 定义与机制
> **定义（parametric 记忆）**。通过梯度更新 θ → θ′ 将信息写入权重；读取无显式操作，查询 q 直接进入 M(θ′)，信息以模型行为的方式涌现。
parametric 与 token 最深刻的差异在**读取端**：token 有显式、可观测的读取动作；parametric 没有——一条事实被写入权重后，不存在任何操作叫“读取这条事实”，它弥散于数百万权重的调制之中，由整个网络协作重构出来。
### 4.2 层级关系、写入形态与地址性程度谱
**层级关系**：预训练知识本身就是 parametric 记忆——冻结基座即一个巨型参数记忆库。Agent 语境下的 parametric memory 特指预训练之上的**增量写入**；预训练权重中的存量知识不因本框架而改变地位，但“agent 控制的写入”这一来源条件将其排除在 agent memory 的操作对象之外（附录 B-9）。
**写入的两种物理形态**。增量写入在结构上分两支：**原位修改**（对既有权重做定向编辑——ROME、MEMIT、MEND、AlphaEdit 一脉；或全参数/继续训练）与**附加参数模块**（冻结主干之外挂载 Δθ——LoRA、adapter、辅助 LM；WISE、ELDER、K-Adapter 一脉）。后者具备模块化、可逆、可回滚的独立属性，与原位修改的纠缠属性形成结构对照。但须明确：按读取时刻判据，附加模块的生效位置仍在权重——Δθ 参与前向计算——故两支同属 parametric 载体，此划分是写入物理形态的划分，非载体划分。
**地址性是一个程度谱，且在写入与删除两个方向不对称**：
- **定位发现的证据与争议**。Geva et al.（2021）提出 Transformer FFN 层在功能上近似 key-value memory——中间神经元匹配输入模式，输出向量近似指向词汇语义分布；Dai et al.（2021）的知识神经元与 Meng et al.（2022, ROME）的因果追踪将这一方向推向事实级定位。但 Hase et al.（2023）的实验表明，**因果追踪的定位结论与编辑有效性之间缺乏稳定对应**——定位结果不能预测哪个 MLP 层是最佳编辑位置，且 denoising 干预与 counterfactual 编辑的因果结论互不一致。定位在统计意义上存在，其操作有效性无保证。
- **写入方向：近似可定位**。知识编辑方法已实现单事实定向写入，在 CounterFact、zsRE、KnowEdit 等基准上可测；但定向是近似的、有牵连效应的、随编辑次数退化的。
- **删除方向：近不可定向**。与写入不对称，“从权重中抹除特定事实而不伤及其他”没有稳定操作子；只有覆盖或重训。灾难性遗忘自联结主义时期即是该载体的核心议题，知识编辑近年发展出独立评测体系（zsRE、CounterFact、KnowEdit、Lifelong-M 一脉），是一个完整的活跃母学科。
### 4.3 写入通道：重开梯度
冻结关闭了梯度通道；parametric 的写入是有代价地重开它。按写入的空间范围与精度，存在从粗（全参数更新，与存量知识全面相互干扰）到细（低秩增量、定向编辑）的连续谱。该谱系的展开属 parametric 内部的设计问题，本框架作为对照载体仅记录其存在（附录 B-10）。
### 4.4 成本结构与“买断制”的适用域
**成本结构与 token 对称反转：写贵，读免费。** 写入是离线训练（GPU 时、数据管线、回归评测）；读取即普通推理，零额外开销，写入成本被读取次数摊薄。parametric 是**买断制**的记忆——但该表述仅对**静态知识、低频变化、高频读取**的场景成立。agent memory 的核心场景恰是持续经验积累，此时顺序编辑的叠加退化使成本随编辑次数超线性增长：买断制的正确表述是**对静态知识适用、对持续增量受限**。
### 4.5 记忆与能力的不可分离性
读取端没有操作，意味着不存在“使用记忆”的可辨识时刻。由此产生一个构成性后果：**parametric 记忆的贡献无法与模型固有能力相分离**——答对时没有任何手段区分“因为它记得”与“因为它会推理”。评测上只能测编辑前后的行为差异，不存在“检索质量”这样的独立环节。
这一不可分离性同时波及预训练知识的记忆地位：预训练知识与能力同样不可分离，故“预训练知识本身就是 parametric 记忆”与“parametric 记忆的记忆地位被不可分离性削弱”只能同时以弱化形式成立。本框架的统一表述：parametric 记忆的“记忆”地位是**程度问题而非本体问题**——行为上可辨识的记忆效应（写入后行为改变）可测，概念上记忆与推理的边界在权重层面不存在。这一张力是载体的本质特征而非表述缺陷：它同时解释了 parametric memory 的工程可验性（编辑改变行为）与概念尴尬性（何为记忆、何为能力）。
### 4.6 失败模式
灾难性遗忘（写入损伤存量）、编辑牵连效应（改了事实而关联推理不跟随）、顺序编辑叠加退化（每次编辑污染上次）。所有失败均不可见——湮没于权重深处，无法归因到任何可指认位置。

## §5 latent 载体（对照载体）
### 5.1 KV cache 的机制回顾与语义升格
自回归生成中，第 t 个 token 依赖全部前文；若每步重算前文各层的 K/V 投影，总计算量为平方级重复。KV cache 的工程解法：每层 K/V 只算一次、存下复用，将复杂度从二次降为线性。它因此是推理系统的标准组件。
latent memory 的核心洞察是换一个视角：**KV cache 里存的是模型对前文的处理结果**——每层 K/V 编码了前文 token 在该层注意力下的角色。丢弃它们，下次要重新计算“理解”；保留它们，就是保留“理解”本身。
近年有三组独立证据表明 KV 状态已脱离“缓存”的原始语义（所引安全文献的核验状态见附录 C）：
1. **语义承载**。KV 状态是模型对上下文内部理解的压缩编码——模型可直接消费、人类不可读，即 **Transformer 的原生记忆格式**。
2. **可操纵性**。Cartridges、LLMSteer、PASTA 等工作证明可直接编辑 KV 状态以操纵模型行为——对“缓存”执行记忆操纵。
3. **安全边界化**。共享推理环境的前缀缓存复用产生真实的攻击面——跨请求时序侧信道、缓存投毒——多租户部署须以作用域隔离管理 KV 状态。当某个对象需要被隔离、授权、按作用域管理时，它在系统中已承担记忆的角色（§1.3 治理检测器的直接适用）。
### 5.2 定义与注入点
> **定义（latent 记忆）**。将前向计算的中间产物以张量形式持久化，并在后续前向计算中直接注入复用，跳过“从 token 重新计算”的环节。
注入点覆盖前向计算的三个阶段：KV 张量拼接（attention 层入口，主流形态）、hidden states 拼接（层间）、连续向量作为前缀嵌入（embedding 层，即 soft tokens / continuous prompt）。与 token 的根本区别：**token 让模型重新理解一遍文字；latent 直接保存并复用模型上次理解的结果**。
### 5.3 生命周期与记忆地位
KV 状态在机制上**始终满足 §1.1 判据**：请求内 decode 的每一步都复用此前前向的 KV——信息已在前向之间存活，只是复用半径限于本请求、信息来源限于本请求前文，工程语境因此称之为“缓存”。跨请求持久化与复用改变的不是“是否为记忆”，而是三个工程参数：**复用半径**（本请求→跨请求/跨会话）、**信息来源**（本请求前文→历史请求内容）、**治理地位**（瞬态→进入威胁模型与存储预算）。“单请求内是优化、跨请求是记忆”的日常二分因此是**治理语义**而非本体语义；本框架的表述是：KV cache 从机制上就是（短程）记忆的载体形态，生命周期决定的是它的记忆半径与治理要求。
基础设施侧的演进与该判断同向：KV 持久化已形成 GPU→CPU offload→SSD→对象存储的层级，商业存储厂商提供 KV 专用存储系统，推理框架以内容哈希为键实现跨请求前缀复用，多 agent 工作流出现两阶段协议（第一阶段处理初始 prompt 并保存 cache，第二阶段加载 cache 续推）——KV 状态已被当作**可复用数据**而非瞬态计算副产物对待。压缩、剪枝、选择等深化路线属 latent 内部的设计分化，本框架仅记录其存在（附录 B-10）。
### 5.4 存储成本：形态对称的算例
fp16 下每 token 的 KV 体积为 2 × n_layers × n_kv_heads × d_head × 2 字节：
| 模型 | 配置 | 体积/token | 100K token 总量 |
|---|---|---|---|
| Llama-2-7B | MHA，32 层 | ≈ 512 KB | ≈ 51 GB |
| Llama-3-8B | GQA，8 KV 头 | ≈ 128 KB | ≈ 12.8 GB |
| Llama-3-8B + 8× 压缩 | 量化 / 逐层低秩（保留率可低至 12% 或更低） | ≈ 16 KB | ≈ 1.6 GB |
同一 100K token 的文本本体约 0.4 MB——未压缩形态相差约 4.5 个数量级，8× 压缩后缩至约 3.6 个数量级。两端对称陈述：**存储侧**，“存极重”仅在未压缩形态下绝对成立，压缩技术持续收窄量级差；**读取侧**，“读近零”精确说是“免重新 prefill”，注入后与查询的注意力交互成本与 token 注入同级（§6.1）。latent 的真实读取优势是**免 prefill**——对长上下文场景显著，对短上下文不显著。综合成本结构：**写即计算（prefill 副产品），读免 prefill，存重且持续**——三类载体中唯一为“保存”本身持续付费的形态。
### 5.5 性质：含条件攻击面
**不可回读**：张量对人不可读，从 KV 解码文本属于重新生成而非保真回读。**版本绑定**：绑定特定权重与推理配置（量化方案、位置编码实现、模型版本任一改变即作废）——与 parametric 更新构成结构性冲突。**坐标可寻址**：KV 按（层，头，位置）组织，可做定点张量操作——这种精细度在 token 与 parametric 处无对应物。
**时间维度的对称表述**：三类载体在事件时间表示上均无内在通道，均需系统层设计——token 的时间戳可由系统写入文本，latent 的时间元数据同样可由系统附带并按序拼接，二者处境对称。parametric 的特殊性是程度性的：梯度更新虽有时间顺序，但收敛后顺序效应湮灭为不可读的动力学痕迹，系统层补救手段也最少。
**条件攻击面**。独占部署下，latent 与 parametric 一样不存在推理期注入等价物；但共享推理基础设施中，前缀缓存与 KV 复用使 KV 状态成为攻击面：跨请求时序侧信道可窃取其他请求的输入内容（InputSnatch 一脉）、缓存投毒可操纵后续共享该前缀的请求行为、多租户部署须以作用域隔离管理 KV 状态。因此 latent 的攻击面是**部署条件性的**——单租户独占部署无此暴露；共享前缀缓存场景暴露真实存在。“黑箱性带来内生隐私保护”的主张必须限定：黑箱性构成对**人工检视**的遮挡，不构成对**侧信道**的防御——二者是不同威胁模型下的不同属性，同一文档中不可混用。
**缺席的失败模式补全**：跨会话 KV 拼接引入分布偏移（位置编码错位、注意力分布失配），是 latent 最现实的失败模式之一；压缩失真的记忆没有页面可翻开来检查它错成了什么样子。
### 5.6 内部谱系的存在性
latent 内部已形成一个按“latent 状态的**来源**”划分的三分谱系，作为存在性事实记录（其展开属后续任务，附录 B-10）：
- **生成型**：辅助模块合成全新 latent 表示并注入——AutoCompressor（长文档压缩为 summary 向量）、MemoRAG、CARE、MemoryLLM/M+（模型内嵌专用 memory token，M+ 扩展为跨层长期记忆）、LM2（逐层 latent memory slot）、Titans（在线更新的压缩权重在推理时产生 latent 向量）、MemGen（LoRA 对动态决定注入位置与 latent 内容）；
- **复用型**：直接复用模型自身的原始 KV，不做变换——Memorizing Transformers（显式存储历史 KV 并做 KNN 检索）、LONGMEM（SideNet 将历史 KV 作为持久记忆库）；认知科学中 Gershman 等人对生物记忆的 key-value 抽象与该型高度对应；
- **变换型**：对已有 latent 做选择、聚合、压缩或重构——Scissorhands、SnapKV（head-wise 投票聚合）、PyramidKV（跨层预算重分配）、SirLLM、Memory3（只存关键注意力 KV 对）、RazorAttention（补偿 token）、H2O（逐出策略）。
一处须防范的表述滑移：该谱系的通用属性表（写入成本、读取语义）以生成型形态写就，而复用型的写入是 prefill 副产品（近零成本）、变换型的写入是选择与压缩——三个亚类共享同一张属性表时会系统性失真。本章按 §1.2 纪律不展开，仅指明该失真风险的存在。

## §6 边界与判例
### 6.1 裸上下文窗口：token 内容跑在 latent 载体上
**裸上下文窗口本身，就是 token 形态的内容跑在 latent 载体上的实现**：每轮输入的 token 序列进入模型后立即被转写为 KV cache（latent 形态）参与计算。token 记忆与 latent 记忆是**同一物理对象的两个侧面**——前者问“往窗口里注入什么内容”（内容侧），后者问“如何持久化、压缩、复用窗口的计算态”（载体侧）。两个推论：token 记忆的读成本隐含 latent 载体的 prefill 计算成本（成本轴上两载体交汇，非三分）；任何 token 注入自动获得一个 latent 副本（多载体并存的最小形态，§7.4）。
### 6.2 判例表
按 §2.3 判据（读取时刻的内容生效位置为准）：
| 系统 | 写入技术 | 读取时刻载体 | 归类 | 判例意义 |
|---|---|---|---|---|
| Mem0、Letta（MemGPT）、Zep、MemoryBank、A-MEM | LLM 抽取 | token 注入 | **token** | 标准形态 |
| HippoRAG / AriGraph | 图结构索引构建 | token 注入 | **token** | 图是组织拓扑与检索机制，内容仍以 token 生效 |
| 系统内嵌的向量索引 | embedding 化 | **从不进入前向计算** | **不是 latent** | latent 要求“以激活形态进入计算”；仅用于检索匹配的向量不满足——载体判据的精确化（§1.1）；亦即“latent ≠ RAG”的判据化表述 |
| WISE 类（LoRA 银行 + 路由） | LoRA 追加 + router | Δθ 参与前向生效 | **parametric** | 模仿外部存储的追加结构，生效位置在权重 |
| MemGen 类 | RL + LoRA | latent token 以 KV 形态进入计算 | **latent** | 写入动用 parametric 技术、读取在激活空间——读取时刻为准 |
| 为用户语料预填充后跨会话复用的 KV | 一次预填充 | 张量拼接 | **latent** | latent 最纯粹的产品化形态 |
| M+ 类 | 协同训练的 latent memory tokens + 检索器 | 检索出的 latent token 以激活形态进入计算 | **latent** | 内容在激活空间、寻址机制是 token 级检索——内容与机制的又一分化实例 |
| LMLM / HierMemLM 类 | 预训练写入参数化检索头，知识留外部 token 库 | 机制位置 = parametric；内容位置 = token | **判据分歧判例：本框架判 token（机制辅助）** | 两套判据的最小分歧案例：按机制位置归类为 parametric、按内容位置归类为 token；判据选择显式化，因其直接改变占比统计（§8.1） |
| RAG（外部静态语料） | 无写入 | token 注入 | **token 载体形态** | 载体轴**无法**区分它与 token 记忆——区分落在“检索对象的来源”上，属来源轴（B-9）；此判例标定本轴判别力的边界 |
| Voyager / AWM 类技能库 | 代码与工作流生成 | token 注入后触发工具执行 | **token（程序性）** | 引入内容功能分化：读取后不是被理解而是被执行（§3.2） |

## §7 载体的对比
### 7.1 总表
| 维度 | token | parametric | latent |
|---|---|---|---|
| 物理位置 | 输入序列（离散符号） | 模型权重（原位或附加 Δθ） | 激活空间（连续张量） |
| 写入通道 | 文本操作（无梯度） | 重开被冻结关闭的梯度通道 | 前向计算的副产品（复用型）或编码前向（生成型） |
| 读取 | 显式：检索 + 拼接 | 隐式：与推理无边界 | 张量拼接（免 prefill） |
| 记忆与计算的关系 | 外置：读取后仍需理解（陈述性）/ 执行（程序性） | 无界：使用时刻不可辨识 | 内置：读取即计算态 |
| 与内化知识的融合通道 | 经输入编码注入，融合深度有经验上限 | 本身即内化 | 激活态直接叠加进注意力 |
| 成本位置 | 读端（逐次计费，重复前缀可摊销） | 写端（静态知识买断，持续增量超线性） | 存端（压缩收窄量级差，免 prefill 的读取优势对长上下文显著） |
| 存储介质与基础设施 | 任意外部介质（文件/库/向量库） | checkpoint、adapter 权重 | KV 存储层级（GPU→CPU→SSD→对象存储），专用 KV 存储产品 |
| 信息形态 | 离散、可回读 | 弥散 | 连续、不可回读 |
| 地址性与定向操作 | 天然可寻址，文本操作可定向编辑/删除 | 写入方向近似可定位（有争议），删除方向近不可定向 | 坐标可寻址，可做定点张量操作 |
| 时间的事件表示 | 无内在通道，系统层设计 | 顺序效应湮灭，系统层补救最少 | 无内在通道，系统层设计 |
| 与模型的解耦度 | 解耦：记忆宿主在外部，独立存续 | 同一：记忆即模型本体 | 版本绑定：有效性系于特定权重与推理配置 |
| 失败可见性 | 可归因到条目 | 湮没于权重 | 湮没于张量 |
| 推理期攻击面 | 注入攻击面（外部可控文本直接进入前向） | 无此暴露面（风险在训练/分发环节） | **条件暴露**：独占部署无；共享前缀缓存/多租户场景存在侧信道与投毒面（§5.5） |
| 设计自由度 | 相对当前工程实践最显著（部分源于分类粒度） | 受优化动力学约束 | 受张量几何约束 |
| 代表 | Mem0、Letta、Zep、HippoRAG | ROME、MEMIT、WISE、ELDER、AlphaEdit | 前缀缓存谱系、MemGen、MemoryLLM/M+ |
四行需正文补强。**记忆与计算的关系**是最深一行：token 的记忆在计算之外，latent 的记忆在计算之内，parametric 的记忆与计算无边界；该行同时决定三者的评测形态——token 可测检索质量这个独立环节，latent 可测压缩与复用的系统指标，parametric 只能测编辑前后的行为差异。**融合通道行**把“理解深度上限”从失败模式提升为结构属性，是压缩度与内容功能两根子轴的物理动机。**地址性行**统摄定向编辑与遗忘的物理基础：可归因失败、可定向删除、可版本管理这些工程性质，全部是地址性的下游。**设计自由度行**回答本章与后续章节的接口：parametric 与 latent 的内部主要是物理约束下的工程优化，token 的内部是组织学问题——后续章节长在 token 里，既是占比问题，更是唯有它拥有需要专门分析框架的设计空间。
### 7.2 三种经济学
**每一个记忆设计决策，本质都是在选择把成本放在哪里**：token 放读端（其内部一切设计——压缩、组织——都在与逐次付费搏斗，缓存可部分摊销）；parametric 放写端（写入必须批量、离线、充分评测；持续增量场景成本超线性）；latent 放存端（其内部设计——淘汰、压缩——都在与保存持续烧钱搏斗，换取免 prefill 的读取优势）。三种经济学并非严格正交（§6.1 揭示 token 与 latent 在 prefill 成本上交汇），但作为透镜仍有价值：token 内部的各种分化，骨子里是读写成本的再分配。
### 7.3 可通约性
三类载体当前评测协议高度分离：多轮对话召回（token）vs 编辑三指标（parametric）vs 压缩比与长程检索（latent）；失败归因方式不同——同一现象“答错了”，在 token 处归因于检索，在 parametric 处归因于训练动力学，在 latent 处归因于张量几何；工程栈分离（检索生态 / 训练管线 / serving 引擎）。
但“三类之间不存在可通约性”的绝对表述不成立。**反证有二**：其一，混合系统是工程常态（§7.4），说明三类在系统层可组合；其二，端到端度量载体无关地存在——任务性能、总拥有成本、每比特有效记忆的延迟、记忆投毒鲁棒性。准确表述是：**三类载体当前缺乏通用评测协议与工程栈，形成三个母学科传统（信息检索 / 持续学习 / 推理系统），但在问题本体层存在部分共同度量衡**。“数据库索引、训练方法、虚拟内存不该同框”的类比亦须谨慎——learned index 与 KV cache 管理恰在系统社区被统一研究，跨学科融合正在发生。
### 7.4 混合形态：成本互补性、两种混合与控制变量
载体框架不排斥混合；混合是部署常态，且有**成本结构上的必然理由**。
**成本互补性推导**。三种经济学在生命周期各阶段互补：token 的写入/更新成本最低而读取逐次付费、受上下文预算约束；latent 的读取免 prefill 而检视性最差、存储持续付费；parametric 的读取零额外开销而写入最昂贵且不可逆（持续增量场景超线性）。任何需要同时满足“**高频更新**（token 擅长）+ **高密度消费**（latent 擅长）+ **长期巩固**（parametric 擅长）”三要求的记忆系统，在成本结构上必然走向混合。该推导是**条件性的**：三要求并存时混合是必然；单一要求占主导的系统可纯化——这同时是单载体研究纲领成立的成本论据。
**两种混合形态**。其一，**技术借用**（写入技术跨载体迁移）：MemGen 用 RL + LoRA（parametric 技术）生成 latent token，读取发生在激活空间；token 记忆语料蒸馏入权重是“token 写入喂给 parametric 写入”的双段式；LMLM 将检索机制参数化而知识留外部库。读取时刻判据使这类系统的归类不产生歧义——这正是 §1.2 两轴解耦的操作性收益：内容的管理可以在一处，生效可以在另一处。其二，**副本同存**（同一信息的多载体冗余）：最小的混合是自动的——任何 token 注入即获得其 latent 副本（§6.1）；产品形态中可见三级冗余：会话日志（token）+ 定期微调摘要（parametric）+ 常驻前缀 KV（latent）。内容视图（操作轴的组织决策）与载体视图（各副本的生效位置）是两组独立设计。
**对本研究的意义：纯 token 研究纲领的边界条件**。混合是常态，纯化是方法。聚焦单一载体不损失框架有效性——载体轴恰恰把混合解析清楚之后，才使单载体的独立研究成为可能。但纯 token 研究的结论须声明三条适用前提，它们同时是实验设计中的控制变量：
1. **冻结基座**：若 parametric 更新与 token 记忆并行存在，模型行为既被记忆注入又被权重改变，token 记忆的可归因优势（失败定位到条目）被稀释，评测信号混杂；
2. **单一生效通道**：token 记忆的优化目标函数假设“效果经由注入产生”；若部署中存在常驻前缀 KV（latent 副本固化了部分记忆），检索优化的反馈信号被污染；
3. **版本稳定**：token 记忆相对 parametric / latent 的核心优势是可迁移（模型更换后记忆保留）；该优势在基座升级时需主动验证迁移有效性，而非默认成立。
三条不是纯化研究的缺陷，而是其诚实声明：token 级记忆的优化设计在上述控制变量下推进，混合部署下的结论外推作为独立问题留在接口层（附录 B-7）。

## §8 范围与取材
### 8.1 分类实在性的证据与偏倚声明
**主证据：学科结构**。三载体各自继承完整母学科——token 背后是信息检索与数据库传统（数十年检索研究、向量检索产业与 RAG 生态的全部积累）；parametric 背后是持续学习与知识编辑传统（灾难性遗忘自联结主义时期起即是核心议题，知识编辑有独立评测体系）；latent 背后是推理系统社区（serving 基础设施与 KV 管理的工程文献）。三个文献宇宙各有自己的会议、基准与综述谱系，彼此引用稀薄。
**偏倚声明**：该证据存在循环风险——先按载体分学科，再用学科分离证明载体是根本轴；且分类仓库的收录本身有选择偏倚（持续学习与知识编辑社区未必自我认同为"agent memory"，parametric 占比可能被系统性低估）。学科结构支撑的是“三个传统的分离是事实”，不直接支撑“分离在本体上是必然的”。此外，占比统计依赖判据选择：§6.2 的 LMLM 判例表明，机制位置判据会系统性抬高 parametric 占比——任何载体分布数字都应连同其判据声明一起引用。
**辅证据：数量分布的双向读法**。一份收录 199 篇 agent memory 论文的分类仓库（截至 2026 年 8 月）给出：token 约 72%，latent 约 16%，parametric 约 12%；混合形态的多数组合格近乎空白。同一数据有两个方向的读法：其一，token 载体的研究成熟度与工具链密度最高（门槛论据）；其二，载体轴的覆盖高度偏斜，混合形态是大量未开垦区域（空白论据）。两读法不矛盾——偏斜既是焦点所在也是盲区所在。单一来源、社区维护，作方向性参考。工程侧信号同向：可直接部署的记忆产品几乎清一色为 token 方案；latent 的工程化集中于推理引擎侧；parametric 的落地集中于特定场景的权重交付。
### 8.2 门槛与最优的区分
token 的多数地位有相当部分源于门槛：复用成熟检索栈、可回读、易调试、运营生态成熟。**多数不等于最优**——parametric 的读免费与 latent 的免 prefill 在各自适用场景中是 token 无法企及的结构优势；token 自身亦有结构性限制（融合深度上限、上下文预算、注入攻击面）。对 token 的选择是可通约性与工程现实性的选择，不是性能优越性的判断。
### 8.3 聚焦声明
本研究的对比分析聚焦 **token 载体**。parametric 与 latent 在本章作为分类学对照出现——其载体级结构（物理位置、成本位置、地址性、解耦度、失败可见性、条件攻击面）已在本章交付，其内部的设计分化不属本研究。聚焦的理由是四重实用主义，无一为结构必然性：
1. **研究能量分布**（§8.1）：token 载体占据当前研究能量与工程落地的绝对多数，是问题最密集处；
2. **设计空间的存在性**（§3.2）：唯有 token 载体拥有需要专门分析框架的开放设计空间——parametric 与 latent 的内部主要是物理约束下的工程优化，token 的内部是组织学问题；
3. **控制变量的清晰度**（§7.4）：单载体研究使优化目标函数、评测信号、失败归因三个环节都免于跨载体混杂——注意力与精力分配的考虑，在此转化为方法论上可辩护的控制变量声明；
4. **控制面角色**：在混合形态成为常态的部署中，token 载体承担检索、路由、冲突处理与审计接口，是记忆系统对外可观测、可控制的面——研究 token 即研究记忆栈的控制平面。但该论据须带一个限定：控制面角色**预设了其他载体的存在**——它论证的是“token 是理解整个记忆栈的入口”，不直接论证“token 是唯一值得研究的载体”；纯 token 结论向混合部署的外推仍受 §7.4 三条控制变量约束。
本章为后续章节留下接口（附录 B）：token 内部的分化至少包含存储引擎、信息压缩度、组织拓扑、陈述性/程序性内容功能等子轴；操作轴（生命周期算子分解）作为与载体正交的第二根分析轴整体移交；parametric 写入谱系与 latent 持久化/生成/变换谱系作为对照载体的内部分化问题；混合部署下的结论外推问题，同在接口清单中。
