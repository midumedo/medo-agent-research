## 1. 保留、可用、实际使用与改善是四个不同判断

### 1.1 从历史差异到未来行为

设一次请求开始时，当前输入为 `CurrentInput`，跨请求延续的全部相关状态为 `RetainedState`。在给定运行条件下，可以将行为和更新写成：

```text
Action ~ Policy(CurrentInput, RetainedState)
NextState = Update(RetainedState, Experience)
```

`Experience` 是本次运行可获得的输入、输出与反馈。这里没有假定 Policy 必须是神经网络，也没有假定 Update 必须训练参数。参数、文本记录、持久向量、选择器状态都可能成为 RetainedState 的组成；是否纳入环境中留下的结果，需要在研究范围中说明。

**命题：如果两段历史在当前输入和全部可用状态上没有留下任何区别，且运行过程与随机条件相同，系统就没有据此区别两段历史的资源。**

推导很直接：相同的条件交给相同过程，得到相同的输出分布。系统不能通过一个已经不存在、也没有从其他通道重新传入的差异作出区分。随机猜测可能偶然正确，但不会使系统可靠地区分那些没有可用线索的历史。

这个命题要求状态描述对所讨论问题足够完整。若外层路由保留了历史、工具能读回旧文件或当前输入直接给出了答案，就不能只把 LLM 的一个输入张量叫作“全部状态”，再据此推出系统无法利用过去。将某变量排除出研究范围，也不等于证明它在实际系统中没有作用。

### 1.2 四种判断各自需要什么

| 判断 | 要说明的内容 | 一个不足以替代它的观察 |
|---|---|---|
| 保留 | 先前信息的某种差异跨越指定边界仍存在 | 文件名还在，但内容已被覆盖或丢失 |
| 可用 | 当前系统存在发现、读取、恢复并消费该差异的可行路径 | 备份存在于当前系统无法访问的介质 |
| 实际使用 | 某次执行确实访问、输入或依赖相应状态 | 检索器返回条目，却在组装时被截掉 |
| 改善 | 在明确任务和对照下，相应结果优于所选基线 | 条目进入了输入，回答却更差 |

“实际使用”还要分操作事实与因果作用。日志可以证明读取发生，输入记录可以证明内容进入模型；但它们不单独证明输出依赖该内容。要判断因果贡献，至少需要合适的替换、移除或写入前后对照，并保持其他条件可比。对于随机系统，比较的是分布或重复测量，不是把两次不同回答直接归因于记忆。

因此，四项不是四个可以互相替代的指标。保留是后续使用的基础，可用路径让保留有机会影响任务；实际使用不保证正确，正确利用也不保证相对基线有增益。例如，一个任务本来就能被正确解决，加入记忆后同样正确，不能仅凭“读过记忆”宣称获得了质量提升。

### 1.3 Memory、context、cache 与冗余副本

本文把“跨指定边界保留先前信息，并存在后续利用路径”的状态纳入 memory 分析。这是研究使用的操作范围，不要求它在每次请求中都被读到，也不要求它唯一、永久或支持完整生命周期。

Context 描述当前计算可用的内容。历史记录被选入输入时，同时属于一次记忆使用和当前 context。Cache 描述一种派生与复用关系：保存某个可由其他状态构造的结果，以免重复计算。一个跨请求保存、被后续调用的 KV 工件，可以同时承担记忆利用和计算缓存的角色。

**增加备份不会取消记忆。** 假设一份记录保存某个历史事实，复制后两个副本都能由另一个恢复。变化是实例数、恢复条件和维护成本，不是该事实突然没有任何持久承载者。“删除某一副本会不会永远丢失信息”不能作为该副本是否参与记忆的唯一判据。

可再生性也有条件。文本、生成模型、版本、配置或构造程序缺失时，派生状态未必可被精确重建。应写明“从哪些仍存活的状态、用什么过程、以什么代价、恢复到何种精度”，而不是只给一个“可再生”标签。

**可继承的结果：** 保留关系、当前上下文、计算复用和副本地位可以分别判断。它们可以在同一对象上重合，不必先把对象分成互斥的 memory/cache/context 类别，才能研究实际机制。

## 2. 三形态的稳定判定依赖固定实现与接口契约

### 2.1 为什么不能只看物理形式或训练方式

文本、权重和 KV 最终都能编码为有限精度数字并保存在相同介质中。量化权重的取值离散，不会使它自动成为 token memory；一个向量经过梯度优化，也不自动说明它作为目标映射的系数被读取。

这里的“接口契约”指实际实现已经区分的参数、符号输入和状态输入角色：某个数值块被哪个消费者读取，以什么算子角色参与计算，以及跨研究边界保存的究竟是哪个对象。先固定这项实现事实，再判定 form。

任意计算重写不能用作临时改判工具。一个程序既可以被视为固定执行器的一段数据，也可以被视为任务映射本身；如果每次遇到边界案例就换一种描述，类别会随着说法变化。本文不追求在所有等价重写下保持不变的本体分类，而要求在同一实现与同一接口口径下得到可重复的判定。

### 2.2 本文采用的判定规则

固定目标模型、实际实现和一次使用事件后：

1. 持久状态作为所分析映射的系数、权重或参数增量参与计算，登记为 **parametric** 路径。
2. 持久符号内容经目标模型的离散符号输入路径使用，登记为 **token** 路径。
3. 持久状态作为非参数的数据表征，经向量、激活、KV 或相应状态接口使用，登记为 **latent** 路径。

“外部”相对于目标映射的参数角色，不是相对于机箱、进程或显存。常驻服务显存的 KV 可以是外部数据状态；从磁盘加载的 adapter 可以是参数。若研究目标换成记忆生成器或检索器，就应对那个模块另外登记参数与输入，不能把它的参数自动算作目标 LLM 的记忆内容。

这三条覆盖的是已声明接口范围中的机制。原始媒体、工具运行态、访问凭证、数据库程序、环境中的行动结果，都不必强行成为目标 LLM 的三种持久记忆工件。

### 2.3 典型边界可以直接判定

| 对象与实际使用 | 判定及理由 |
|---|---|
| 文本记录经过 tokenizer，进入模型的符号输入 | Token 路径；模型内部随即产生 embedding 与激活，是这次读取的计算过程 |
| 持久的连续 soft prompt 作为前缀状态输入 | Latent 路径；它可以在训练文献中被称为可训练参数，但此处按其实际输入角色登记 |
| LoRA 的 A、B 以 `Wx + B(Ax)` 改变目标层映射 | Parametric 路径；未合并或独立保存，不改变其作为映射系数的作用 |
| 某段文本的 K/V 被跨请求保存并直接复用 | 增加一个 latent 派生实例；源文本若仍在，仍是另一个实例 |
| 向量索引只负责选择文本，LLM 最终读返回文本 | 索引是选择过程的状态；内容使用走 token 路径，没有据此证明 LLM 直接读取索引向量 |
| 请求内临时生成、请求结束即丢弃的 KV | 当前跨请求范围中的执行状态；它没有自动成为独立的持久 latent 记忆 |
| 保存 JPEG 或音频，使用时临时编码为 embedding | 原始媒体是来源工件；发生了表征接口使用，但尚未保存一个跨请求 latent 工件 |
| 保存编码后的媒体表征，后续直接调用 | 在相关消费者的状态接口下登记持久 latent 实例，并记录编码器与兼容条件 |
| 代码被 LLM 阅读，或被外部运行器执行 | 前者是符号内容使用；后者是程序执行。执行结果回传后再按实际路径分析 |

[LoRA](index.md#source-lora) 与 [Prefix-Tuning](index.md#source-prefix-tuning) 给出了两种可以分开的机制：前者改变目标映射的参数增量，后者冻结主体并优化连续前缀。它们都可能使用优化，但优化这一共同点不能替代读取角色的区别。

量化码的判断同样依赖实际路径。若量化码用于恢复某个权重或 KV，其角色随恢复后的系数或数据状态分析；若码被当作词表符号，经模型的符号输入使用，则是另一条路径。不能以“都是整数”把两者合并。

### 2.4 多条使用路径不需要强求唯一归属

同一信息可以被复制或转换，形成多个工件；同一份代码也可以在一次被阅读、另一次被执行。判定的是具体实例的一次使用，而不是给整个系统永久贴一个标签。

一个优化过程若直接产生 K/V，结果可以按 latent 工件使用；如果另一实现用 LoRA 保存任务相关变化，结果按参数路径使用。这不由方案名称决定。[Cartridges](index.md#source-cartridges) 的具体 K/V 实现与其框架讨论的其他参数化方式，应据实际工件分别分析。

**可继承的结果：** 三形态可以稳定地区分机制，但稳定性来自固定实现与接口。写入时机、是否使用梯度、保存设备与读取角色是可以分别记录的事实；不需要让其中一个事实代理全部归类。

### 2.5 为什么主体权重固定，前缀或 KV 仍然能够被训练

设模型输出为 \(f_\theta(x;s)\)：\(\theta\) 是主体权重，\(x\) 是当前任务输入，\(s\) 是通过指定接口提供的连续状态。训练目标是让模型输出接近目标 \(y\)，误差记为 \(\mathcal L(f_\theta(x;s),y)\)。

冻结主体指不更新 \(\theta\)，但输出仍然是 \(s\) 的函数。只要这条计算路径可微，就能按链式法则计算：

$$
\nabla_s\mathcal L
=\left(\frac{\partial f_\theta}{\partial s}\right)^\top
\nabla_f\mathcal L.
$$

系统由此可以调整 \(s\)，同时保持 \(\theta\) 不变。误差的计算经过主体，并不等于主体权重接受了更新。Prefix-Tuning 和 Cartridges 的具体连续状态实现提供了这类机制实例，定位见 [index](index.md#source-prefix-tuning) 与 [Cartridges 条目](index.md#source-cartridges)。

与此对应，参数训练可以固定输入状态而更新 \(\theta\)。两者都使用优化，也都可以改变输出；区别在于优化改变了什么，以及更新结果在之后通过权重还是状态输入被使用。这里的可微性只说明可计算更新方向，不保证找到全局最优、有限状态足够表达目标，或训练外任务自动泛化。

<a id="external-adaptation"></a>
## 3. 固定规则加外部记录，足以构造持续的信息适应

### 3.1 一个不依赖 LLM 性能的构造

考虑一个规则始终不变的程序：

```text
收到 STORE(User, Secret)：
    在持久文本字段中保存 User 对应的 Secret。

收到 GET(User)：
    读取该字段并返回；字段不存在时返回“尚未提供”。
```

这里的 User 是用户标识，Secret 是此次经验提供的新暗号。两次请求之间保留文本字段，其他程序规则完全固定。新暗号没有从其他通道传入，之后的 GET 请求也不包含答案。

**命题：不改变消费者程序或主体模型参数，也能让完整系统获得并持续利用新的信息。**

证明分三步：

1. 写入前，对相同旧状态可能给出不同的新暗号。系统没有线索保证正确返回任意一个尚未提供的值。
2. STORE 把新差异写入持久字段，两段不同经历因此形成可区别状态。
3. GET 的固定读取规则把该差异带入输出。只要保存与读取正常，系统便能在以后请求中返回对应的新值。

改变的是记录，而不是消费者规则。这个构造足以反驳“没有主体参数变化，系统就不可能持续获得新信息”的普遍断言。它证明可实现性，不是声称所有外存系统都实现了正确写入和调用。

### 3.2 LLM agent 对应哪条机制

在一条典型 token 使用路径中：

```text
TextStore_next = Write(TextStore, Experience)
SelectedText = Select(TextStore_next, Query)
ModelInput = Assemble(CurrentInput, SelectedText)
Answer ~ Model_theta(ModelInput)
```

TextStore 是持久符号库；theta 在这段比较中固定。长期变化可以发生在库中，选择与组装将它变成后续输入差异。模型能够正确利用相应内容时，完整 agent 能回答的问题或采取的行动便可以随历史改变。

相应测量应落在实际链条：信息是否写对，能保留多久，能否被选到，进入输入后能否正确消费。新暗号程序的精确保证不能直接迁移为任意 LLM 的可靠性保证。构造与真实实现的差别已经确定在这些环节，无需再把可实现性退回为未定。

这也解释了 token memory 的一个结构性特点：**长期保留与当次使用可以分别变化。** 增加库内容不自动增加单次输入；保持记录不变而改变选择策略，可以改变可用信息；在没有读取路径的位置追加记录，则未必改变当前任务行为。存储保留、读取机会与行为效果应分别比较。

### 3.3 获得信息、形成规则与改变参数不是同一个结果

上述构造获得的是指定新值的后续调用能力。它没有证明系统能归纳规律、解决组合性新任务、把经验迁移到新领域，或在移除全部外部依赖后仍保留能力。

这些目标可以有自己的可检验标准，但不能互相充当定义：

- 参数值改变，说明发生了参数更新；不单独证明任务能力改善。
- 外部状态改变并影响未来行为，说明存在系统级持续适应；不单独证明规则泛化。
- 保存一条规则文本，说明该表示存在；不单独证明消费者能执行或迁移它。
- 新任务成功，需要排除答案泄漏、原有能力和其他信息来源，才能判断新增经验的贡献。

若某研究将 learning 专指参数更新，暗号程序不属于该窄义 learning；名称不改变已经构造出的信息保持与后续调用。

### 3.4 组件消融能回答依赖，不能自动裁决“真学习”

移除暗号字段后，GET 失败，说明成功依赖该状态。这是一个有效的组件依赖结果。它没有证明完整系统在保留组件时未获得信息；原研究对象如果包含外部存储，移除它就已经改变系统。

反过来，移除原记录后仍成功，也不自动证明能力进入主体权重：摘要、KV、副本、其他工具或预训练知识仍可能提供答案。

因此，组件消融应配合所问问题解释：

- 问“完整 agent 能否跨请求利用新信息”，保留其记忆组件并比较写入前后。
- 问“成功依赖哪个组件”，移除或替换该组件，记录其他可达路径。
- 问“是否已内化到主体参数”，固定主体边界，切断相关外部来源并控制其他解释。

三个问题分别有明确结果，不需要合成一个脱离系统边界的“有没有真正记住”。

<a id="attention-and-capability"></a>
## 4. 局部 attention 限制怎样成立，为什么不等于整条通道的能力上限

### 4.1 固定内容打分时的直接推导

考虑一个 attention head 的某个查询位置。先固定该位置的 query、所有内容 key/value、相对内容可见性及位置处理，并假定至少有一个可见内容位置。对可见位置采用有限实数打分，以标准 softmax 计算；用 `s_j` 表示对内容位置 j 的打分，用 `r_k` 表示新增前缀位置 k 的打分。定义：

```text
ContentMass = sum_j exp(s_j)
PrefixMass  = sum_k exp(r_k)
```

没有前缀时，内容位置 j 的权重为：

```text
OldWeight_j = exp(s_j) / ContentMass
```

增加前缀、但没有改变原内容打分时：

```text
NewWeight_j = exp(s_j) / (ContentMass + PrefixMass)
```

因此，对任意两个仍可见的内容位置 j、l：

```text
NewWeight_j / NewWeight_l
= exp(s_j - s_l)
= OldWeight_j / OldWeight_l
```

这证明的是：**在这次同层计算且内容打分固定的条件下，增加前缀项不改变原内容位置之间的相对权重。** 它改变共同归一化分母，并让一部分权重流向前缀。

相应 head 输出可写成：

```text
NewOutput
= ContentMass / (ContentMass + PrefixMass) * OldOutput
  + sum_k exp(r_k) / (ContentMass + PrefixMass) * PrefixValue_k
```

这明确给出该接口能做什么：缩放原内容输出，再加入前缀 value 的加权贡献。单个前缀与多个前缀的可用 value 子空间也不同，不能一律写成对任何输入都完全相同的偏置数值。

这一代数关系对应 [Petrov、Torr、Bibi 的限制分析](index.md#source-petrov-limits)中的局部机制。本文只使用上述条件化推导，不把摘要中的简短能力表述扩大成所有 token memory 系统的定理。

### 4.2 不能省掉的条件

推导的关键是原内容打分没有变化。若添加前缀同时改变了内容位置编码、掩码、输入表征或其他运算，必须重新判断这个前提。

即使本层满足条件，前缀也可能改变本层输出；输出经过后续变换后，又会改变下一层的 query/key。此时下一层的 `s_j` 已经不同，不能把本层的比例不变继续原样套用。该论文 §6 明确讨论了后续层效应。

因此，局部结论不直接推出以下全称命题：整个深层模型的 attention 模式不变；任何新输入输出映射都不可能；动态检索与工具交互等价于一个固定前缀；所有 token memory 只能复现预训练行为。

要证明具体模型在某类任务上的上限，还需给出目标函数类、可变输入、允许交互、深度及全部消费者的条件，并证明该上限穿过这些计算仍成立。

### 4.3 构造性存在结果的正确量词

[Petrov、Torr、Bibi 的通用逼近工作](index.md#source-petrov-universal)研究了另一种量词：存在专门构造、随后固定的模型权重，通过可变的连续前缀逼近规定函数类；前缀长度可以增长。该文使用的“预训练”参数在构造中固定，并不意味着任取一个实际预训练 LLM 都满足结论。

可把其用于本问题的逻辑形状简写为：

```text
存在合适的固定模型；
对规定函数类中的目标和所需精度，存在相应连续前缀。
```

不能交换成：

```text
对任意现成模型、任意任务，都存在一个短离散 prompt，
而且可从少量经验有效学得，并在新样本上可靠泛化。
```

前一个存在性结果足以阻止仅凭“冻结”或“使用前缀”推出统一的能力不可能；它不证明外部文本 memory 已经获得任意技能。这里无需把前缀长度界、构造层数或全部证明移植为 memory 分类的一部分。

**可继承的结果：** 接口会形成具体结构约束；约束必须连同固定变量和量词使用。某个真实模型可能有很强的任务上限，但不能仅由 form 名称获得这个上限。

<a id="finite-capacity"></a>
## 5. 有限容量限制可区别状态，不推出每次写入必然干扰

### 5.1 精确容量论证

假设一个系统用于保留历史信息的全部可用状态总共只有 B bit。固定解码过程，不允许查询、环境或未计入的辅助状态重新提供目标事实。要求它精确保存 m 个任意独立二值事实，之后按索引准确取回任意一项。

**命题：在零错误恢复要求下，若 m > B，这项任务不可能对所有事实组合都成功。**

推导如下：

1. m 个任意二值事实有 `2^m` 种组合。
2. B bit 状态最多有 `2^B` 种可区别取值。
3. 若 m > B，至少两个不同事实组合落入同一个保留状态。
4. 这两个组合至少在一个索引上取值不同。给出该索引时，系统得到相同查询和相同状态，不能保证返回两个不同的正确答案。

随机性不能在零错误、所有组合准确恢复的要求下弥补信息缺口。若允许错误、只问部分任务、事实可压缩或查询包含额外线索，证明条件就变了，需要针对新的失真或任务要求讨论。

### 5.2 为什么推不出逐写必干扰

上界说明某些足够大的任意负载最终不可无损容纳；它没有说明当前状态已满，更没有说明任意一次写入都必须破坏旧行为。

反例可以直接构造：在预留的独立存储槽中保存一个新值，读取旧值仍只访问各自旧槽。只要容量尚足，新增写入不需要覆盖旧内容。元数据同样计入总容量即可，这不违反容量上界。

实际系统也可能在容量尚未耗尽时已经干扰：共享参数更新改变旧输入的输出，检索排序变化使旧条目不再命中，组装预算被新内容挤占。这些是具体的表示、更新和选择机制造成的失败，不是单从 B bit 上界推出的必然事件。

因此至少要区分：

- 状态最多容纳多少可区别信息。
- 当前编码怎样使用这些状态。
- 更新怎样改变已占用部分。
- 检索与消费怎样让可保留的信息变得不可用。
- 所选任务怎样把这些变化映射成成功或失败。

这些区分用于定位一个具体干扰，不是要求建立另一套分类体系。

### 5.3 可扩展存储与固定参数的比较条件

如果外部库可以增加介质容量，而参数方案的大小被固定，外部库确实更容易继续增加保留空间。但这项比较同时改变了资源约束。参数系统若允许添加模块，也能增加状态；外部库若有固定预算，同样需要覆盖、压缩或拒绝新增内容。

“外部追加”和“参数更新”可以有不同干扰风险，必须从相应写入、隔离、检索和消费机制说明。规模化写入没有损伤已测旧任务，不等于违反有限容量；少量写入损伤旧任务，也不证明容量已经耗尽。

**可继承的结果：** 容量比较应明确总状态、精度、可扩展资源、目标负载、恢复要求和辅助信息。扩大磁盘直接改善保留量的资源上限，不自动改善能找到多少、找到后能正确使用多少。

<a id="cost-and-reuse"></a>
## 6. Text、KV 与参数的成本怎样从机制推出

### 6.1 Prefill 和解码承担不同计算

Prefill 指对已给定输入前缀构造相应模型状态的计算。在普通稠密全注意力、模型维度固定的条件下，长度 L 的前缀有随 `L^2` 增长的注意力交互部分，同时仍有随 L 增长的投影和逐位置计算。不能把整个模型的每个算子都写成二次复杂度。

KV cache 保存已计算位置的 key/value，使后续解码不必反复重算它们。为精确计数，设后续有 T 次新增查询，第 i 次查询面对 L+i 个历史位置，i 从 0 到 T−1；这里只计历史位置，不计当前 query 位置自身。逐步读取历史的交互总量为：

```text
L*T + T*(T-1)/2
```

这是对 L 到 L+T−1 的 T 个历史长度求和的结果。若每步还关注当前位置自身，再增加 T 项；首个输出的预测若已由 prefill 完成，则生成 token 数与新增查询次数也应分别登记。这些计数差异不改变普通稠密实现中的 O(LT+T²) 量级。缓存避免重算历史表征，不使任意长自回归生成一概变成线性成本。窗口、稀疏机制和不同架构还会改变这项计算。

Embedding 位输入的连续前缀仍需通过后续层；可直接使用的各层 KV 才可能绕过其源内容的相应编码。Latent 这个名称本身不保证“免全部 prefill”。

复杂度也不直接给出墙钟时延。硬件、批量、带宽、布局和计算内核决定实际比例；省运算、少占内存、少传数据和降低延迟是不同可测结果。

### 6.2 一个明确分母的 KV 体积算例

假设单条序列，保存所有相关层、所有位置的 K/V，不使用压缩，布局额外费用暂不计入：

```text
KVBytes
= 2 * Layers * KVHeads * HeadDim * BytesPerValue * Positions
```

因子 2 对应 key 和 value；KVHeads 是实际保存的 KV 头数，不必等于 query 头数。以 32 层、32 个 KV 头、每头 128 维、每数值 2 字节为例，每位置是 524,288 字节，即 512 KiB；100,000 个位置约为 48.83 GiB。

若另假设源文本平均每 token 4 字节，同样 100,000 个 token 的文本为约 0.4 MB，二者字节比为 131,072。文本估算随语言、编码与序列化方式变化；KV 体积随头数、数值精度、保存范围与压缩变化。这个算例说明特定完整 KV 可能比源文本大很多，不构成所有 latent 工件的数量级定律。

比较压缩也要保留分母。相对完整 KV 缩小若干倍，不等于相对源文本达到同样比例；不同模型、任务与质量条件的数字不能无条件相乘。构造一个更小的工件，还可能增加写入计算或改变可用信息，需另计。

### 6.3 重复前缀的 KV 复用经济条件

固定同一前缀与相关兼容条件，在同一观察时段使用 n 次。比较两条达到相同任务效果的实际路径：每次从文本构造，或首次构造后保存并复用。

定义 `Encode` 为一次完整构造成本；`Common` 为 n 次使用中确实相同的累计后续成本。`Keep`、`Load`、`Rebuild`、`Manage` 均为该时段中相对于重算路径新增的累计费用，分别覆盖写入与保留、装载与传输、失效重建、选择与同步管理。只有可换算到同一单位时才求和。

```text
Cost_recompute = n * Encode + Common

Cost_reuse = Encode + Common + Keep + Load + Rebuild + Manage
```

于是，在这项明确的成本分解下，复用更便宜恰好要求：

```text
(n - 1) * Encode > Keep + Load + Rebuild + Manage
```

首次构造两边本来都需要；缓存失效后额外发生的构造进入 Rebuild，不能从费用中消失。Load 是累计装载费用，不是漏乘 n 的单次量。各项可能随 n、命中率和保存时间增长，因此不能不加条件地把右侧当成固定常数，推出一个统一复用次数阈值。

例如，在无失效的给定时段，Encode 为 10 个统一成本单位，新增费用累计为 15：使用三次节省 20，复用更便宜；使用两次只节省 10，便不够。这里只是代入同一公式的算例，不是任何产品的费用报告。

该推导给出的判断已经明确：较多有效复用、较贵编码与较低新增费用支持缓存；频繁重建、较重装载与较长驻留可能抵消节省。实际数值需要测量，但机制条件不必等到获得某个产品数字后才成立。若更关心时延和内存上限，就保留多维可行性比较，不用单一货币公式替代。

### 6.4 参数的“读取无额外成本”要相对基线解释

若仅将固定 dense 计算图中的权重 W 替换为 W'，推理结构可以保持不变。相对这个基线，知识改变未必增加前向算子；它不表示模型读取和运行本身免费，也不表示写入、评测、检查点、加载与多实例部署免费。

LoRA 可以合并为等效权重，未合并实现则可能额外计算低秩分支。是否增加时延取决于实现、合并、批处理与路由，不能仅因其属于 parametric 就宣布读取成本为零。

参数写入也不等于只能对目标参数执行梯度下降。直接赋值、闭式编辑或合并都可能改变系数；[ROME](index.md#source-rome) 的目标权重更新与目标 value 求取分别涉及闭式形式和优化，不能把“最终写回不是梯度步”扩大成全流程无梯度。[AlphaEdit](index.md#source-alphaedit) 的局部约束也不能自动成为全模型旧知识不变的保证。

若只比较初始写入和重复读取，且 token 的每次读取确实比参数方案贵，两方案交点为：

```text
ReadCount_cross
= (Write_param - Write_token) / (Read_token - Read_param)
```

正的摊销门槛还要求参数写入更贵；若分母不正，就没有由“重复读取节省”产生的同类门槛。持续更新、失效重建、质量变化与容量限制会改变模型，不能只是默认为一个额外常数。

**可继承的结果：** Form 提供成本结构线索，决策落在具体路径。文本保存与 KV 复用可以构成合理分工；参数写入也可能在特定负载下值得。结论分别由同口径账单与任务要求支持，不由固定的 form 优劣次序支持。

<a id="instances-and-revocation"></a>
## 7. 信息、实例、任务等价与删除兼容怎样分别完成判断

### 7.1 “同一信息”需要说明相同到什么程度

一个历史事件可以生成原始日志、摘要、索引、KV 和参数更新。共同来源不保证这些工件具有相同内容，更不保证可逆转换。

| 所说的关系 | 实际要求 |
|---|---|
| 完整复制 | 在所声明内容口径下保持一致 |
| 事实保留 | 指定事实在结果中仍可识别或恢复，不要求保留全部源内容 |
| 可逆重建 | 给定辅助条件，可以恢复目标精度下的源实例 |
| 任务等价 | 在规定任务与质量标准下，两个工件产生等价或允许误差内的效果 |
| 共同来源 | 结果由该来源参与构造；不单独承诺上述任何等价 |

任务等价必须固定消费者、问题集合或分布、评价标准与允许误差。对摘要问答足够的表示，未必能恢复原文；不能恢复原文的工件，也未必在指定任务上更差。压缩可以突出有限消费者能利用的相关内容，但也可能丢失以后才重要的细节。信息减少与特定任务表现下降不是同一命题。

### 7.2 何时产生独立的持久实例

文本在一次前向中转成 embedding 与 KV，是读取过程的一部分。只有相应状态跨所选边界保存、并具备后续利用关系时，才登记一个持久派生实例。否则所有模型输入都会因产生激活被自动叫作多形态记忆，分类失去对长期设计的区分力。

新增实例意味着可以出现分别更新、分别选择、分别复用与分别失效的对象。它不意味着每个实例包含不同事实，也不要求每份副本拥有不同模块。

例如，更新一条文本后，旧摘要与 KV 可能继续存活；此时不是“文本更新功能失败”，而是更新尚未覆盖要保持一致的实例集合。相反，删除 KV 而保留源文本和兼容构造过程，可能只改变后续重算成本。

### 7.3 删除目标决定完成标准

“删除记忆”至少可以指四种不同承诺：

1. 移除一个指定实例，例如一条数据库记录。
2. 阻止当前系统经指定路径再次读取，例如撤销访问、失效索引或停止使用某缓存。
3. 撤销某来源在已知派生实例中的持续影响，例如同步清理摘要、KV 或相应训练工件。
4. 使系统不再能表现出某个语义事实的知识，无论它还可能从什么来源推得。

这些承诺强度不同。前一项完成不能单独证明后一项完成。第四项尤其不能靠删去一份源记录保证：其他独立来源或仍保留的事实可能支持重建。已经执行到环境中的行动，也不会因删除输入记录自动撤回。

可完成的操作应写明目标范围：要移除哪个实例、阻断哪些路径、处理哪些已知派生物，以及验证什么行为。不必把所有删除都提升为不可操作的全语义消除，但也不能把局部删除冒充那个更强目标。

已知派生关系提供处理范围，有限行为测试提供指定任务上的效果证据；二者都不单独证明所有潜在问题上绝无残余影响。

### 7.4 兼容是生产者、状态与消费者的关系

一个 KV 工件能否直接复用，要看它是否仍满足目标消费者的语义与数值接口。相关条件可包括：生成它的权重、前缀与前置上下文、位置处理、attention mask、头布局、精度和运算约定。

精确兼容要求相应状态等价；近似兼容则要给允许误差和任务标准。布局转换后可用、数值有误差但任务可接受、完全不适用，是三种不同结果。

“模型版本改变”是风险线索，不是必然失效证明。如果改变没有触及产生和消费该状态的相关计算，就可能仍兼容；如果改变了相关映射，即使文件能正常加载，也不能仅凭接口不报错保证语义有效。源文本还在，也不保证缺少旧权重和配置时能精确重建旧 KV。

Token 内容的保存通常更少绑定这些内部数值约定，但不同模型可能以不同方式理解同一文本。跨模型可继续保存和注入，不等于跨模型任务效果不变。

**可继承的结果：** 实例可定位使复制、更新、失效和撤销有了具体对象；来源关系和兼容条件使操作可以被检查。它们不能被一个笼统的“可编辑”“模型无关”或“不可逆”标签替代。

<a id="hybrid-necessity"></a>
## 8. 从分工有利到必须混合，还需要哪些证明

### 8.1 先明确“纯”和“混合”在比较什么

这里比较的是指定任务记忆怎样保存与使用。若把预训练权重、所有临时激活和符号输入全部算入，几乎任何 token 系统都可被称为混合，这对实际分工没有区分力。

一次比较可以固定底座与共同计算，只把新增或维护的任务记忆路径作为变量。此时，“单 form”指候选方案的相关持久记忆采用一种已声明路径；“混合”指相关持久实例或使用路径跨形态分工。范围必须在比较前确定。

### 8.2 条件必要性的充分论证

给定任务与负载、正确率要求、允许资源、时间尺度和候选机制集合，要证明该集合内必须混合，至少需要：

1. **单形态排除：** 每个允许的单 form 方案都无法满足所声明约束。
2. **混合可行：** 至少一个混合方案满足这些约束，并计入转换、同步、检索、路由、加载与失效成本。
3. **范围保持：** 排除结论与可行方案使用相同任务、质量、资源口径和允许辅助信息。

对有限、列明的工程候选，可以逐个比较；若要对所有可能的单 form 设计作必要性声明，就需要覆盖那一设计类的上界、下界或其他排除论证，不能只测几个实现后换用全称措辞。

“高频更新、高密度消费、长期保存并存”只描述需求。不同 form 各有成本，说明存在权衡；没有说明每个单 form 都越过预算，也没有证明混合方案的协调费用足够低。

还要避免把结论写进需求。如果先把“巩固”定义为写入主体参数，再要求另有文本持久库，那么跨 form 已经由定义保证，不能再称为从成本推导出的发现。

### 8.3 没有必要性证明，也可以得到具体分工结论

前文的重复前缀算例已经给出一项可执行判断：保留文本提供源内容和重建条件，保存兼容 KV 避免部分重复编码。若累计节省大于全部新增费用，这个具体分工在给定负载下更便宜。

该结论不要求证明所有其他方案均不可能；同样，它也没有证明所有系统都应缓存。若前缀只用一次、频繁变化或搬运费用较大，不等式就可能不成立。

**可继承的结果：** 具体分工的合理性可以由比较直接成立；“必须混合”是更强结论，需要另加排除证明。研究可以先完成前者，再在确有需要时承担后者，而不必等待一个普适的三形态经济学定理。

本文已经得到一组可直接使用的推理结果：历史影响需要可保留且可利用的差异；三形态在固定实现接口中可以稳定判定；固定消费者加外部记录可以实现新信息的持续调用；容量上界不包含逐次干扰；KV 复用有明确的同口径收益条件；复制、等价、删除与兼容分别对应具体关系；分工有利与分工必要需要不同强度的论证。真实系统的质量、长期稳定与资源数值，应在这些已明确的对象和条件上测量。
