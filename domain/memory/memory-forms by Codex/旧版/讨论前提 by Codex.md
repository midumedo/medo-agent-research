## 总体诊断：为什么此前不断修订，却没有形成稳定结论

这批稿件讨论的实际对象，早已超过“三个词分别是什么意思”。它们尝试同时回答：过去如何影响未来；什么状态有资格叫 memory；信息以何种角色进入计算；一个系统怎样维持记忆；学习和能力如何成立；不同方案的代价为何不同；认知理论能帮助解释到哪里。forms2 反复修订计算边界，05 把形态放回生命周期，06 又把信息、实例、消费者与功能角色分开。这些进展应保留，不能因本项目继续使用三形态，就把后两份稿缩成分类旁注。

整批讨论最有价值的认识是：**同一 form 不决定同一生命周期；同一信息不等于同一个状态实例；同一个存储基底不决定同一种使用角色；同一个机制名称不决定能力、成本与治理结果。** 这些认识能够直接改善后续 token 研究的比较单位。

当前最大问题也不只是个别术语不准，而是论证经常连续换层：从“某种抽象下可以这样表示”走到“物理上只能如此”，从“这种实现通常这样付费”走到“该形态具有这种普遍性质”，再从“各方案各有代价”走到“必须混合”。中间缺少固定的系统边界、任务、资源约束与反事实比较。版本修订降低了部分主张的强度，但“加上条件”“登记开放问题”“作者自评已解决”不能代替补齐证明。

还有一条不应遗漏的来源链：早期提示词已经指定三形态，同时要求从第一性原理推导三形态；较后提示词又把结果写成下一章的已定背景。这会形成循环：**任务给定的分类，被文章写成计算必然，再被后续任务继承为事实地基。** 纠正方式不是取消用户的分类选择，而是把“项目选择”“定义”“机制事实”“条件推论”“经验判断”分开。

第一轮综合稿已经纠正了这些推论，但也留下一个问题：许多章节以“不能直接推出”“仍取决于条件”结束，最终交付的主要还是研究纪律。本次修订把正面判定与可实现机制放到前面，并补齐它们的最小推导；原稿对照承担说明理由的责任，不再要求读者先重走全部争论才能知道结论。

## 1. 研究目的、分类用途与预设从哪里进入

### 1.1 用户目的、提示词约束和稿件新增目标不是同一层

[原始提示词](prompts/memory-forms-原始.md) L2–17 明确：学习理解 agent memory，建立对比式研究框架，不提出新方法；已决定主研 token；生命周期可以用于解释，但另作研究。这支持“把 forms 的定义、机制和边界讲清楚”，不支持默认增加“证明必须混合”“找出人类式巩固缺口”或“为部署给出最优选型”。

[展开提示词](prompts/memory-forms.md) L2–13 增加了更强的前提：载体是任何设计的第一分岔；接入点统一决定载体；三类由计算位置给出。L25–31 同时要求不为 token 选择作事后辩护，并限制混合与生命周期的篇幅。这里有真实张力：分类既被指定为任务入口，又被要求作为无预设推导的产物。最诚实的处理应是“审计这套给定分类在何范围有用”，不能声称从零推导后恰好发现了全部预设。

[整理提示词](prompts/整理.md) L16 进一步预判 KV 的内容在 latent、索引在 token，已经把一个待分析案例写成结论。L34 的旧输出目录只是材料中的指令，不是本次授权。[memory分类](prompts/memory分类.md) L2–14 与 [分类2](prompts/分类2.md) L2–14 则把“位置屈指可数”“外部存储无界”“读取只能经由输入”等继续向下传播。它们是前提传播的证据，不是这些前提已验证的证据。

[0203分类](02分类/0203分类.md) L1–12 提出了生命周期优先的第一人称意图，但没有对话角色、时间和确认元数据。它证明材料中出现过这个研究方向；不能据此宣布当前用户推翻了已确认的 forms 顺序。

05 在 §3、§8、§10（L47–57、147–188）把工程选型、成本交汇和巩固提升为重点；06 在 §7、§9、§11（L206–218、262–308）进一步提出容量解释和分类工具竞争。这些分析可以有价值，但价值来自它们回答了新问题，不来自它们是原始任务的必然展开。本文吸收其有效认识，同时标明它们增加了哪些论证责任。

### 1.2 同一个分类，在不同用途下有不同成功标准

| 分类用于什么 | 成功意味着什么 | 不能据此直接宣布什么 |
|---|---|---|
| 领域理解与文献组织 | 读者能找到材料、辨认典型机制、保留重要差异 | 社区常用词就是唯一自然分类 |
| 机制解释 | 入口、消费者、写入与因果作用可以追踪 | 同类系统必有相同成本或失败模式 |
| 工程比较 | 在明确任务、约束与负载下能排除劣解或解释权衡 | 某 form 普遍最优或混合普遍必需 |
| 能力判断 | 在固定系统边界与评测协议下解释保持、迁移、泛化 | 仅由载体名称推出能力天花板 |
| 安全与治理 | 能追踪来源、传播、副本、撤销及残留影响 | 可读文本必然可解释、可删除即已消除全部影响 |

06 §11.3（L297–308）明确讨论概念负担、文献兼容和分析增益，这是重要进展。需要收紧的是其中“多数产品选型三形态足够”“通道框架经济推导更强”等效果判断：表中的自评没有提供用户任务或对照结果。本项目保留三形态是合法且已确认的组织决策，不需要借这些未测效果主张背书。

### 1.3 第一性原理不能替代目的与可选抽象

第一性分析可以要求：任何因果影响必须有可追踪的计算或状态路径；一个推论必须保留它依赖的条件。它不能独自决定研究者应该按什么轴分类。把一个程序解释成“固定解释器读取数据”，或解释成“可变程序改变映射”，都可能准确，哪种有用取决于问题。

因此，分类的审计标准应是：固定对象和用途以后，它是否遗漏会改变判断的差异，是否把不同层级混在一起，是否使边界案例可重复判定，新增概念是否带来足够分析收益。不是“能否用一条看似物理的起点推出三个名字”。

### 1.4 将修订单位固定为命题，而不是整篇版本

本稿采用的推进单位是一个可明确回答的问题。例如“有备份是否取消 memory 资格”，处理结果是：给出备份反例，撤销排他判据，保留恢复关系，并提供新的可用表述。这个问题已经收束，不因后来出现新的缓存论文就自动重开。若新增证据改变的是重建速度，只更新成本判断。

“详尽”在这里意味着把一个结论的前提、推导、判例和作用范围讲透。继续增加系统名称、重复各版本自述或列出没有改变结论的限制，不算新的认知进展。允许相邻问题继续开放，但必须说明它会改变当前哪个判断；不能让“还有问题可研究”成为本轮永远不能结束的理由。

## 2. “无状态”“持久状态”“所有影响经过前向”各能推出什么

<a id="causal-model"></a>
### 2.1 从可保留差异到后续使用：最小过程模型

不先假设 LLM 无状态，也不先假设三个载体。将一次研究边界后的系统写成：

`Action_t ~ Policy(CurrentInput_t, RetainedState_t)`

`RetainedState_(t+1) = Update(RetainedState_t, Experience_t)`。

CurrentInput 是本次观测与请求；RetainedState 是跨已声明边界延续的相关状态；Experience 是本轮可获得的输入、输出和反馈；Policy、Update 只是对实际行为与更新过程的描述，未指定必须使用神经网络。参数、外部记录、运行状态都可以成为 RetainedState 的组成；未研究的共同运行条件在比较中保持一致。随机性可以由分布或另列的随机状态表示。

这个模型给出三步推导。第一，若两个不同历史在当前输入及全部可用保留状态上没有留下任何区别，系统无法仅凭不存在的区别辨认它们。第二，保存差异还不够：状态若永远不可被发现、读取、恢复或消费，它不会通过该路径影响后续任务。第三，路径存在也不保证每次使用正确，选择失败和消费失败仍可能使具体任务失败。于是，**保留、可达使用、任务效果是不同待判断事项**，不应让“存进了库”或“接入了 prompt”代替全部结论。

一个最小判别场景是：两段历史分别写入“暗号为松木”和“暗号为白石”，之后给出相同的询问。若系统有可用的写入和读取路径，它可以输出不同的对应答案；若这些历史只存在于已丢弃输入中，当前状态与输入又完全相同，则该系统没有据此区分两段历史的资源。这是构造分析，不是本轮运行过的实验，也不是对任意 LLM 正确率的承诺。

此处已经得到研究顺序：先找哪种历史差异被保留，再追踪它怎样进入使用，最后检查使用结果。三形态发生在这条路径中对状态及接口的分类阶段；它不是这两条过程表达式唯一推出的三个物理对象。

### 2.2 无状态函数是计算抽象，不是对所有部署的无条件事实

05 L10–12、06 L42–45 都从 `f_θ(x)` 出发，称两次调用若无显式搬运便因果独立。把 `f_θ` 定义为固定参数、给定输入到输出分布的函数，确实没有额外的跨调用内部变量。这是所选抽象的性质。它没有证明实际服务没有 KV、会话状态、在线参数更新、随机数状态或外层控制状态；这些可以被纳入参数、输入或另一个状态变量。

“独立”还要区分两件事：没有从上次执行结果到本次的状态传递，不等于两次输出统计独立。未被条件化的共同随机输入、共同外因或相关随机源仍可能使输出相关；共享固定参数本身则不必产生这种相关。较准确的表述是：**在计算所依赖的全部参数、输入和运行状态固定以后，未被这些变量承载的过去，不会额外影响这次计算。** 这是一条关于因果充分描述的要求，不能直接给出记忆的三个类别。

本次一手核对的 Transformer-XL 原文 §3.2 明确复用上一段隐藏状态。它证明“模型计算必须完全不带状态”不是架构无关的命题；却不自动证明某个部署在请求间保留这些状态。架构支持与服务生命周期仍是两件事。参见文末 [Transformer-XL 核对记录](#source-transformer-xl)。

### 2.3 过去影响未来需要某种延续，但不只限于模型内部

为了不把结论写进符号，可先用最宽的过程描述：在时刻 t，系统根据当前观测、保留下来的状态和运行过程生成行动，并产生下一时刻的状态。保留状态可以是文本、参数、向量、控制记录；当前观测也可能携带过去通过环境留下的结果。

于是，“过去要影响未来必须有某种信息延续”是很弱但可靠的因果要求。若研究只讨论 agent 内部 memory，就需明确排除或单列环境中的延续；例如 agent 写入的外部文件下次被工具读回，不能一会儿当环境、一会儿当内部库而不告知边界变化。06 L69 把环境排除并标为约定，这比默认忽略更清楚，但这种排除不能用于宣称已覆盖所有 agent 行为来源。

持久也必须相对某个边界定义：跨一次前向、跨一次请求、跨任务、跨会话、跨模型版本是不同要求。forms2 v5（L941–965）选择请求边界并区分控制、执行与前向内容；v7（L1198–1225）退回单次前向。这里不是单纯措辞更新：同一段请求内 KV 可以跨前向存在，却不跨请求存在。若先换边界再说它的 memory 资格改变，改变的是判定规则，不是工件突然有了新物理性质。

### 2.4 “所有影响都经前向”必须说明影响的是什么

如果讨论的是固定模型输出的 logits，即模型对词表产生的分数，进入其计算的因素当然必须位于该计算的依赖图中。若讨论采样结果，解码器还会使用温度、约束、随机性等。若讨论整个 agent 行动，外层路由、工具执行、权限和调度都可能改变结果，而无需修改这次前向的内部数值。

因此，05 L12 的宽泛表述不能与 L44–45 的控制面覆盖同时无条件成立。把编排代码叫 parametric、编排文本叫 token，只是换用“任何程序参数/任何符号”的宽词义，无法补齐原来以 LLM 前向为消费者的定义。06 的 `O(D(f_θ(x)))`（L70–95）确实让消费者在场，纠正了这个遗漏；但它是为分析而选的管线分解，不是所有系统唯一且天然的三层分解。

### 2.5 架构条件、冻结条件和穷尽性应分别讨论

forms2 v5 L965 明确：冻结参数不是三路分析的穷尽性前提；参数若在线更新，仍可描述其参数角色。v7 L1225 明列的条件是“基座冻结、计算为单次前向、载体以读取时刻生效位置为准”。**提供一组足够条件，不等于声称其中每个条件必要。** 不能用这个逻辑错误批评 v7。

真正应审计的是：v7 L1195 说三项条件的松动都“对应框架的明确修正方向”，但需要分别说明改变的是穷尽性、实例判定，还是成本与写入时序；不能把所有修正都理解为分类失效。v5 已说明冻结并不决定穷尽性。更广的问题是，各稿从“当前讨论接口可以这样列”推到“物理位置只有这三处”，却未独立证明架构与接口枚举的唯一性。可继承的结论是**给定消费者、状态角色与接口粒度后，三形态能组织这里的一批机制**，不继承架构无关的唯一性证明。

<a id="memory-boundaries"></a>
## 3. 什么有资格叫 memory：context、cache、config、知识与经验

<a id="working-boundary"></a>
### 3.1 本文采用的范围与可直接执行的判据

**本文默认研究跨 LLM 请求保留的信息，包括同一会话中的跨请求保留；不要求必须跨会话。** 请求内的 KV 仍是历史状态和执行复用机制，只在采用前向或 token 步作为边界时纳入相应时间尺度的 memory。讨论原论文时尊重它的边界并标明差异，不因此反复修改本文默认。这个默认是本稿为可比性选定的工作范围，不冒充用户新确认的领域定义。

在此范围内，将某状态登记为当前系统的可用记忆实例，要求两件事：它保留先前获得的信息；在当前已具备的系统机制和允许的运行路径中，它可以被发现、寻址、读取或恢复，并供某类相关任务消费。“有路径”不是设想将来重写系统后任何字节都能接入，而是现有机制确实容许这类状态的使用；自主搜索也可以是一种路径，不要求每条记录都预先硬编码。

“消费”还要求有效依赖：至少在某种允许的相关后续运行中，保留的信息能够通过现有机制影响下游计算或行动；读取后无条件丢弃的字段不因发生过读操作就满足这一点。冗余副本可以共同承载这种依赖，不能把每个副本都必须单独不可替代当成要求；改变信息时也需保持必要的副本一致性与有效输入条件。这里判断的是可发挥作用，不预设这种作用正确或有益。

这里不要求每次命中，也不要求单个实例不可替代。一条记忆暂时未被选到仍可属于库；两个互为备份的实例仍可承载同一记忆。若日志只留在人可查阅、agent 无访问或恢复路径的离线介质中，则可以确认它是保存的历史档案，却不把它算作当前运行可用记忆。接入恢复机制以后，改变的是系统可用范围，而不是这份档案过去从未保存信息。

来源另外记录：预训练、人工录入、外部知识和 agent 交互都可能承载先前信息。本稿不以“必须由当前 agent 自己经历”排除其中任何一种；下一项研究若只关注运行中的经验积累，可以在此基础上收窄样本。静态知识是否更新与它来自哪里也分别记录。

据此，三个问题已有不同答案：**是否保留信息**看状态及来源；**是否属于当前可用记忆**看保留边界和实际可达路径；**是否正确完成记忆任务**看具体运行结果。只读或有备份不取消前两项，检索失误也不自动否定整套机制存在，但它会使第三项失败。

### 3.2 Context 是本次可用内容，memory 是跨边界的保留与利用关系

当前用户输入可以是 context 而没有此前持久保存；长期记忆库中的内容没有被选中时，不在本次 context 中。某段历史进入 prompt 后，既是持久记忆的一次使用，又是当前上下文的组成。两词描述不同关系，并非互斥物种。

“只在上下文里存在”也有两种情况：从未在外部保留的临时内容，和存在外部库但本次经上下文使用的内容。批评前者无法跨会话保留，不能直接否定后者在完整系统内的持续效用。这个区分会在学习问题中再次承担推理责任。

### 3.3 05 的生命周期完整性：有效提醒，过强的资格门槛

05 §2.2（L39–42）指出同一物理载体可以承载静态 RAG 或动态经验，差异应看操作与生命周期。这纠正了“凡 RAG 都不是 memory”这种按系统名称裁决的做法。但“只有检索没有更新淘汰的是 RAG，有完整生命周期才是记忆”仍把架构名称和功能完备度混在一起。

一份只追加、暂不淘汰的经历记录依然能跨会话影响行为；只读且不会继续增长的已学知识，也不因停止更新而失去记忆资格。反过来，有增删改和治理的企业知识库不一定记录这个 agent 的经验。**生命周期完备度、内容来源和检索架构是三个可以分别改变的属性。** RAG 原始论文的机制是生成模型与检索所得非参数知识结合，它没有把“缺乏淘汰功能”作为 RAG 的定义条件，见 [RAG 核对记录](#source-rag)。

05 对 cache 的“静态、无条件读取”描述也过窄：缓存可以动态失效、按查询选择；记忆可以固定回放。是否随查询参数化，不能独自裁定缓存与记忆。

### 3.4 06 的权威副本判据：适合标记冗余关系，不适合取消记忆资格

06 §2.3（L61–62）尝试把 cache 定为可再生投影，把 memory 定为删除后永久失去信息的权威副本。这比按静态/动态分类更接近缓存的派生关系，但把“权威”和“唯一”混为一谈。

考虑同一历史笔记复制成备份：复制前它满足“删除即信息丢失”，复制后两个副本都可由另一份再生。如果资格依赖“删除当前副本是否永久丢失”，增加备份竟会使这段信息不再有任何 memory 实例。这违背该判据原本想表达的持久信息保存。权威副本通常涉及哪份拥有更新与冲突裁决地位，未必是唯一可恢复来源。

更可用的拆分是：某工件是否承载并参与记忆利用；它是源记录、备份还是派生投影；给定仍存活的源、模型版本、配置和生成程序，能否准确或近似再生；重建要花多少资源。这样，跨请求 KV 可以同时是计算缓存、历史信息的一种持久实例和某条 latent 使用路径。是否在本研究中简称 memory，要看声明的范围，而不是要求三种角色互斥。

“可再生”也不是无条件属性：源文本在而旧模型和位置配置不在，并不保证原 KV 可以重建。仅仅没有保存源文本，也不能证明一个学习工件是该信息的唯一权威来源；其他模型、数据或副本可能仍保有它。

### 3.5 06 的来源判据：划清研究范围，但需要处理混合来源

06 §2.4（L64–65）把交互历史产生的状态叫记忆，把预先 authored 且不随经验更新的状态叫配置，并诚实标为宣布式划界。这解决的是“本研究追踪哪类经验”，不是发现 memory 的物理本质。

它带来的代价是：预训练知识可能被排除，而后文仍分析 parametric 存量；人工录入的真实个人历史可能被误判配置；由一次经验触发的提示修订又可能同时包含原有策略和新事实。解决办法是记录来源与修订段落，不要求整个文件只有一个来源类别。知识资产、配置、经验记录可以在同一存储基底共存，功能与来源不能从文件格式读出来。

forms2 v7 的治理信号（L1214–1215）也只能补充边界分析：需要保护、删除或防投毒，说明状态重要，不足以证明它是 memory；密钥、权限和当前输入同样可能进入威胁模型。

**当前可继承的边界判断：** memory/context 是保留关系与当前使用的不同视角；cache 应标明派生和再生条件；config 与经验的分界是一条用途相关的来源约定；生命周期、来源、唯一性和形式均不能单独承担全部资格判定。

<a id="forms-and-channels"></a>
## 4. 三形态、五元组与六通道分别刻画了什么

### 4.1 保留三形态，但把组织约定写准确

<a id="form-decisions"></a>
**判定参照固定为已声明的模型实现及接口契约。** 这里的“接口契约”指这个实现把哪些量作为权重或权重增量、哪些作为符号输入、哪些作为可续用的前缀、激活或 KV 状态；不要求存在公开 API。只说“系数”和“数据”还不够，因为数学上可以把固定前缀吸收到复合函数参数，也可以把权重作为更高层解释器的数据。本稿不按这种任意重写重新归类，而是固定实现后比较具体状态的一次使用。

判定依据是已声明计算中的实际消费关系，而非变量名、文件名，或是否被训练框架注册为可训练参数。接口参照仍是一项分析选择，但选定后不得为了迁就某个案例临时改写它。

先判断某实例是否落入所选 memory 范围，再按下表分类。分类结果不能反向证明一个对象必定是 memory：例如同为 token 路径的当前用户指令，可能没有跨边界保留。

| 一级组织 | 二级组织 | 本文采用的读取角色 | 必须附带的限制 |
|---|---|---|---|
| 参数记忆 | parametric | 状态进入所选实现的权重或权重增量路径，改变该映射 | 需要指明模型或模块；“被优化过”不足以判定 |
| 外部记忆 | token | 状态作为离散符号内容保留，经符号输入路径被消费 | 文件可以保存字符串或 token ID；普通编码与传输不改变其符号角色 |
| 外部记忆 | latent | 状态作为持久的前缀、激活、KV 或其他表征数据，经相应状态路径被消费 | 有限精度、量化、物理驻留位置不改变其表征数据角色 |

这里“外部”相对于所分析映射的参数角色，不等于不在显存、不在进程、不在模型文件中；“参数”也不等于大模型训练前已经拥有的主权重。按用户加载的 adapter 可以是参数记忆，驻留在模型服务内的 KV 可以是外部数据状态。若讨论的是检索器或记忆生成器，它们各自的参数应注明模块，不能自动算作目标 LLM 已记住相应内容。

因此，LoRA 增量按参数路径归类，按输入表征使用的连续 soft prompt 按 latent 路径归类，源文本按 token 路径归类。前两者都可经过优化，这并不改变已经固定的读取角色；原论文机制依据分别见 [LoRA](#source-lora) 与 [Prefix-Tuning](#source-prefix)。文献将连续前缀称作可训练参数并不构成本稿内部的未决问题，只需注明它采用的词义不同。

文本被读取后必然产生表征，不据此把源文本重新判成 latent；分类跟踪的是这次被使用的持久实例。另行保存并跨请求复用的 KV 是另一个实例，按 latent 路径处理。纯粹将文本压缩为文件字节再无损解码，也没有改变其符号内容与消费接口。若编码器产生表征工件，再由另一个解码器生成文本，则分别记录工件与生成文本的消费者，不强行给整段路径贴一个单一 form。

以下判例在上述参照下可直接裁定，不继续登记为笼统的“归属无共识”：

| 具体对象与使用 | 本文判定 | 判定改变的实际条件 |
|---|---|---|
| LoRA 增量作为目标层的权重增量 | 参数路径 | 若分析改为另一模块或真正改用另一接口，重新登记 |
| 优化得到的连续前缀按前缀状态使用 | latent 路径 | 把它转换成离散符号并经符号接口使用，才是另一结果实例 |
| 索引向量只用于挑选文本，LLM 最终读文本 | 索引承担选择，内容使用走 token 路径 | 若将向量直接送入目标模型状态接口，增加相应 latent 使用 |
| 同一文本与跨请求保存的 KV | token 源实例与 latent 派生实例 | 删除某副本、改用另一条路径，会改变实例集合或使用分工 |
| 代码被 LLM 阅读、被运行器执行、执行结果再回传 | 分别是符号使用、程序执行、结果使用 | 消费者与过程不同；代码执行不冒充 LLM 参数写入 |
| 请求内临时 KV | 当前默认范围外的执行状态 | 跨请求保留时进入本文的记忆分析；采用更细时间边界时另行标注 |

三形态不是三种物理介质。文本、权重和 KV 最终都能保存在数字存储器中；量化权重也不会因为取值离散而变成 token memory。forms2 无版本稿 L167–178 用“离散/连续 × 显式/隐式”推出三个非空格，实际上需要预先约定这些词的含义，不能作为独立于定义的穷尽证明。这里保留分类的代价已经明确：它依赖固定参照，也允许范围外的控制和执行路径；换来的是典型对象可重复的判定，而不是一套任意计算重写下均不变的本体。

### 4.2 05 的五元组：把被压扁的差异重新展开

05 §1.1（L17–25）给出 entry、persistence、temporal granularity、scope、mutability 五个字段，分别关心进入位置、保留边界、生效时间粒度、作用范围、修改机制与成本。其有效贡献是让读者看到：同为 latent 的请求内 KV 与跨请求工件，或者同为参数的离线训练与推理期更新，不能只用一个 form 标签描述。

但五元组不是一个已证明充分的机制模型。它未显式提供内容、寻址与检索规则、读取算子、版本依赖、生成器、消费者以及工件之间的关系。同一个五元组仍可对应很不同的系统。字段也不都处于同一层：寿命是属性，更新是过程，成本是机制在负载与资源下的结果。

因此，05 L27 的“多数边界争议自然解决”应解释为“可以把争议拆成多个判断”，不能解释为“矩阵自动决定所有归属”。soft prompt 的写入方式与读取角色确实可分别登记；若争论双方本来就用不同的 form 定义，填写字段只显示了分歧在哪里，并没有替双方选择词义。

### 4.3 06 的数据/映射与六通道：让消费者和功能角色出现

06 §3（L67–95）选择模型前向 f、解码 D、编排 O，并区分被过程消费的数据与构成过程的系数、规则或程序。六通道因此包含 token、latent、parametric，以及解码态、控制态、程序。它的重要增益是：先前被排除的工具调度、代码执行和解码约束有了分析位置。

但数据/映射是**相对于某次计算的角色**。固定解释器可以把程序当数据读取；从所执行的任务看，这个程序又定义一个映射。06 L77–78 已承认使用相对性与解码面弱判定，应把这个自限贯彻到底。尤其“被注意力读取”和“参与矩阵乘法”不是互斥判据：attention 本身就有矩阵乘法，输入数据也参与乘法。更准确的是看该状态在已声明的接口中作为可更换的数据实例，还是作为所分析变换的系数或执行规则。

六通道也不是六种同层物理载体：有的按表示细分，有的按消费者或功能命名。O 若由另一 LLM 实现，顶层控制态可能成为子模型的 token 输入；06 L95 已记录这一递归性。其范围排除了环境状态，并把采样种子登记为边缘选择通道后，按低带宽排除出记忆讨论（L69、89）。固定分解和排除规则以后，可以审查覆盖情况；如果每遇到新对象就重定义 f、O 或 latent，便无法再把“未发现第七类”当成强证据。

### 4.4 三者关系：互补、尺度变化和冲突分别处理

五元组相对三形态增加寿命、更新和作用域，主要是补充描述维度。六通道相对只看目标 LLM 的三形态扩展了消费者，主要是分析尺度变化。它们不必争夺一个“更根本”的位置。

真正的冲突是同一概念使用不同判据却不说明：05 L44 把代码划到 parametric，06 L173–176 另列程序；05 L41 用静态/动态分 cache，06 L62 改用可再生性；forms2 的请求内 KV 资格随边界反复变化。这里应明确哪条判据被改变以及产生什么代价，不应笼统称为“无共识”，也不能据文件数字认定后一稿已替代前稿。

本项目继承 06 L308 允许的组织读法：**三形态继续作一级入口，分析具体机制时补上消费者、角色、实例关系和生命周期。** 代价是明确放弃“单一三分法即可穷尽整个 agent”的覆盖声明；收益是保留可查找的文献词汇，同时不丢掉 05、06 的实质认识。

<a id="instances-and-use-paths"></a>
## 5. 信息、状态实例与使用路径：不能都叫“混合”

### 5.1 分清内容、工件、生产者与消费者

“同一信息”是关于内容或任务相关关系的说法；“同一实例”是关于一个具体保留状态的说法。历史事实可能同时存在日志、摘要、向量索引、缓存与参数贡献中。这些实例是否保留相同信息、是否能重建、是否产生相同任务效果，都需另外判断，不能仅因共同来源而宣布等价。

因此，“同一信息有多个实例”应至少说明同一到什么程度：完整副本可以要求逐内容一致；摘要通常只声称保留指定事实；KV 与文本共享构造来源，却未必允许从 KV 精确还原源文；参数更新可能只在一组任务上保留源材料的部分作用。共同来源、内容等价、可逆重建和任务等效是不同关系。这里不需要为它们另造 form，只需要避免把一种关系当作另一种关系的证明。

06 L180 的多实例思想是整批材料的重要进展。可用一条统一描述关系来吸收它：**源实例 → 构造或转换操作及其执行者 → 结果实例 → 使用接口 → 消费者与角色。** 这是一条分析路径，不是要求每个系统都增加这些模块。

| 现象 | 需要分开的对象与关系 | 能说明什么，不能说明什么 |
|---|---|---|
| 文本与向量索引 | 文本实例；由编码器得到的索引向量；向量检索器；返回文本的 LLM 使用 | 索引帮助选择，不自动证明 LLM 直接读取 latent 内容 |
| 前缀缓存 | 源文本；给定模型和位置条件产生的 KV；后续 KV 使用 | 存在派生实例和计算复用，不意味着源文本消失 |
| 普通文本前向 | 输入符号与本次执行中的激活 | 有表示转换，不自动增加独立的持久记忆系统 |
| Soft prompt | 优化器更新的持久向量；目标模型按前缀状态读取 | 写入用优化不决定它在所选读取分类下必须是 parametric |
| LoRA | 参数增量；合并或附加计算路径 | 磁盘外挂不等于外部数据记忆 |
| 技能代码 | 保存的代码；作为提示阅读的使用；交给解释器执行的使用 | 同一实例可换消费者，未必产生第二个记忆实例 |
| 多模态内容 | 原始媒体、编码器参数、输出向量及注入事件 | 生成器属于参数模块，不等于每次生成输出都是参数写入 |
| 经验蒸馏 | 经验记录、训练数据、更新程序、结果参数与保留的源 | 是否迁移、压缩或只是复制部分任务能力，需要验证 |

<a id="token-retention-use"></a>
### 5.2 Token memory 的正面机制：保留与使用可以分别改变

设外部符号库为 TextStore，本次问题为 Query。一次典型使用可写为：

`SelectedText = Select(TextStore, Query)`

`ModelInput = Assemble(CurrentInput, SelectedText)`。

这里的 Select 可以是全部读入、按键读取、搜索、语义检索或 agent 自主查找，不预设专门向量数据库；Assemble 包括必要的格式化、序列化与输入构造。若当前直接使用的是已保存的 KV，则登记另一条派生实例使用路径，不能让缓存实现把这条源内容关系抹掉。

这两步已经推出三个有用结果。第一，库中的保留内容量与单次输入量是两个不同量，可以分别增长和受限。第二，只要没有改变已有条目，追加一个记录可以保留原条目的存储内容；它仍可能通过排序、检索竞争或组装预算改变旧内容被使用的机会，所以存储保留不等于行为无干扰。第三，改组织或选择机制而不改记录，也可能改变系统的可用信息；改记录而没有可达读取路径，则未必改变当前任务行为。

由此，后续 token 研究已经有四个明确对象：保留的内容与表示、记录之间的组织、被选入的条件、进入消费者时的表达。它们是从具体使用关系中分离出来的问题，不是已经宣布穷尽的四个正交主轴；是否合并或细分，要由后续比较需要决定。这里也不需要证明 token 是最优路线才能继续。

### 5.3 “桥”的定义可以保留问题意识，不能原样当统一解释

06 L180 把桥定义为写通道与读通道不一致，L184–189 的表却混用源内容、写入算法、生成器和读取角色：前缀缓存的 token 是源工件；soft prompt 的 parametric 指优化器写入；多模态一行把编码器本身当写通道；Titans 一行写、读都是 parametric，按该定义并不是桥。

因此，不需要否定表中现象，而应取消一个混合标签代替多条关系的做法。复制是增加实例；压缩是带目标与损失的转换；代码执行是角色变化；训练生成器是改变生产过程；把经验写进参数是修改另一个持久实例。先明确是哪一种，再讨论是否跨 form、是否值得叫混合。

forms2 v3 L611–612、v7 L1316、1360 把 token 前向自然产生 KV 说成最小混合，容易使所有 token 系统都自动变成同类混合。若讨论的是计算实现，这种说法可以成立为“同一执行有多种表示”；若讨论独立记忆设计，必须加上保存边界、可管理工件和独立使用路径，否则失去区分度。

### 5.4 参数写入的算法不等于参数读取的定义

forms2 v5 L1026–1029 已把参数写入扩到优化、直接编辑与权重运算，v7 L1261、1271 又收窄为梯度。05 L81–93、06 L146–151 对内部谱系的展开应保留：原位还是附加、离线还是推理期、优化还是数值求解、共享还是按用户绑定，应分别记录。

[ROME](#source-rome) 是一个足以拆开争议的机制实例：目标权重的最终更新可采用闭式秩一形式，但所需目标 value 的求取又用了优化。因此可反驳“写入目标参数只能对该参数做梯度下降”，不能说“ROME 全流程没有梯度”。同理，推理期更新参数不会只因时标很快就变成 latent；梯度优化一个前缀也不会只因用了梯度就决定其读取角色。

[LoRA](#source-lora) 的增量以 `BAx` 参与目标映射；它可以合并进已有权重。[Prefix-Tuning](#source-prefix) 则冻结主体并优化连续前缀。二者足以说明训练范式、物理保存位置和读取角色需要分别描述。具体成本和兼容性仍取决于部署，不能由“可训练”或“外挂”两词推出。

### 5.5 Latent 内部至少有不同构造与读取路径

05 L106–110、06 L123–124 区分复用、变换、生成，这是有效的构造过程拆分：保存已有状态，压缩或量化已有状态，由编码器或其他模块生成新状态。三者可以串联，不是严格互斥类别。读取端还应区分嵌入位、各层 KV、层间激活、持续循环状态，因为它们绕过和保留的计算不同。

Cartridges 给出了需要修正原稿的具体例子。本轮核对其 v1 §3、§4.2：固定主体模型，直接优化工件的 K/V。05 L151 把它解释为 latent→parametric 固化或训练独立模块产生工件，混淆了优化对象和结果角色。这个例子支持“可以用训练构造持久 KV”，并不证明内容已写回主体模型权重。其任务效果也不能替代关于所有 latent 的结论，见 [Cartridges 核对记录](#source-cartridges)。

多模态同样需要固定实例：图像文件、视觉编码器参数、输出 embedding 与离散媒体码是不同对象。只分析编码后注入的连续实例时可使用 latent 视角；不能倒推所有多模态资产或架构都属于同一种 form。

### 5.6 多实例关系让删除与失效成为可完成的具体操作

删除源文本不保证摘要、索引、KV、训练贡献和执行副作用全部消失。反过来，删去一个缓存而保留源文本，可能只是改了重算成本。forms2 v5 L1088、1148 所讨论的按用户 KV 区间删除，也要考虑后续状态已吸收前文影响，不能从位置删除推出语义消除。

但这不意味着任何删除结论都必须证明整个世界再无相关信息。操作目标可以明确完成：

| 目标 | 可以确认的完成结果 | 需要另作判断的更强目标 |
|---|---|---|
| 删除一个指定记录 | 该实例在声明存储范围内已不存在，常规读取不再返回它 | 其他摘要、备份或行为是否仍保留相关作用 |
| 撤销一次已记录的更新 | 对应参数增量或版本已按记录回退 | 某个语义事实是否在所有其他路径中消失 |
| 撤销一项偏好的当前效力 | 当前机制选择新版或不再采用被撤销记录，指定任务按约定处理 | 超出已测任务的全部行为是否不再受影响 |

例如，实验系统确认某次偏好只写入一个字段，没有派生摘要、缓存或参数更新，删除该字段就完成这一实例的删除，不需要再调查预训练模型是否知道相同偏好句子。若后来增加摘要，新的依赖关系进入删除范围。条件变化时扩展检查，不提前把无限追溯当作完成门槛。

这也保留了文本可定位操作的实际优势：对于明确记录与已知依赖，可以直接执行有目标的增删改并核对结果。需要行为实验的是更强的效果主张，而不是已经观察到的工件操作本身。

<a id="functions-and-lifecycle"></a>
## 6. 功能需求与生命周期：成立条件、设计要求和产品要求

### 6.1 六功能可作检查维度，不能一律当定义

06 L57–58 的六功能覆盖持久化、重注入、选择、更新/淘汰、作用域、治理。它已把前两项与其余项分开，是比“完整系统才有记忆”更清楚的认识。但将后四项统一称设计必要，仍需要任务条件。

| 功能 | 在何意义上必要或有用 | 不能自动要求的内容 |
|---|---|---|
| 保留 | 要利用跨指定边界的过去差异，差异须以某种形式延续 | 永久保存、必须磁盘持久化 |
| 后续利用路径 | 系统须有利用所保留差异的可能路径 | 每条记忆每次都被读取、必须注入 LLM prompt |
| 选择 | 系统总会有某种使用策略，“全部使用”也可算一种 | 必须有语义检索模块或按当前查询筛选 |
| 更新与淘汰 | 面对过时、冲突、有限预算时常很重要 | 不支持删除就不是 memory |
| 作用域 | 需要说明状态能影响谁、由谁读写 | 单用户研究原型必须实现复杂权限体系 |
| 治理与安全 | 在特定来源、部署和风险下成为要求 | 完整回滚与审计是所有记忆现象的物理前提 |

这样重写并不是削弱生命周期的重要性，而是防止把产品成熟度和对象资格合并。关于六功能是否足以描述实用系统，原稿没有证明；例如来源质量、冲突解决和任务评价仍可能需要单列，是否单列由研究问题决定。

<a id="functional-requirements"></a>
### 6.2 从具体任务推出管理要求，而不从名称推出

**记忆资格由保留和可用关系判断；系统是否合格，由它承诺完成的任务判断。** 这给六功能一个正面的使用方法：每当任务增加一个要求，就检查没有相应能力时是否出现可构造失败。

只有一位用户、记录不变暗号、要求下次准确取回时，写入和按键读取已能实现这项最小记忆任务。增加第二位用户，且同名键的暗号不同、不得混用，主体绑定或其他等效隔离便成为合格条件。再允许暗号修改，就需要正确覆盖、版本选择或冲突处理；只追加旧值而无法判断何者当前有效会违反任务。再增加有限输入预算且历史不断增长，就需要某种选择、压缩或任务分解，而不能承诺无限原样读入。

这些必要性由具体失败推出来，不由“成熟记忆系统应该有六大组件”预设出来。相应能力也不一定实现成独立模块：单用户系统的作用域可以由结构隐含满足，直接覆盖也可以完成更新。05 的生命周期矩阵与 06 的功能列举因此成为检查具体承诺的工具，既有价值，也不再决定所有 memory 的入场资格。

### 6.3 生命周期不与 forms 竞争同一个位置

Form 描述某实例在某次使用中的表示与角色；生命周期研究它怎样形成、保存、选择、使用、修订、派生和退出。一个结构可以经历多个操作；一个操作也可以跨多个实例。因此不能只用“是否换物理载体”判断所有争议属于形态还是操作（05 L40）：同一载体换消费者已足以改变作用机制，某次更新也可能同时改变内容、组织与工件类型。

05 §3 的生命周期成本矩阵应继承为提问方式，而不是原样继承其中的排序。沿此矩阵展开，可以把 token 的抽取与验证、参数的编辑与评测、latent 的构造与装载纳入同一账单，解释为什么“读便宜”不等于总成本低。第 8 节将进一步审计其经济推论。

### 6.4 可检视、可归因、可撤销需要分别判断

forms2 多稿、05 L56、68–77、06 L111–113 与 §10 把文本可读、条目可操作和错误可归因连在一起。应拆成四个问题：能否访问状态本身；能否理解其内容；能否识别它如何影响行为；能否撤销目标影响。

文本通常提供可定位条目，但专用编码和歧义文本不保证人直接理解；人理解的句义也不保证模型按同样方式使用。参数与 latent 的数值可以检查、复制、比较和干预，困难主要在语义解释与效果识别，而非物理上不可见。模型失败可能来自多个条目与指令的交互，不能从日志存在就宣告“全部可归因”。

[Hase 等的定位研究](#source-hase) 给出一个明确边界：特定因果追踪位置对特定编辑效果的预测，并非想当然地成立。这支持把“哪里对当前计算敏感”与“在哪里修改能达到目标且少伤害其他行为”分开，不支持所有定位无价值或参数不可研究。[AlphaEdit](#source-alphaedit) 对给定表征矩阵的零空间约束也不等于完整模型所有知识不变。

可撤销性同样取决于记录与部署：独立 adapter 或保存的检查点可以整块卸载或回退，这不等于精确遗忘某一语义事实；文本条目能删除，也不等于清除全部派生影响。Form 给出约束线索，具体撤销能力需要沿实例关系判断。

### 6.5 兼容性与安全：机制差异存在，完成标准也可以明确

Token 工件跨模型继续保存、继续可注入，不保证语义效果不变；forms2 v5 L1003 已作这个有效区分。Latent 精确复用更依赖生成与消费它的相关权重、位置机制、布局和数值约定，但“任何模型改动均立即作废”“寿命必不超过版本寿命”（05 L118；06 L130）过强：改动可能未触及相关子图，或只产生可容忍误差。是否兼容、能否转换、转换后有何损失，应分别测量。

相应完成标准应分开：字符串可被新输入接口接受，可以确认符号输入兼容；张量满足状态接口声明的输入约束或实际通过接口校验，可以确认相应输入接口兼容；在所需测试范围保留行为，才确认相应功能兼容。前两项通过后，不应因为第三项未完成就把一切降回未知；同样也不能把前两项当成第三项的证明。

06 L135 的“绕过一切文本安全管线”“语义审核不存在”也超出机制能证明的范围。没有原始字符串只意味着仅接受字符串的检查不能直接作用于该工件；不能推出来源控制、行为探针、重构或其他检查一概不可能。反过来，可读文本也不自动安全。

06 L279–290 关于投毒固化与近不可逆的推论，应改为传播问题：不可信内容可能经过检索、摘要、执行或训练形成多个持久影响，移除源对象未必移除全部影响；回滚能力、权限与检测条件决定处置难度。仅从数据/映射标签，无法推出攻击一定可删除、一定不可逆或攻击者一定偏好某通道。

<a id="learning-and-capability"></a>
## 7. 记忆、学习与能力：定义澄清以后还有哪些实证问题

<a id="external-adaptation"></a>
### 7.1 不更新主体参数，也能获得并利用新的持久信息

**外部可写存储能够承载完整系统的持续信息适应，即使消费者的程序或主体模型参数保持固定。** 这个最低能力可以用一个明确构造说明，无须等待“学习”一词取得唯一共识。

考虑规则始终固定的程序：第一次收到某用户的新暗号时，把它保存到按用户寻址的文本字段；另一请求询问暗号时，读该字段并返回。在新暗号未由其他通道给出的条件下，写入前不能保证正确返回任意新暗号，写入后则可按记录返回。变化发生在持久记录，后续行为依赖新历史，而程序规则没有改变。因此，“没有主体参数变化，系统就不可能持续获得新信息”作为普遍命题不成立。

这个构造证明的是信息写入与后续调用的可实现性，不证明任意冻结 LLM 都能可靠抽取、检索或使用任意笔记。对于 LLM agent，历史更新 TextStore，选择与组装改变 ModelInput，固定模型能够利用其中信息时，整个 agent 的任务能力就可以改变。需要测量的是这条实际路径的保持、可达性与消费质量，而不是再次争论外部变化在逻辑上是否允许改变系统。

也没有从这里推出新规则归纳或组合泛化。保存某个新值、归纳可复用规则、把规则写入主体参数、迁移到新任务，分别有不同成功条件。若研究将 learning 专指参数更新，该构造不属于该窄义 learning；命名变化不撤销它已展示的持续信息适应机制。

### 7.2 05 的三种学习定义解决了同名异义

05 §7（L130–145）区分权重的持久改变、表征的持久改变、行为能力的持久改变。它的贡献不是为三者选一个正确含义，而是阻止研究者在不同定义之间移动结论。如果学习被定义为主体权重更新，主体冻结的纯外部记录当然不满足；这是定义上的排除，不是实验发现了外部记忆没有适应能力。

这张表还需补上两个限定。“表征”若泛指信息的表示，符号库同样是表征；要排除 token，就已把词义收窄到特定内部数值状态。“权重”也要说明是谁的权重：主 LLM 冻结，不代表检索器、记忆生成器或 adapter 都没有更新。主体参数、持久工件、整个 agent 的状态是不同的观察对象。

05 L143 将争议概括为定义依赖是对的，但若据此说它不再是经验问题，就过头了。**选择定义解决“测量什么”，不能替代“是否测到”。** 权重改变不保证能力改善，持久表征改变不保证被使用，一次回答变好不保证保持或泛化。

### 7.3 “移除笔记后还能用”测量的是状态依赖，不是学习的通用判据

05 L133–142、06 L117 转述的挑战把移除笔记后的能力保持放在中心。这个测试有意义，但首先是组件消融：原系统包含笔记时可用，移除后失能，说明能力依赖那个组件。若研究对象本来就是包括外部存储的 agent，不能因移除组成部分后失能，否定完整系统发生过持久适应。

相反，移除原笔记后仍成功，也不自动证明形成了模型内泛化能力：可能还有摘要、副本、缓存、检索线索，或任务本来就能用预训练知识完成。要把这个现象解释成迁移或巩固，必须排除相关替代路径，并明确结果状态在哪里。

因此，真正要分别问的是：新信息在哪里保留；能跨哪个时间边界调用；成功是否超出直接复述；是否能应对新输入、组合或分布变化；如果主张已进入主体模型，切断哪些外部依赖后仍成立。这些问题不能用一句“改变权重才算学习”合并裁决。

### 7.4 前缀注意力限制不能承担通道级能力上限

05 §4.4（L71–73）已经明确：某种注意力限制不足以推出“只能诱发旧技能”。06 §4.1.4（L114–119）进一步列出简化模型到深层网络、固定前缀到自由上下文、特定任务到整条通道的外推桥。这些自限应完整保留，而不是只留下负面结论。

本次进一步核对 Petrov、Torr、Bibi 的原文：在固定内容表征下，前缀不能任意改变某层内容之间的相对 attention，是特定结构结论；其 §6 明确讨论前缀改变后续层 attention 的可能性。因此“token 注入不能改变整个模型的相对注意力模式”仍过宽。它也不直接覆盖动态检索、交互构造、工具反馈或任意上下文算法，见 [前缀限制核对记录](#source-prefix-limits)。

该文 §4 还讨论了不改变相应 attention 模式而改变输入到输出映射的可能性。因此，05 L73、268 所问的问题不能全部留作未知：构造意义上的新映射并非已被排除；真实模型是否能从有限经验有效学得、保持并泛化，则仍是另一问题。

同一作者组 2024 年的通用逼近工作使用特制的固定权重与连续前缀，给出构造性存在结果。它的作用是阻止仅从“冻结”或“前缀接口”推出普遍不可能；不能证明任意现成预训练 LLM、短离散 prompt 都能实现任意能力，更不能证明这种前缀可有效学得或可在新任务上泛化。这里也不能把连续前缀结果直接算作外部文本 memory 的成功证据，见 [通用逼近核对记录](#source-prefix-universal)。

06 另列隐式梯度下降、贝叶斯推断、归纳头等 ICL 解释，是提醒双方假设不同的有效文献线索。但本轮未逐一核验这些结果，故不把其 `[V]` 继承为本文新证据，也不借其中任何一种读法宣布所有 ICL 的统一机制。Xu 的具体证明假设、MemGen/T-Mem 的能力和涌现描述同样未核验，不用于支撑本稿的能力结论。

### 7.5 能力不是由保存位置单独决定的

相同的外部笔记，交给不同消费者、配以不同选择规则和任务提示，可能有不同可用能力；相同参数量，也可能因为训练、路由和目标不同而表现不同。形式只约束信息可进入哪些计算路径，不直接决定消费者能从信息中提取什么。

这还解释了压缩问题：一个工件保留的源信息较少，不等于在有限计算消费者上任务表现必更差。压缩可能突出任务相关内容，生成器也可能加入自身先验。若要使用信息论上限，须固定随机变量、来源、允许的额外信息及损失准则；不能从“是压缩产物”直接推出所有任务上的表达能力排序。06 L132 的全称关系应据此收紧。

### 7.6 目前可裁定与真正未决的部分

已经可裁定的是：冻结主体不等于完整 agent 没有状态更新；外部记忆依赖不自动取消系统级学习资格；权重更新不保证能力提升；局部结构限制不构成整个 token memory 的能力上限。

仍需实证的是固定系统与任务之后的保持、规则归纳、组合泛化、更新纠错和样本效率。本次未运行行为实验。最有区分力的后续检查应分别设置：同一系统写入前后与无关写入对照；跨会话保留；清除全部相关副本后的依赖测试；在不泄漏目标答案的新任务上测试迁移。每一步回答不同问题，不能用一个总分替代。

主研 token 不要求工程系统完全没有参数模块或缓存。固定底座和缓存策略可以帮助归因；析因设计也可以研究 token 与参数更新的交互。forms2 v3 L653–655、v7 L1362–1364 的控制变量建议，应作为特定比较设计，不能升为研究 token 的必要条件。

## 8. 成本、容量与混合：把缺失的中间推理补出来

### 8.1 Form 给出成本线索，完整账单由机制和负载决定

05 §3、§8 与 06 §7 共同推进了一个重要方向：从“哪种形态好”改问“哪个生命周期阶段付费、在什么负载下值得”。需要撤回的是把特定实现的费用写成 form 的固定性质。

Token 的被动记录可以不调用生成模型，但采集、写盘、复制、抽取、摘要、检索、校验和索引仍可能付费。参数原位修改在固定计算图中可以不增加前向算子，但训练、模块加载、检查点、租户实例与评测不是零成本。Latent 的构造、驻留、传输和读取也各不相同，不能一概以完整 KV 衡量。

“只有 latent 承担持续存储费”使用了不对称基线：把已有权重驻留并入基础设施、把文本存储忽略，却单列 KV。若关心增量费用，可以采用这个基线，但必须说明；若关心总拥有成本，三类实例都要计入相同边界。

### 8.2 Prefill、解码与缓存节省的是不同计算

在普通稠密全注意力、其他维度固定的假设下，长度为 L 的前缀有随 L² 增长的注意力运算部分，同时还存在随 L 线性增长的投影和逐位置计算。使用 KV 后，生成 T 个新 token 的注意力交互仍包含约 `L·T + T(T−1)/2` 的历史读取项。缓存避免重算已缓存前缀，不把整段自回归解码一概变成线性复杂度。forms2 v4 L870、v7 L1282 的整体降阶表述不应继承。

也不能把复杂度等同于墙钟时间：硬件、带宽、批处理、内核、稀疏或窗口机制都会改变实测比例。06 L105 关于 ANN 的近对数跳数也不能作为所有索引、数据分布和召回目标的保证。

“免 prefill”更只适用于可直接复用的相应中间状态。嵌入位 soft prompt 仍需通过后续层；加载 KV 还付数据搬运与后续 attention。forms2 v4 L851–856 对这点区分较好，后稿统一写 latent 免 prefill 时反而丢失了条件。05 L117、06 L128 保留解码和带宽成本的修订应吸收。

### 8.3 KV 算例可以复核，数量级不能脱离分母

对保存所有层 K/V 的特定实现，字节数可写成：

`KVBytes = 2 × Layers × KVHeads × HeadDim × BytesPerValue × Positions`。

假设 32 层、32 个 KV 头、每头 128 维、每数值 2 字节，则每位置为 524,288 字节，即 512 KiB；100,000 个位置约 48.83 GiB。这是明确参数下的算术，不是所有 latent memory 的成本定律。若另假设原文平均每 token 4 字节，则约 0.4 MB，二者相差约 131,072 倍；文本估算取决于语言与编码，KV 公式也随头数、压缩、量化和保存范围变化。

05 L162 将 Cartridges 的 38.6 倍压缩解释为从约五个数量级降到两个数量级以内，存在分母与算术问题。该压缩相对完整 KV；即使暂把两个算例直接拼接，`100,000 / 38.6 ≈ 2,591`，仍超过三个数量级，不能得到小于 100。不同实验基线原本也不能这样直接拼接。06 L225 的“压缩后仍至少三阶”又是另一种全称：本轮没有对所有方法、架构和目标质量验证它，也不继承。

本稿保留的是成本计算方法和分母纪律，不裁定某一 form 必须维持多少数量级的优势。

### 8.4 摊销点需要两边同口径、同质量

06 L216 的 `W/c_r` 展示了一次写入与多次读取之间的最小权衡，是可用的简化思路。若用统一货币或统一资源单位比较，可把某实现 i 在给定时间段内的成本写为：

`Cost_i = InitialWrite_i + Reads × ReadCost_i + Updates × UpdateCost_i + Storage_i + Other_i`。

其中 Other 包含该比较需要的检索、验证、失效重建、同步与治理费用。若没有合理换算，就保留算力、内存、时延等多维结果，不应硬加成一个数。质量要求也必须固定，否则便宜可能只因丢弃更多信息或降低正确率。

只考虑写入和读取、并且 token 每次读取确实比参数方案更贵时，两方案的成本交点才是 `(Write_param − Write_token) / (Read_token − Read_param)`；要有正的摊销门槛，还需参数方案的初始写入更贵，否则在这个二项模型里无需等待摊销。原稿的 `W/c_r` 是其中把 token 写入和参数边际读取设为零的特例。更新、失效及质量变化会改变结论，不只是在原有数上补一个经验惩罚系数。

<a id="kv-reuse-decision"></a>
### 8.5 一个已经能作判断的案例：重复前缀何时值得保存 KV

不必先证明混合必然，就能比较两条具体可行路径。假设同一前缀使用 n 次，相关模型与位置条件兼容，两条路径达到相同任务效果。Encode 是一次完整编码的成本；Common、Keep、Load、Rebuild、Manage 均为这 n 次使用及同一观察时段内的累计成本，Common 表示两路径相同的后续计算。

`Cost_recompute = n × Encode + Common`

`Cost_reuse = Encode + Common + Keep + Load + Rebuild + Manage`。

Keep 是相对于重算路径新增的写入和保留费用；Load 是新增装载、传输费用；Rebuild 是失效后的重建；Manage 是新增的选择、同步或管理费用。公共项只在确实相同的条件下抵消，不把不同硬件、质量或输出长度的运行强行当作同一比较。

于是在这个明确模型里，复用值得的条件就是：

`(n − 1) × Encode > Keep + Load + Rebuild + Manage`。

首次构造两边本来都需要，不重复计作复用的额外成本；缓存未命中或失效则进入重建费用。这个判断直接说明：重复使用、较贵的编码、较稳定的状态有利于复用；较重的装载、较低的复用次数、频繁失效会抵消收益。若资源不能换算到同一成本单位，则比较可行性约束和多维资源，不使用这个单一不等式作总排序。

这已给出 token→持久 KV 分工的一项可操作结论。具体部署的各项数值尚未测量，不妨碍条件本身成立；相反，也不能因为有这个机制就宣称任何工作负载都应该缓存或混合。

### 8.6 有限容量只能推出有限区分能力，不能推出每次写入干扰

06 L208–213 尝试用容量解释数据/映射分工，但缺少必要条件。一个有限精度、总共 B bit、无其他信息来源的状态，最多有 `2^B` 个可区别状态。因此，它不可能无损保存任意多的独立二值事实。这是关于所需信息与可区分状态的上界。

它并不说明当前容量已经用满，也不说明每次写入都会破坏旧能力。仍有空位、允许扩容、内容可压缩、新旧规律一致、模块或子空间隔离，都可能让一段时期的新写入不干扰已测试旧任务。反之，算法可能在容量尚未耗尽时已经产生干扰。**容量上界、表示效率、优化干扰、检索竞争和行为失败，是不同的问题。**

若外部库固定预算，它同样会淘汰或压缩；若参数系统允许新增模块，它同样能扩容。把可扩容外部数据与固定大小 θ 对比，可得到特定工程权衡，但不能因此把“加性/竞争性”视为两种角色的内禀性质。

原框架自身也给反例：程序属于 06 的映射通道，却可以追加一个不被旧调用路径使用的函数而不修改旧结果；06 L253 甚至把程序、解码态写成干扰低。这已经否定“所有映射的容量竞争无局部性，失败结构性全局”（L212）。

因此，观察到规模化无干扰写入，最多挑战某种固定预算和算法下的干扰主张，不自动违反有限容量。06 L213、312、320 把它叫容量律违例，应撤回。只有同时固定容量、精度、任意独立信息负载、精确恢复要求和所有辅助信息通道，才谈得上检验所宣称的容量界。

原稿约 0.14N 的联想记忆量级还有模型条件：本次找到更直接的 Amit、Gutfreund、Sompolinsky 1985 一手来源，讨论指定网络模型与稳定态设定。它不能被用于所有深度网络或程序映射的容量证明。06 L209 自己承认向 LLM 是类比，这一限制必须约束后面的推论，见 [容量来源核对记录](#source-capacity)。

对后续 token 比较，容量至少要落到具体测量对象：保存了多少内容、在给定预算下能找到多少、找到后能正确使用多少。扩大磁盘可以直接改善第一项的资源上限，却不能保证后两项同步增长。这个分离同时保留了外部库可扩展的真实优势与检索、消费可能成为瓶颈的事实；不需要把外部 memory 说成无限，也不需要把参数系统说成每次写入必遗忘。

### 8.7 从代价互补到“必须混合”，缺的是可行性证明

05 L153 与 forms2 v7 L1358–1359 已把混合必然限定于高频更新、高密度消费、长期巩固并存。不能将它们误批成无条件命题；但条件写出来仍不代表推理完成。

要对一个明确候选集合证明必须混合，需要至少完成三步：给定工作负载、正确率与资源阈值；证明每个允许的单 form 方案均不满足约束；证明至少一个混合方案满足约束，并计入转换、同步、路由、失效与治理成本。原稿给出的“各有代价”和技术参数敏感性，不等于完成这三步。

还有一个潜在同义反复：若把“长期巩固”先定义成写入参数，再把 token 存储列为其他必须满足的要求，那么多形态已被写进需求。若巩固仅指稳定保存、压缩或提取规律，就必须比较其他实现能否做到，不能预先把参数当唯一答案。

当前可接受的判断是：不同机制的成本分布提供了混合分工的动机；某些明确约束下混合可能必要；本批材料尚未证明其条件必然性。05 附录 L263 的“解决”应理解为作者认为已补论证，本次复核不接受这个完成状态。

<a id="cognitive-reference"></a>
## 9. 认知科学参照与巩固：四种论证载荷不能混用

### 9.1 词汇、启发、机制对应与经验支持

借用“情景”“程序性”“巩固”等词，可以只是在帮助命名；从一个理论提出新问题，是启发；声明两个系统在某些状态、操作和动力学上对应，是机制映射；用实验结果支持关于目标系统的效果，则需要可迁移的证据链。前一种用途不自动升级为后一种。

05 L164–170 把 CLS 从独立裁判收缩为部分映射的启发源，是有效修订。06 L262–263 同样声明参照不是证据，却在 L273–274 又写出结构同构、半同构。若要使用数学意义的同构，需要明确对象、操作、对应关系与保持的结构；当前材料没有做到。若只想说有相似的功能分工，就应该保留较弱且准确的表述。

### 9.2 CLS 的价值在学习机制，不在为三 form 安排脑区

Complementary Learning Systems（互补学习系统）讨论快速记入具体经历与跨经历整合结构怎样协作，以及学习速度、表征重叠、重放和干扰怎样相关。将 token 的快速记录与海马功能作比较，能提出有用问题；它不证明文本库就是海马，也不证明参数更新只有新皮层式作用。

1995 原论证涉及海马与新皮层中的突触变化，不能把两者按物理载体对应成“外部数据 / 参数映射”。2016 与 2020 的更新又讨论海马参与泛化、既有结构一致的新信息可较快整合等情况，不能简化成海马只有逐条记录、新皮层天然慢且独占泛化。参见 [CLS 核对记录](#source-cls)。

06 L265 的书目信息也混合了两篇：Kumaran、Hassabis、McClelland 的 *Trends in Cognitive Sciences* 更新是 2016 年；McClelland、McNaughton、Lampinen 的相关 2020 年文章刊于 *Philosophical Transactions B*。这不独自推翻认知分析，但说明“已核验”标签不能替代回源。

“Latent 在 CLS-1995 中没有一对一位置”只说明当前映射不覆盖它，不能推出它为 LLM 独有或认知科学没有相关参照。06 L137、267 提到快权重等其他理论线，拓宽了比较范围；本轮没有逐篇核验这些理论，故只保留为后续文献入口，不借它们宣告 latent/parametric 必然合并。

### 9.3 ACT-R 支持使用角色分析，不支持双向类别同构

ACT-R 是一种认知架构。此次核对的作者原文以 chunks 描述陈述性知识，以 productions 描述程序性知识，并让规则检索或操作相关状态。这支持一个对本研究非常重要的区分：知识以什么方式被使用，不由保存它的符号或数值基底单独决定，见 [ACT-R 核对记录](#source-actr)。

但 token 中可以保存可执行代码，也可保存关于如何执行的说明；连续参数也可以实现程序性操作。06 L269、273 把 token/控制态与陈述性、解码/程序与程序性作双向结构映射，超出了这个参照能证明的内容。可保留的是功能与消费者的比较问题，不是四组类别天然一一对应。

### 9.4 “通道不存在”与“持续闭环尚待建立”是两件事

05 L170、187 将缺口定位为 parametric 巩固通道；06 L278–279 改成已有蒸馏/回放路径，需关注运行内自动、持续、选择性的迁移。这是实质进步：一个系统能进行一次离线训练，不等于它已形成持续发现经验、决定更新、验证收益并在失败时恢复的闭环。

对具体系统，闭环应追问：哪些经历被保留；什么标准决定选择与转换；结果写到哪里；怎样判断新能力与旧能力；更新何时生效；源与派生物如何同步；错误更新怎样停止或回退。安全也是其中一部分，但不能把全部质量控制缩成投毒检测。

不过，本文没有完成当前全部 agent 系统的普查；06 的验证债务也没有支持“领域普遍缺失自动闭环”这个全称判断。应继承为**具体系统的完成度问题与研究方向**，不继承为已核验的全球现状。某个产品存在后台整理，也不能只凭名称就证明参数巩固、长期稳定和泛化全部实现。

对后续 token 研究，巩固也可以先描述为从零散经历形成更可复用的记忆组织或规则，再明确是否发生跨 form 迁移。若采用专指参数训练的窄含义，应提前声明；否则会把认知词汇悄悄变成必须采用某条工程路线的要求。

### 10.3 “证伪”表里其实包含不同类型的失败

06 L309–314 的条目至少需要分成四类。固定定义下发现无法覆盖的状态，是覆盖主张的反例；新轴不能改善边界裁决，是工具价值不足；KV 压缩改变收益，是经济参数变化；跨通道系统数量不增长，是采用或趋势预测不符。它们都可以促使研究调整，却不是同一种逻辑事件。

尤其，KV 与文本存储大小接近，也不意味着两种接口在加载、版本依赖、语义可读性和生成成本上合并；“桥上居民”不再增长也不消灭已有的实例转换；无干扰更新不自动违反有限容量。因此，能改变工程结论的条件，不等于能证伪分类定义或容量定理的条件。

定义本身是否好用也可以有经验内容。例如，让多个分析者对一组预先固定的案例归类，比较一致性、错误原因和完成任务所需信息，可以评估工具效果。不能仅因数据/映射是一种分析约定，就把所有关于它“更有解释力”的说法免于检验。

### 10.4 本批材料真正留下的研究债务

当前最需要另行验证的不是三名字还该不该保留，而是更具体的问题：在同一任务与预算下，不同实现如何保持和泛化；相同内容在多个实例间如何失真、过时或留下残余；长期写入的干扰来自哪里；何种负载值得转换或缓存；给定系统的持续更新闭环实际完成了哪些环节。

原稿引用的前沿性能数字、论文比例、超线性退化、普遍安全缺口和“最有区分力”等比较主张，本轮没有全量复核。它们可保留在原文中作为研究线索，但不能未经处理进入下一阶段的默认前提。本文也没有训练或运行 agent 行为实验；本次完成的是材料审计、一手关键机制核对、反例与条件分析，以及本地算术和链接检查。

## 11. 后续 token memory 研究可以继承什么，以及如何使用

### 11.1 下一阶段已经拥有的基础

下一阶段可以直接把目标对象放在“跨请求保存符号内容，经选择和组装供后续使用”的机制上研究，无需重新证明三形态唯一、无须先把所有学习定义统一，也无须先证明混合必然。这条路径已经能够解释新信息怎样被保留和调用，以及为什么保留量、选入量和任务效果可以不同。

具体对象的判定也已经落地：文本、选择它的向量索引、从它派生的 KV、生成或消费它的模型参数分别分析；LoRA 与连续前缀按既定实现中的接口角色裁决；复制不取消记忆，普通临时激活不自动构成独立持久混合。遇到这些案例可以直接使用结论，不需要每次重述“多种框架各有道理”。

本轮没有固定下一章的全部维度，只建立了它的对象与可用推论。后续要问的是：同在这条 token 使用路径中的方案，哪些差异会改变保留、找到、理解、更新或任务效果。05 的生命周期与 06 的实例、角色认识已经进入这个问题，不再只是单列的补充阅读。

### 11.2 下游提示词中需要带条件继承的前提

[memory分类](prompts/memory分类.md) 与 [分类2](prompts/分类2.md) 已把上一阶段结论作为下一阶段坐标系的地基。下面这些改写最能防止前提继续失真：

| 下游现有表达 | 后续应采用的条件化表达 | 改写的实际作用 |
|---|---|---|
| 行为由前向计算决定 | 目标模型内容使用经其前向计算；完整 agent 还包括解码、控制、工具与环境回流 | 不漏掉选择与执行角色 |
| 位置屈指可数，构成三个载体 | 在已声明模型、接口和读取视角下使用三形态组织 | 不把项目分类误写成普适定理 |
| 外部符号存储无界 | 外部存储通常可独立扩展，但任何具体资源、时延与治理预算有限 | 允许研究增长、淘汰和维护成本 |
| 上下文有限，因此推出全部设计自由度 | 有限上下文是重要约束之一；任务、来源、更新、可靠性和权限也能产生差异 | 不让一个约束冒充完备推导 |
| Token 读取只能经输入 | 当目标消费者为 LLM 时，符号内容经其输入路径使用；索引与执行另列 | 区分内容使用、选择与程序运行 |
| 存什么、如何组织、如何选择都是独立自由度 | 先尝试分别改变并观察差异，再记录可行性耦合 | 不把概念可分当成统计独立或实现正交 |
| 结构与生命周期完全分章 | 可分研究责任，但写明接口：更新会改变结构，选择依赖组织 | 防止互相排除后出现空白 |
| 分类维度要穷尽 | 在明确对象集合、任务与比较分辨率下检查遗漏，保留新增机制入口 | 避免无范围的完备性承诺 |

这些是本稿给出的分析性修订建议，本轮没有改写原提示词，也不把它们自动升级为用户确认的新研究任务。

### 11.3 不应再作为默认地基的命题

后续不要默认：token 只能诱发已有技能；有检索就不是学习；只有参数变化才可能构成完整系统的学习；缓存可再生就不能参与记忆；三形态已经穷尽 agent 全部状态；latent 统一免 prefill；文本完全可归因；参数一概不可回滚；有限容量必然逐次干扰；各形态各有成本所以必须混合；CLS 或 ACT-R 已证明工程分类同构。

也不需要继续论证“为何研究 token 才合理”。用户已作选择，研究价值来自把该范围内的问题理解透，而非证明其他方向差或永远不可通约。

### 11.4 什么情况才需要重开，什么情况只需继续使用

| 新情况 | 应当重新判断什么 | 不必一起重开的内容 |
|---|---|---|
| 研究时间单位改成单次前向或 token 步 | 哪些临时或持续状态跨越了新边界 | 备份不取消记忆、形态与管理能力分开 |
| 实际模型接口改变，或状态被转换为新的工件 | 新实例、消费者与 form 判定 | 原接口下 LoRA、前缀、文本等已有判例 |
| 任务加入更新、主体隔离、资源或正确率承诺 | 哪些功能成为合格条件、哪些路径仍可行 | 这些功能并非所有 memory 的普遍资格门槛 |
| 新实验改变兼容性、可靠性或成本数值 | 对应实现和负载下的效果与决策 | 成本需同口径、容量不推出逐次干扰等推理关系 |
| 在同一范围与判据下出现无法解释的反例 | 直接修改被反驳的判据或机制主张 | 没有被反例触及的独立判断 |

换术语、追加版本、找到另一种分类或提出尚未测量的更强能力，都不足以让已经收束的命题自动退回未定。反过来，真实反例出现时也不能以“这是项目约定”回避它暴露的遗漏；应明确调整范围还是改变判断。

本轮的完成点是：有明确默认范围、有可以重复使用的典型判例、有解释 token 持续信息适应的机制、有可以计算的具体分工条件，并区分了哪些任务效果尚未验证。后续研究从这些结果出发；不要求本轮先完成全部 agent memory 理论。
