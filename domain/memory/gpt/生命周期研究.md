# 生命周期研究：状态怎样形成、再次生效、修正与转化为经验

> GPT-6（Codex），2026-11-03。依据五问题、Forget、Consolidate、Skill及既有运行综合重建。是对关键研究成果的整合，不是被删文件的逐字恢复；没有新增模型运行或实验。

**本研究已有实质成果：将记忆从“保存一种内容”推进为“维护一条能够持续生效的信息关系”。** 写入、组织、选择、投递、更新、撤销和经验转化各有不同目标，也存在相互反馈。Forget、Consolidate与Skill的价值应从这些目标理解；其少数过强定理有问题，不等于整个操作研究可以删掉。

当前已有完整问题分解、机制条件、构造案例和候选研究路线。缺的是对操作语义的进一步收束、在真实实现中的完整对应，以及需要效果判断时的运行证据。概念澄清本身可以继续推进，不必先搭完整评测系统。

## 1. 生命周期研究已经带来的认识

[五问题模型](../cc/02-core-computation/01-five-questions-model.md)分别问：交互如何形成单元，单元如何组织，当前任务选什么，集合如何维护，选中内容怎样成为本次Context。它的主要价值是把一条信息的变化落到决策位置：同一句错误答案，可能是写入丢掉条件、索引找不到新值、检索取错版本、渲染截断，或模型得到证据后未正确使用。

例如用户先要求“本项目本地处理”，后来改为“允许离线远程批处理，在线查询仍应保持原限制”。写入若只记“允许远程”，已丢范围；原文完整但仅召回旧条目，是选择问题；新旧记录均召回而没有标清有效范围，是投递与解释问题。不能用增加记忆条数同时解决所有环节。

五问题的边界也需要保留：它是token系统的分析清单，不是已经证明完备、正交且可分别最优化的定理。单元粒度会影响索引、检索与最终预算；写入时预先提炼什么，会改变后续任务能够恢复什么；维护后的表示又可能要求重建索引。原稿已描述多处反馈，应该以这些耦合继续深化，而不是用“相互独立”掩盖它们。

[运行综合中的生命周期解释](../../agent-runtime/memory-lifecycle.md)已把控制权、写入时机、更正传播和删除范围加入这一关系。调用内、任务结尾、后台整理和读取时解释，主要是在不同阶段分配等待、计算与信息选择。移到后台可以减少当前响应等待，也会使其他读取者暂时看到旧状态；是否适合需要看下次使用是否依赖刚发生的更新。

## 2. 更新的对象是当前采用关系，历史不必被抹去

同一事实在不同时间或项目范围中成立，不必形成逻辑矛盾。“以前用A，现在用B”可以同时保存在历史中；当前选择B，与回答“当时为何选A”需要不同结果。生命周期因此不能只描述数据库里的字符串替换，还要说明哪个读者在什么时候使用哪一版本。

原始记录、当前状态、摘要、索引、已经组装的输入和在途分支都可能承载旧值。更新其中一个对象，不保证其他对象随即改变；但这也不要求每个系统先维护完整依赖图。小规模资料可以重建派生表示，复杂场景才可能需要更细的来源和依赖管理。真正要解释的是：变化是否到达实际消费处，以及仍存活的旧表示承担什么身份。

来源关系也不是“所有提及同一实体的记录都一起失效”。一段摘要可能由多个独立来源支持，一条事件记录只是在引用旧判断，另一条当前事实才直接依赖它。撤回来源、否定事实、替换当前值和保留历史是不同操作，不能用“关联”一词自动决定级联范围。

## 3. Forget：值得保留的是目标语义与风险分解

[Forget稿](../cc/03-forget-operation/01-why-forget-matters.md)实质提出了四类难点：未来用途未知，误删代价可能延迟出现，删除影响会传播到派生表示，评价必须同时看移除成功与误删损失。这些认识有独立价值。时间、频率、最近访问和重要性都只是未来价值的代理；低频信息也可能是关键约束，高频信息也可能已经过期。

应先确定“遗忘”的承诺：停止本次注入，停止某条查询路径，停用一份记录，移除已知持久副本，还是撤销来源对派生结果的影响。冷存归档能支持误判后的恢复，却不满足销毁原始内容的目标；反过来，物理删除一条源记录也不保证已生成摘要和已执行动作被撤销。目标不同，完成标准就不同。

因此，原稿提出活跃区、冷存区和销毁区的分层有实际研究意义：它把保留全部内容与彻底销毁之间的可选状态显式化。是否采用三层、何时迁移，还需依据任务、恢复成本与明确删除要求，不能把这套设计当作所有系统的必需架构。

原稿“库增长使top-k精度必降”的证明需要撤回。它把全库噪声比例当成被检索概率；精确键查询可以在其他键持续增加时保持正确。因此必须分别研究容量压力、选择干扰和事实过时，而不能从其中任何一项推出硬删除的数学必然性。这个修正减少错误前提，不否定维护选择的价值。

反事实评价仍是可用方向：在可比初始状态和任务条件下，比较移除与保留后的效用，检查错误移除造成什么损失。但原稿“保留成功率－删除后成功率”若被最大化，会奖励伤害，应作为损伤最小化或改正符号。预测模型给出的未来分数也只是估计，不能冒充已知反事实。详细定位已保留在[必要纠错](推理与争议.md)，原稿列举的法律与“唯一基准”等外部断言尚未在此核实。

## 4. Consolidate：三种不同目标不应被压成一个深度数值

[三种模式稿](../cc/04-consolidate-operation/02-three-modes-of-consolidate.md)将去重、摘要和泛化拆开，是这组研究最有用的进展之一。

**去重处理的是可被认作相同的重复。** 两次确认同一偏好，既可能重复，也可能额外证明不同时间仍然适用。合并前应明确要保留哪些事实、来源、时间和范围；字节重复与语义近似不能使用同一种“无损”承诺。它的目标可以是减少重复结果，而不必删除全部来源记录。

**摘要为某种读取目的生成较短表达。** “这次讨论主要有哪些争议”可能只需要叙述摘要，摘要已经是适合的终点，不必再提炼成原子事实才算完成。是否有损要相对于要求保留的内容说明；是否能恢复还取决于原始记录和访问路径是否仍存在。摘要本身的压缩，与系统整体能否补读，应该分别判断。

**泛化提出超出具体案例的新规则。** 它改变了结论作用域，因此比忠实复述承担更强的证明责任。若三次等待后重试成功，仍不能仅由案例数推出“所有类似错误都至少等待60秒”；环境状态、负载、错误类别和其他动作可能同时改变。失败样本和适用条件有助于确定规则边界，却不自动构成因果识别。

[处理深度稿](../cc/04-consolidate-operation/01-processing-depth-spectrum.md)的重要问题是“加工到什么程度才值得停”。但压缩程度、抽象程度、可执行性和任务价值不必沿同一方向变化：一段脚本可以比一句建议更长，却减少运行时重建步骤；一句很短的原则可以适用广，却不足以指导当前操作。未定义估计方法的熵式和示意深度数值暂不能作为测量模型，ROI也需先给共同单位或明确多维比较。

可继承的正向结论是：选择表示取决于未来任务需要保留哪些差异，以及提前加工能否减少反复工作。多种表示共存有时有益，但同时增加一致性和更新责任。这比把所有输出排成从原文到技能的升级阶梯，更接近实际待判断的问题。

## 5. 经验与Skill：形成知识与降低执行重建是两个变化

[经验—技能稿](../cc/05-experiential-skill/01-compilation-interpretation-spectrum.md)指出一条关键差别：自然语言经验由模型每次解释并适配，可调用程序把部分步骤预先固定。后者可以减少重复生成，但仍需选择技能、提供参数、处理异常和验证结果。由此可以研究哪些工作被提前完成，哪些仍留在当前任务。

环境的动作接口、可观测状态和反馈质量影响可固定的程度。稳定接口和可检查结果有助于保存可执行步骤；动态目标和缺少状态信息时，通常仍需运行时判断。但这不是从环境名称就能得到的“100%编译率”：代码可以包含动态分支，语言规则也可能非常固定；同一技能在不同调用方中需要不同适配。

抽象层级与执行方式也不能合成一条轴。某个高层工作流既可由语言描述，也可由程序解释；低层步骤可直接执行，也可每次由模型生成。Skill是否能跨模型复用，还取决于工具协议、选择能力和环境依赖；一次保存并不意味着之后零token、零维护或无损迁移。

原稿对失败经验的强调值得保留：失败实例能帮助发现某规则不适用的条件，避免只存成功路径。但“成功与失败不同”仍不直接证明某个动作是差异原因。相关系统的“首个”“完全可迁移”等判断应回原论文核验；本页把它们保留为待核材料，不当作已确认能力。

## 6. 研究的下一步，不必等同于搭一个大系统

生命周期研究当前可以继续完成一个清楚的对象解释：选择一条会被更正、摘要并转化为步骤的约定，逐项说明原记录、当前值、派生表示和消费事件的责任。然后检查一次更新或撤销，究竟需要改变什么、不需要改变什么。这个最小切片既能检验五问题的边界，也能检验Forget、Consolidate和Skill是否被混用。

若要声称改进质量、节省费用或稳定迁移，再追加相应运行比较；若当前目标是建立概念关系，则应先把关系讲清，不以没有模型实验为由停止理论推进。[统一综合稿](../cc/06-synthesis/01-unified-framework.md)已把这些问题连成地图，但其中沿用的全称定理和深度数值仍要保持各自证据身份。

供其他研究使用的短介绍：生命周期研究已将写入、组织、选择、投递、更新、撤销和经验转化分成不同职责，并说明它们相互反馈。其核心成果是明确操作目标、保留条件与失效位置；下一步是形成可被具体实例检验的闭环解释。分类可以服务于这些操作，也可以发现操作流程仍解释不了的差异，两者关系仍值得专门讨论。
