# 分类维度研究：生命周期已解释什么，还需要哪些额外区分

> GPT-6（Codex），2026-11-03。依据任务原文、载体/多维草稿、综述对照及局部论文正文重新整理。是本轮重建的研究综合，不是被删文件的逐字恢复，也不是已经完成的维度体系。

**本研究真正未闭合的问题，是哪些差异值得成为可反复使用的比较维度，以及它们与生命周期解释怎样互补。** 仓库已有充分候选材料与局部反例，但没有完成从结构约束出发、忠实审计习用分类并对具体对象一致定位的整套论证。重要资产应被保留为可继续研究的材料，不能因为尚未收敛就只留下一个任务标题。

目前不能替用户宣布唯一下一步。仓内同时存在两份不同组织意图：[token分类任务](../mine/prompts/分类2.md)提出载体边界暂不重开，进入token内部维度；[0203分类](../mine/02分类/0203分类.md)明确提出生命周期作为第一主项，再问其他维度是否仍有必要。没有足够证据确定二者的先后继承或最终采纳关系。它们可以构成同一研究的两个观察方向，但需要把接口论证出来，不能只用章节名决定。

## 1. 为什么生命周期很重要，却不自动使额外分类多余

生命周期回答状态怎样随事件变化：怎样形成、保存、找到、使用、更正和退出。它适合解释运行中的因果连接，也能避免围绕“情景/语义/程序”等名词先建存储，再寻找用途。[五问题稿](../cc/02-core-computation/01-five-questions-model.md)已把许多具体设计选择放进这些过程，是有价值的分析基础。

但相同操作序列可以作用于不同表示。两个系统都执行写入—检索—摘要—更新，一个保留带条件和来源的事件，另一个只保留当前原子事实；同样的“检索”可以返回原文、关系或已综合答案；同样的“更新”可以覆盖当前值或追加历史版本。如果这些差异改变可回答的问题、可检查的错误或维护责任，单看步骤名还不能完成比较。

反过来，一个候选维度若只是给流程节点换名字，也无需再设一套分类。例如“读取型记忆”若只是指它在检索阶段被读取，没有增加可区别的机制，就可能只是重复。额外维度的价值，应由它解释了生命周期描述仍然留下的哪种差异来判断。

因此，两种研究意图可以在具体对象上相遇：先追完整流程，再记录在相同或相近流程下仍能改变的属性；又用这些属性反查流程需要承担什么操作。这个方法是本页提出的接续方式，尚未替原任务完成分类裁决。

## 2. 什么使一个比较维度成立

任务原文提出“可独立变化，且变化携带后续研究关心的差异”。它不应被简化成所有属性在所有架构中都能任意组合。实现约束可能使属性耦合；需要说明耦合，不能为了得到工整笛卡尔积而把不可能组合当作设计自由。

当前可采用四个检验问题：分类单位是什么；按什么可观察或可论证的判据区分取值；变化后影响什么研究问题；与已有维度是否重复或依赖。这里“影响”可以是能力、可恢复性、更新语义或可观察边界等概念差别，未必先要求测得平均性能收益。

例如，同一批带来源的事实可以用倒排索引或向量索引定位，说明内容与定位方法不是同一属性。但更换索引可能同时改变候选召回与成本，并不证明两者在所有任务中完全独立。又如一份叙述摘要与一组原子事实可能具有相同长度，却分别保留事件脉络与字段精确性；将其差别称为“压缩深度”会隐去真正变化。

这类对照先验证比较口径是否有区分力，再决定是否形成稳定维度。不是每个差别都必须单列主轴：有些是派生性质，有些是某条路径的实现参数，有些只适合作为解释性描述词。

## 3. 已有候选材料有什么可继承的内容

[forms2](../mine/02分类/forms2.md)后段已经区分存储引擎、表示压缩与组织拓扑，也指出“图”可能同时指数据库、关联结构和检索算法。这是重要的去混叠进展。它还把来源、内容功能、混合实例等问题交给后续研究；这些是明确提出的接口，不等于相应子轴已经被系统证明。

[cc的多维综合](../cc/Memory_Forms综合.md)尝试把载体、内容、时间和作用分开。其有价值的地方，是承认相同内容可以通过不同载体生效、同一形式可以承担不同功能，并主动指出“情景性不等于原文、摘要也可保留时序”。但四维表中的取值仍混合包含关系与不同层次：例如陈述性与情景/语义并非简单四个互斥同级项；时间跨度与工作状态也不能未经论证合并。该稿应作为候选关系与反例库，而非已证明的正交坐标系。

[载体稿](../cc/载体.md)与[评价稿](../cc/评价.md)还提出了来源、主体、范围、可编辑性和未来意图等属性。它们提醒研究不能只看“存什么”，也要看谁持有、为谁服务、当前适用范围及后续行动目标。但评分、组合数量或作者赞同不能替代属性判据。应从同一批具体对象上检验哪些区分有用，再决定保留、合并或降级。

由这些材料可以形成一组待检查的问题，而非现在宣布最终维度：保存的单元及粒度是什么；单元保留哪些条件和来源；单元怎样关联与定位；有效时间和作用域怎样表达；由谁选择和消费；同一材料的不同派生实例怎样对应。它们各自是否独立、归于生命周期还是结构解释，仍需裁决。

## 4. 习用分类应该怎样审计，现有对照哪里已有进展

[跨综述分类研究](../../memory-taxonomy/index.md)与[六篇分类卡片](../../memory-taxonomy/taxonomies-by-survey.md)已经显示，各作者在回答不同问题：形式、功能、操作、控制策略和记忆主体等轴并不一致。这项成果的价值是让引用者先说明作者的对象和边界；并不要求所有论文归到一套新分类，也不能由标签不同直接推出实验不可比。

直接回读[2512.13564本地正文](../../../resources/papers/md/arxiv-2512.13564.Survey.Age%20of%20Agent%20Memory.md)的相关段落后，有三项会影响后续分类的修正：

**RAG的边界不是无交集。** §2.3.2（L274–288）既区分经典知识获取与持续交互形成的记忆，也承认技术、动态化和任务上的重叠。因此“RAG全部不算记忆”超出了原文；比较一种检索基线与一种维护机制，也不要求概念集合互斥。

**KV的边界存在张力，但不能只靠同名证明逻辑矛盾。** §2.3.1（L264–272）Overlap段将用于保存任务信息的KV压缩纳入短期记忆，Distinctions段又排除部分内部状态机制。后续形式章节继续讨论复用和变换。要判断同一对象是否被同时排除和纳入，仍需固定用途、时间边界与操作；旧主文的“内部不一致已证”应收窄为需细化判据的范围张力。

**程序性不能由“无需检索”定义。** §4.2.3（L724–734）明确列出可调用、可验证、可组合的代码、脚本和API，并讨论检索。[经典分类详解](../../memory-taxonomy/cognitive-classes.md)把需要检索的步骤一律划成语义记忆，无法忠实映射这类文献用法。同一脚本改为启动预载或按需加载，改变的是访问策略，未必改变其保存的过程知识和执行关系。

另一个容易遗漏的区别是“论文提到某机制”与“在主分类轴中列出该机制”不同。[2603.07670本地正文](../../../resources/papers/md/arxiv-2603.07670.Survey.Autonomous%20Memory.md)§3.2（L125–137）列context-resident、vector-indexed、structured、executable与hybrid，并未在该枚举中列参数。不能据别处提过权重便说六篇都用同一形式轴；§3.3也已明确讨论启发式、模型自控、学习式控制，故“谁决定读写遗忘”并非本仓首次提出。

本轮直接核对的是以上两篇机器转换正文的相关段落；未逐页校PDF，文件没有vN，版本未知。原论文描述自身分类属于直接来源，论文引用其他系统的能力仍需回原始研究。对人类记忆的科学定义，本页没有新做原始文献核验，不让工程反例冒充认知科学结论。

## 5. 哪些工作会使研究继续，而不是再积累一份分类表

首先，选择同一批对象追完整生命周期，并用对象说明候选属性：一条原始事件、一条带来源的当前事实、一份叙述摘要、一个检索后执行的脚本。每增加一个维度，都说明它保留了哪项原先无法清楚表达的差异，以及是否能与已有区分合并。

其次，对习用分类按最强实际用法审计。情景/语义可追问信息是否保留特定事件关系，不能只按原文/摘要判；程序性可追问保存的过程与消费者，不能只按是否可言述或是否检索判；短期/长期可分别追问保存时长、有效期和读取频率，不能让一个词代理全部时间性质。

最后，明确生命周期与分类的分工结论。如果某个差别已经被写入、选择、变换与撤销的关系充分解释，就无需再建重复主轴；若相同流程下仍存在会改变问题答案的结构差异，应保留额外维度。此时才有依据决定章节组织，不能先宣布其中一个方向唯一正确。

供其他研究使用的短介绍：本课题已经积累多套分类候选、跨综述对照与关键反例，尚未完成统一维度集。它研究的是哪些差异能帮助稳定比较系统，以及生命周期解释后还需补什么。载体研究提供消费接口，生命周期研究提供过程关系，分类研究检验剩余差异及习用术语；三者可以互相约束，当前没有证据要求删除其中任一研究。
