# 记忆的载体：token、parametric 与 latent

> **定位**：地基性参考文档。后续所有章节默认此处判断成立。本文按四条要求写成：详尽（覆盖优先于篇幅）、准确（机制按机制写）、无偏（描述性陈述）、第一性原理（论证起点是计算问题）。
>
> **研究立场**：允许破坏式重构。若第一性原理推导发现框架问题，可重构整个结构。论证优先于维护现有结论。

## §1 引言：冻结的前提

### 1.1 冻结

Agent memory 研究的全部前提可以压缩为一个事实：**基座模型在部署之后参数冻结**。预训练结束，参数 θ 不再随使用而改变，模型以只读函数的形式提供服务。

这一冻结并非技术必然，而是经济必然。单次梯度更新的开销是单次前向传播的数个数量级；若每次会话都触发训练，服务的成本结构无法成立。于是学习成本被一次性摊销到预训练阶段，此后模型作为固定函数运行。

冻结制造了一道结构性裂缝：**模型的知识存量在部署时刻成为常量，而世界的信息增量持续产生**。Agent memory 的研究问题即在于：如何让一个常量的函数，应对一个增量的世界。

一个值得记录的历史细节：在 agent 范式之前，"记忆"并未构成独立研究对象——训练本身即记忆，每一步梯度下降都是一次写入，模型的知识即其训练轨迹的凝固。冻结之后，记忆才第一次从训练中剥离，成为需要独立设计的系统组件。这是 agent memory 作为研究领域的诞生时刻。

### 1.2 判据：什么构成记忆

考虑一次普通的前向计算：模型在该次计算中"包含"了全部输入 token——但这是**当下**，不是记忆。本文采用的判据是：

> **定义（记忆判据）**。设信息 i 在时刻 t₁ 的计算 C₁ 中产生或出现。若存在机制，使 i（或其变换）在 t₂ > t₁ 的另一次计算 C₂ 中影响计算结果，则称该机制实现了对 i 的记忆。

使信息成为记忆的，不是它被存储，而是它**能够跨越计算边界存活**。由此，任何记忆系统必然包含两个功能组件：**持久化介质**（信息在两次计算之间的存身之处）与**重注入机制**（信息重新进入后续计算的通道）。

**粒度说明**：本文显式定义"计算"为**单次前向传播**。这一粒度选择的后果需正面承认：按此粒度，会话内跨轮 KV 复用已满足记忆判据（第一轮信息影响第二轮计算）。这与某些工程直觉中"会话内状态不是记忆"的看法冲突。本文的处理是：承认这是判据的自然结论，跨请求与会话内的区分是产品层裁量，不是本体层跃迁（§5.3 详述）。

### 1.3 记忆系统的算子分解

无论载体为何，一个完整的记忆系统可分解为五种算子：

- **写入 W**（经验→存储项）
- **存储 S**（维护记忆的物理存在）
- **读取 R**（推理时选择并注入）
- **更新 U**（修改或合并）
- **遗忘 F**（淘汰）

本文的核心论点是：**三类载体是这五种算子在三个不同物理位置上的实例化；位置的不同导致算子的实现方式、成本结构与失败模式产生根本性分野。**

注意，五算子是分析工具而非分类——本文不使用它对任何记忆内容或功能做分类。

## §2 三个物理位置

### 2.1 前向计算的信息解剖

设冻结模型 M(θ)，输入序列 x = (x₁, …, xₙ)。前向计算中，与信息相关的物理存在只有三处：

1. **输入序列 x**——信息进入计算之前；
2. **模型权重 θ**——计算赖以进行的通道，冻结条件下为常量；
3. **中间激活**（各层 K/V 张量、hidden states）——信息在计算中流动时的瞬时状态。

需排除两个看似候选的位置：

**其一是输出**：输出位于计算出口，要再次影响计算，必须作为后续输入进入序列（自回归的当下延续），或被写成文本保存（后者已落入 token 载体的写入来源）。输出不是独立的持久化位置。

**其二是梯度通道**：反向传播本来是信息写入权重的通道，冻结恰恰意味着该通道被关闭——parametric memory 的本质，正是有代价地重新打开这条被冻结关闭的通道（§4.3 详述）。在冻结前提下，梯度通道不可用，故不在三个位置之列。

### 2.2 穷尽性命题：为什么恰好是三个

> **命题（载体的穷尽性）**。在基座冻结的前提下，任何使信息跨计算存活的机制，其记忆载体必居三者之一：**token**（使输入持久）、**parametric**（使通道持久）、**latent**（使中间态持久）。

这不是分类学惯例，而是关于计算结构的推论。推导如下：

**第一步：表征形式轴**。信息在计算上只能以两种形式存在：离散符号序列，或连续实值向量。这是模型处理信息的两种基本表征，无第三种。

**第二步：读取方式轴**。状态进入计算的方式只有两种：
- **隐式读取**：状态即权重，无需单独的读取步骤，每一次前向传播都自动携带全部权重。
- **显式读取**：状态作为独立的数据结构存在于权重之外，需要一次单独的注入操作才能参与计算。

**第三步：组合与排除**。两轴交叉至多给出四个格子：

| 表征形式 | 读取方式 | 格子 | 是否存在 |
|---------|---------|------|---------|
| 离散符号 | 显式 | 格子 A | **存在** → token 载体 |
| 连续向量 | 隐式 | 格子 B | **存在** → parametric 载体 |
| 连续向量 | 显式 | 格子 C | **存在** → latent 载体 |
| 离散符号 | 隐式 | 格子 D | **空的** |

**格子 D 为何是空的**：离散结构一旦折叠进权重并被隐式读取，其在计算上就表现为连续权重的效应，不再保有离散性。任何在权重中保留离散码本（如 codebook、lookup table）的方案，读取时仍需一次显式查表操作（从 ID 到向量），故归入显式一侧（格子 A 或 C）。

**结论**：计算上存在的载体恰好是三个。这不是研究者偏好的分类学选择，而是由"状态可以放在哪里"这个计算问题的结构唯一确定的。

**与文献的对照**：arXiv 2512.13564（2025年12月）明确提出 token/parametric/latent 三分法；arXiv 2602.06052（2026年1月）将其列为主分类轴；arXiv 2603.07670（2026年3月）称之为 substrate。本文的推导路径与文献结论一致，但推导本身是独立的——从计算结构出发，而非从文献归纳。

### 2.3 归类判据：以读取时刻为准

本文采用的归类纪律需要先行确立，因为它贯穿所有后续判例：

> **判据**。混合系统的归类，以**读取时刻**信息所处的载体为准，而非写入时使用的技术。

**理由**：载体分类的对象是"记忆如何生效"，而非"记忆如何被制造"。写入技术可以在任何载体间借用（例如：用梯度训练生成软提示向量，但读取时作为 latent 注入；用 LLM 抽取文本，但经训练折叠进权重后成为 parametric），但生效位置由计算结构唯一决定。

**判例集见 §6.2**。这里先给一个典型案例说明判据的使用：

- **MemGen 类系统**：写入时动用 RL + LoRA（parametric 技术），但生成的记忆以 latent token 的 KV 形态注入计算。按读取时刻判据，归入 **latent** 载体。写入技术不决定载体归属。

## §3 Token 载体

### 3.1 定义与机制

> **定义（token 记忆）**。模型 M(θ) 冻结；维护外部记忆库 D（符号集合）；每次推理执行检索 r(q, D) → S ⊆ D，将 S 序列化后与查询拼接，模型计算 M(θ; q, S)。信息影响计算的唯一通道是输入 token 序列。

结构上，token 记忆是一个**围绕冻结模型外围的信息检索与注入系统**——模型本身完全不知晓记忆的存在，记忆对模型而言只是上下文的一部分。

**五算子的实例化形态**：
- **写入**：文本生成（无梯度），或被动记录原始对话
- **存储**：任意外部介质（文件系统、向量库、关系数据库、图数据库）
- **读取**："检索 + 拼接"的显式动作，受上下文窗口与 token 成本的注入预算约束
- **更新与遗忘**：文本级操作（字符串编辑、条目删除）

全部算子均以 API 调用完成，全程不触碰模型内部。

### 3.2 设计自由度：token 内部分化的必然性与悬置

token 的写入在物理上只有一条约束：**可序列化为文本**。文本操作没有形态限制——可以存原文、存摘要、存结构化事实、存图、存树、存任何构造物。

这与其他两类载体形成鲜明对照：
- **Parametric** 的写入形状由优化动力学决定（梯度下降的收敛要求、损失函数的形状）
- **Latent** 的写入形状由张量几何决定（维度匹配、位置编码兼容性）
- **Token** 的写入形状完全由设计者决定

由此得到一个载体级推论：**token 载体的设计自由度最大，因此其内部必然产生分化，且分化是多维的。**

正因如此，本文对 token 内部的组织方式保持克制——直觉在讨论这些分化时极易把三件不同的事混为一谈：

- **存储引擎**：向量库、图数据库、关系库——工程介质的选择
- **信息压缩度**：原文、原子事实、摘要——写入路径的有损变换档位
- **组织拓扑**：平坦、树、图——条目间的关联结构

三者正交：同一份原子事实可以放进向量库也可以放进图库；图拓扑下组织的既可以是原文也可以是摘要；"图"一词更是同时跨越了引擎（图数据库）、拓扑（图结构）与检索算法（图遍历）三个层面。

对这三根子轴的分别分析——它们各自的谱系、取舍与组合方式——是后续章节的任务。本文只确立载体级事实：**写入自由度最大意味着设计空间全开放；这既解释了 token 何以成为工程主流（无物理门槛），也解释了为什么对它的内部分类必须推迟到专门章节（过早分类会在混淆的轴上锁死框架）。**

### 3.3 成本结构与性质

**成本结构：写便宜，读贵，且反复付费。**

- **写入成本**：一次性的 LLM 调用（若需抽取/摘要），或零成本的被动记录（若存原文）
- **存储成本**：外部存储的边际成本极低（相对于模型推理）
- **读取成本**：每次生效都占据上下文窗口、付出推理成本。同一记忆被使用一千次，就支付一千次注入成本。

Token 是**订阅制**的记忆。

**工程性质由"载体是通用文本"派生**：

- **模型解耦**：记忆库与模型可独立更换，记忆资产独立于模型存续。换一个底层模型（如从 GPT-4 到 Claude），记忆层不需要动。
- **可回读**：人类可直接阅读每一条记忆——可审计、可版本管理的基础。
- **可迁移**：跨系统、跨供应商迁移时记忆保留。
- **合规可操作**：被遗忘权、数据删除要求在字符串粒度上可精确执行。

这是 token 在工程落地中占绝对多数（§8.1）的根本原因——不是因为效果最优，而是因为它是三类中唯一**可运营**的。

### 3.4 失败的可见性

Token 的失败集中而可见：
- **读取端**：召回失败（相关记忆未被检索）、精度失败（检索到不相关内容）
- **注入端**：噪声挤占注意力、长上下文中的位置偏置
- **写入端**：抽取丢失信息、摘要过度压缩
- **维护端**：新旧记忆冲突未消解、过期信息未淘汰

可见性本身是资产：错误可定位到具体条目与具体检索决策——可归因，可修复。工程上可以针对每个失败环节设计改进（更好的检索算法、更精细的抽取提示、冲突检测机制）。

**与 RAG 的边界**：token 记忆与 RAG 在载体轴上不可区分——二者都是"检索文本并注入 prompt"。区分落在"检索对象的来源"上（agent 自身经历 vs 外部静态知识），属其他轴的管辖。本文在 §6.2 判例表中专门标注这一判别力边界。

## §4 Parametric 载体

### 4.1 定义与机制

> **定义（parametric 记忆）**。通过梯度更新 θ → θ′ 将信息写入权重；读取无显式操作，查询 q 直接进入 M(θ′)，信息以模型行为的方式涌现。

Parametric 与 token 最深刻的差异发生在**读取端**：token 有一个显式的、可观测的读取动作，parametric 没有。一条事实被写入权重后，不存在任何操作叫"读取这条事实"——它弥散在数百万权重的调制之中，由整个网络的协作计算重构出来。

### 4.2 与预训练的关系，及写入的机制基础

层级关系须先澄清：**预训练知识本身就是 parametric 记忆**——冻结的基座即是一个巨型参数记忆库。Agent 语境下的 parametric memory 特指**预训练之上的增量写入**。

写入的机制基础来自一个关键发现：Transformer 的 FFN 层在功能上近似 key-value memory——中间神经元匹配输入模式（key），输出向量近似指向词汇空间的语义分布（value）。Meng et al. (2022) 的因果追踪实验表明，事实性知识大量存储于中层 FFN。这一发现是知识编辑方向的支点：知识既然有近似定位，就有近似的定向修改可能。

### 4.3 写入通道：重开被冻结关闭的梯度

冻结关闭了梯度通道；parametric memory 的写入，本质是**有代价地重开它**。按写入的空间范围与精度，存在一个从粗到细的连续谱：

**全参数更新**（fine-tuning）：写入整个通道。代价是与存量知识全面相互干扰（灾难性遗忘）。适用场景：领域适配、任务专门化。

**低秩增量**（LoRA、adapter）：将写入约束在冻结主干之外的 ΔW = BA 上，其中 B、A 是低秩矩阵。优势：写入便宜、可插拔、可关闭、多个 adapter 可按需切换。代价：表达能力受秩限制。WISE 等系统将 LoRA 作为模块化记忆机制使用。

**定向修改**（ROME、MEMIT）：借 §4.2 的定位结果，对特定层的特定投影做手术式修改。ROME 将修改建模为闭式线性系统求解；MEMIT 扩展到批量编辑。优势：精度最高，单个事实的写入开销小。代价：牵连效应（修改波及无关推理）、顺序编辑的叠加退化（后续编辑污染前面编辑的效果）。

**注意**：这个"粗细谱"本身也是后续章节的候选讨论对象，此处仅作为写入通道的物理描述，不构成对 parametric 内部技术路线的分类承诺。

### 4.4 成本结构与性质

**成本结构与 token 完全对称反转：写贵，读免费。**

- **写入成本**：离线训练（GPU 时间、数据管线、回归评测）。即使是定向编辑，也需要因果追踪、矩阵求解、验证集测试。
- **读取成本**：零边际成本。Parametric 记忆的读取即普通推理，不增加计算量。
- **成本摊销**：写入成本被无限次读取摊薄。Parametric 是**买断制**的记忆，适合高频复用、低频变化的知识。

**性质由"信息弥散于权重"派生**：

- **无地址性** → **不可定向删除**：不存在"删掉这条事实"的操作，只有重训或等待自然遗忘（通过后续训练覆盖）。
- **不可回读**：无法从 θ′ 读出写入过什么。审计与合规在记忆级别上不可能——只能通过行为探针间接观察。
- **时间无表示通道**：权重是纯函数参数，一次前向没有"现在"的概念。梯度更新虽有时间顺序，但收敛后顺序效应湮灭为不可读的动力学痕迹。时间信息无法在 parametric 载体中显式表示（见 §7.1 总表）。

### 4.5 记忆与推理的不可分离性（核心论点）

读取端没有操作，意味着**不存在"使用记忆"的可辨识时刻**。

**与另两类载体的对照**：
- **Token 记忆的使用有明确边界**：检索发生（调用向量检索 API）、注入发生（拼接到 prompt）、模型开始阅读（前向传播从拼接点开始处理）。三个时刻都可观测、可打断、可度量。
- **Latent 记忆的使用也有边界**：张量拼接发生在哪一层的哪一步是确定的（如在第 0 层 attention 之前拼接 KV cache）。注入时刻在计算图中有明确位置。
- **Parametric 没有边界**：写入权重的事实与模型固有能力之间的边界，在计算图中不存在任何对应物。θ′ 的每一次前向传播都携带全部权重，无法区分"这次计算用了记忆"与"这次计算只用了推理能力"。

由此产生一个**构成性的（而非仅仅是工程性的）后果**：**parametric 记忆的贡献无法与模型能力的贡献相分离**。

当模型答对一个问题，没有任何手段区分：
- "因为它记得"（权重中存储了这条事实）
- "因为它会推理"（从已知前提推导出答案）
- 两者的某种组合

**向下投射：评测的根本困难**

Parametric 记忆的评测只能通过**编辑前后的行为差异**间接测量：
1. 编辑前测试：模型对事实 f 的回答
2. 执行编辑：将 f 写入权重
3. 编辑后测试：模型对 f 及相关问题的回答

评测指标（zsRE、CounterFact 等）测量的是行为变化，不是"记忆质量"这个独立维度。

对照：token 记忆可以独立评测**检索质量**（召回率、精确率、MRR），这个指标与下游任务性能解耦。Latent 记忆可以独立评测**压缩质量**（重建误差、压缩比）与系统指标（延迟、吞吐量）。

**向上投射：概念问题**

当记忆与能力不可分，"记忆"在 parametric 载体中还剩多少独立内容？这不是本文回答的问题，但需要标注为开放问题：parametric 是否应该被称为"记忆"的一种形态，还是应该被重新归类为"知识"或"能力"？文献中存在分歧，本文承认这一分歧而不强制收敛。

### 4.6 失败模式

Parametric 的失败模式全部**不可见**——湮没在权重深处，无法归因到任何可指认的位置：

- **灾难性遗忘**：写入新知识损伤存量知识。经典现象，在序列学习中广泛观察到。
- **编辑的牵连效应**：定向修改波及无关推理（修改"埃菲尔铁塔在巴黎"后，模型对"法国首都"的回答也改变），或改了事实而关联推理不跟随（修改"巴拉克·奥巴马的妻子是 X"后，询问"X 是谁的妻子"仍答旧值）。
- **顺序编辑的叠加退化**：Mitchell et al. (2022) 在 MEMIT 上观察到，数百次顺序编辑后精度显著下降，甚至出现"致残编辑"使模型整体失效。

对照：token 失败可定位到具体条目（"检索召回了错误的文档 #42"），latent 失败可定位到具体张量（"第 5 层的 KV 被过度压缩"），parametric 失败只能说"模型行为退化了"。

## §5 Latent 载体

### 5.1 KV cache 的机制回顾

自回归生成中，第 t 个 token 依赖全部前文；若每步重算前文各层的 K/V 投影，总计算量为 O(n²)。KV cache 的工程解法：每层的 K/V 只算一次、存下复用。

KV cache 因此是推理系统的标准组件——**本职是计算优化，算完即弃**。典型流程：
1. Prefill 阶段：处理输入序列，为每层每个 token 计算并缓存 K、V
2. Decode 阶段：逐 token 生成，每步只计算新 token 的 K、V，与缓存拼接后做 attention
3. 请求结束：缓存销毁

Latent memory 的核心洞察是换一个视角看这批张量：**KV cache 里存的，是模型对前文的处理结果**——每一层的 K/V 编码了前文 token 在该层 attention 下的角色。丢弃它们，下次就要重新计算"理解"；保留它们，就是保留"理解"本身。

### 5.2 定义与注入点

> **定义（latent 记忆）**。将前向计算的中间产物以张量形式持久化，并在后续前向计算中直接注入复用，跳过"从 token 重新计算"的环节。

注入点恰好覆盖前向计算的三个阶段：

1. **KV 张量拼接**（attention 层入口）：主流形态。将持久化的 KV 条目拼接到当前请求的 KV cache 前端。
2. **Hidden states 拼接**（层间）：如 Memorizing Transformers，将记忆的隐状态作为额外的 attention 对象。
3. **连续向量作为前缀嵌入**（embedding 层）：即 soft tokens / continuous prefix，如 prompt tuning。

这是 latent 作为"第三位置"的完整性佐证——三种注入点分别对应计算流程的三处间隙（输入层、注意力层、中间层）。

**与 token 的根本区别**：
- **Token**：让模型重新理解一遍文字（token → embedding → 逐层变换）
- **Latent**：直接保存并复用模型上次理解的结果（跳过 embedding 与部分变换）

### 5.3 记忆临界点：何时是优化、何时是记忆

KV cache 何时成为记忆？这是锐化 latent 边界的关键问题。

**会话内**：KV cache 是当前上下文的注意力缓存，请求结束即销毁——此时它是**计算状态**，是推理引擎的优化对象。按本文 §1.2 的记忆判据，会话内缓存不满足"跨计算存活"（同一次前向传播的不同步骤不算不同计算）。

**跨请求持久化**："上一次的计算结果"存活到了下一次计算——信息在 t₁ 的计算 C₁ 中产生（生成 KV cache），在 t₂ > t₁ 的计算 C₂ 中影响结果（复用 KV cache）。按 §1.2 判据，**这一刻它升格为记忆**。

> **判据（记忆临界点）**：会话内缓存是系统优化；跨请求可复用的持久化 KV 才是记忆。

**工程形态上，这一临界点已被跨过**：

- **前缀缓存**（Prefix Caching）：多个请求共享相同前缀（如系统提示词）时，将前缀的 KV cache 持久化并跨请求复用。Anthropic、OpenAI 等服务商已产品化。
- **跨会话 KV 复用**：将用户对话历史的 KV cache 存储在用户会话中，新一轮对话直接加载。
- **压缩与生成**：SnapKV、H2O、PyramidKV 等方法对 KV cache 做剪枝或压缩后持久化；AutoCompressor、gist tokens 训练压缩模块生成"记忆向量"。

从压缩、生成到定点操作的多条路线，都属 latent 内部的设计分化，按本章纪律悬置至后续讨论。

**粒度说明的后果**：按本文"计算 = 单次前向传播"的粒度定义，会话内跨轮复用已满足记忆判据。这与某些工程直觉冲突（"会话内不算记忆，只有跨会话才算"）。本文的处理是：承认这是判据的自然结论，"会话内 vs 跨会话"的区分是**产品层裁量**（何时销毁状态、何时持久化），不是**本体层跃迁**（状态性质的根本改变）。读者若采用不同粒度定义（如"计算 = 整个会话"），临界点会相应移动，但推理框架不变。

### 5.4 存储成本：算例

FP16 精度下，每 token 的 KV 体积为：

```
2 (K + V) × n_layers × n_kv_heads × d_head × 2 bytes
```

具体算例：

- **Llama-2-7B**（MHA，32 层，32 头，d_head=128）：
  - 每 token ≈ 2 × 32 × 32 × 128 × 2 = **524,288 bytes ≈ 512 KB**
  - 10K context ≈ **5 GB**

- **Llama-3-8B**（GQA，32 层，8 个 KV 头，d_head=128）：
  - 每 token ≈ 2 × 32 × 8 × 128 × 2 = **131,072 bytes ≈ 128 KB**
  - 100K context ≈ **12.8 GB**

**对照**：同一 100K token 的文本本体约 0.4 MB（UTF-8 编码，平均每 token 4 字节）——同一内容的 token 形态与 latent 形态相差 **3–4 个数量级**。

Latent 的成本结构由此清晰：

- **写入成本**：写即计算（KV cache 是 prefill 的副产品），无额外开销
- **读取成本**：近乎免费（张量拼接，O(1) 操作）
- **存储成本**：极重——为"保存"本身持续付费，三类载体中独一份

### 5.5 性质

**不可回读**：张量对人不可读。虽然理论上可以从 KV cache 解码出文本（通过 attention 反向操作），但这属于重新生成而非保真回读——生成的文本不保证与原文一致。

**版本绑定**：绑定特定权重与推理配置。KV cache 只对产生它的那组权重、位置编码实现、量化方案有意义。任一改变即作废：
- 权重更新（如模型从 v1 fine-tune 到 v2）→ KV cache 失效
- 量化方案改变（FP16 → INT8）→ KV cache 失效
- 位置编码改变（如从 RoPE 切换到 ALiBi）→ KV cache 失效

这与 parametric 更新构成**结构性冲突**：若对模型做 parametric 写入（fine-tuning、LoRA 追加），所有已存储的 latent 记忆即成为"孤儿"——张量仍在，但对新权重无效。

**坐标可寻址**：KV cache 按 (层，头，位置) 组织，可在指定坐标上做定点操作——这种精细度在 token（只能整条删除）与 parametric（无地址性）处均无对应物。H2O 按"重击者"逐 token 驱逐，SnapKV 按头投票逐 token 保留，都利用了这一性质。

**失败不可见**：一个被压缩失真的记忆，没有页面可翻开来检查它错成了什么样子。只能通过下游任务性能间接观察。

## §6 边界与判例

### 6.1 裸上下文窗口：token 内容跑在 latent 载体上（收拢全局的观察）

一个收拢全局的观察：**裸上下文窗口本身，就是 token 形态的内容跑在 latent 载体上的实现**。

**机制**：每轮输入的 token 序列，进入模型后立即被转写为 KV cache（latent 形态）参与计算。模型从不直接操作离散 token——token 经过 embedding 层后即成为连续向量，经过各层 attention 后成为 KV cache。

**两个侧面**：Token 记忆与 latent 记忆因此面对**同一个物理对象的两个侧面**：

- **Token 记忆（内容侧）**：问"往窗口里注入什么内容"。关注点是检索策略、信息组织、压缩粒度。
- **Latent 记忆（载体侧）**：问"如何持久化、压缩、复用窗口的计算态"。关注点是 KV cache 管理、张量压缩、跨请求复用。

**成本交汇点**：Token 记忆的读取成本中，隐含着 latent 载体的预填充计算成本。"检索并注入 1000 个 token"的成本包含：
1. 检索成本（向量检索、排序）
2. Prefill 成本（将 1000 个 token 转为 KV cache）
3. Decode 成本（每生成一个 token，与 1000 个 KV 条目做 attention）

两类载体在成本上共享同一个计算瓶颈（prefill），但优化方向不同：
- Token 侧优化：减少检索量、提高检索精度
- Latent 侧优化：压缩 KV cache、复用已计算的 KV

这个观察说明：载体分类不是系统的互斥划分，而是看待同一计算过程的不同视角。

### 6.2 判例表

按 §2.3 判据（读取时刻为准），对若干边界案例做归类：

| 系统 | 写入技术 | 读取时刻载体 | 归类 | 判例意义 |
|---|---|---|---|---|
| Token 记忆系统<br/>（Mem0、Letta等） | LLM 抽取 | Token 注入 | **Token** | 标准形态 |
| 系统内嵌的<br/>向量索引 | Embedding 化 | **从不进入<br/>前向计算** | **不是 latent** | Latent 要求"以激活形态进入计算"；仅用于检索匹配的向量不满足——这是 latent 定义的精确化 |
| WISE 类<br/>（LoRA 银行+路由） | LoRA 追加<br/>+ router | 进入某个参数化<br/>实例生效 | **Parametric** | 虽模仿外部存储的追加结构，生效位置在权重 |
| MemGen 类 | RL + LoRA | 以 latent token<br/>的 KV 形态<br/>进入计算 | **Latent** | 写入动用 parametric 技术、读取在激活空间——读取时刻为准 |
| 为用户语料<br/>预填充后<br/>跨会话复用的 KV | 一次 prefill | 张量拼接 | **Latent** | Latent 最纯粹的产品化形态 |
| RAG<br/>（外部静态语料） | 无写入<br/>（预存在） | Token 注入 | **Token 载体形态** | 载体轴**无法**区分它与 token 记忆——二者的区分落在"检索对象的来源"上，属其他轴的管辖；此判例标定本轴判别力的边界 |
| Soft prompts<br/>（prompt tuning） | 梯度训练 | 连续向量<br/>前缀注入 | **Latent** | 写入动用 parametric 技术，但读取是显式注入，不是隐式全量携带 |

**最后一行值得强调**：**载体轴的判别力是有边界的**——它能回答"记忆如何生效"，不能回答"什么算记忆、算谁的记忆、用于什么目的"。后一类问题需要其他维度（来源轴、功能轴、主体性轴），本文刻意不做覆盖。

## §7 载体的对比

### 7.1 总表（经审计）

本表经逐行审计，两处修正：

1. 原"信息保真"一行缺乏参照系（保真相对什么而言？Token 相对原文是转写、parametric 是行为化、latent 是确定性中间态——三者不在同一参照系上不可比），已并入"回读与可审计"一行。
2. 原"时间语义"一行将"token 天然携带时间戳"误写为载体属性（时间在 token 中是**可表示的**，表示与否是设计选择），修正为"时间的可表示性"。

另新增三行：记忆与计算的关系、与模型的解耦度、设计自由度。

| 维度 | Token | Parametric | Latent |
|---|---|---|---|
| 物理位置 | 输入序列（离散符号） | 模型权重 | 激活空间（连续张量） |
| 写入通道 | 文本操作（无梯度） | 重开被冻结关闭的梯度通道 | 前向计算的副产品 |
| 读取 | 显式：检索 + 拼接 | 隐式：与推理无边界 | 张量拼接（近零开销） |
| **记忆与计算的关系** | **外置：读取后仍需理解** | **无界：记忆即能力，使用时刻不可辨识** | **内置：读取即计算态** |
| **成本位置** | **读端（订阅制）** | **写端（买断制）** | **存端（为保存持续付费）** |
| 信息形态 | 离散、可回读 | 弥散、无地址 | 连续、坐标可寻址 |
| 回读与可审计 | 可回读、人可读 | 不可回读 | 不可回读 |
| 时间的可表示性 | 有通道（设计选择） | 无通道（顺序效应湮灭） | 仅序列位置，无事件时间 |
| **与模型的解耦度** | **解耦：记忆宿主在外部，独立存续** | **同一：记忆即模型本体** | **版本绑定：有效性系于特定权重与推理配置** |
| 编辑的物理形态 | 文本操作 | 需动权重（牵连） | 张量定点操作 |
| 遗忘的物理形态 | 介质销毁（可定向） | 不可定向，只能被覆盖 | 预算淘汰 |
| 失败可见性 | 可归因到条目 | 湮没于权重 | 湮没于张量 |
| **设计自由度** | **无物理约束，组织空间全开放** | **受优化动力学约束** | **受张量几何约束** |
| 代表系统 | Mem0、Letta、Zep | WISE、知识编辑谱系 | 前缀缓存谱系、MemGen |

**表中三处需要正文补强**：

**记忆与计算的关系**（新行）是本表最深的一行。

- **Token** 的记忆在计算之外——读取后模型仍要从 token 重新理解。记忆是输入的一部分，不是计算本身。
- **Latent** 的记忆在计算之内——记忆本身就是计算状态。保存的是"理解的结果"，不是"待理解的内容"。
- **Parametric** 的记忆与计算**无边界**——不存在"正在使用记忆"的可辨识时刻（§4.5 已详述）。

这一行同时决定了三者的评测形态：
- Token 可测**检索质量**这个独立环节（召回率、精确率、MRR）
- Latent 可测**压缩与复用**的系统指标（重建误差、压缩比、延迟降低）
- Parametric 只能测**编辑前后的行为差异**（zsRE、CounterFact 等基准）

**设计自由度**（新行）回答了本文与后续章节的接口问题：

- **Parametric 与 latent 的内部主要是工程问题**：在物理约束下把写入/存储做好。Parametric 受优化动力学约束（梯度下降的收敛、损失函数的形状），latent 受张量几何约束（维度匹配、位置编码兼容性）。
- **Token 的内部是设计问题**：组织空间全开放，选择空间巨大。这就是为什么后续章节注定长在 token 里：不只是占比问题，而是唯有它拥有需要专门分析框架的设计空间（§3.2 已述）。

**与模型的解耦度**（新行）统摄了原表的"迁移性"并更深一层：

- **Token** 记忆的宿主是外部介质，模型存亡不影响记忆资产。换基座模型（GPT → Claude → Gemini）时记忆保留。
- **Parametric** 记忆与模型是同一物。删除模型即删除记忆。
- **Latent** 记忆虽可存于任何张量存储，但其**有效性**系于特定权重版本——权重一变，存下的张量即成为不可用的"孤儿"。这是三者中最脆弱的绑定关系。

### 7.2 三种经济学

表中分量最重的一行仍是**成本位置**。**每一个记忆设计决策，本质都是在选择把成本放在哪里**：

- **Token 放读端**：其内部一切设计——压缩、组织、检索优化——都在与"每次读取付费"搏斗。降低读取成本的策略：更精确的检索（减少注入量）、更激进的压缩（每条记忆占更少 token）、层级组织（先检索摘要再展开细节）。
  
- **Parametric 放写端**：写入必须批量、离线、充分评测。单次写入的高成本迫使系统采用批量编辑策略，并在写入前做严格的回归测试。增量写入（如 MEMIT）试图降低单次写入成本，但仍需要因果追踪与验证集。

- **Latent 放存端**：其内部设计——淘汰、压缩、生成——都在与"保存持续烧钱"搏斗。降低存储成本的策略：激进压缩（H2O、SnapKV）、选择性保留（只保留"重击者" token）、低秩近似（MLA）。

这根成本透镜将在后续章节继续使用：token 内部的各种分化，骨子里仍是读写成本的再分配。

### 7.3 不可通约性（核心论点）

三类载体表面都在解决"让 agent 记住"，实际分属**三个学科**：

**Token 的核心问题**：表示、写入、检索、更新——**信息检索与数据库工程**的问题。母学科：
- 信息检索传统（BM25、TF-IDF、神经检索、dense retrieval）
- 向量检索产业（FAISS、Milvus、Pinecone）
- RAG 生态（LangChain、LlamaIndex 等框架）
- 数据库社区（图数据库、知识图谱、时序数据库）

**Parametric 的核心问题**：不破坏存量地写入增量——**持续学习与知识编辑**的问题。母学科：
- 灾难性遗忘研究（自联结主义时期起即是核心议题）
- 知识编辑方向（ROME、MEMIT、近年发展出独立评测体系：zsRE、CounterFact、KnowEdit、Lifelong-M）
- 模型压缩与微调社区（LoRA、adapter、parameter-efficient tuning）

**Latent 的核心问题**：压缩与复用计算状态——**推理引擎与系统**的问题。母学科：
- Serving 基础设施社区（vLLM、TGI、TensorRT-LLM）
- KV cache 管理的工程文献（PagedAttention、FlashAttention、continuous batching）
- 模型压缩社区（量化、剪枝、知识蒸馏）

**三个文献宇宙各有自己的会议、基准与综述谱系，彼此引用稀薄。** 这个结构本身比任何论文计数都更硬地支撑本节论点：它们不是同一个领域的三个分支，而是三个领域在"记忆"名义下的相遇。

**评测协议互不可通约**：

- Token 记忆的评测：多轮对话召回、问答准确率、检索质量（MRR、NDCG）
- Parametric 记忆的评测：编辑三指标（efficacy、paraphrase、specificity）、KnowEdit 基准
- Latent 记忆的评测：压缩比、长程检索（RULER、Needle-in-Haystack）、系统吞吐量

三者没有共同的评测语言。

**失败归因互不可通约**。同一现象"模型答错了"，在三处的归因完全不同：

- **Token 处归因**："检索召回了错误的文档"、"相关记忆未被检索"、"注入的噪声干扰了推理"
- **Parametric 处归因**："训练动力学未收敛"、"编辑产生牵连效应"、"灾难性遗忘损伤了存量知识"
- **Latent 处归因**："KV cache 被过度压缩"、"张量几何失配"、"位置编码外推失效"

三者指向完全不同的修复方向，没有共同的调试工具。

**工程栈完全分离**：

- Token：检索栈（Elasticsearch、Pinecone、Weaviate）+ LLM API 调用
- Parametric：训练管线（PyTorch、DeepSpeed、Megatron）+ 知识编辑库（EasyEdit）
- Latent：Serving 引擎（vLLM、TGI）+ 模型内部 API（past_key_values、inputs_embeds）

三者所需的基础设施、工程角色、运维流程无交集。

**结论**：三类载体不是同一问题的三种解法，而是**三个问题恰好共用了"记忆"这个名字**。强行统一对比，等价于把数据库索引算法、神经网络训练方法与操作系统虚拟内存放进同一张实验表。

## §8 范围与取材

### 8.1 分类实在性的证据

本节回答：三分法是否只是分析便利，还是对应领域的真实结构？

**主证据：学科结构。** 三个载体各自继承了完整的母学科（§7.3 已列举）。三个文献宇宙各有自己的会议、基准与综述谱系，**彼此引用稀薄**。这个结构本身比任何论文计数都更硬地支撑分类实在性：它们不是同一个领域的三个分支，而是三个领域在"记忆"名义下的相遇。

**辅证据：数量分布。** 一份收录 199 篇 agent memory 论文的分类仓库（awesome-agent-memory，截至 2026 年 8 月）给出：token 约 72%，latent 约 16%，parametric 约 12%。单一来源、社区维护，应作方向性参考。

工程侧信号同向：
- 可直接部署的记忆产品几乎清一色为 token 方案（Mem0、Letta、Zep、MemGPT 等）
- Latent 的工程化集中于推理引擎侧（其主流形态按 §5.3 判据严格说属"系统优化"）
- Parametric 的落地集中于特定场景的权重交付，尚无通用 agent 记忆产品形态

两路证据指向同一结论：载体轴上的研究能量与工程现实高度偏向 token。

### 8.2 门槛与最优的诚实区分

Token 的多数地位有相当部分源于**门槛**：

- **复用成熟检索栈**：不需要从零搭建，可直接使用 Elasticsearch、Pinecone 等成熟服务
- **可回读**：每条记忆都是人类可读的文本，调试、审计、版本管理都在文本粒度上进行
- **易调试**：失败可定位到具体条目（"召回了错误的文档 #42"）
- **可运营**：支持增删改查、用户隔离、权限控制、合规删除等运营需求

**多数不等于最优，聚焦不等于神化**。Parametric 的"读免费"与 latent 的"近零读取开销"在各自适用场景中是 token 无法企及的结构优势：

- **Parametric 适用场景**：高频复用、低频变化的知识（如领域术语、公司规则、专业技能）
- **Latent 适用场景**：长上下文对话、会话状态保持、计算结果复用

本文对 token 的聚焦是**可通约性与工程现实性**的选择，不是性能优越性的判断。

### 8.3 声明

本研究的对比分析聚焦 **token 载体**。Parametric 与 latent 在本文作为分类学对照出现，此后不再展开——理由不在其不重要（二者各自是完整的活跃学科），而在于深入的对比需要可通约的技术栈、评测协议与失败归因方式，而三类载体之间不存在这种可通约性（§7.3）。

**聚焦不是兴趣的偏狭，而是对"对比需要共同度量衡"这一方法论要求的服从。**

本文同时为后续章节留下接口：

- **Token 内部的分化**是必然的、多维的，且至少包含存储引擎、信息压缩度、组织拓扑等彼此正交的子轴（§3.2）
- **Parametric 内部的写入精度谱**（全参数 → LoRA → 定向编辑）与 **latent 内部的持久化路线**（复用 → 压缩 → 生成），同为各自载体的内部分化问题

对这些子轴的分别建立分析框架，是后续章节的任务；本文的使命只有一件事——**把"载体"这根轴立直**。

## 结语

### 载体作为第一分岔

三种载体由前向计算的结构唯一确定（§2.2）：

- **Token**：离散符号 + 显式读取
- **Parametric**：连续权重 + 隐式读取
- **Latent**：连续张量 + 显式读取

它们各自的读写代价、可检视性、作用范围与容量约束，全部从这三条维度推出，且互为镜像：

- Token 写廉读昂，parametric 写昂读廉，latent 居中
- Token 完全可检视，parametric 完全不可检视，latent 可搬运不可读
- Token 解耦于模型，parametric 即是模型，latent 绑定模型版本

**不存在一种载体在所有维度上占优**，因此任何"某载体是正确选择"的判断都是事后论证。本文后续章节的主研对象选在 token 级，是路线选择，不是优劣裁决——选择的理由是可运营性、可通约性与工程主流地位，不是性能优越性。

### 边界案例与转化

载体之间会转化、会并存、会在边界案例上纠缠——KV cache、软提示、记忆 token 这些骑在边界上的对象本身就是证据。但作为分析框架的地基，本文坚持以**读取路径为首要判据**、以表征形式与存放位置为次要判据，把每一处边界的两侧证据都摆开。

后续所有章节默认此处的判断成立；有争议处已如实标注，不替读者收敛。

### 研究立场的兑现

本文按四条要求写成（§开头所列）：

1. **详尽**：边缘案例同样处理（软提示、LoRA 银行、MemGen 等），宁可臃肿不可略过。
2. **准确**：机制按机制写（§2.2 的穷尽性推导、§4.5 的不可分离性论证、§5.3 的临界点判据），禁用类比。
3. **无偏**：Token 的主流地位归因于门槛与可运营性（§8.2），不归因于"更好"；parametric 与 latent 的结构优势如实陈述。
4. **第一性原理**：从"状态可以放在哪里"出发（§2.1 → §2.2），每一步给出依据；文献只作证据与对照。

允许破坏式重构的研究立场未被触发——初稿框架经第一性原理审查后成立，无需推翻。但论证链已全面补强：穷尽性有严格推导（§2.2）、不可分离性有深化展开（§4.5）、临界点有判据精确化（§5.3）、不可通约性有学科结构支撑（§7.3）。
