# 案例与证据（step5p）

> 配套[主稿](first-principles.md)。三态分标：**观察**（本地可复核或已有研究已核实）、**推断**（推出但未验证）、**未验证**（缺一手证据，不得下游引用）。
> 所有字节数与行数为 2026-10-17 本地实测。

## 案例 1：本项目 AGENTS.md 层级的实测

**观察**：排除 `archive/` 与 `.rivet/backups/` 快照，在用的 `AGENTS.md` 共五份：

| 文件 | 字节/行 | 内容构成 |
|---|---|---|
| 根 `AGENTS.md` | 1192 B / 22 行 | 项目身份＋当前阶段＋目录语义＋认知规则（不为迎合假设填框架）＋思维模式＋限制（不重复造轮子、不随意哈希、术语首现解释、不用无意义代号）＋index（当前研究位置＋简称表） |
| `domain/AGENTS.md` | 323 B / 5 行 | 思维模式＋草稿归属约定（AI 生成的文档要能看出是哪个 AI 生成） |
| `domain/repo-context/AGENTS.md` | 1140 B / 23 行 | 背景诊断（vibe docs 管理混乱、实际用法只能参考）＋最终目的＋设计（允许子研究耦合后解耦） |
| `domain/repo-context/11AGENTS/AGENTS.md` | 246 B / 4 行 | 研究立场（第一性原理、不受市场混沌影响）＋AI 归属约定 |
| `sources/repos/AGENTS.md` | ~7 KB / 194 行 | 账本规则（三文件各管一段）＋取证纪律（四态区分）＋长文本外置判据＋不做的事清单 |

**观察**：层级不是复制，是作用域细化——根管全项目身份与纪律，`domain/` 管草稿归属，`repo-context/` 管子研究立场，`11AGENTS/` 管单个研究任务的约定。每层只含该作用域内不可推断的内容；合计约 2.9 KB（不含 `sources/` 层）。

**推断**：

- 该形态是「常驻定向通道」在真实项目中的收敛结果，且**不是任何市场模板的复制品**——市场样本中无同类（见案例 4）。主稿第三节的七类职责在这里逐一有对应：身份与阶段（3.1）、目录语义（3.2）、一行粗状态＋简称表（3.3）、认知纪律（3.4）、权限（3.5）、AI 归属（3.6）。
- 一个符合推导的细节：根文件的状态内容只有一行「目前在研究 domain\repo-context」加简称表；详细规划在 `规划.md`，任务入口在 README。状态被保持为指针级粒度。
- 一个未闭合的张力（判据表第 5 问指向的待办）：index 段的简称表与「当前在研究」没有显式的更新触发约定——新增子研究目录时谁来同步它，文件里没写。按维护律，这一段要么补问责，要么接受它比别的段更易腐。

## 案例 2：git 历史中的维护律实测

**观察**（`git log -- AGENTS.md` 抽样，2026-10-17）：

- `db7c2ad docs(root): 精简根级 AGENTS.md，四份职责文件归档到 以前的/` —— 薄化，正本归档
- `67d3da8 refactor(docs): dedupe repeated facts in root meta-docs and merge domain AGENTS` —— 去重
- `922b8eb docs: 收敛 AGENTS.md 约定并移除过时的 repo-context/TASK.md` —— 移除腐化的状态正本
- `88c9e8a docs: 补充文档模型工作词、讨论记录与代号约定` —— 按需增补（简称表）

**观察**：`archive/` 下三版历史 AGENTS.md 均为 2026-09-20 同日快照（1740–3727 B），是当时的并列草稿而非时间序列；`以前的/` 收存四份职责文件（ARCHITECTURE/CONVENTIONS/STYLE/TRADEOFFS，2026-10-13 归档）。现行根文件 1192 B。

**推断**：维护动作方向与维护律同向——常驻内容薄化、正本唯一（移除 TASK.md）、按需增补。这是维护律的一个**正例**，不是证明：单条历史也可能是审美变化，区分需要删除理由留痕。相比市场样本，本仓库的commit message 承担了一部分理由留痕（「dedupe」「精简」），可追溯性更好，但仍无系统记录。

## 案例 3：本仓库实际消费的 harness 机制约束

**观察**：

- 本机存在 `.rivet/` 备份目录（含 `AGENTS.md` 快照），说明 rivet 系 harness 参与过本仓库编辑；按 02docsdefine 与 codex 机制研究，Tianshu 的 loader 读取当前工作目录下 `AGENTS.md` 与 `.rivet.md`，standard 项目指令块 8,000 字符，超限按节优先级挑选（H14）。
- 本会话由 WorkBuddy 消费同一份 `AGENTS.md`——同一仓库多个 harness 消费同一通道的实证。
- Codex 侧事实：项目文档按加载链累计 32 KiB 预算，超限保留前缀、截断后续（H03）；祖先链拼接意味着嵌套文件共享同一份预算。

**推断**：

- 五份 `AGENTS.md` 合计约 10 KB，远离任何已知硬限——这是「常驻内容最小化」的结构性结果，不是巧合。即使四份全部被同一 harness 拼接消费，裁切断言也不触发。
- 但继承链的可用性依 harness 而异，对本仓库是真实约束：Codex 式拼接能消费根→子目录的差异化约定；Tianshu 式按工作目录读取则只消费当前目录那一份。**设计嵌套层级时不能假设所有 harness 都会合并祖先链**——这是主稿未决问题 2 的本地实例。
- 一个可检验的脆弱点（未验证）：Tianshu 的按节选择含「表格占比高 → 倾向归入 Reference 降级」的启发式（H14）。本仓库 `AGENTS.md` 多用短列表与表格；若某节表格占比继续升高，该节可能被重分类而改变保留顺序。本项目是否真会触发未测。

## 案例 4：市场编码场景 AGENTS.md 的体检（为何不可抄）

**观察**（引自 [02docsdefine/definitions.md](../../02docsdefine/definitions.md) 的已核读实例，L26–L204）：

- 11 仓的 `AGENTS.md`/`CLAUDE.md` 内容构成高度一致：工程约束＋目录地图＋构建/测试命令＋验证方法＋边界。没有一份承载研究状态、证据纪律或结论路由。
- 载体混乱：`mem0`/`Raven`/`deepseek-harness` 的 `CLAUDE.md` 与 `AGENTS.md` **逐行相同**（副本）；`goose`/`qwen-code` 用一行 `@AGENTS.md`（指针）；`Tianshu-harness` 拆成三份互补（`AGENTS.md` 架构地图＋`CLAUDE.md` 工程提示＋`.rivet.md` 操作约定）。
- 少数正向设计：`ZCode` 把可机器检查的架构策略外置到 `architecture-policy.yaml` 并有脚本消费——「强规则送可靠位置」的实例；`Raven` 的 `CLAUDE.md` 把导航与规则分离（L192–L204）。

**推断**：任一篇目迁移到深度研究仓的净效果是**「体裁完整、职责空缺」**——得到虚构的构建命令、无对象的代码风格节、无关的 PR 流程，同时缺失主稿 3.1–3.7 全部七类内容。这与用户「不要被市场混沌状态严重影响」的判断一致，且给出了机制解释：市场的篇目结构由编码场景的失效模式塑造（命令错、风格错、PR 错），与研究场景的失效模式（状态错、证据错、结构语义错、结论静默矛盾）没有交集。

## 案例 5：近邻正例——sources/repos/AGENTS.md

**观察**：`sources/repos/AGENTS.md`（~7 KB）是一份非编码场景的项目指令。它承载：账本规则（`index.csv`/`_commits.json`/`CHANGELOG.md` 三个文件各管一段、没有第四份清单）、取证纪律（四态区分、引用要带目录名+快照+路径）、长文本外置判据（工具面没有列投影，账本一行多宽每次读就付多少）、不做的事清单。数据与状态在账本文件里，本文只给规则与路由。

**推断**：这是「研究支撑层」的定向通道实例，与主稿推导一致——它**不描述数据内容**（数据在账本），只规定怎么读、怎么更新、什么不能做。它同时示范了纠错协议的物化：「三个文件各管一段」是正本唯一原则的表格化。更深一层的含义：`AGENTS.md` 的体裁不是六段式，而是**「该作用域内不可推断的规则＋路由」**；不同场景填不同内容，通道逻辑不变。

## 案例边界

- 案例 1、2、3、5 是本地观察＋推断，未运行任何模型行为实验；「该层级是最优形态」之类的比较级断言均未经验证。
- 案例 4 的市场判断引用 02docsdefine 的核读范围（固定本地快照），不代表上游当前版本。
- 本文件不构成对任何现有 `AGENTS.md` 的改写建议；改写属于治理动作，按 11AGENTS 立场留给后续。
