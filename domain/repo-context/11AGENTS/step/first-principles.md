# AGENTS.md 的第一性原理：场景#50「深度研究」

> 产出者：Step-5-Preview（step5p）· 日期：2026-10-17
> 性质：AI 研究稿，可纠错。观察、推断、未验证三态分标；未运行 harness 行为实验。
> 场景约定：「深度研究」= 以产生经证据支持的认知综合为目标的长期、多会话、多智能体研究型仓库。解释假设见 [README](README.md)。

## 一、场景定义：先钉住「深度研究」是什么

不从任何产品或模板出发。场景由任务结构定义。

一次深度研究任务的结构是：**承接或提出问题 → 规划 → 获取证据（外部检索、本地阅读）→ 交叉核验 → 形成或修正结论 → 产出可追溯的综合**。这个结构给出五个属性，后文全部推导从它们出发。

| 属性 | 内容 | 与编码场景的系统性差别 |
|---|---|---|
| 产物即知识 | 仓库内容本身就是产品；文档不是对外部产物的说明书，而是工作成果的载体 | 编码场景里代码是产品，文档是地图 |
| 验证是证据性的 | 结论没有编译器或测试兜底；错误结论不会在执行时报错，会静默传播并沉积 | 编码场景的错误在执行时暴露 |
| 跨会话延续 | 工作单元是研究状态，不是一次性任务；会话结束后靠仓库恢复线索，恢复成本主要是上下文重建 | 编码任务多以 issue/PR 为界，边界自带状态 |
| 状态高易变 | 「当前认为」随新证据改写，比代码的「当前实现」更易过期，且过期不产生任何信号 | 代码变更由 diff 可见，结论松退只在对比时可见 |
| 多智能体协作 | 多个不同 AI（及不同 harness）先后在同一仓库工作，结论必须能被未参与写作的一方复核 | 编码仓通常一个主干一条流水线，复核者有执行手段 |

**本节的关键推论**：在这个场景里，`AGENTS.md` 不是「环境说明书」，而是**每次会话开始时，一个不带记忆的协作者需要的第一份工作记忆**。研究仓的目录名编码研究模型，结论与证据分层存放，「当前状态」高速过期。因此通道内容的选择标准与编码场景系统性不同——而且不能反过来从市场现状反推（这是 11AGENTS 立场，第五节说明为什么）。

## 二、机制层：AGENTS.md 是一个通道，不是一种体裁

先忘掉「`AGENTS.md` 应该写哪些段落」。它的第一性身份由 harness 的加载机制决定。以下机制事实来自本项目已核实的固定版本源码研究（[codex/research/harness-evidence.md](../../codex/research/harness-evidence.md) H01–H18，[04 阶段 ds 取证](../../04how-agent-read-file/ds/read-tool-and-skill-loading.md)），本文引用而不重新主张：

1. **发现**：harness 按固定文件名与目录作用域发现。Codex 从项目根到当前工作目录逐层择一并拼接；Tianshu 读取当前工作目录下的 `AGENTS.md` 与 `.rivet.md`（该版本核对的 loader 如此，未核实是否合并祖先链）。
2. **预算**：常驻注入有硬上限。Codex 的项目文档共用 `project_doc_max_bytes`，默认 32 KiB，**按加载链累计**；Tianshu 的 standard 项目指令块 8,000 字符，子代理 4,000。
3. **裁剪**：超限时 Codex 保留前缀、从耗尽处截断后续文件；Tianshu 按 `#`/`##` 分节并依优先级挑选后恢复原序。结构（标题层级、表格占比）可以改变哪些内容被保留。
4. **成本重复**：每个会话、每次上下文重建都要重付；且位置靠后的内容同时面对截断与注意力衰减两个方向的作用。
5. **无 schema**：没有校验层。字段写错、命令缺 flag、约束描述含糊，都不会在任何一步被工具拦下，只在 Agent 实际行为里暴露。
6. **软约束**：文件内容可被用户显式指令覆盖；模型是否遵循取决于注意力，不取决于文件本身。需要不可绕过的约束时，可靠位置是 CI、hook 或权限配置，不是指令文件。

由此得到通道的五条性质，作为后文判据的机制依据：

- **C1 默认在场**：会话开始即进入上下文（或注入流水线的第一现场），这是它与仓库中任何其他文件的唯一区别。
- **C2 成本重复**：每会话重付，行数即每会话的固定税。
- **C3 容量有限且裁剪不可控**：超限后的裁掉谁，取决于 harness 的实现细节，不取决于作者的意图。
- **C4 无校验**：正确性完全由写法和维护保证。
- **C5 软约束**：它改变的是概率，不是保证。

**定义（本文采用）**：`AGENTS.md` = **会话起点的常驻定向通道**。它的内容取舍由通道性质（C1–C5）与场景需求联合决定，不由「`AGENTS.md` 这种文档按惯例应包含什么」决定。

体裁先行的写作——先列出「标准六段」再往里填内容——是市场混乱的主因之一。本场景要求反向操作：先问「第一次行动前必须知道什么，通道送什么最划算」，再决定写什么。

## 三、推导层：第一次行动前，Agent 必须知道什么

对每一类候选信息问三个问题：**缺席时第一次行动会怎么错？能否被 Agent 低成本再推导？保持它为真是否廉价？** 三个答案的组合决定它的归属。

### 3.1 项目身份与场景类型（常驻）

- 缺席失效：把研究仓当代码仓——找构建命令、按代码整洁度 reorganize、把草稿和过程稿当废弃文件清理、用 PR 思维对待尚未定型的研究结构。这是**场景误置**，错误发生在第一次行动，且事后修复要连带恢复被删的结构。
- 可推导性：不可。目录名 `deepdive/analysis/domain` 的语义没有任何机制能推断；本项目自身的 index 段（「目前在研究 X」）就是为此存在。
- 成本：两三行。

### 3.2 结构语义与路由（常驻）

- 缺席失效：把结论写进分析目录、把对象拆解放进综合目录，或相反。结构腐化后，所有后续会话的检索与归档判断都退化，且腐化不可自动恢复。
- **一个场景反转**：编码场景里「目录结构说明」通常是噪声（框架默认约定可从清单文件推断）；研究场景里，目录语义恰是最不可推断的一层。同一判据（可推断性）在两个场景得出相反结论——这证明判据是场景无关的，**结论不是**。照搬编码场景的「少写结构」建议，会在研究仓丢掉最关键的语义层。
- 路由指针必须带适用条件：「研究 X 类问题 → 去 Y」。「文件在哪」无条件的指针等于没有指针，Agent 不知道该何时跟随（codex 研究已记录这一点）。

### 3.3 状态指针（常驻指针，不常驻状态）

- 缺席失效：重做已裁决的问题；或沿着已被自己推翻的结论继续推进。
- 为什么只能是指针：状态是深度研究场景**最易变**的内容（属性 4），而常驻通道每会话重付且裁剪不可控（C2–C3）。把状态详情写进 `AGENTS.md`，等于制造一个必然腐烂、且**默认被信任**的文件。**腐烂的常驻通道比缺失更糟**：它不会被怀疑，错误结论会被当作项目前提继续引用。
- 形态：「当前在研究什么」一行粗状态 + 指向状态正本；正本有归属者和更新触发条件。粗状态廉价到值得常驻（更新一次一行），详情留在正本（按需读取）。

### 3.4 认知纪律（常驻，本场景价值密度最高）

- 缺席失效：引用未核读的原文；把文档声称当代码存在、把默认启用当已验证；结论与证据脱节后任何一方都无法复核。
- 为什么常驻：属性 2 决定了错误不报错，纪律是唯一防线；且纪律是**改变每次行动**的规则，缺席时 Agent 按训练先验行动——默认会把声称当事实、把均值当因果、把样本结论当普适定律。这是先验与项目需要的系统性偏差，只能显式纠正。
- 形态：短、可判定的条目；展开版路由到方法论文档。本项目实测在用的例子：「区分代码存在/文档声称/默认启用/已验证」四种状态（[sources/repos/AGENTS.md](../../../sources/repos/AGENTS.md) 取证纪律节）；「不能因目录名称被提升成实证定律」（README）。

### 3.5 权限与边界（常驻）

- 缺席失效：把精力花在安全门禁上；该破坏式重构时不敢动；或相反方向的越界。
- 成本一行，收益是每次会话的行为前提。本项目实例：「个人项目且处于初期，允许破坏式重构，不要把注意力放在安全门禁等」「不要在小改动后全量回归」——不可推断、改变行动、无别处正本。

### 3.6 协作协议（常驻，本场景特有）

- 缺席失效：多个 AI 的草稿混在一起无法归属，无法判断哪个结论出自哪种偏见结构；结论不带证据锚点，后来的 AI 要复核只能全读。
- 内容：AI 归属命名约定（本项目：父文件夹按 `{ai}` 命名或文件名注明所用模型）；交叉可复核的最低要求（结论带证据位置）。这是多智能体协作（属性 5）的直接需求，编码场景不存在同类问题。

### 3.7 纠错协议（常驻规则，或路由到很近的正本）

- 缺席失效：多会话研究积累**静默矛盾**——两个文件两个答案，后来的 AI 和人无法判断哪个是当前版本。这是属性 2 的时间维度：错误不仅传播，还会沉积。
- 内容三条：结论的正本唯一（当前答案在哪，可指名）；发现冲突时的修正动作是改正本并记录改写，不允许留下两份冲突结论无人裁决；引用结论必须连同其证据基础，不允许凭会话记忆转述。
- 本项目实例：[dialogue/](../../../dialogue/README.md) 存讨论与重要决定，[archive/](../../../archive/) 存历史快照——「当前结论/历史理由」分工是这个协议的物质形态。

### 小结：常驻通道在深度研究场景的职责集合

| 职责 | 为什么必须常驻 | 形态 |
|---|---|---|
| 项目身份与场景类型 | 防场景误置，第一次行动前生效 | 两三行 |
| 结构语义与路由 | 目录语义不可推断；路由带适用条件 | 语义一句一目录 + 任务→材料指针 |
| 状态指针 | 防重做与沿错误结论推进；状态本身只配做指针 | 一行粗状态 + 正本指针 |
| 认知纪律 | 无执行验证，纪律是唯一防线 | 短条目 + 方法正本指针 |
| 权限与边界 | 行为前提，成本一行 | 祈使句 |
| 协作协议 | 多 AI 归属与可复核性 | 命名约定 + 最低复核要求 |
| 纠错协议 | 防静默矛盾沉积 | 正本唯一 + 修正动作 + 引用规则 |

## 四、反廊：什么不进常驻通道

与职责集合互补的排除集合。每一条都有推导理由，不是风格偏好。

| 不进 | 理由 |
|---|---|
| 目录树与结构清单 | 可廉价再推导（列目录即可）；但**语义层除外**（见 3.2 反转）。清单是噪声，语义是刚需 |
| 别处有正本的长内容：定义全集、方法论全文、历史理由 | 重复即腐化源；两处各改一半比不改更糟。给指针 |
| 能被 lint/CI/hook 强制的规则 | 通道是软约束（C5），把强规则放在不可强制执行的位置是错位；要可靠就放到可靠位置 |
| 状态详情 | 3.3：必然腐烂，且默认被信任 |
| 工具命令式段落（构建/测试/PR 流程） | 本场景不适用；硬填产生空洞或虚构的段落，是「体裁先行」的直接症状 |
| 一次性事故补丁 | 规则膨胀的起点。只增不减的文件会同时耗尽预算（C3）与注意力；「更多规则并不产生更好表现」有市场实证支持（E07 与 qwen 报告引述的失效模式研究） |

## 五、维护律：常驻通道的腐败动力学

把机制性质与场景属性合起来，得到 `AGENTS.md` 特有的失效结构：

- 成本每会话重付（C2）→ 内容每行都是固定税，行数有上缴压力；
- 越易变的内容，保持为真的成本越高（属性 4）；
- 越不可廉价核对的断言，腐烂越难被发现（C4 无校验兜底）；
- 腐烂的常驻文件不报错、默认被信任（属性 2 的通道版）。

由此得到**维护律**：

> 一条内容配不配常驻 = 「保持它为真的成本」 < 「它缺席时每个会话的重建成本」。

以及两条配套规则：

- **可核对性优先**：常驻内容优先选「能用廉价手段机械核对」的断言（路径存在吗、章节在吗、命令能跑吗——本场景对应「结构、纪律、权限」），把「需要重读证据才能判定」的论断（状态、结论）交给被指向的文档。
- **问责**：每条常驻内容有一个责任主体与一组更新触发条件。**没有问责的状态段，删掉或改为指针**——没有 owner 的常驻内容是全文件最脆的一段。

维护律的一个实测正例在本仓库的 git 历史里（见 [cases.md](cases.md) 案例 2）：精简、去重、移除过时状态文件，方向与推导一致。注意这是正例不是证明——单条历史也可能是审美变化；区分二者需要删除理由留痕，git commit message 已部分承担这个职能。

## 六、判据表：一行内容能不能进

对任一候选条目依次问五个问题，答案组合决定归属：

| # | 问题 | 否/是的走向 |
|---|---|---|
| 1 | 时机：Agent 第一次行动前必须知道吗？ | 否 → 外置（按需读） |
| 2 | 可推断：Agent 读仓库能低成本自己得到吗？ | 是 → 不写 |
| 3 | 易变与可核对：保持它为真廉价吗，能被廉价核对吗？ | 易变且是状态 → 改为指针 |
| 4 | 唯一性：它改变行动吗？能被机器强制吗？ | 能强制 → 送工具；不改变行动 → 不写 |
| 5 | 归属：别处有正本吗？ | 有 → 路由（指针） |

五问全过 → 常驻。这个程序就是「管理 vibe docs 的 skill」的逻辑骨架（程序化见 [implications.md](implications.md)）。

一个使用注意：判据表的输出是四分类（常驻/路由/外置/拒绝），不是一个分数。内容经常同时满足多个去向的理由（例如既有指针价值又有正本），此时按「最不可推断、最不可延迟」的分支裁决。

## 七、可迁移性分析：市场研究里哪些结论能拿到本场景

与编码场景的 `AGENTS.md` 研究相比（qwen 报告的实证汇总、codex 的 E01–E07），分三类：

**场景无关，可迁移：**

- 非可推断判据（反事实测试：删掉这行，Agent 能自己发现吗）。注意它在两个场景的施用对象不同（3.2 反转），判据本身不变。
- 成本记账：输入侧、输出侧、缓存命中分开报告，不混为一个「长短」问题。
- 失效模式分类：规则膨胀、静默丢失（长会话中间位置指令被忽略）、过时结构描述。三类在本场景**更严重**——没有执行验证兜底，腐烂直接进入结论。

**可迁移但需改写形式：**

- 「保持文件稳定以命中缓存」的市场建议 → 本场景改写为：常驻部分尽量稳定，易变部分外置。与维护律同向，但理由是保真成本而非缓存价格。
- 行数阈值（100–200 行等）→ 来自工程实践与工具限制，不是实测最优点；本场景的约束来自内容结构（七类职责的去留），行数是结果不是目标。

**场景特定，不能迁移：**

- 六段式骨架（项目概述/构建测试/代码风格/安全边界/目录约定/PR 规范）：除「项目概述」与「边界」外，其余四节在深度研究场景基本为空或虚构。
- 跨工具桥接策略（`CLAUDE.md` 一行 `@AGENTS.md` 等）：那是多工具团队问题；本场景是多 AI 协作问题，解法是归属约定（3.6）而非桥接文件。
- 「构建命令放前面」类位置建议：对本场景仍有机制依据（截断与注意力），但本场景需要前置的是身份与纪律，不是命令。

## 八、未决问题

诚实列出推导未能闭合的部分：

1. **指针 vs 内联的定量权衡**：粗状态一行与详情指针之间是否存在更优粒度，需要行为实验（同任务、两种信息结构，测重做率与沿错误结论推进率）。本轮未运行。
2. **多 harness 下的统一定价**：常驻内容要同时满足 Codex（累计预算、祖先链拼接）、Tianshu（工作目录读取、按节选择）等不同裁剪行为；「一份内容在所有 harness 下都活到被读到」没有保证。本仓库自身就是跨 harness 消费的实例（见 cases.md 案例 3）。
3. **认知纪律的会话衰减**：纪律条目在长会话中是否同样被「中间位置丢失」磨掉，需要剂量-反应数据；若衰减显著，可能需要周期重申机制，其成本又回到 C2。
4. **归属约定对复核有效性的影响**：AI 归属与证据锚点是否真的提升了跨 AI 复核质量，未测。
