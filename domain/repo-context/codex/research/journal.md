# 研究过程记录：问题、取证、修正与交付

> Codex / GPT-6 · 2026-09-26。本文记录本轮公开可检查的研究动作和选择依据；结论在[综合正文](../index.md)维护，方法在[method](method.md)复用。各路线的详细查询、命令和阅读范围由对应证据记录负责。

## 请求与范围

用户要求：基于第一性原理深度研究 `domain/repo-context/`，将产出放到 `domain/repo-context/codex/`，不仅保存研究报告，还保存整个研究过程中特别可复用的内容。

据此，本轮同时交付主题解释、证据与纠错记录、可复用研究方法、可运行测量及后续实验设计。研究覆盖文档职责与分类、相似文件取舍、格式、当前正文与历史、命名、实际读取及维护。现有目录顺序不当作成品顺序，其它 AI 草稿也不当权威来源。

开始时检查到已有未提交内容；后续检查时这些既有变更已进入项目历史，测量基线为 `2d99421b71a88ae2a9dff0b9492078a81c788e21`。本轮没有覆盖、回退或纳入那些文件，只新增本 codex 工作区。第三方源码只读取，来源账本的冲突作为观察记录。

## 阶段一：理解现有问题，而不是继承现成框架

实际读取根级项目说明、内容归属、写作与架构约定，随后阅读 `domain/` 与 `repo-context/` 局部约定。以用户手写的[初步计划](../../初步研究计划.md)、[draft0](../../01docsclassify/draft0.md)和[draft1](../../01docsclassify/draft1.md)理解问题变化，再读定义、清单、读取研究与历史草稿。

首先确认三件事：目录只是研究分工；用户已怀疑正交矩阵是否有用；已有文件定义里混有产品行为、项目约定和推断。于是问题从“补全所有名字的分类表”转向“哪些信息责任与机制真正改变读取、维护和行动”。没有删除候选文件名，而是把名字作为读者入口，按责任解释它们。

读取工具有两次聚合输出被截断。本轮没有把未显示的尾部当作已读；对进入论证的目标文件按范围补读，各路线记录具体读取范围。证据链以实际原文读取和检查结果为准，不由“调用过读取命令”自动完成。

## 阶段三：证据怎样改变了最初可疑的判断

| 遇到的问题 | 实际观察或核验 | 对研究的改变 |
| --- | --- | --- |
| 名字是否足以决定职责 | Tianshu AGENTS 是架构地图；EverOS CLAUDE 有实体项目说明；MemOS CLAUDE 是适配分工 | 放弃按名字一一对应，采用开放责任模型 |
| 根级样本可以证明不存在吗 | 11仓旧定义与18个ID新清单不一致，ROADMAP 已有直接实例 | 零命中必须带样本与时间，库存也需固定口径 |
| 记录是否一律只增不改 | active 与 archived 在实际项目中采用不同维护约定 | 用身份与失效触发解释生命周期，避免“过去/永恒”标签决定一切 |
| 无专用列参数是否意味着必须读整行 | 完整工具面有 shell；两条路线各自实际完成标准解析和投影 | 撤回能力不存在的推断，另把自主使用可靠性留为待检验 |
| 拆分是否自然解除限额 | Codex 固定实现按加载链累计预算；Tianshu 按节选择；Gemini 下游还有裁剪 | 分开文件结构、选择范围与传输预算 |
| 有 AGENTS 是否普遍提升表现 | 两篇直接实证版本和指标不同，效率论文没有全面正确性评估 | 正确性、耗时、tokens、费用分开报告 |
| 保存全部理由是否应默认内联 | E07 的维护者与执行者通道有明确人工处理条件 | 研究理由的可达性，不把论文干预直接变成文件模板 |
| 有版本字段是否已闭合来源身份 | 两个账本六处 SHA 冲突，文件大小仍全部匹配 | 分清元数据一致性与文件存在检查，冲突项目不冒称固定上游版本已核 |

所有修正都指向原始位置或测量结果。旧稿仍保留，作为可追溯材料；本轮没有把历史正文替换成新的理解。

## 阶段四：检索、交叉核验与失败记录

实证路线实际执行的八组查询、原文读取与 PDF 表格核对见[实证过程表](empirical-evidence.md#实际检索与读取过程)。源码路线的搜索、固定 commit、代表文件远端比对、HTTP 读取及失败查询见 [H01–H18](harness-evidence.md)。本地路线记录了误用 `repo` 字段、确认表头后改用 `id` 的更正，详见[审阅方法](local-material-audit.md#可复用的局部审阅方法)。

主研究整合时另行实际搜索并打开了以下原件：

- `site.arxiv.org "2602.11988"`、`"2601.20404"`、`"2608.11095"`：返回结果不足以直接核验，随后打开三份固定版本 HTML，检查比较指标、表格、实验通道和限制。
- 官方域检索 `Codex custom instructions AGENTS.md`，实际打开 AGENTS guide 和 advanced config。前者在本次页面 L853 使用 combined，后者 L1375 使用 each；与源码路线的累计预算结果相对照。网页行号仅是本次抓取定位，稳定地址记录在 [H17](harness-evidence.md#h17-官方文档表述差异)。
- 搜索还返回 Eric Provencher 的 *Rethinking skills and prompts for GPT-6 Astra*，2026-09-11，实际打开 `https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra` 的 Better skills / Up-to-date AGENTS.md。它被归为厂商工程建议，未纳入七份实证，也不当作本项目模型效果已验证的证据。

本轮协作中曾出现“网页已打开”的状态早于实际读取；该状态随即撤回，后续以真正完成的网页/HTTP读取核对。没有把那些提前报告当证据。可复用教训是：**计划、开始执行、读取成功、事实核对完成，四个状态应分别报告。** 不需要保存重复通信全文来证明研究完成。

## 阶段五：执行可复跑的小测量

由于问题中已有关于格式成本和工具能力的强判断，本轮没有只提出实验计划，而是完成一项无需模型的实际测量。脚本只用已有 Python 标准库，未安装新依赖，未调用模型 API。

```powershell
python domain/repo-context/codex/experiments/probe_repository.py --output domain/repo-context/codex/experiments/results/2026-09-26
```

成功输出[原始 JSON](../experiments/results/2026-09-26.json)和[可读报告](../experiments/results/2026-09-26.md)。原始数据含三份输入指纹、133份文件的完整哈希、六处版本差异，以及筛选/投影/序列化结果。算法内检查等价数据的往返和引用 CSV 反例。它证明局部工具与表示事实，不承担模型性能结论。

没有可用 tokenizer，本轮也没有必要为了该问题安装一个；明确记录 `not_measured`，不使用字符除以固定系数伪造 tokens。下一轮若要研究计费，应直接记录真实请求、缓存与输出用量，而非从磁盘字节推算。

## 阶段六：整合审查与实际修正

两条子研究对新综合、治理正文和脚本作只读核对，指出两个实质问题，已修正：

1. 初稿“只有自然语言才能表达的条件才写成规则”排除过强。改为让工具承担可靠检查，文档仍可负责操作入口、范围与理由。
2. 脚本生成报告把日期写死为本轮日期，影响以后复用。改从原始结果的实际 UTC 观测时间生成；原始测量数据不覆盖，可读报告按同一 JSON 重新渲染。

整合审查还提醒新入口一度链接到尚在写入的方法与实验文件。交付时补齐这些实际文件，并统一检查目标与锚点。对子研究的静态机制推论和数据口径，整合审查未指出新的实质错误；这不被表述为证明不存在未知问题。

Git 保存只包含本目录新增材料；既有文件和来源保持原状。未来重新验证时，应复用输入指纹与本轮证据，只重查发生变化或仍未回答的部分。
