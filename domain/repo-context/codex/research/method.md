# 可复用研究方法：从争议句到可检查的使用链

> Codex / GPT-6 · 2026-09-26。这里保存本轮实际使用的方法和一个工作样例，不是给项目增加固定流程。专题入口见 [index](../index.md)。

“第一性原理”在这里指把问题拆回必要关系和可变条件，明确哪些推论依赖哪些前提，再用材料寻找反例；它不意味着可以绕开实证、从词义推出软件行为，或把一个漂亮公式当作已经证明的规律。

## 1. 先把研究对象从名字改成需要区分的解释

例如，“AGENTS 应该很短”不是足够明确的问题。可以改写为：“对某类任务，项目入口缩短后，是否仍能得到必要约定，并减少无关阅读和总工作量？”这时至少有四个竞争解释：长入口包含必要地图；长入口包含无关要求；短入口可可靠路由；短入口导致漏读。

研究目标不再是搜集赞成长或短的观点，而是寻找能区分这四者的证据。文件清单可以说明有哪些内容，源码可以说明如何加载，运行轨迹可以说明实际读了什么，对照任务结果才能说明某种设计是否更有用。每种材料只承担它能承担的证明责任。

## 2. 画出足够具体的使用链

用一句话描述任务，然后顺着信息路径追踪：

```text
哪条信息 → 由谁维护 → 怎么发现 → 选择与读取
→ 什么内容进入哪条消息 → 后续仍否可见
→ 如何影响行动 → 用什么结果检查
```

不要求每次追完每一层。例如只想反驳“所有 AGENTS 只有硬约束”，找到一份架构地图式正文已经足够；要声称该地图改善任务表现，则远远不够。研究深度应随所要判断的命题而变。

同时记录最小比较条件：任务、模型、客户端与版本、配置、仓库状态、可用工具、实际输入、主要指标。未获得哪项，就说明当前结论停在哪；不要补猜。

## 3. 三条证据路线可以并行，但要在同一问题处汇合

| 路线 | 本轮做法 | 可复用价值 | 常见误读 |
| --- | --- | --- | --- |
| 本地文档与反例 | 从争议文件家族选有机制或职责差异的样本，返回正文核对 | 测试定义边界，发现已有材料的内部矛盾 | 把少数仓库频率当行业比例，把零命中当不存在 |
| 源码与消费者 | 固定 commit，追发现、裁剪、工具结果与注入，核对代表文件 | 确定可行路径、约束与配置前提 | 把代码存在当默认启用，把静态路径当运行观测 |
| 实证研究 | 找原始论文最新可核版本，读方法、表格和附录 | 分清效果指标与外推边界，形成可检验假设 | 从摘要或二手数字直接推出普遍设计准则 |

本轮的汇合点是：文件容器不决定加载，加载不保证使用，使用不等于任务成功，成功一次不保证维护长期有效。这不是四句泛泛警告，而是四个可以分别测量和纠错的位置。

## 4. 检索与纳入：为解决缺口检索

先从已读材料提出需要证实或推翻的句子，再组合对象名与机制词检索。例如 AGENTS 效果查 evaluation/efficiency，加载查 ancestor/budget/import，维护查 instruction growth/comments。找到论文后固定版本并查实验细节；找到官方网页后实际打开，不把搜索摘要作为最终证据。

纳入材料须有具体用途：给出机制差异、可核条件、直接反例或原始评估。营销数字、无法定位的转述以及同一论文的重复报道，不当独立支持；不因与初始立场相反而排除。材料过旧也不必删除，可用来解释变化，只是不当作当前产品承诺。

本轮各路线的实际命令、查询和失败分别保留在 [本地审阅](local-material-audit.md)、[机制记录](harness-evidence.md)、[实证记录](empirical-evidence.md)；汇合与转向见 [journal](journal.md)。它们保存了可复查的公开研究轨迹、选择和解释依据，而非每一个临时思考片段。

## 5. 一个完整工作样例：CSV 没有专用列参数就只能整行付费吗

**起点。** 旧 [read 工具见解二](../../04how-agent-read-file/ds/insights.md) 从专用工具缺少列选择参数，推出加宽账本就必然在每次读取付出全部列成本。这包含一个未明说的前提：消费者除了这个工具，没有其它字段选择路径。

**反例设计。** 核对完整工具面，发现有 shell 的实现可以调用解析器。先不调用模型，在本地用标准 CSV 解析器完成筛选和投影。这足以测试“能力不存在”的绝对判断；还不能测试“模型能可靠使用”。

**实际操作。** [probe_repository.py](../experiments/probe_repository.py) 读取既有 134 条账本记录；筛选 `kind=agent-entry` 且 `status=verified`，获得 22 条；投影 `id,path`。输出统一 UTF-8、LF、有表头的 CSV，分别为 10,579、1,750、423 字节。[原始结果](../experiments/results/2026-09-26.json)

**修正。** “专用接口没有字段选择”保留；“整个系统只能返回所有字段”撤回；“投影可能减少进入下一层的输出”得到本地支持。至于 Agent 是否知道正确字段、工具包装与缓存如何计费、任务是否因此更快更准，仍需独立行为实验。

**第二次反证。** 为防止把这次成功推广成“任何 CSV 都用逗号切分”，脚本构造包含逗号、双引号和换行的单记录。标准解析往返成功，裸拆行和逗号失败。这个示例是明确构造并实际执行的确定性检查，不是产业样本，也不证明解析器在所有输入都正确。

这个过程可复用于其它命题：找到推论的隐藏前提，构造能改变结论的具体输入或消费者，再把结论缩到证据范围。一个反例能推翻全称命题，但不能估计一般失败率。

## 6. 怎样写出可复核的证据记录

不是每段都要模板化。对需要独立复用的关键记录，至少保留以下内容：

```text
问题：要区分什么解释？
对象与身份：来源 URL / commit / 论文版本；本地路径及必要指纹。
定位：函数与行号、章节与表格，或具体操作输入。
实际动作与结果：读到了、运行了、失败了什么。
支持范围：来源所述 / 本地观测 / 推断 / 待检验分别在哪里。
反例与替代解释：什么条件改变结果？
复用：下次从哪一步继续，哪些材料无需重做？
```

数字还应带单位与分母。paper 的成功率、输出 tokens、总 tokens、价格和 latency 不是可互换指标；“提升 23.1%”与“增加 11.6 个百分点”也不能混用。版本元数据冲突时记录冲突；文件存在、首行一致、字节一致与完整内容一致是不同级别的观察。

对线上动态材料，存访问日期与简短、必要的原始措辞或页面定位；无需复制整个网站。对源码选稳定 commit 链接，并说明本地快照是否逐文件核验。对实验保留输入标识、代码、原始结果和解释，不覆盖旧结果来营造一致性。

## 7. 综合怎样产生，而不是把笔记粘在一起

先找不同材料共同作用的条件，再解释它们为什么能同时成立。例如，人工挑选的非标准约定可能补充缺失知识，自动生成的目录摘要可能重复已有事实，而任意新增指令都可能要求更多操作。于是“上下文有用”与“更多上下文有害”不是需要投票的口号；要分别检查内容增益和引入的行动。

综合正文须保留改变选择的条件和反例，证据记录承担版本与取证细节。每个局部结果不必都升级为主题结论。本轮六处账本冲突可解释来源维护问题，但不能据此宣布全部来源不可靠；本地输出减少也不能成为性能提升广告。

最后检查一个关键问题：如果删去新造术语，读者还能否知道下一步做什么？若不能，可能只是换了说法而没有解释机制。若某个分类没有改变读取、维护或复核行动，暂时不必成为新的字段。

## 8. 何时继续，何时结束这一轮

存在能改变当前结论的已知矛盾时，先解决或准确缩小范围；存在无法用现有来源回答的行为问题时，把它转成明确实验，而不是无限检索。所需条件、对照、判定结果已经明确后，没有必要为同一句话继续积累更多相同链接。

本轮选择完成综合、来源核验、反例和可复跑测量，把模型因果比较留作明确的下一轮。继续研究的触发应是新问题或新证据：不同客户端、不同任务、模型升级、规则失效、实际漏读。方法本身也可改；复用是减少重复工作，不是每次必须重走所有步骤。
