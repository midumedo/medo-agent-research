# 02 · Define：从 00 台账定义文档模型

本阶段把 `00docslist` 的实测材料转换成可审查的定义。`00` 负责回答“哪些材料在样本中出现、以什么路径和字节数出现”；本阶段回答“这些材料承担什么信息使用任务，以及哪些看似不同的名字可以由同一模型解释”。

## 上游与边界

- 上游事实：[`00docslist/README.md`](../00docslist/README.md)、[`index.csv`](../00docslist/index.csv)、各仓明细 [`ds/`](../00docslist/ds/)。
- 上游模型：[`01docsclassify/v10/文档模型.codex.md`](../01docsclassify/v10/文档模型.codex.md)、[`基础理论.codex.md`](../01docsclassify/v10/基础理论.codex.md)、[`研究依据与复核.codex.md`](../01docsclassify/v10/研究依据与复核.codex.md)。
- 历史输入：[`ds.md`](ds.md)。它保留旧的 D01–D42 文件名定义，不能规定本阶段的模型数量、边界或结论。

00 的 `kind`、旧 `role`、文件名和目录只是检索线索。`index.csv` 的 `verified` 证明一条实例记录在取证范围内存在；它不自动证明正文职责、运行时加载或效果。`claude-code` 的 `absent` 是无本地 checkout 的覆盖边界，不是一个文档类型。

## 推导流程

对每个候选模型先回答四个问题：

1. 它保存或规定什么信息？
2. 它使谁在什么任务中作出什么判断或动作？
3. 哪些关系使这些内容需要共同组织？
4. 什么变化会使它过期、被替代或需要重建？

然后用多个 00 实例和最易混邻居检查“合并后失去什么”。只有合并会丢失正确行动所需的任务、关系或演化差异时，才保留不同模型。名称、路径、格式、语言或仓库归属本身不产生新模型；一个实例也可以同时映射到多个模型。

## 两个观察层

- `Cxx` 是**基本内容职责模型**：说明材料保存什么、支持什么判断。
- `Txx` 是**复合使用任务模型**：说明多个职责怎样围绕入口、协作、技能、治理、记录或派生交付共同组织。

两层允许交叉映射。它们不是互斥分类树，也不要求一个模型对应一个文件。

## 条目 schema

`models.md` 的每个模型都包含：定义、回答的任务、内容职责或复合关系、使用主体与触发、演化条件、边界/混合实例、反例与重开条件、实例证据和证据缺口。

`mapping.md` 对 `index.csv` 的每一行保留：仓库、路径、原始 `kind`/`role`、C 模型、T 模型、映射理由、证据状态和需要复核的事项。相同模型的实例不重复写定义，但不删除实例差异。

## 证据状态

`I` = 台账实例已核对（文件存在或明确 absent）；`B` = 正文边界已由本地材料核读；`R` = 消费者/加载路径已由固定版本运行系统研究核对；`E` = 效果实验有直接证据。大多数本阶段条目为 `I`，部分有 `B`；不能把 `I` 推成 `R` 或 `E`。

## 文件

- [`models.md`](models.md)：去重后的 C/T 模型定义。
- [`mapping.md`](mapping.md)：00 台账逐条映射与判断理由。
- [`gaps.md`](gaps.md)：正文、消费者、版本和效果证据缺口，以及模型重开条件。
