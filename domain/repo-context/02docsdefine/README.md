# 02：文档定义

本阶段保留两种定义视图：[逐实例定义](definitions.md)为 00 所记录的每条实际存在路径独立说明用途和边界；[同名定义锁定](same-name-definitions.md)按跨仓相同文件名归纳一个共同的工作定义。逐实例正文保持各自的事实差异，同名稿提供本版一致的简称和引用表述。文件名是同名稿的分组起点，定义内容仍须由正文和使用任务推导；旧 `kind`、旧 `role` 不决定定义。

研究范围包括 Agent 开发材料和与这些工作并列存在的通用项目文档。通用文件不是附属噪声；许可证、社区规范、变更记录、贡献材料等都要按各自正文准确界定。不能因为旧台账曾有分类，就默认其文本是 AI 时代必需、同类或有效。

## 覆盖结果

`index.csv` 的 133 条 `verified` 记录在 [`definitions.md`](definitions.md) 中各有一个实例条目；`claude-code` 的 1 条 `absent` 记录没有定义条目，因为本轮没有本地正文。这个覆盖结果只说明样本路径被逐条处理，不说明 00 台账完整，也不说明文档当前仍有效或被运行系统使用。

[`same-name-definitions.md`](same-name-definitions.md) 的第一版覆盖其中跨仓同名的 12 个文件名、83 条实例。每个名字锁定一个主定义，在定义内部剖析职责、载体差异和实例边界。“锁定”表示本版一致使用，可以迭代，不要求正文相同，也不把多个职责先拆成互斥文档类型。

## 单实例定义格式

`definitions.md` 中每个条目对应 00 的一个 `verified` 文件路径。标题中的中文名和英文短名承担“实例与简称”字段；正文包含：

- **实例与简称**：可读的中文概念名、英文短名和确切仓库相对路径；简称用于定位该定义，不假设其他同名实例也同职。
- **定义**：该文件在当前证据下实际是什么。
- **回答的问题**：谁在什么任务情境中使用它来回答什么问题。
- **成立内容**：缺少哪些信息或关系，就不再是对此实例的准确描述。
- **边界与组合**：与最易混实例的区别，以及它和同文件其他职责的关系。
- **演化条件**：什么变化会使其需要更新、替代、冻结或重新核对。
- **证据状态**：给出正文行号；分别说明正文观察、来源自述、消费者核对和效果证据，不将它们混为一谈。

文件是否存在只作实例入口。尚未核读正文的路径不得写成已确认定义；`absent` 记录没有可定义实例，只能注明缺口。00 的 134 条数据行中有 133 条 `verified` 和 1 条 `absent` 占位；本阶段不把旧 role 与新定义逐项对账。
