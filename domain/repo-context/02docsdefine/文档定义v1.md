# 文档定义 v1

> 状态：工作定义。本文对 `00docslist/docslist.md` 中的候选名称做第一轮去重和定义；名称与原分组仅是研究线索，不证明某种文档真实存在、常见或有效。
>
> 本文回答候选名称可能承担什么独立的信息任务，不回读 `sources/repos/`。01 的 `doc-model` 可作比较线索，但尚未定型的边界和 00 的旧分组、旧 D 编号都不直接沿用为结论。定义可被后续研究修订。

## 判断口径

文档类型由它所支撑的问题、所需信息关系及其权威性和更新方式共同辨认。名称不同不自动构成不同类型；名称相同也不保证同一类型。一个文件可以组合多项职责，组合不等于同义。

只有当候选项回答的问题不同，或其读者、触发时点、权威性、生命周期至少一项不同到会改变正确判断或行动时，才暂分为不同类型。否则先合并为一个主要定义，并在名称映射中保留异名、载体和组合关系。

“常见结构”只列初步设计的大标题，用来显出任务所需的信息关系；它不是模板，也不要求所有实例具备每个标题。

## 主要文档定义

### 项目介绍与进入

**定义**：回答项目是什么、面向谁、提供什么，以及读者如何开始或继续了解项目。

**常见结构**：

- 项目身份与目标读者
- 能力与适用范围
- 首次进入或开始路径
- 资料与下一步导航

**边界**：身份、安装、架构和导航可以组合在入口页，但组合部分不因此互为别名。完整操作步骤和系统内部结构各有独立任务。

### Agent 指令入口

**定义**：为特定 Agent 或协作工具提供适用范围、约束和所需信息的入口关系。

**常见结构**：

- 适用范围与优先级
- 行为约束
- 阅读与工具路由
- 交付和验证要求
- 局部覆盖关系

**边界**：入口名称不规定正文一定是规则；它可以承载项目地图、操作方法或架构说明。工具专属入口可以是适配、指针、副本或互补材料，不能仅按名称认作别名。

### 项目身份与原则

**定义**：说明项目存在的理由、目标方向、稳定价值取舍和身份边界。

**常见结构**：

- 使命与愿景
- 服务对象
- 核心原则与价值取舍
- 身份边界
- 不可接受的行为

**边界**：不代替当前操作规则、架构说明或用户画像。它可以成为项目介绍的一部分；是否独立取决于其维护与使用任务。

### 项目地图与目录

**定义**：帮助读者定位项目组成、资料、技能、模块或登记对象。

**常见结构**：

- 地图或索引范围
- 入口与目标位置
- 条目或模块说明
- 生成来源或维护方式

**边界**：地图描述位置和可发现对象，不替代对象内容。目录、图示、清单和机器登记是不同呈现方式；登记若保存独立状态或可执行字段，不应仅因可导航而并入人读索引。

### 术语与领域词典

**定义**：稳定项目中特定词、缩写及领域概念的含义和相互关系，以便不同材料使用一致语义。

**常见结构**：

- 术语与定义
- 同义词与禁用词
- 缩写和命名
- 概念关系
- 适用范围或来源

**边界**：回答“词是什么意思”，不等于描述系统此刻的上下文、入口路由或一般写作风格。

### 项目上下文说明

**定义**：提供理解当前项目、任务或决策所需的背景、约束、状态和信息入口。

**常见结构**：

- 背景与范围
- 当前状态或约束
- 相关系统/资料入口
- 需要据此作出的判断

**边界**：回答“理解当前对象需要什么背景”，不等同于术语词典。上下文可组合术语、地图或项目介绍，但这些组成不因此成为别名。

### 系统与架构说明

**定义**：解释系统边界、组成部分、职责分配及它们之间的结构关系。

**常见结构**：

- 系统边界
- 组件与职责
- 交互和依赖关系
- 关键数据流或状态关系
- 结构不变量

**边界**：回答“系统由什么构成、如何相连”，不等同于领域词义、设计契约或选择理由。领域模型和数据模型可以作为其内容，也可以独立描述对象关系。

### 设计方案与技术契约

**定义**：描述拟议或已选的设计方案，或规定实现必须满足的接口、结构和行为条件。

**常见结构**：

- 问题与目标
- 方案或接口边界
- 约束与不变量
- 兼容性条件
- 验收条件或裁决状态

**边界**：未裁决提案记录候选设计，已裁决契约规定可依赖的条件；两者生命周期不同。接口参考解释当前接口，不必然具有规范权威。设计的“是什么”与决策“为什么选它”可互链，但不等同。

### 开发约定与质量规则

**定义**：规定代码、文档、评审、提交或验证活动中持续适用的做法和质量要求。

**常见结构**：

- 适用范围
- 编写与组织约定
- 变更、评审与协作规则
- 测试及质量要求
- 版本与兼容政策

**边界**：描述人应遵守的规则，不等于执行规则的 linter 或检查器；Agent 入口可引用这些规则。政策与操作步骤应区分。

### 操作规程

**定义**：按前提、动作顺序和完成条件，指导执行者完成一个可重复的工作任务。

**常见结构**：

- 前置条件
- 操作步骤
- 结果确认
- 故障处理
- 回退或交接

**边界**：安装、发布、部署、迁移、贡献和测试都可能包含规程；名称相近不代表它们共享同一操作任务。逐步教学路径、诊断参考和精确接口查询是相邻任务。

### 教程与学习路径

**定义**：按学习者的前置知识和概念依赖组织内容，使其逐步掌握一个主题或完成一组递进任务。

**常见结构**：

- 学习目标
- 前置知识
- 递进步骤
- 阶段性结果
- 后续练习或主题

**边界**：教程按学习顺序组织；操作规程按实际任务组织。示例可以支持教程，也可以只是参考材料。

### 技术参考

**定义**：供读者按需查找精确事实、接口、字段、命令、错误或配置含义。

**常见结构**：

- 查询对象与范围
- 条目、签名或字段
- 参数与返回/结果
- 约束和关联入口

**边界**：参考材料强调准确定位，不必提供从头到尾的操作步骤或学习顺序。FAQ、速查表和示例是不同呈现形式，不能仅按形式认作同一内容类型。

### 参与与社区规则

**定义**：规定参与者如何加入、贡献、协作，以及参与空间中的行为边界。

**常见结构**：

- 参与对象与范围
- 贡献入口和协作流程
- 行为要求
- 报告或求助渠道
- 处理责任

**边界**：贡献流程、行为准则、治理权责、维护者名册和支持入口回答不同问题；可组合在同一页面，但不是彼此别名。候选映射保留其分支，不把它们压成单一规则定义。

### 安全、风险与能力边界

**定义**：说明安全相关的威胁、信任和权限条件、漏洞处理方式，或系统已知不能满足的能力边界。

**常见结构**：

- 适用主体与资产
- 信任和权限边界
- 风险或能力限制
- 安全事件/漏洞报告路径
- 响应或缓解条件

**边界**：漏洞披露入口、产品风险说明、Agent 行为限制和一般能力限制是可组合的不同任务。`SECURITY` 等名称不能单独决定归属。

### 规划与当前状态

**定义**：表达未来目标、待办、未解决问题、风险或当前进展，以支持优先级和下一步安排。

**常见结构**：

- 目标与优先级
- 当前状态或问题
- 依赖、风险与阻塞
- 里程碑或行动项
- 更新条件

**边界**：方向规划、任务队列、问题登记和风险登记可以互相关联，但分别回答未来做什么、接下来做什么、现在出了什么问题、哪些不确定性会造成损失。它们不等同于历史经验或决策理由。

### 决策记录

**定义**：保存某个选择所处的问题、候选方案、取舍理由及决定状态，使后来者能够理解选择及其影响。

**常见结构**：

- 背景与待决问题
- 候选方案
- 取舍理由
- 决定及影响
- 替代或后续关系

**边界**：计划记录准备采取的动作；决策记录解释为何选定某方案。未裁决提案不是已做出的决策，索引也不是决策正文。

### 变更与活动记录

**定义**：按时间保存已经发生的版本变化、活动、事件或协作过程，以便追溯发生了什么。

**常见结构**：

- 时间与范围
- 事件或变化
- 影响与结果
- 关联问题或决定
- 后续修正

**边界**：面向用户的版本变化摘要、内部事件日志、对话记录和事故时间线有不同读者与保留粒度；它们可共享时间线组织方式，但不互为别名。未来规程不属于历史记录。

### 实验、验证与测量

**定义**：记录为回答问题或检查系统表现而进行的实验、测试或测量，并使结果能够与条件及解释区分。

**常见结构**：

- 问题或目标
- 条件与方法
- 观测结果
- 限制与反例
- 结论或后续检查

**边界**：实验计划属于规划；可重复测试规程属于操作；测试/基准结果属于验证记录；指标和仪表盘是持续测量的视图。相同名称可指这些不同阶段。

### 权利、来源与贡献归属

**定义**：记录作品使用和再发布的权利条件、第三方来源义务、引用/资助信息或人员贡献归属。

**常见结构**：

- 适用对象
- 权利与义务
- 第三方来源或例外
- 引用、资助或贡献归属
- 来源入口

**边界**：许可证、NOTICE、引用说明、贡献名册和第三方材料清单相关但不可互换。被归档的第三方材料本身属于来源存档，不等于法律声明。

### 用户与本地环境上下文

**定义**：记录特定用户、机器或个人工作区的偏好、当前状态、权限和环境条件。

**常见结构**：

- 适用主体与范围
- 偏好或局部约束
- 环境条件
- 权限与当前状态
- 更新和失效条件

**边界**：用户画像、用户记忆、本机环境和本地 Agent 规则有不同来源与生命周期；`AGENTS.local` 若规定局部行为，应映射到 Agent 指令入口并注明本地作用域，不因“local”而并入用户画像。

## 00 候选名称去重映射

本表按 00 原文保留候选名称及其语境分支。关系标签说明候选与主要定义的关系，不声称所有名称都已成为稳定文档类型。

|---|---|---|
| `README` / `README.md` | 项目介绍与进入 | 主要名称；可组合项目身份、操作入口或地图；原文的 `mirror` 指镜像身份内容时为组合关系，不是通用别名。 |
| `THISIS` / `THISIS.md` | 项目介绍与进入；项目身份与原则 | 同类/可组合；介绍项目是什么与说明身份原则是不同职责。 |

| `TREE`、`INDEX` / `INDEX.md`、`outline` | 项目地图与目录 | 呈现变体；树、索引和大纲只说明组织/位置，不是同义名称。 |
| `registry`、`MANIFEST` / `MANIFEST.md` | 项目地图与目录 | 同类/机器登记候选；仅提供位置时是地图，保存对象状态或解析字段时保留独立登记职责。 |

| `CHEATSHEET` | 项目地图与目录；技术参考 | 呈现/查阅变体；按其内容是导航速查还是事实速查确定。 |
| 生成式 `TREE`、`BRIEF`、`outline` | 项目地图与目录 | 载体变体；生成属性描述维护方式，不自动构成新语义类型。 |
| `CONTEXT` / `CONTEXT.md` | 项目上下文说明；术语与领域词典 | 同名异职/可组合；解释项目背景、约束和路由时归上下文，定义词义时归词典。 |
| `GLOSSARY`、术语表、命名词典、缩写表、`DOMAIN-GLOSSARY` | 术语与领域词典 | 同类候选；名称粒度不同，均须以词义及概念关系为核心。 |
| `ARCHITECTURE` / `ARCHITECTURE.md` | 系统与架构说明 | 主要候选；若主要内容是强制限制，另映射开发约定或设计契约。 |
| `DOMAIN`、`DOMAIN-MODEL`、`DATA-MODEL` | 系统与架构说明；设计方案与技术契约 | 同类/可组合；解释对象关系与规定数据形状分别标记。 |
| `DIAGRAMS` | 系统与架构说明 | 呈现载体；图示服务于所解释的系统关系，不单凭图形形式成为独立类型。 |
| `MODELS` | 系统与架构说明；项目地图与目录；技术参考 | 待按对象判断；可能是解释模型、模型清单或参数参考。 |
| `DEPENDENCIES` | 项目地图与目录；系统与架构说明；技术参考 | 同类/载体变体；依赖清单、依赖关系解释和版本参考要区分。 |
| `DESIGN` | 设计方案与技术契约；项目身份与原则 | 同类/可组合；设计公理或视觉规范与单次设计方案分支不同。 |
| `SPECS`（未裁决） | 设计方案与技术契约；决策记录 | 生命周期变体；待选方案与已裁决契约不合并。 |
| `SPECS`（已裁决） | 设计方案与技术契约；决策记录 | 组合/状态变体；当前约束与当时选择理由分别表达。 |
| `API`、`OpenAPI`、`typedoc` | 技术参考；设计方案与技术契约 | 参考或契约载体；精确描述接口不必然意味着它拥有规范权威。 |
| `PERFORMANCE`（现状） | 实验、验证与测量；技术参考 | 状态/测量视图；报告当前表现或测量结果，不自动成为性能要求。 |
| `PERFORMANCE`（约束） | 设计方案与技术契约；开发约定与质量规则 | 规则/契约分支；规定必须达到的性能条件。 |
| `COMPATIBILITY`（现状） | 技术参考；实验、验证与测量 | 状态/测量分支；说明当前支持范围或结果。 |
| `COMPATIBILITY`（政策） | 开发约定与质量规则；设计方案与技术契约 | 规则/契约分支；规定兼容承诺及条件。 |
| `LIMITATIONS`（能力边界） | 安全、风险与能力边界；项目介绍与进入 | 可组合；公开限制说明可概述在入口，详细边界单独组织。 |
| `LIMITATIONS`（禁令） | 开发约定与质量规则；安全、风险与能力边界 | 同名异职；可执行禁止项按适用主体和违反后果归属。 |
| `CONVENTIONS` / `CONVENTIONS.md`、`STYLE`、`CODING-STANDARDS` | 开发约定与质量规则 | 同类候选；写作风格可作为约定的一部分，是否独立取决于受众和更新权威。 |
| lint 规则说明 | 开发约定与质量规则；技术参考 | 组合；说明规范与查询工具配置的方式不同。 |

## 补充说明

`GOVERNANCE`、`MAINTAINERS`、`SAFETY`、`codebase-index` 和独立的 `Quickstart` 是此前初稿额外引入、并非 `docslist.md` 原始候选的名称。本版不把它们计入全量映射；以后如需加入，应作为新候选另行说明来源和理由。

## 当前边界

本版完成的是候选去重和主要文档的初步定义，不是行业分类，也不是按文件名判断实例的工具。后续研究可以拆分、合并或撤回任何定义；必要时再用实例正文和使用情境检验边界。
