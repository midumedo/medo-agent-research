## 2. 逐文件分析

### 2.1 `AGENTS.md`（17805 字节）

- **取到的原文**：L1 `# AGENTS.md`（`L1=204aa1e7`）；L3 `DeepSeek Harness is an all-plugin Cordis agent harness. Read docs/architecture.md before changing \`packages/\`; follow docs/AGENTS.md for documentation.`
- **它回答什么**：作为 Agent 在本仓必须遵守什么。**且第一件事就是分发**——架构去 `docs/architecture.md`，写作规则去 `docs/AGENTS.md`。
- **边界**：根级只放「标准命令」（standing orders），细则下沉到子树同名文件。`docs/AGENTS.md` 里有完整去向表的自述：*"standing orders → root `AGENTS.md` with a rationale link"*。

### 2.2 `CLAUDE.md`（17805 字节）

- **判定**：**整份复制**。`cmp -s AGENTS.md CLAUDE.md` → 逐字节相同（本轮实测）。
- **含义**：Claude 系 harness 读的是另一份**独立副本**，不是指针。任何对 `AGENTS.md` 的修改若不同步，两份规范立刻分叉——而 `CONTRIBUTING.zh.md` 那套 i18n 同步机制**不覆盖** `CLAUDE.md`（它没有 sidecar）。
- 这是本阶段对 `domain\repo-context\02docsdefine\ds.md` D10 的直接反证，见 §4。

### 2.3 四组「正文 + `.zh.md` + `.i18n.yaml`」三件套

`README` / `CONTRIBUTING` / `SAFETY` / `BRAND_GUIDELINES` 各有三件：英文正文、中文对照、翻译同步 sidecar（最小 382B，最大 1082B）。

- **它解决了什么**：把「翻译与原文是否同步」这件机器可判定的事，从散文里挪到一份结构化文件里。
- **边界**：`.i18n.yaml` 不是文档，是**同步状态**；所以 `kind=machine`、`role` 留空（`02docsdefine` 的 D01–D42 里没有对应类型）。

### 2.4 `THIRD_PARTY_NOTICES.md`（23KB）

- 首行是生成标记，**禁止手改**；`pnpm run gen-third-party-notices` 重生成。
- 与 `ZCode/THIRD-PARTY-NOTICES.md`（1.9MB，`node scripts/licenses.mjs notices` 生成）同类——**巨型法务件不进人工审阅循环**。

## 3. Agent 面（vibe coding 相关文件管理）

### 3.1 指令分级：22 份 `AGENTS.md` + 4 份 `CLAUDE.md`

实测路径（节选）：

```
AGENTS.md                       ← 根：标准命令
docs/AGENTS.md                  ← 文档写作规则 + 去向表
benchmarks/AGENTS.md
scripts/AGENTS.md
packages/AGENTS.md  + packages/{client,experimental,schedule,web}/AGENTS.md

website/AGENTS.md

apps/cli/tests/profiles/AGENTS.md
snapshots/session/**/AGENTS.md   ← 测试夹具，非治理面
```

**判据**：指令按**子树辖域**分配，越靠近根越抽象、越靠近子树越具体。`snapshots/session/**` 下的几份是**测试夹具**，不是本仓治理约定——枚举时必须按路径排除，否则会虚增「分级」的规模。

### 3.2 Agent Notes：用**目录**表达生命周期

底层 README（`.agents/notes/README.md`）自述路径编码两条轴：`{lifecycle}/{class}/yyyy-mm-dd-topic-title.md`

- `proposed/` — 提案，未落地
- `implemented/` — 已落地，**且要求与实现保持同步**（代码改名/挪文件时同一改动内更新，只改事实不改决策）
- `rejected/` — 被否决，**只有在其理由能防止一个诱人的错误时才保留**，否则整组删除
- `archived/` — 冻结历史，**永不是当前权威**

三条硬规矩，逐字可核：

1. **不建索引**：`"Do not add a centralized INDEX.md"` —— 理由由一条独立 Agent Note 承载（`implemented/process/2026-07-19-remove-generated-agent-note-index.md`）。**这与 `Tianshu-harness` 的 `docs/INDEX.md` 是正面对立的两条路线。**
2. **引用必须用相对 markdown 链接**，不许裸写编号或散文——「so they are mechanically checkable and survive moves between folders」。
3. 文件格式含**强制段 `Alternatives considered`**，`Status:` 三值 `proposed` / `implemented` / `rejected — <why>`。

### 3.4 文档去向表（`docs/AGENTS.md` 第 22 行起）

这是本样本里**最完整的一份文档治理规则**：逐类材料给出「放哪 / 不写什么」。三条值得单列：

| 材料 | 归口 | **明确不写在这里** |
|---|---|---|
| Agent Notes | `.agents/notes/README.md` | 迁移计划、验收清单、夹具讲解、决策落地后的 spec-speak；`archived/` 是冻结历史，**永不是当前权威** |
| `postmortem/` | 事故复盘 | 这是**唯一**允许出现「战史叙事」的层 |
| 生成参考（`subsystems/` 的 `cordis-surface` 区、`tool-catalog`、`config-catalog` …） | 由源码重生成 | **手改生成区**；中文对照只走配对流程 |

末句给出总判据：`Placement: bugs → postmortems; rationale → Agent Notes; procedures → cookbooks; type definitions → subsystems; package contracts → READMEs; standing orders → root AGENTS.md`。
