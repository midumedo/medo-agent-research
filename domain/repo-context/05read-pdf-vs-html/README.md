# 05 · 读 PDF 与读 HTML，对 AI 哪个更省

同一份文档的两种格式表示，各读取管线在**上下文成本**上的确定性对比。与 [04how-agent-read-file](../04how-agent-read-file/README.md) 相邻：04 查的是 harness 有哪些读工具、怎么实现，这里问的是「同一内容、不同格式，哪条读取路径更划算」。

## 为什么用这本书做对照

`sources/books/Agent-Memory-绿皮书.老刘说nlp/` 下有同名的 `.pdf` 与 `.html`，且**两者同源可证**：PDF 的 producer 是 `Skia/PDF m153`（Chrome 打印管线），每页页脚留着 `file:///…/Agent_Memory_绿皮书.html`，两版汉字量比值 0.987。内容相同、表示不同，这是格式对照里最干净的一种——排除了「两本书本来就不一样」这个混淆项。

## 「省」按什么算

不按文件大小算——文件大小对 AI 读取不直接成立，PDF 再小也得先抽取才能进上下文。三次测定义：

| 层 | 问什么 | 本轮状态 |
| --- | --- | --- |
| C1 体积 | 读完之后有多少字符 / token 进上下文 | 已测（确定性） |
| C2 结构 | 标题、表格、代码在读取后还能不能恢复 | 已测（确定性） |
| C3 噪声 | 朴素读取引入多少非内容开销 | 已测（确定性） |
| C4 理解 | 同一问题上，模型答对率与总成本 | 待执行（需模型） |

C1–C3 由 measure_read_cost.py 一次跑完，结果见 [2026-09-26 报告](results/2026-09-26.md) 与 [同名 JSON](results/2026-09-26.json)。

## 已完成：确定性测量

脚本只读输入、不调用模型，覆盖这些读取管线：

- **HTML**：原样 → 去样式 → 去标签全文 → DOM 转结构化文本（带 98% 可见文本覆盖率断言，防「靠丢内容变短」）
- **PDF**：文件体积 → PyMuPDF 文本抽取 → 页眉页脚与断行碎片统计 → 字体/字号信号统计 → 视觉路径 token 粗估

主要结论（详见结果报告）：**HTML 更省，但省的不是总量而是结构**——两条文本路径字符量只差 0.9%，HTML 却以 6.8% 的标记税带上了 140 个标题、34 张表与 271 处代码；PDF 文本抽取在字符量相当的前提下丢结构，另带 88 行页眉页脚噪声；PDF 走视觉则约 2 倍于文本路径。

复跑（换一个未使用的输出前缀以保留原观察）：

```bash
python domain/repo-context/05read-pdf-vs-html/measure_read_cost.py \
  --out domain/repo-context/05read-pdf-vs-html/results/replication-01
```

依赖策略与项目一致（`pyproject.toml` 声明零第三方运行时依赖）：HTML 侧只用标准库 `html.parser`；PDF 侧的标准库无法完成（需解压内容流并处理字体映射），PyMuPDF 是**可选**依赖——缺失时脚本仍产出全部 HTML 侧结果，PDF 侧标 `unavailable` 并给出安装命令，不静默降级。

## 待执行：模型在环的行为比较

下面是最小设计，不是已完成的实验；没有模型执行条件和预算前不预填结果。

**问题。** 文本量相差 0.9% 的两条路径，结构带来的差异在真实任务上值多少？

**实验单位。** 一项任务 × 一种读取管线 × 一次独立尝试。同一持续对话里先喂一种再喂另一种会让历史泄漏答案，必须隔离。

**条件。** A = PDF 文本抽取；B = HTML 结构化文本；C = PDF 视觉渲染（1× 与 2× 各一组）；D = HTML 原始（含标签与 CSS）作对照，用来量化「朴素读」的代价。

**任务取样。** 至少各一：一个只能靠表格回答的问题（本书 34 张表）、一个跨小节关系问题（140 个标题提供锚点）、一个代码片段问题（271 处 `code`）、一个简单事实负对照。

**固定量。** 记录输入指纹、模型与客户端版本、配置、工具、预算；只改读取管线，不改内容、命名与提示。主要看正确性（按预定义答案判），再看 input/output/cached tokens 与读取回合。

**必查项。** 1× 渲染（29,392 tok，本表最省）是否读到 8.2 pt 中文正文——若读不清，这一档的「省」是假的。这条必须实测，不能从像素数推断。

**撤回条件。** 若 B 在表格任务上并未优于 A，则结构优势限定在特定任务类型，不推广成「一律用 HTML」；若 D 的朴素读在真实 harness 里并不常见（harness 通常自带解析），则 C1 表里的 HTML 劣势应缩小到确有缺口处。

## 不做的事

- 不把本目录的字符数当作任何具体 harness 的 token 账单——token 估算用了透明假设，未装 tokenizer。
- 不因「HTML 更省」就建议删除 PDF 原件；PDF 是可打印、可归档的那一份，本实验只关心读取成本。
- 不把结论外推到扫描件 PDF（本书有完整文本层，`pdf_images=0`）。图像型 PDF 只能走视觉或 OCR，成本结构完全不同。
