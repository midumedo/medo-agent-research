# 分类

## 受众
两个角色：agent，developer（或者说human？human developer？），
ps：还可以之前还分出了个reader。但这是二等公民，更适合用触发skill的方式进行维护，不让agent把注意力放在这个上面。后续不再讨论。
下面只讨论agent和developer。
1. 读取和维护是两个概念
2. agent和developer不是非此即彼，一份文档可能对于两者都极其重要，比如AGENTS,README
  如：developer 几乎从不“阅读” AGENTS.md（他们写的，内容在脑子里），却必须重度维护它。

所以分类时不是简单一个维度区分为agent，developer，更不是那种权重和为100%的情况。
可能需要我们深入讨论该怎么做
最起码的是 agent，developer分开作为两个维度，进行讨论。
但是如果2*n进行正交分类的话，是否又太繁琐

也需要定义好两个role，这是锚点。

新想法： 现在agent，其实也容易分为两个维度，
    1. coding agent/work agent，负责本项目的管理
    2. memory agent，负责本harness的一些指导，比如 MEMORY.md USER.md SOUL.md都是归这个的，
也是需要讨论
