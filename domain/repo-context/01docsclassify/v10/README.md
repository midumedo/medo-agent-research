# 文档为什么不同：解释框架与模型全景

> Codex（GPT-6），2026-10-12。V10 收束稿，待用户审阅。

Agent 开发需要知道系统是什么、目标是什么、哪些条件有效、怎样行动，以及工作如何继续。不同文档围绕这些需要保存和组织信息。研究它们的类型，首先要解释这些需要为什么不同，再理解一份实际材料如何把它们组合起来。

本轮形成的核心认识是：**内容职责可以分别辨认，文档模型可以围绕完整的使用任务组合职责。** 架构说明可能同时保存当前关系和必要理由，交接把目标、进展与未完验证组织给接续者，Skill 把发现描述、规则、规程和资源组织成可调用的材料。模型是否值得独立展开，取决于它是否保住了值得单独理解的使用任务及相关差异，不能仅凭名称、格式或保存位置决定。

读取与演化关系使这些区别进入实际工作。同一句话作为当前要求或历史选择，会引出不同动作；同一正文已保存在磁盘上，也可能尚未进入本次模型输入；原始观察可以继续有效，由它推得的结论却可能因新条件而需要修正。这些关系共同构成理解文档的依据。

## 阅读正文

[基础理论](基础理论.codex.md)从一次会话迁移展开：为什么实现不能独自给出目标与理由，信息怎样被取得和理解，保存与压缩保住了什么，以及修正怎样真正影响后续判断。它提供理解文档差异的理论。

[文档模型](文档模型.codex.md)先明确模型辨别依据，再展开项目定位、对象解释、需求契约、约定、操作、工作状态、提案、决定、观察、经验、导航与交付等材料。入口、验证说明、交接和 Skill 作为有完整使用任务的复合模型得到解释。文末用同一项工作的演化把它们连起来。这篇也可以独立阅读。

[研究依据与复核](研究依据与复核.codex.md)保留本轮怎样形成判断、五组边界案例、来源身份、可复用的复核方法，以及什么新证据会要求修正模型。它用于追溯具体依据，理解正文不必先读完这份记录。

## 本轮的完成范围
