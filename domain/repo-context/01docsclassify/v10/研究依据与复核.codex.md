# 文档模型研究：依据与复核

> Codex（GPT-6），2026-10-12。本文记录 V10 文档模型的形成依据、反例与复核方法。本轮完成的是本地材料静态审阅、来源登记核对和文件指纹计算，没有运行 Agent 行为实验，也没有重跑此前的测量或论文实验。

## 本轮研究怎样形成模型辨别原则

V10 要交付解释文档的框架与文档类型全景。解释框架需要说明信息职责、使用关系和变化怎样影响文档；类型全景需要让读者辨认实际会遇到的材料及其差别。具体仓库应建立哪些文件、怎样安排入口和维护流程，由并列的组织方法研究处理。本轮据此检查：现有材料是否已经支持这两项成果，哪些未解问题会迫使核心模型改变。

[V9 的文档模型](../v9/文档模型.codex.md)第 7–13 行提出内容职责、读取与维护原型、文档实例三种观察位置；第 227 行同时保留了细分原型与保留一个模型加条件说明两种做法。这些提供了有用的起点，但尚未给出一贯的辨别原则。V9 是本轮检验的候选解释，不能因已有完整篇幅就认为分类已经成立。

早期[本地材料审阅](../../codex/research/local-material-audit.md)已经找到几类有区分力的反例：同名文件承担不同职责，活动记录与归档记录采用不同维护方式，导航和解释出现在同一页。这些反例使“文件名对应一种固定职责”“记录一律只追加”“一份文件只能归入一类”等说法不能继续成立。本轮回到这些原文，再补看实际 Skill 和子 Agent 定义，检验把文件拆成若干内容标签后，是否会遗漏它们作为完整材料的使用任务。

由此采用的工作口径是：先分别辨认**内容职责、使用关系、演化方式**。内容职责说明保存什么、支持哪种判断；使用关系说明谁在什么任务中依赖它，以及它怎样与其他材料和消费者发生联系；演化方式说明什么变化使它需要更新、被替代或结束。三者是观察同一对象的不同角度，不是必须逐层归属的目录。

当一种材料反复服务可辨认的使用任务，并把相关内容组织成能够共同使用的整体时，可以形成可复用的文档模型。这里的“稳定”指这种使用任务和组织关系能够辨认，不要求正文长期不变。Skill 把触发描述、规程、资源与结果检查组织起来；交接把目标、进展、未完验证与下一步组织给接续者。它们可以是复合模型，不必因此新造一种不可再分的内容职责。单例可以提出模型候选，跨案例对照帮助判断其适用范围；候选存在与广泛有效是不同程度的结论。

名称、位置、载体或采纳状态变化，不自动产生一种新模型。它们仍可能通过具体消费者改变使用关系：受程序识别的文件名改了，发现路径可能改变；方案被采纳后，读者可以怎样据此行动也会改变。研究要说明这项变化实际改变了什么，再决定是否需要独立展开，不能仅凭名字相同就合并，也不能仅凭标签不同就拆分。

本轮按“提出区分—寻找会使区分失败的材料—逐段解释—回看是否遗漏真实差别”的顺序审阅。取样优先覆盖同名异职、同页异责、同一记录内不同变化方式，以及文本与结构化元数据共同参与使用的情况。目标是检查模型能否保住这些差异；没有估计各类文档的行业占比，也没有把穷尽所有文件名当作完成条件。

这套过程可以复用到后来出现的材料：先写出当前解释和可能推翻它的具体情形，再从原文定位相关内容；将来源的自述、观察到的文本组织、对使用方式的推断分开；最后检查新材料能否在不抹掉条件的情况下得到解释。需要重组模型时，保存造成改变的段落和理由。全文检索之前还要确认范围，本地来源受忽略规则影响，本轮使用了显式路径和包含被忽略文件的检索；一次未命中不能直接变成“没有这种材料”。

## 五组本地边界案例

以下行号与文件指纹对应 2026-10-12 实际读取的本地文件。来源中的“必须”“禁止”等句子，是各来源表达的规则，作为研究对象解释；本轮没有执行它们，也没有检验来源所称的运行效果。

### 同名入口可以分别侧重约束与系统解释

[Raven 的 AGENTS.md](../../../../sources/repos/Raven/AGENTS.md)第 3–7 行将自身描述为 AI 协作规范，并把内容限定为硬约束；第 9–16 行列出注释、分支、提交、依赖、测试与术语要求。[Tianshu 的同名文件](../../../../sources/repos/Tianshu-harness/AGENTS.md)第 1–4 行自称架构地图，第 6–38 行展开项目定位、能力及实现位置。二者使用相同文件名，正文的重心却明显不同。

如果只按文件名给出“入口就是规则”的定义，就会丢掉 Tianshu 入口中的解释和导航责任。如果将两者都当作普通背景说明，又会丢掉 Raven 对协作行为所表达的要求。分别辨认内容职责后，两者仍可共享“开始工作时的协作入口”这一使用关系；入口模型容纳多个内容职责，职责本身仍可分辨。

这个案例直接支持“入口名称不能唯一决定正文职责”。它没有证明所有运行系统怎样发现这些文件。Raven 第 5 行还声称某种对话冲突优先关系，那只是文件的自述，不能由此认定消费者实际执行了该优先级。Tianshu 入口中的性能数字也未纳入本轮结论。

对应到 V9，文档模型第 27–31 行已保留这种区分；本轮复核确认原始案例仍支持它。模型需要明确保住“入口的共同用途”和“正文职责的差异”，无需为每一种入口组合增加一个文件类型。

### 活动决定记录可以更新实施事实，同时保留决定身份

[deepseek-harness 的 Notes 说明](../../../../sources/repos/deepseek-harness/.agents/notes/README.md)第 9–19 行按 proposed、implemented、rejected 组织记录；第 13 行要求已实施的活动记录随代码变化更新路径、名称和结构事实。[活动记录约定](../../../../sources/repos/deepseek-harness/.agents/notes/implemented/AGENTS.md)第 7 行进一步要求原位修正过期事实，第 11–13 行同时规定：改变决定或理由需要新记录并交叉引用。由此可见，同一份记录中的实施事实与决定身份并不采用相同的更新方式。

归档又增加了另一种使用条件。Notes 说明第 40–42 行与[归档约定](../../../../sources/repos/deepseek-harness/.agents/notes/archived/AGENTS.md)第 3–5 行把归档记录视为冻结的历史快照，限制其编辑，并要求新决定与当前事实使用活动材料。归档时仍保留 `Status: implemented`，因此“已经实施”与“当前仍作为活动依据”不能压成同一个状态。

只把这类材料归为历史事件，会遗漏活动记录对当前实施的解释责任；只归为当前说明，又会抹去其所保存的选择、备选与理由。把“维护方式”赋给整个文件后宣布只能改写或只能追加，也无法描述这个实例。内容职责、使用身份与具体部分的变化方式必须可以分别观察。

V9 文档模型第 153–159 行已经允许当前短理由、完整决定记录、活动事实更新和后续替代同时存在。本轮案例不要求新增一种内容职责，要求的是把记录作为复合材料展开，并明确观察可以细到同一文件的不同部分。deepseek 的冻结、分目录与合并策略是这个项目的组织选择；本轮没有运行其校验脚本，也没有把这些选择推广为其他仓库的规程。

### Skill 的整体用途不能只靠“操作步骤”解释

[deepseek 的归档 Skill](../../../../sources/repos/deepseek-harness/.agents/skills/dsh-archive-agent-notes/SKILL.md)第 1–4 行含名称与触发描述；第 10–16 行要求取得当前规则，并在新增记录时检查替代关系；第 18–29 行给出按未来使用价值判断的分支；第 31–52 行提供校准例子；第 54–68 行给出归档步骤、检查与报告内容。

这些部分组合成“在有关任务出现时取得必要规则，判断应走哪条路径，完成操作并说明结果”的使用整体。若只留下操作步骤，会丢掉什么时候用、判断依据在哪里和怎样选择分支。若把各段分别标成导航、规则、例子与操作后就结束分析，也尚未解释为什么它们被组织成同一个技能包。

因此 Skill 可以作为复合模型展开。它没有带来一种与规则、导航、操作等平行的基本内容职责；它带来的是这些内容如何共同服务一个可重复使用任务。这个案例支持 V9 文档模型第 95–97 行的组合解释，也使“所有类型都只能按内容职责区分”过于狭窄。

这里实际观察到的是技能文件的组织。触发描述是否被系统列出、何时取得正文、正文以后是否仍在输入中，需要追查消费者。[既有运行系统研究记录](../../codex/research/harness-evidence.md)中的 H06、H12、H16 分别保存了固定版本下不同技能加载路径的检查，已经显示读盘、描述展示、激活与持续提供可以分离。本轮没有重跑这些路径，也没有把该 deepseek 技能的可读文本当成激活成功的记录。

### 子 Agent 定义同时安排角色、输入依据与产出形式

[MemOS 的 design-reviewer 定义](../../../../sources/repos/MemOS/.claude/agents/design-reviewer.md)第 1–5 行包含名称、描述和工具字段；第 7 行指向项目事实；第 9–18 行说明审查对象与职责；第 20–29 行规定审查输出；第 31–35 行说明它与实现者、代码审查者和人工采纳者的分工。[MemOS 的入口](../../../../sources/repos/MemOS/CLAUDE.md)第 7–19 行还把它放进子 Agent 的角色表。

若将这份材料仅理解为用户偏好或助手人格，角色之间的分工、产出要求和工具字段就会被弱化。若只当成一份给人看的“设计审查指南”，又会忽略它被放在子 Agent 定义位置，并以结构化字段描述消费者所需配置的事实。正文职责仍包含约束、操作指引和项目引用；这些职责共同构成特定工作角色的定义。

V9 文档模型第 193 行已经容纳助手行为设定，观察维度第 163–169 行也区分名称的程序作用与结构契约。需要补足的是对“工作角色定义”这一实际用法的展开，而不是因为新增文件名就新造基本职责。这个案例也限制了模型的说法：本轮只看到了 `tools` 字段与相应说明，没有追查解析器，不能声称这些字段确实在运行时限制了工具权限。

MemOS 的版本登记仍有冲突：仓库账本写 `12acdad694d0`，抓取元数据写 `a7367d07e55db61099f7b4e2c1108bc5831a24f3`。这里保留“当前本地文件如此”的观察和文件指纹，不选择某个字段补成已确认的上游版本。

### 一份地图可以同时帮助选材料和理解系统边界

[Raven 的 CONTEXT-MAP.md](../../../../sources/repos/Raven/CONTEXT-MAP.md)第 5–8 行指向运行时、终端界面、网页界面与 Agent 服务材料；第 12–14 行直接解释通信边界与组成关系；第 19–25 行为架构术语提供进一步读取位置。这份短文件同时承担导航与解释。

第 12 行“终端界面只通过协议与运行时通信”的信息，已经参与理解系统，不能当成只有路径的索引。第 19 行以后又没有展开完整术语定义，不能说它已经承担了全量词表。区分各段职责，才能判断读到这页已经知道什么、哪些内容仍需要继续取得。

这个组合可由现有模型直接解释，无需建立“地图型文档只能包含导航”的排他类别。它也没有证明混合总比拆分好：本轮检验的是同页组合是否丢失了模型中的差异。实际是否拆页、怎样维护跳转和重复内容，属于组织方法的比较。

## 这些证据允许收束什么，什么情况需要重开

本轮五组案例支持三个核心判断。第一，文件名和位置不足以唯一决定内容职责，入口对照与地图组合提供直接反例。第二，材料的使用身份、内容职责与演化方式需要分别辨认，deepseek 的活动事实、决定身份和归档状态不能用一个标签代替。第三，完整的使用任务可以使若干内容职责形成复合模型，归档 Skill 与子 Agent 定义展示了这种组织关系。后两者不要求模型全部互斥，也不使职责分析失去作用。

这些案例没有反驳本轮的模型辨别口径。它们迫使口径保留两种尺度：既能解释单个内容职责，也能解释多个职责为何共同成为一份可使用的材料。因此类型全景可以在 V10 收束为有定义、有关系、有具体例子的模型集合；模型数量不是证明充分性的依据。交接作为复合模型的解释可由面向接续者的使用关系提出，但本轮没有把它列为新增实物核验案例，不能声称所有列入全景的模型都取得了同样强度的经验支持。

需要进一步区分支持来源。本轮回读的本地文件，证明这些文本内容和组织方式确实存在；消费者会怎样解析、选择和传递内容，应引用[固定版本的运行系统研究](../../codex/research/harness-evidence.md)，保留它的版本、配置与未核对部分。前者不能代替后者，后者的源码检查也不等于模型已经正确使用了所得信息。

关于效果，继续使用[既有实证核验记录](../../codex/research/empirical-evidence.md)保存的条件。该记录中的 E01 与 E02 分别讨论项目指令条件下的测试通过率与效率，评价对象不同；E05、E06 研究代码补全检索，不直接验证本文的文档模型；E07 的维护理由实验具有特定信息缺失与干扰条件。它们帮助限定可作出的行为主张，没有证明本文的模型集合能提高任务成功率或降低总体成本。本轮未重新打开这些论文作版本更新核验，所引仍是 2026-09-26 的研究记录。

[V9 保存的 2026-09-26 原始数据](../v9/data/local-observations-2026-09-26.json)、[2026-10-05 原始数据](../v9/data/local-observations-2026-10-05.json)与[测量工具](../v9/tools/probe_repository.py)继续承担旧测量的追溯作用。它们记录过账本核对、表示体量及查询投影等工作；V9 基础理论第 225–257 行也注明了口径问题。本轮没有运行该工具，不把旧数据改写成 V10 新实验，不据静态体量推断当前模型的成本或理解效果。

真正需要重开核心模型研究的情况，是新材料暴露了现有区分无法表达的差别。例如，被视为同一模型的两类材料，在内容、使用关系和演化方式已经说明后，仍有一项会改变正确解读或后续行动的区别无法安放；或一种反复出现的材料，只有不断添加临时例外才能解释。届时应保存造成失败的原文与任务情境，检查需要细分模型、改变定义，还是补上此前忽略的关系。单纯出现新文件名，通常只需要为已有模型增加实例。

另一种需要修正的结果，是复合分析把真正的依赖拆散了。如果将一份交接拆成若干独立事实后，接续者已无法判断哪些结果尚未验证，问题就不在“标签能不能填满”，而在这种分析遗漏了任务状态之间的关系。反过来，若两个独立展开的模型在有区分力的案例中始终只产生同样解释，也应检查是否合并更清楚。这两种检查都围绕解释是否保留必要差异，无须把唯一归类或固定类型数量当成目标。

消费者版本变化可能推翻具体的加载与解析结论，应重查相应实现路径。某种仓库组织是否更高效、哪种默认输入组合更可靠，则需要固定任务与材料进行比较，属于并列的组织与效果问题；新结果只有在改变了模型对材料本身的解释时，才需要连带修改这里的核心模型。

V10 的收束依据是：现有反例已经支持主要区分，本轮实际材料可以在保留关键差异的情况下得到解释，仍未验证的效果问题已各自定位。后续版本由能改变解释的新证据推动，不预先把尚未完成的主要论证推给 V11，也不以未来不再修订作为本轮完成的条件。
