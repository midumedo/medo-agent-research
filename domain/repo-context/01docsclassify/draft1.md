# 一套可推导治理规则的分类系统
**设计目标**：不是给现有文件“贴标签”，而是构建一个**生成性分类系统**——任何文档（包括未来出现的）都能被定位，且坐标本身就决定了它的位置、预算、更新流程和审查规则。类比化学周期表：元素的位置预测其化学性质，文档的坐标预测其治理属性。

# 一、“优质分类”的四个判据？？？
在设计前先明确验收标准，这也是排除劣质方案的依据：
| 判据 | 含义 | 排除的反例 |
|---|---|---|
| **1. 正交性** | 轴与轴独立变化，改变一个轴值不需要联动另一个 | ❌ 按“目录位置”分类（root/docs/）——位置是治理的**输出**而非本质属性，循环论证 |
| **2. 规则可推导性** | 每个轴值至少绑定一条独立的治理规则，否则轴无存在意义 | ❌ 按“文件大小”分类——大小是衍生属性，推不出规则 |
| **3. 完备性** | 能安置任意未来文档，不留“无法归类”的孤儿 | ❌ 平铺式功能列表（“这是架构文档、这是约定文档”）——只是枚举，无法预测 |
| **4. 最少轴数** | 4 轴已覆盖全域，不为边缘案例加第 5 轴 | ❌ 加“更新频率”轴——与时向/嬗变高度耦合，非正交 |
这个本来就是工程化为主，而不是理论，所以概念上的东西，纯从概念区分，感觉很难说清楚！
1. 工程上怎么确定正交呢？感觉会为了概念放弃可读性
2. 规则可推导倒是没问题，但是感觉会被其他的包含住
3. 依旧存在长尾的东西，冗余的维度 与 完备性需要取舍
4. 工程上最小轴，跟正交性有牵连，工程上，不一定能完全正交开诶。

感觉就是可以考虑的`角度`吧，维度的话太正交且单轴了，但是我这一个维度可能有好几个可选值，甚至不是选项，仅为描述。
