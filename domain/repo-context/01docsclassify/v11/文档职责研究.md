# 文档职责研究

> 当前综合是基于已核读样本形成的工作解释。它同时包含已有正文证据支持的区分和仍待扩样/追消费者的候选，不是最终分类表。

## 以任务而非“AI 专属”划界

一项文档职责的研究价值，取决于它是否保存或组织了某种信息，使读者能够回答一个实际问题、采取动作、核验约束或恢复工作。Agent 开发中有些材料会直接约束执行，有些提供系统认识，有些只在发布、合规、协作或历史追查时起作用。通用文档不因不是 AI 专属而被排除；它们在研究中作为独立对象，和 Agent 工程文档并列分析。

“对 Agent 的作用”还需要分层：文本规定某种动作，不代表消费者会读取；消费者读取不代表模型实际收到全文；模型收到不代表正确使用；行为发生变化也不等于任务成功。当前样本多数只足以判断正文在说什么。

## 目前可由样本支持的区分

### 项目定位与任务入口

项目介绍回答项目是什么、面向谁、提供什么能力及后续资料去哪找。README 常把这项工作与安装、首次运行、架构介绍、论文或 API 示例组合在一起，所以 README 不是单一职责的天然标签。首次可运行路径又可嵌在 README，也可独立成 Quickstart；关键差别是它是否给出前置条件、动作顺序与成功判据。

### 行为规则、制度与责任

材料中的“必须”可能面向不同对象：开发者的代码变更约束、社区参与行为、漏洞披露政策、组织治理权责并不因此成为同一语义类型。维护者名册回答谁当前负责，治理说明回答谁能作什么决定以及流程如何运行。贡献指南通常覆盖参与和变更路径；外部 PR 专项页可能是某个双仓项目中的子流程，是否独立成型要看其是否具有可单独执行、更新和交接的任务。

Agent 入口文件是开始协作的载体关系，不是一类固定正文职责。入口可以含项目地图、命令、规则、测试、架构或工具路由；运行时正本、指针、副本和互补材料也不能只按扩展名推断。

### 系统说明、规则与设计条件

当前实现解释、领域概念、接口契约和设计原则需要区分。系统说明解释组成和关系；概念说明固定本地词义；契约规定可依赖行为或结构；设计规范则约束生成或修改产物。实际文档可能把它们组合，或通过入口相互引用。正文目的及缺失后的误判决定边界，`CONTEXT`、`DESIGN`、`ARCHITECTURE` 这些名字只提供查找线索。

人读规则、机器可解析规则和执行工具是三种关系。架构策略 YAML 可以表达层次、依赖或所有者，但仅存在文件并不能证明检查器消费它。规则说明、可运行检查与检查结果应分别识别。

### 操作方法、工作进展与验证

规程回答如何在某些条件下完成工作；参考材料用于精确查询；任务状态说明还未完成什么；记录说明过去发生过什么。安装、发布、迁移、外部 PR 流程和 Skill 都可能含操作步骤，但 Skill 候选额外涉及发现/触发、资源、规则引用和结果检查。若这些关系没有正文或消费者证据，应只称作候选工作流材料。

测试要求、验证方法和某次结果不能互相替代。一次发布清单可能以规程组织动作、以检查表组织验收，并调用 Agent 生成测试计划；它不是单纯的历史记录。路线图中的原则、优先级和外部看板链接也不能一概等同可承诺的交付计划。

### 历史、来源和派生关系

CHANGELOG 记录按版本可感知的既往变化，不自动成为当前规范。RELEASE 手册安排未来动作，二者词面相近而时间方向和任务不同。LICENSE 确定使用/修改/再发布条件；NOTICE 说明第三方材料和保留义务；CITATION 给出学术或软件引用方式；ACKNOWLEDGMENTS 表达影响或感谢；CONTRIBUTORS 记录人员与贡献。它们有联系，但各自回答的问题不同。

翻译正文、生成文档及 sidecar 需要按来源—派生关系理解。相似的语言文本不证明内容一致；sidecar 存在也不证明校验实际执行。派生关系可以是文档模型的重要部分，但机器元数据不必因此成为与正文职责平行的类型。

## 仍待研究的边界

1. 一份 Agent 入口在多大程度上可作为独立模型，取决于固定文件名/发现机制与正文组织的相互作用；当前材料支持“入口用途”和“正文职责”可分，但不足以对所有 harness 作统一定义。
2. 外部 PR 处置页是否独立于贡献指南，需要比较单仓与双仓场景中执行主体、状态交接和更新边界。
3. SECURITY 文档中漏洞披露、产品安全说明、Agent 权限边界和信任模型可能共存；需要进一步说明它们是否同类任务的组成，或多个独立职责组合。
4. 结构化元数据、插件市场、架构策略、工具配置和翻译 sidecar 不应仅因 YAML/JSON 就放入“机器文档”一类。消费者和被描述对象需要逐个核对。
5. 文档定义可以依据文本与任务写得足以判断实例，但“被 Agent 实际读取/产生效果”仍属于另外的消费者与实验研究。

## 给后续定义阶段的交付边界

本研究解释类型差异及其证据，不替后续阶段写定义条目。后续阶段可使用本研究的正反例、任务问题和证据链接，但应自行把边界写成可供新文档判断的定义。若一个定义只有依赖文件名才能识别，或必须把所有内容装入互斥分类，说明模型或定义仍需修正。
