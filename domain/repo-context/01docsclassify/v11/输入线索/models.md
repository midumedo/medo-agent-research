# 模型定义

这些模型从 00 的实际材料和 01 V10 的“内容职责—使用关系—演化方式”框架推导。编号只是本阶段引用稳定性，不是成熟度或优先级。

## C：基本内容职责模型

### C01 项目定位与进入说明

**定义**：组织项目身份、目标、能力边界和开始使用所需的最短路径。它可以同时包含定位、安装、示例和进一步导航，但这些段落仍可分别辨认。

**回答的任务**：这个项目是什么，我现在怎样开始使用或继续查找？

**使用与演化**：新用户、贡献者或 Agent 在首次进入项目时使用；产品范围、安装方式、平台支持和入口关系变化时更新。语言或平台变体是派生表示，不能假定与正本逐段一致。

**边界/混合**：只写步骤的 QUICKSTART 可同时属于 C06；完整 README 不因此变成纯操作规程。与 C04 导航的差别是它还要形成足够的项目理解。

**反例与重开**：若某份“README”只列机器目录而不承担进入任务，应映射 C04/C13；若它包含不可替代的系统解释，应保留混合映射而不是拆成新模型。

**实例证据**：00 中 17 个 `README.md` 及其语言/平台变体均为 `I`；部分正文在各仓明细中有 `B`。

### C02 协作规则与治理约束

**定义**：规定参与者在项目中可以或必须怎样行动、哪些行为被禁止、规则适用到什么范围，以及争议如何处理。它可以是 Agent 操作守则、贡献规则、安全政策或治理制度。

**回答的任务**：在这个项目里，谁在什么范围内必须遵守哪些约束？

**使用与演化**：Agent、贡献者、维护者或社区参与者在行动前或遇到冲突时使用；工具链、权限、社区结构和政策变化时更新。不同消费者的入口别名可能复制、指向或互补，不能预设一种策略。

**边界/混合**：C02 规定约束；C05 解释系统；C06 给出完成动作的步骤；C11 登记责任主体。AGENTS 可以同时承担 C03/C04，但“入口”不是 C02 的充分定义。

**反例与重开**：若正文只列当前维护者姓名，应映射 C11；若规则由机器执行且人读文本只是说明，应同时映射 C07。若同名入口在不同仓库的约束与架构解释比例改变正确行动，保留多重映射。

**实例证据**：AGENTS/CLAUDE/GEMINI、CONTRIBUTING、CODE_OF_CONDUCT、SECURITY、GOVERNANCE、SAFETY 等均有 `I`；Raven/Tianshu/DeepSeek 边界案例有 `B`。

### C03 系统、领域与概念解释

**定义**：描述组成部分、领域对象、边界、数据流、术语关系或设计原则，使读者能解释系统为何产生某种行为。它保存理解关系，不等于操作命令或历史选择。

**回答的任务**：系统/领域由什么构成，它们如何联系，这些词在此处是什么意思？

**使用与演化**：维护者、Agent 或贡献者在定位影响范围、阅读代码和解释行为时使用；结构、领域关系或概念边界改变时更新，历史理由可另存 C09/C10。

**边界/混合**：C03 解释“是什么/如何联系”；C09 保存“为什么当时这样选”；C04 只负责去哪找。CONTEXT-MAP 可能同时是 C03 与 C04。

**反例与重开**：若新材料只有字段注册表、没有关系解释，应映射 C04/C13；若设计原则直接约束 UI 产出，应另映射 C07/T04。出现无法保留系统边界的反例时重开模型。

**实例证据**：Raven/ZCode `CONTEXT.md`、Raven `CONTEXT-MAP.md`、Tianshu `star.md` 和 AGENTS 架构地图为 `I/B`。

### C04 导航、库存与路由线索

**定义**：把问题、对象、文件或资源连到可继续读取的位置，或登记对象的身份和可查询属性。它可以带少量解释，但核心产出是选择下一项材料。

**回答的任务**：我该去哪找、有哪些对象、哪个入口适合当前问题？

**使用与演化**：Agent、维护者或安装器在发现阶段使用；路径、对象登记、生成索引和资源分布变化时更新或重生成。手写索引与生成索引是组织方式差异，不是两个基本模型。

**边界/混合**：C04 不替代 C03 的完整关系解释，也不替代 C01 的项目进入说明。marketplace 的发现字段属于 C13，并可映射 C04；`CONTEXT-MAP` 还可能属于 C03。

**反例与重开**：如果目录中的说明已经规定了必须执行的步骤，加入 C06；如果机器登记字段本身是分发接口，加入 C13。

**实例证据**：Raven `CONTEXT-MAP.md`、Tianshu 的索引相关文件在 00 研究报告中有 `I/B`；根台账未收录全部子树索引，缺口见 `gaps.md`。

### C05 能力、环境与主题参考

**定义**：说明系统能做什么、需要什么运行条件、某个主题的精确用法或错误含义。它可以是平台安装手册、SDK/LLM 参考、错误目录、基准说明或主题指南。

**回答的任务**：在什么条件下能做什么，相关接口、平台或主题的具体规则是什么？

**使用与演化**：用户、贡献者或维护者在选择能力、排查环境和查接口时使用；依赖、平台、接口、错误文本和产品能力变化时更新。若文档主要教一连串动作，另映射 C06。

**边界/混合**：C05 是查询和解释；C06 是按前提执行；C07 是必须满足的约束；C10 是已经发生的记录。

**反例与重开**：只因文件名含 BUILD 不足以判定是 C06；若正文是概念架构，应映射 C03；若记录一次运行结果，应映射 C10。

**实例证据**：00 的 BUILDING、CUSTOM_DISTROS、RISCV_SETUP、LLM、SDK、ERRORS、I18N、BENCHMARK、QUICKSTART 等为 `I`，正文核读程度不一。

### C06 操作规程与检查方法

**定义**：在给定前提下，组织完成安装、构建、发布、迁移、测试、外部 PR 处置或其他工作的动作、依赖和结果检查。

**回答的任务**：为了完成这件具体工作，应按什么顺序做，怎样知道做到了？

**使用与演化**：执行者在行动过程中使用；命令、工具、前提、失败分支和验收条件变化时更新。Skill 可能把 C06 与 C02/C04/C05 组合成 T04。

**边界/混合**：C06 不等于 C05 的解释，也不等于 C08 的未完成计划；BENCHMARK 的测量步骤属于 C06，结果属于 C10。

**反例与重开**：若只记一次命令执行结果，不应强行归为规程；若一份外部 PR 文档同时规定双仓边界和步骤，应保留 C02/C06/T05 的交叉映射。

**实例证据**：RELEASING、RELEASE_CHECKLIST、BUILDING、INSTALL-LATEST、SKILL、EXTERNAL-PRS 等为 `I`；Tianshu `.rivet.md` 的命令段有 `B`。

### C07 契约、策略与机器可判定约束

**定义**：规定参与方、数据或工具可以依赖的行为、结构、兼容条件、设计系统规则或机器可判定的限制。约束可以是人读散文，也可以是结构化数据。

**回答的任务**：哪些行为、结构或边界必须成立，谁或什么可以检查它？

**使用与演化**：实现者、调用者、Agent 或检查工具在作出或验证变更时使用；接口、数据结构、架构边界、设计 token、权限政策变化时更新。工具是否实际执行策略需另有 R 证据。

**边界/混合**：C07 与 C02 都能写“必须”，但 C02 面向参与者行动规则，C07 面向被依赖/可检查的行为或结构。C03 解释结构，C09 解释选择理由。

**反例与重开**：若 YAML 只是生成配置而无约束关系，应映射 C05；若设计文档只描述审美背景而不约束产出，应映射 C03/C05。

**实例证据**：ZCode `DESIGN.md`、`architecture-policy.yaml`、DeepSeek `SAFETY.md` 和部分 SECURITY/CONTRIBUTING 为 `I/B`；执行器关系多为缺口。

### C08 计划、问题与工作状态

**定义**：保存尚未完成工作的方向、优先关系、问题现象、当前进度、阻塞或下一步。它描述工作处于哪里，不把计划自动写成事实。

**回答的任务**：接下来要推进什么，已知问题是什么，当前工作走到哪一步？

**使用与演化**：维护者和接续者在安排、恢复和避免重复工作时使用；动作完成、问题关闭、优先级改变或计划被替代时更新。历史完成结果应转入 C10，而不是覆盖状态造成误读。

**边界/混合**：C08 不是 C09 的选择理由，也不是 C10 的已发生记录；一份计划可以同时含提案和状态，需分段映射。

**反例与重开**：若 ROADMAP 只发布已完成版本记录，应映射 C10；若 MERGE_FIXES 是临时工作稿，保留 C08 的暂定状态，不升级成正式路线。

**实例证据**：`gemini-cli/ROADMAP.md` 为 `I`；`goose/MERGE_FIXES.md` 的临时性由明细文本 `B`；00 根级范围未覆盖全部 plans/issues。

### C09 决定、立场与理由

**定义**：保存一个选择、原则或方案为何在特定问题、约束和备选下成立，以及承担的后果。它可以是立论、架构理由、决策记录或取舍分析。

**回答的任务**：为什么采用这个方向，而不是当时可行的其他方向？

**使用与演化**：维护者、设计者和未来重构者在解释现状、重访选择时使用；当决定被替代时保留原身份并记录替代关系，当前实施事实可另行更新。

**边界/混合**：C09 不是 C03 的结构说明，也不是 C10 的事件时间线；`star.md` 可能同时承担 C03/C09。旧决定与当前约定不能互相冒充。

**反例与重开**：若文档只列“现在是什么”而无选择关系，应映射 C03；若只列实验观察和结论，应映射 C10，除非明确连接到选择。

**实例证据**：Tianshu `star.md`、Raven plans/specs 与 DeepSeek Notes 的相关组织为 `I/B`；根台账不含所有决定目录，缺口见 `gaps.md`。

### C10 事件、变更、实验与复盘记录

**定义**：把发生过的动作、版本变化、观察、实验设置/结果、事故时间线或复盘判断绑定到一定时间和条件，供回看和比较。

**回答的任务**：当时发生了什么，观察支持了什么，结果和解释分别是什么？

**使用与演化**：维护者、用户或研究者在追溯、发布、诊断和复核时使用；事实记录通常追加或冻结，错误解释可以被更正但不应改写已发生事件。活动记录可更新实施事实，同时保留决定身份。

**边界/混合**：C10 的 CHANGELOG 面向对外可感知变化；C09 保存选择理由；C08 保存未完成状态。生成的法务清单属于 C12 的派生记录，不因生成而成为实验。

**反例与重开**：若文件只列未来计划，不映射 C10；若一次报告没有输入条件和观测，不能升级为可比较实验结论。

**实例证据**：CHANGELOG、RELEASE、RELEASING 的记录部分、NOTICES 生成记录均为 `I`；效果结论不由台账推出。

### C11 主体、角色、责任与贡献

**定义**：说明参与者是谁、承担什么职责、负责哪部分维护、拥有什么联系或权限，或记录历史贡献与致谢关系。

**回答的任务**：谁对什么负责，谁参与过，如何找到正确的责任入口？

**使用与演化**：维护者、贡献者和治理参与者在分派工作、追责和致谢时使用；人员、责任范围、权限或贡献记录变化时更新。名单与治理制度必须分开。

**边界/混合**：MAINTAINERS 是当前责任登记；CONTRIBUTORS/CREDITS/ACKNOWLEDGMENTS 是贡献或致谢记录；GOVERNANCE 是制度与决策规则，不能互换。

**反例与重开**：若角色文件还规定审查流程，应加 C02/C06；若主体是产品用户画像而非仓库责任人，属于不同的用户/工作角色材料，需另行说明。

**实例证据**：goose `MAINTAINERS.md`、Tianshu `CONTRIBUTORS.md`/`CREDITS.md`、EverOS `ACKNOWLEDGMENTS.md` 为 `I/B`。

### C12 法务、来源与对外归属

**定义**：说明代码或资料的许可、第三方声明、引用方式、版权归属、致谢或可分发条件，供外部使用和合规判断。

**回答的任务**：我能如何使用、分发或引用这些材料，来源和归属是什么？

**使用与演化**：用户、分发者和法务参与者在发布、复制和审查时使用；依赖、许可证、第三方清单和归属变化时更新或重生成。

**边界/混合**：C12 不是 C11 的当前责任名单，也不是 C10 的一般变更日志；生成清单还具有 T07 派生关系。

**反例与重开**：若 NOTICE 只记录一次内部事件，应转 C10；若文件只规定漏洞报告渠道，应映射 C02/C07 的安全策略。

**实例证据**：LICENSE/NOTICE/NOTICES/THIRD_PARTY_NOTICES/CITATION/ACKNOWLEDGMENTS/CONTRIBUTORS/CREDITS 均有 `I`。

### C13 机器库存、发现与分发登记

**定义**：以机器可读取的字段登记可发现、可安装或可分发的对象、入口、版本、类别和元数据，供安装器、harness 或目录消费者查询。

**回答的任务**：机器可以发现、选择或安装哪些对象，从哪里取得？

**使用与演化**：工具和分发流程在发现/安装阶段使用；插件入口、版本、策略或目录对象变化时更新。它与人读 README 的介绍任务不同。

**边界/混合**：marketplace 是分发发现；registry 可能只是维护者内部登记；C04 是更宽的导航/路由关系。实际消费者是否读取需 R 证据。

**反例与重开**：若 JSON 只是生成缓存、没有发现契约，应映射 C14/C05；若对象登记由人读表格维护，也可能只属于 C04。

**实例证据**：`mem0/marketplace.json` 为 `I`；字段语义由本地正文可核读，安装器消费关系仍是缺口。

### C14 派生、翻译与同步元数据

**定义**：记录一份正文、翻译或生成物与其来源之间的对应、分块校验、同步状态或重生成关系；它描述派生关系，不承担正文内容本身。

**回答的任务**：这份派生表示对应哪个来源，怎样判断它是否同步？

**使用与演化**：翻译工具、生成脚本和维护者在同步/重生成时使用；正文段落、源目标关系或生成方法变化时重写。元数据存在不证明同步检查实际运行。

**边界/混合**：翻译正文仍映射 C01/C02/C07 等原职责；`.i18n.yaml` 不能被当作普通主题手册。生成的 THIRD_PARTY_NOTICES 正文属于 C12，同时可有 T07。

**反例与重开**：若 YAML 本身是业务配置或架构策略，应映射 C07/C05；若它只登记插件版本，属于 C13。

**实例证据**：DeepSeek 四个 `*.i18n.yaml` 均为 `I/B`；同步脚本执行关系为 R 缺口。

## T：复合使用任务模型

### T01 项目进入与对外交付

把定位、能力、最短路径、限制、许可证或语言/平台派生表示组织成一次“进入/使用/分发”任务。典型载体是 README、QUICKSTART、LICENSE 套件。它可以组合 C01、C05、C12，不等于任何一个单独职责。

**边界与反例**：若材料只供内部维护者回看，不映射 T01；若 README 只是目录入口，应转 T08。若合并后读者无法判断如何开始或如何合法使用，应保留 T01。

### T02 Agent/协作入口

把常驻约束、子树辖域、上下文路由、别名适配和必要的自检入口组织成一次“开始协作”任务。AGENTS、CLAUDE、GEMINI 和部分 CONTRIBUTING 可以参与，但正文职责仍按 C 模型分段。

**边界与反例**：名称不保证入口被某 harness 读取；正文存在不证明投递到模型输入。若文件只供机器注册，不映射 T02。

### T03 规则执行与验证关系

把人读政策、机器规则、命令检查和结果门槛连接成“某项行为应满足什么、由谁/什么确认”的任务。它组合 C02、C06、C07，执行器证据必须单独核验。

**边界与反例**：规则文本和实际执行是两件事；没有运行轨迹时只能说明声明关系。若规则只解释概念而无验证关系，转 C03。

### T04 可发现、可调用的工作流/Skill

把触发描述、发现路径、规则引用、分支步骤、资源和结果检查组织成一次可调用工作。SKILL.md、带 frontmatter 的 INSTALL-LATEST，以及某些主题手册可参与；“叫 SKILL.md”不是充分条件。

**边界与反例**：普通操作手册只有 C06；有步骤但没有发现/触发/资源关系时不能声称 T04。文件存在也不证明 harness 激活或持续投递。

### T05 社区治理与维护协作

把治理制度、责任名单、贡献入口、外部 PR 流转和行为准则连接成“谁能以什么规则参与、如何进入维护链”的任务。它组合 C02、C06、C11，必要时连接 C12。

**边界与反例**：名单孤立存在只属于 C11；一般贡献步骤不自动说明治理结构。若外部 PR 只是普通 issue 流程，不应引入双仓投影关系。

### T06 当前状态与历史记录的连续工作

把计划、活动事实、决定理由、当前实施状态、归档关系和下一步组织给当前执行者或接续者。它组合 C08、C09、C10，允许同一记录部分更新、部分冻结。

**边界与反例**：CHANGELOG 只做对外发布记录时可只有 C10；若没有恢复/接续任务，不强行映射 T06。决定被替代不等于历史事实消失。

### T07 派生生成与一致性交付

把来源正文、翻译/生成物、sidecar、重生成命令和一致性检查连接成可重复的派生链。它组合 C12/C14 或其他正文职责，生成标记、sidecar 和脚本是关系证据。

**边界与反例**：两个文件内容相同不证明派生关系；没有来源声明时只能标为疑似。派生链是否实际运行需 R 证据。

### T08 机器发现与注册

把可查询库存、入口、版本和安装策略组织成机器消费者的发现任务。marketplace、生成式 docs index、registry 类材料可参与。

**边界与反例**：人读目录只属于 C04；机器格式不自动证明有消费者。若字段只记录架构限制，应映射 T03/C07。
