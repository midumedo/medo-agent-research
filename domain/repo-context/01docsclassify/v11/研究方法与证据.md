# 研究方法与证据

## 研究问题

项目文档为什么会有不同类型？起点不是文件名，而是行动所依赖的信息不同。Agent 要改代码时，至少可能需要知道：目标是什么、当前实现如何工作、哪些条件必须满足、怎么完成操作、怎么验证、谁有权限决定、过去发生过什么。缺少其中一项，可能造成不同种类的错误。

因此 v11 研究“什么信息差异会改变判断或行动”，以及这些信息在一份或多份材料中如何组合。**文档模型**概括可重复的信息任务及其内容组织、使用关系和演化方式；**文档定义**则把一个可识别的语义类型界定到足以判断新实例。模型是本阶段的解释工具，定义属于后续阶段。

## 从实例到模型

对一个候选差异依次问：

1. 材料实际保存、要求或记录了什么？把正文中的当前事实、要求、建议、过程状态、历史记录、解释和索引分别读出来，不从标题补正文。
2. 谁在什么情境中依赖它，回答什么问题，并可能因此改变什么判断或行动？只先记录文档自述和任务逻辑；消费者确实读取它要另查实现。
3. 哪些内容必须连在一起，才能让该任务成立？如果它们放在不同地方，是否仍能被识别、取得并共同解释？
4. 什么变化会使内容失效、被替代、冻结或需要重建？按它描述的对象和承诺变化来判断，不按扩展名推断。

再用正反实例测试边界：相同名字的正文是否支持不同判断？不同名字是否承担同一任务？同一文档是否混合多个职责？若合并两个候选解释，会不会丢失能改变正确行动的条件？若拆分，是否会丢失必须一起读取或维护的关系？

模型只有在重复出现的任务/关系确实需要独立解释时才成立。样本数少不禁止提出候选，但不能把单例提升为普遍规律。新名称本身不构成新模型；同名也不保证同职。

## 证据层次

- **文本观察**：固定版本的文件含有何种陈述、结构或引用。
- **来源自述**：文档声称给谁使用、有什么权威或何时更新。这是文本中的主张，不自动等于运行事实。
- **消费者行为**：程序是否发现、解析、选择、注入、缓存或使用材料。需要核对具体版本和执行路径。
- **行为效果**：材料是否改善正确性、效率、成本或安全。需要与目标相符的任务实验；文件存在和源码中有解析器都不足以证明。

V11 的样本原文主要支持前两层。`00/index.csv` 的 `verified` 只说明条目在其测量范围内得到存在性记录。`absent` 只说明在明确范围内未命中或没有本地 checkout。

## 怎样报告不确定性

每个重要推断都指向足以复核的正文位置，并说明它是观察、推断还是待验证假设。强反例与正例同等重要。某条材料的作用范围、消费者或现时效力不明时，保留问题，不用通用行业惯例代替本地证据。

报告模型时要说明：成立条件、最易混邻居、可能推翻边界的材料、适用范围以及剩余证据缺口。模型可以因新案例而分拆、合并或撤回；不要求所有实例唯一归属，也不预设固定模型数量。
