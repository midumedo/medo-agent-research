# 样本判例

以下判例用来检查职责边界。路径指向 `sources/repos/` 的固定本地 checkout；引文是文档自述或实际正文，只能证明文本内容，不自动证明运行系统执行了这些陈述。

## 项目介绍不等于单一门面职责

- ReFind 的 README 同页包括项目描述、研究方法/实验配置、引用信息与 API request-response 示例：[README.md](../../../../sources/repos/ReFind/README.md#L17)。同一文件不能仅凭名字归入一个互斥类型。
- Codex 的 README 把产品边界与不同发行形态/文档入口并列：[README.md](../../../../sources/repos/codex/README.md#L1)。这支持“项目定位+路由”组合。
- OpenHands 的 [README.windows.md](../../../../sources/repos/OpenHands/README.windows.md#L1) 是 Windows + Docker 的具体安装和运行步骤，并将整体项目定位引回 README。平台差异可能改变前置条件和动作，不能只当语言变体。
- EverOS 的 README 内嵌首次运行材料；独立 Quickstart 则给从安装到 health 检查的路径：[QUICKSTART.md](../../../../sources/repos/EverOS/QUICKSTART.md#L3)。这说明“首次成功任务”可以与项目介绍同载体或分载体。

## Agent 入口同名但正文职责不同

- Raven 的 [AGENTS.md](../../../../sources/repos/Raven/AGENTS.md#L1) 明确把内容限制在协作硬约束。
- Tianshu 的 [AGENTS.md](../../../../sources/repos/Tianshu-harness/AGENTS.md#L1) 自称 Architecture Map，正文提供项目/目录定位。
- ZCode 的 [AGENTS.md](../../../../sources/repos/ZCode/AGENTS.md#L1) 指示先更新 spec、调查再修改、按目标模块取上下文，并给命令与模块地图。
- qwen 的 [CLAUDE.md](../../../../sources/repos/qwen-code/CLAUDE.md#L1) 是单一正本指针；MemOS 的 [CLAUDE.md](../../../../sources/repos/MemOS/CLAUDE.md#L3) 自述只保存 Claude 运行时适配；EverOS 的 [CLAUDE.md](../../../../sources/repos/EverOS/CLAUDE.md#L1) 是完整工程指南。文件名不等于正文类型。

这些实例支持“协作入口关系”和“正文内容职责”分开观察；它们没有单独证明相关 harness 的读取、注入和优先级行为。

## 贡献规则、治理制度与责任名册

- goose 的 [GOVERNANCE.md](../../../../sources/repos/goose/GOVERNANCE.md#L14) 规定角色、决策、争议和成员变更流程，并在末尾把当前名单交给 MAINTAINERS。
- goose 的 [MAINTAINERS.md](../../../../sources/repos/goose/MAINTAINERS.md#L1) 是当前维护人员名单。人员变化与制度变化的触发不同。
- goose 的 [CONTRIBUTING.md](../../../../sources/repos/goose/CONTRIBUTING.md#L12) 把 issue 从分诊、设计、ready、实现到验证连接起来；它不仅是 PR 格式说明。
- Tianshu 的 [EXTERNAL-PRS.md](../../../../sources/repos/Tianshu-harness/EXTERNAL-PRS.md#L13) 专讲公开仓作为 dev 仓投影时，外部 PR 如何被移植、适配、验证、同步和记账。它与 CONTRIBUTING 有链接和流程重叠，但双仓交接关系可能需要单独分析。

## 社区行为与产品/漏洞安全

- goose [CODE_OF_CONDUCT.md](../../../../sources/repos/goose/CODE_OF_CONDUCT.md#L4) 规定社区鼓励/限制的行为及报告和处理方式。
- goose [SECURITY.md](../../../../sources/repos/goose/SECURITY.md#L1) 把本地 Agent 权限、提示注入风险、人工确认建议与私密漏洞报告写在同一页。
- DeepSeek Harness [SAFETY.md](../../../../sources/repos/deepseek-harness/SAFETY.md#L5) 解释产品实验状态、沙箱局限和安全使用建议。
- Tianshu [SECURITY.md](../../../../sources/repos/Tianshu-harness/SECURITY.md#L3) 结合漏洞响应、运行时防线和文档信任边界。

因此 SECURITY/SAFETY 名称既可能指外部披露流程，也可能承载产品风险说明或 Agent 行为边界；需要按正文段落和判断任务进一步拆解。

## 变更记录与未来操作

- OpenHands [CHANGELOG.md](../../../../sources/repos/OpenHands/CHANGELOG.md#L3) 声明按版本记录 notable changes。
- Goose [RELEASE.md](../../../../sources/repos/goose/RELEASE.md#L1) 安排发版分支、QA、标记和发布动作；[RELEASE_CHECKLIST.md](../../../../sources/repos/goose/RELEASE_CHECKLIST.md#L1) 组织风险评估、自测和发布前测试计划。
- Gemini CLI [ROADMAP.md](../../../../sources/repos/gemini-cli/ROADMAP.md#L10) 说明优先级由 live issues 跟踪，并明确未来交付不构成承诺。

这些材料的词面都指向“版本/变更”，但过去事实、未来规程和方向优先级不能互换。

## 通用法律、归属与引用

00 的实例显示这些问题需要分别处理：memU [LICENSE.txt](../../../../sources/repos/memU/LICENSE.txt#L5) 提供许可证条款；Raven [NOTICES.md](../../../../sources/repos/Raven/NOTICES.md#L1) 列第三方来源和许可链接；EverOS [CITATION.md](../../../../sources/repos/EverOS/CITATION.md#L5) 规定引用格式；EverOS [ACKNOWLEDGMENTS.md](../../../../sources/repos/EverOS/ACKNOWLEDGMENTS.md#L5) 记录思想来源和感谢；Tianshu [CONTRIBUTORS.md](../../../../sources/repos/Tianshu-harness/CONTRIBUTORS.md#L3) 同时有贡献归属、PR 索引和生成/对账流程。

它们在某些发布、改写、复制、打包或研究任务里会影响行动。各项之间的具体法律效力不由本轮分类研究推定。

## 参考内容与行动工作流

- Tianshu [CLAUDE.md](../../../../sources/repos/Tianshu-harness/CLAUDE.md#L7) 写命令和复杂架构地图；memU [INSTALL-LATEST.md](../../../../sources/repos/memU/INSTALL-LATEST.md#L1) 带 name/description 与显式 Agent 受众，并给安装、验证、配置步骤。
- DeepSeek [BENCHMARK.md](../../../../sources/repos/deepseek-harness/BENCHMARK.md#L1) 的根页只有运行入口和其他细节的链接；同名基准材料可能是规程或结果报告。

程序清单、引用页和流程页需要分别读其内容与消费者，而不能把 `SKILL.md`、`SDK.md`、`BENCHMARK.md` 直接等同于单一语义功能。

## 机器数据与文档自述的证据层级

- ZCode 的 [architecture-policy.yaml](../../../../sources/repos/ZCode/architecture-policy.yaml#L1) 记录模块根、依赖、公开入口、所有者和结构限制。它不只是机器可读的注释：仓内 `architecture-governance` Skill 说明相应检查流程，[package.json](../../../../sources/repos/ZCode/package.json#L19) 注册检查命令，[policy.mjs](../../../../sources/repos/ZCode/scripts/architecture/policy.mjs#L4) 读取并解析该 YAML，[architecture/index.mjs](../../../../sources/repos/ZCode/scripts/architecture/index.mjs#L85) 执行检查。这里可以追到实际机器消费者。
- DeepSeek 的 [README.i18n.yaml](../../../../sources/repos/deepseek-harness/README.i18n.yaml#L1) 是翻译段落配对记录；`verify-translation-pairing.ts` 读取 sidecar 并比较正文配对结构，文档 gate 调用该检查：[run-gates.ts](../../../../sources/repos/deepseek-harness/scripts/run-gates.ts#L794)。这支持“存在机器维护状态关系”的判断，但不证明译文语义准确。
- Tianshu 的 [.rivet.md](../../../../sources/repos/Tianshu-harness/.rivet.md#L1) 自述为项目级指令；其 [README.md](../../../../sources/repos/Tianshu-harness/README.md#L279) 声称文件会自动注入项目上下文。本轮尚未在当前 checkout 中定位对应加载器，因此把“文档自述的消费合同”和“实现核实”分开。
- mem0 [marketplace.json](../../../../sources/repos/mem0/marketplace.json#L1) 登记插件、来源、安装策略、类别和版本；文件本身支持“供发现/分发使用”的解释，但当前样本内尚未定位读取它的消费者。

这些例子反驳“机器文件都是同一类”以及“机器格式一律未证实消费者”两种概括。字段描述的对象、实际消费者和使用后果必须分别检查。
