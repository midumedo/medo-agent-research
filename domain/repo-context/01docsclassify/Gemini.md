产生交互计算。随着注入内容的线性增加，注意力分配会呈现弥散趋势，模型抓取关键约束的能力会显著弱化，产生著名的“迷失在中间（Lost-in-the-Middle）”现象。同时，现代大模型推理服务引入了前缀缓存（KV Caching）机制，只要输入请求的前缀序列完全一致，即可大幅降低首次令牌生成时间（TTFT）与推理算力消耗。这要求治理系统必须对不同模型的上下文预算进行分级管理：指令基线型模型享有最高优先级的常驻预算，但其体量必须受到刚性限制（通常建议控制在 500 至 1,000 个 Token 以内）。该部分内容必须固定在上下文窗口的最顶端，作为 KV 缓存的绝对静态前缀；工程中必须严禁在该类文件中引入动态时间戳、易变环境变量或临时分支名称，防止破坏前缀缓存的持久复用。事实规约型模型采用按需条件激活的预算策略（单次载入建议控制在 2,000 至 4,000 个 Token 之间）。该类文档应处于上下文序列的第二层，通过文件路径模式（Glob Token）。由于该部分位于注意力最为敏感的末端工作记忆区，系统必须对其实施严格的容量监控。一旦智能体陷入多轮调试导致该区域逼近上限，系统应主动触发会话紧凑化（/compact）或瞬态重置，截断中间噪音，只将当前有效状态折叠后保留。演进纪事型模型与外部冷资产型模型在常驻状态下的 Token 预算严格为零。这两类文档坚决不进入初始化提示词，仅通过专有外部工具（如基于向量或符号索引的 RAG
