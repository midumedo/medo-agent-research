`repo-context` 绝不是去教人“怎么写好几篇 Markdown 格式的文档”，它的核心命题是：

> **在 AI Coding Agent（如 Cursor、Claude Code、Windsurf）全面接管研发流程的背景下，代码仓库（Repo）如何以最小的 Token 成本、最高的信噪比（SNR），向模型提供确定性、抗腐烂的“系统心智模型”与“行为控制沙盒”。**

一句话定义：**它是面向 AI 编程助手的代码库上下文工程学（Context Engineering for AI Coding Agents）。**

具体来说，它要深入研究并解决以下 **5 个核心课题**：

---

### 1. 认知负荷与信噪比研究（The Attention & SNR Problem）

* **研究核心**：大模型不是数据库，上下文窗口存在著名的“中间迷失”（Lost in the Middle）现象。把所有文档无脑打包喂给模型，不仅费 Token，还会稀释注意力。
* **具体课题**：
* **常驻上下文与按需检索的分流界限**：哪些规则是每次 Prompt 必须常驻的“寄存器（L1）”，哪些是应该留在磁盘、遇到具体任务才由 Agent 用 Tool 去主动查的“冷存储（L3）”？
* **自然语言 vs 编译工具的职责边界**：如何界定什么是“应该写进文档的语义契约”，什么是“必须踢给 Prettier / Biome / Ruff / TypeScript 的硬性语法约束”？



---

### 2. 文档拓扑与降维模式（Documentation Topology & Compression）

* **研究核心**：面对业界杂乱的 `THESIS`、`CONVENTIONS`、`STYLE`、`ARCHITECTURE`、`DECISIONS` 等概念，如何通过**四维象限法**（时效、抽象层级、知识流向、消费模式）将它们重构为非冗余的最小拓扑。
* **具体课题**：
* **单文件膨胀的破解之道**：为什么 `DECISIONS.md` 单文件是毒药，而原子化（Atomic）的 `docs/adr/0001-xxx.md` 才是解法？
* **消灭伪需求**：论证为什么 `INDEX.md`（人工列出代码文件功能）必然在一周内因代码改动而腐烂失效，以及如何用 Agent 的动态文件检索工具替代它。
* **架构双子星结构标准化**：探索并验证 **`AGENTS.md`（控制执行与红线）+ `ARCHITECTURE.md`（心智模型与边界）** 的最佳形态。



---

### 3. Agent 行为闭环与确定性契约（Agent Operational Sandboxing）

* **研究核心**：人类开发者具备工程常识和自律，但 Agent 经常“自作聪明”、“改完就交卷”，导致大面积幻觉或隐性 Bug。
* **具体课题**：
* **完成标准（Definition of Done, DoD）的形式化约束**：如何设计一份让 Agent 无法敷衍跳过的自检清单（测试运行、类型检查、Lint 自修复）？
* **破坏性防御（Negative Guardrails）**：如何用最精简且不可绕过的自然语言契约，防止 Agent 跨模块乱重构、私自增加庞大依赖、修改敏感配置或执行破坏性指令？
* **规则优先级的裁决机制**：当代码面临“优雅重构（DRY 原则）”与“保持简单不破坏现有测试”冲突时，如何在上下文中建立仲裁阶梯。



---

### 4. 状态持久化与作用域隔离（State, Scope & Memory）

* **研究核心**：长任务、多会话（Multi-turn Sessions）以及多人协作环境下的上下文状态管理。
* **具体课题**：
* **跨 Session 任务断点恢复**：当一个重构任务被中断，或者跨越了上下文窗口上限时，Agent 该如何从类似 `MEMORY.md` 的增量文件中无损恢复执行进度？
* **作用域污染隔离**：如何区分团队全局策略（入 Git）、个人环境配置（如本地端口、私有 Docker，必须入 `.gitignore`），避免 Agent 产生环境偏见的冲突。



---

### 5. 标准化产出与工具化生态（Tooling & Specification）

* **研究核心**：研究成果不能停留在几篇说教文章，必须能转化为主流工程能直接落地的资产。
* **具体课题**：
* **ContextSpec 规范体系**：产出一套公开可复用的 RFC 规范，清晰定义现代 Repo 的标准上下文结构。
* **脚手架与 Linter 工具（CLI）**：
* 比如开发一个 `npx repo-context init`，能根据技术栈一键生成标准的 `AGENTS.md` 和 `ARCHITECTURE.md` 骨架。
* 比如开发一个 `repo-context lint`，能自动扫描项目中是否存在冗余冲突的 `.md`，检测是否有过期的路径引用，计算整个 Repo 的上下文信噪比。





---

### 极简总结

| 传统文档工程（Human-to-Human） | `repo-context` 架构（Repo-to-Agent） |
| --- | --- |
| 给人类新人看的“入职说明书” | 给 AI Agent 建立的“运行时虚拟内存与行为沙盒” |
| 写得越多越详尽越好 | **提纯信号、修剪冗余、零废话** |
| 容忍文档滞后与代码不一致 | **抗腐烂设计，过期文档比没有文档更危险** |
| 单向被动阅读 | **被动常驻注入 vs 主动工具检索的分层调度** |

你要研究的，就是**在代码和 AI 之间，造一套标准化、轻量化、不可动摇的“认知操作系统”**。
