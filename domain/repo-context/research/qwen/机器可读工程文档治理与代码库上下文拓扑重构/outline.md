### 1.2 规则打架的机制根源：拼接而非覆盖

**论点**：指令冲突之所以无法靠"写得更清楚"解决，是因为 Claude Code 一类的加载机制把所有层级的配置文件拼接进同一个上下文而非按作用域覆盖，官方文档明确承认矛盾规则可能被任意选择一条遵循。

### 1.3 文档腐烂率的可核验口径：23.0% 而非 80%

**论点**：仓库级上下文腐烂已有可核验的学术测量，356 个仓库采样中 23.0% 存在过时代码元素引用，另一项 top-1000 GitHub 研究给出 19.2% 的文档级过时率，"高达 80%"的说法在权威文献中找不到对应来源，应予替换或标注待验证。

## 3. 分层加载：把全量注入换成按需披露

### 3.1 渐进式披露的机制与四种实现模式

**论点**：渐进式披露通过先给短描述、再按需加载完整内容来对抗上下文腐烂，其代价收益已被验证——技能元数据仅占约 100 Token 即可支撑路由决策，而全量塞入会在超过阈值后使输出质量非线性退化。

**写作指导**：先解释上下文腐烂与倒 U 型失效模式，再逐一说明索引优先、侦察兵预筛、阶段化加载、技能文件不嵌入参考材料四种模式，最后落到子代理隔离作为跨 Agent 层面的同一原则。

### 3.2 分层目录结构的 Token 账本

**论点**：把根目录文件压到 50 行以内、详情下沉到按需加载的子目录文件，可使单次任务实际加载量从 200 行以上降到 106 至 140 行区间，同时让 Agent 的探索阶段从读 30 个文件变成读 1 至 2 个文件。

## 5. 决策留痕：ADR 从归档文档变成执行护栏

### 5.1 三级执行阶梯与被忽略的决策

**论点**：ADR 对 Agent 的影响分为被忽略、在上下文内但仅为建议、被强制执行三级，只有第三级才产生硬保证——冻结执行基准中 7 项违规全部被捕获，但检索层的 precision@3 仅 0.33，说明瓶颈已从"写下来"转移到"能被检索到"。
