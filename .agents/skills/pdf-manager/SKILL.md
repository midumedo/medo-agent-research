# PDF 管理

交付同名 PDF、可读的机器转换全文和能打开的分类资产。脚本负责取得来源事实、执行文件操作；Agent 根据标题与摘要判断名称和关键词。使用 Python 3.10+ 标准库，无需当前项目的环境配置。

## 根据现状选操作

| 当前任务与材料 | 下一步 |
|---|---|
| 已有可用 MD，只想阅读或判断是否相关 | `metadata` 读标题与完整摘要，随后直接读 MD；不重新转换 |
| 已给论文编号或 PDF 链接，需要收录 | `metadata` → Agent 确定名称 → `download --convert` |
| 只有本地 PDF，尚无可用 MD | `convert`；摘要原先不可得时，转换后再 `metadata` 并按需 `rename` |
| 用户要求整理名称 | 读取摘要确定名称后 `rename`；名称已确定则直接执行 |
| 要管理一批材料或现有索引 | `index`；单篇操作不必创建索引 |
| 怀疑文件或图表缺失 | `check` 指定资料；根据报告补取或转换相应文件 |

先定位本 `SKILL.md`，再找到同目录下的 `scripts/pdf_manager.py`。将下面的 `<脚本>` 替换为其实际路径，并给路径加引号。`a` 只是资料目录示例，使用任务指定的目录。

```text
python "<脚本>" metadata 2501.13956v1
python "<脚本>" download 2501.13956v1 --root "a" --name "Project.Zep" --convert
python "<脚本>" metadata "Downloads/paper.md"
python "<脚本>" convert "a/pdf/xx.pdf"
python "<脚本>" check "a/pdf/xx.pdf"
python "<脚本>" index --root "a"
```

`metadata` 是只读操作，可直接读任意位置的 PDF/MD；本地 PDF 没有可读转换件时，结果的 `needs_conversion` 为 true。不要把缺少摘要补成 Agent 自己写的概括。

## 命名倾向

新收录或用户要求整理名称时，优先采用 `<来源编号及版本>.<类型>.<简称>`，例如 `arxiv-2501.13956v1.Project.Zep`。三部分分别用于确认来源版本、快速判断材料类型和辨认研究对象。

- **来源编号及版本**来自可靠来源，例如 `arxiv-2501.13956v1`；不编造缺失编号或版本。
- **类型**依据标题与完整摘要中的主要贡献选择：`Survey`（综述）、`Bench`（基准）、`Project`（系统或项目）、`Model`（模型）、`Method`（方法）、`Analysis`（分析）。这些是常用取向，可按材料扩展，不为凑类型扭曲内容。
- **简称**优先采用作者自称的系统名、模型名或方法名，保留专名大小写，如 `Zep`、`A-Mem`；没有专名时提炼简短主题，不直接照搬长标题，不重复堆叠类型词。

Agent 负责上述语义判断。下载时显式传 `--name "Project.Zep"`，脚本补齐 arXiv 编号；脚本本身不判断类型或生成简称，省略 `--name` 会回退到来源标题或原文件名。没有可靠来源编号的资料可用 `Report.主题`。

这是默认命名偏好，用户明确指定的名称优先；已有资料在未要求整理时保留名称。改名保持已知来源身份与版本。

## 目录与范围

```text
a/
  pdf/xx.pdf
  md/xx.md
  assets/xx-fig1.jpg
         xx-chart1.jpg
         xx-table1.jpg
         xx-eq1.jpg
         xx-img1.jpg
```

- `a/pdf/xx.pdf` 或 `a/md/xx.md` 可推导根目录 `a`。下载要给 `--root`；外部 PDF 转换时也给目标根目录，脚本复制原件进入 `pdf/`，不搬走源文件。
- 给了 `--root`，裸文件名或编号就在该资料目录查找；带目录的路径按实际路径处理，缺失时不会猜成另一份同名文件。整个目录用显式 `--all`，不要因单篇任务扩大范围。
- 已有 MD、只缺 PDF 时，按原来源执行 `download`；确认同一来源与版本后补回原件，沿用现名并保留 MD 和索引。来源不明或冲突时先核实，不凭同名配对。
- PDF 与 MD 同名。有稳定来源编号时资产用该编号作前缀，否则用文件名主体。

## 改名

需要 Agent 整理名称时，先读标题和完整摘要确定类型与简称；用户已给名称则直接执行。新名称是完整文件名主体，不含扩展名，须保留已有来源编号及版本：

```text
python "<脚本>" rename "a/pdf/arxiv-2501.13956v1.Project.Old.pdf" "arxiv-2501.13956v1.Project.Zep"
python "<脚本>" rename "a/md/旧名.md" "Report.新名称"
```

脚本联动改名本篇 PDF、MD 与分类资产，更新 MD 的登记信息、真实图片引用和已有索引行；关键词、修订日与来源信息保留。有来源编号的资产名称保持稳定；没有编号时，按旧文件名前缀命名的分类图片随改，包含正文未引用的裁图。没有索引时不创建。

目标文件、资产或索引名称冲突会停止，不覆盖其他资料。改名不重新转换；外部研究文稿的引用不由脚本自动修改，按任务范围另行更新。

## 转换与继续处理

使用 MinerU v4 精准解析，默认 `vlm`，凭据为 `MINERU_APIKEY`（Windows 可读取用户环境变量）。命令行的 `--lang` 传给解析器；英文论文可用 `en`，混合语言按资料选取。

正文沿用 MinerU 的 `full.md`，保留公式、HTML 表格、图注，图片使用 `../assets/...` 相对路径。全部返回的内容图片均保留，包含正文未引用的裁图；按可靠类型归入 `fig / chart / table / eq`，未知类型为 `img`。

- 完整转换件默认跳过；缺正文或缺少引用图片会补转，明确需要重转才用 `--force`。转换已检查本次产物，不必再做全库检查。
- 批量部分失败时，成功项仍保留，命令返回非零；只处理失败项。不要把“整条命令报错”当成“所有文件都没处理”。
- 已提交任务超时或结果下载失败，保留原 PDF、文件名和 `batch_id`，用 `convert --batch-id <批次>` 重新查询并下载；不重新提交解析。脚本会对指定 CDN 尝试局部连接回退，仍失败时按 [网络参考](references/mineru-network.md) 定位阶段。
- 名称或资产归属冲突时先处理报告中的对象，不靠 `--force` 覆盖其他资料。

索引只在需要时建立，已有索引自动维护；四列为 `id / name / keywords / revised`，保留暂未下载的记录。关键词由 Agent 判断后写入：

```text
python "<脚本>" index --root "a" --missing-keywords
python "<脚本>" index --root "a" --set-keywords "<编号或名称>" "memory;agent"
```

交付时给出 MD、原 PDF 的位置及失败项。`check` 检查同名 PDF、正文和本地图片引用，也覆盖旧转换件中的其他图片目录；不联网校验远程图片，不能凭 MD 检出未引用裁图的缺失，也不证明识别内容准确。引用数字、表格或公式仍回同名 PDF 核对。
