# 标签噪声：体检口径与修复规则

MinerU v4 的 `full.md` 偶尔会把正常的英文词拆成 `<sub>` / `<sup>` 片段（`Lar<sub>g</sub>e`、`Mem0<sup>g</sup>rema`）。本文定义两件事：`audit` 怎么量，`repair` 只允许怎么改。`audit` 已可用；`repair` 是后续阶段，规则在此先固化，避免实现时临时发明口径。

## 1. 先分清三类尖括号

| 类别 | 例子 | 处理 |
|---|---|---|
| 结构标签 | `<table>`、`<tr>`、`<td>`、`rowspan`、`colspan` | 一律不动；表格整体是保护区间 |
| 行内上下标 | `<sub>…</sub>`、`<sup>…</sup>` | 本文的分析对象 |
| 内容型尖括号 | `<think>`、`<answer>`、`<title>`、`<integer from 1-10>`、`<key>: <value>` | 作者写的提示词或 schema，**不是噪声**，删掉会改变论文内容 |

因此本文所有规则只针对 `sub/sup`，绝不按「尖括号」一刀切。

## 2. 保护区（R0）

脚本按**源文中的显式标记**定位以下区间，整段字节保留，标签计数也不进入密度：

| 对象 | 定位标记 |
|---|---|
| front matter | 文件首 `---` … `---` |
| HTML 表格 | `<table>` … `</table>` |
| 独立公式 | `$$` … `$$` |
| 行内公式 | 成对的 `$…$` |
| 代码围栏 | 行首三个反引号，到下一个同级围栏 |
| 算法块 | `<div class="mineru-algorithm">` … `</div>` |
| 图片行与路径 | 行首 `![`；`../assets/…` 一个字都不能改 |
| 标题标记 | 行首 `#` 与紧随空格；层级不变，标题文字可参与 R1–R5 |

`audit` 当前只屏蔽表格与 front matter：表格内 `sub+sup` 实测为 0，屏蔽它只为让密度口径干净；公式与代码块里的标签数量极少，暂不单独剔除，避免审计口径与 `repair` 的保护逻辑分叉。`repair` 已按上表完整实现。

## 3. 修复单位

1. 只替换**同一行内**的连续字符片段；不跨行、不重排、不增删换行。
2. 替换片段两端落在词边界或标点边界，绝不切开字母。
3. 断言 `body.count("\n")` 前后相等；任何改变行数的操作直接拒绝。
4. diff 按行输出，只显示被替换的字符与左右各 20 字上下文。

MinerU 的段落基本一行一段，所以「同段」与「同行」几乎等价；取「同行」为硬边界，比「同段」更严，把「不重写段落」变成可断言的条件。

## 4. 判定规则 R0–R6

| 编号 | 触发条件 | 判定条件 | 动作 |
|---|---|---|---|
| **R0** | 落在第 2 节任一保护区间 | — | 跳过，记 `skipped` |
| **R1** | `sub/sup` 两侧都是字母，去标签后与前后字母连成一个完整词（`Lar<sub>g</sub>e`） | ①合并词在该行锚定的 PDF 句里逐字命中；②该词在文档词表 ∪ 英文词表成立 | 合并，删除标签 |
| **R2** | 只有一侧是字母（`<sub>p</sub>rowess`、`generat<sub>ing</sub>`） | 同 R1 的两条；任一不成立落 R6 | 合并 |
| **R3** | 词尾、内容为数字或单个字母、前接专名或实体（`Mem0<sup>g</sup>`、`Neo4j<sup>1</sup>`），或位于数学上下文 | 命中白名单 | **不修**；计数前后必须相等 |
| **R4** | 内容为标点或纯符号，删标签不改变字母序列（`<sub>-</sub>`、`<sup>’</sup>`） | 合并后字符序列与 PDF 同句一致 | 只删标签，不补字符 |
| **R5** | 无标签但字符损坏（`afoundation`、`ofering`、`eficienc`） | ①同句内、替换跨度 ≤6 字符；②替换后在 PDF 文本中逐字可查；③结果是词表内的词 | 替换该词 |
| **R6** | 其余畸形片段（`ara</sub>t<sub>e`、`<sub>s</sub>i<sub>ng</sub>l<sub>e-</sub>h<sub>op,<`） | 不猜 | 不改，出 AI 包 |

R1/R2 的两条是「且」不是「或」：只靠词表会把 `Mem0g` 当成坏词，只靠 PDF 命中会放过 PDF 自身印错的情况。

**OOV ≠ 损坏**。参考文献里的人名、术语在 PDF 里逐字可查，即使不在文档词表也不动。只有「PDF 里查不到，且同句存在相似度 ≥0.9 的 PDF 词」才进 R5。

## 5. 白名单

白名单按文件生成、随补丁清单一并存档，**不写死在脚本里**，否则会把新论文里的真上标当噪声。

判定方式：

- 结构候选 = 标签内容为 1–3 字符的数字或单字母，且紧贴在词的末尾；
- 基础词 = 标签左侧紧邻的 token（`BASE_RE`，`\Z` 锚定，中间有空格就不算）；
- 基础词含数字且以字母开头（`Mem0`、`Neo4j`、`GPT4`）、或全大写缩写、或命中白名单 → 记真上标；
- 内容含空白（`Mem0<sup>g i</sup>`）不算真上标，计入跨词标签，交 AI 确认一次；
- 内容为撇号等符号（`Mem0<sup>’</sup>`、`OpenAI<sup>’</sup>`）走 R4，只删标签。

Mem0 的实测白名单：`Mem0<sup>g</sup>` ×5、`Neo4j<sup>1</sup>` ×1；另有 1 条形式损坏的 `Mem0<sup>g i</sup>` 单列。白名单计数在 `repair --apply` 前后必须相等。

## 6. `audit` 的字段

`audit` 只读、纯正则、标准库即可，缺 PyMuPDF 也照常工作。`audit --json` 输出每篇一个对象：

| 字段 | 含义 |
|---|---|
| `chars` | 正文（去 front matter）去掉表格后的字符数，密度分母 |
| `table_chars` | 被表格屏蔽的字符数 |
| `tags.sub` / `tags.sup` / `tags.total` | 表格外的标签计数 |
| `density` | `tags.total / chars × 1000`，与 §1 的历史口径可对照 |
| `noise_tags` | 至少一侧紧邻字母或数字的标签数（排除独立的作者单位标记） |
| `word_internal_tags` | 两侧都紧邻字母的标签数，R1 候选 |
| `word_internal_density` | 词内标签的千字密度，`repair` 建议的主信号 |
| `cross_word_tags` | 标签内容含空白的数量，跨词标签 |
| `words_with_tags` | 含标签的空白分隔 token 数 |
| `true_sup_count` / `true_sups` | 按第 5 节规则判定的真上标数及位置 |
| `auto_fixable` | 词内标签数减去词内真上标，R1 的结构性估算（上限，不是承诺） |
| `blocks_over_threshold` | 超过块级阈值的段落数 |
| `worst_block` | 密度最高的块：正文行号、千字密度、噪声标签数 |
| `suggest_repair` | 见下 |
| `threshold` | 当前阈值参数，随结果一起输出 |

块级阈值：段内标签 ≥3 才参与判定；`噪声标签 ≥5` 或 `千字密度 ≥2.0` 记一个超阈块。2.0 的依据是全库正常件整体最高 0.84/千字，留 2.4 倍余量。

`suggest_repair` 需要同时满足两个条件：**存在超阈块**，且**全篇 `word_internal_density ≥ 2.0`**。只用块级会误报真实的数学上下标（MemoryArena 的 `max<sub>i∈[k],ℓ∈L</sub>`、`<sup>d+k</sup>` 在短块里必然超高），而 `audit` 没有 PDF 文本可证伪。加全篇闸后，全库只有 Mem0 命中；这是对 §10.3「全篇密度不参与触发」的有意偏离，理由与数据见 `analysis/pdf-md-tag-noise-plan.md` 的校准记录。

密度分母是**正文去表格字符数**，不含 front matter。历史表格里的 48.05/千字用的是整文件字符数，所以同一篇 Mem0 在这里是 50.42；两者差 4.9%，不是标签计数变化。

## 7. `repair` 两阶段接口

**阶段一** `repair --out DIR`（已实现），只写库外或 `.rivet_scratch/`：

| 产物 | 内容 |
|---|---|
| `DIR/patches.json` | 自动判定项：`id`、`line`、`start`、`end`、`before`、`after`、`rule`、`reason`、`page` |
| `DIR/diff.txt` | 按行 before/after，展示整行原文与修复后文本 |
| `DIR/ai-packs/p01.md` | 每包 ≤20 条、≤12,000 字；每条含行号、列偏移、MinerU 片段、PDF 邻文与原因 |
| `DIR/stats.json` | 分规则计数、改动行数、白名单保留清单、AI 条目与包数、四项自检结论 |

自检项：行数恒等、保护区 SHA 不变、白名单计数不变、幂等（对修复后文本再规划 0 条补丁）。任一不通过直接报错，不写清单。

**阶段二** `repair --plan … --verdicts … --apply`：

- 按 `before` 校验：偏移处仍是原文 → 应用；原文已不在 → `already-applied`；内容不同 → `conflict`，不改。
- `id` 按 `(行号, 偏移)` 排序生成，无时间戳、无随机数；同一输入两次产物字节相同。
- 缺 `--verdicts` 或某 id 没裁决 → 一律 `keep`，计入 `unresolved`，不猜。
- `--apply` 只接受该文档自己的 `md/` 文件；指向 `assets/`、`pdf/`、库外或软链逃逸一律拒绝。
- 缺 PyMuPDF 时 `repair` 退出码 2 并给安装命令；`audit` 不受影响。

## 8. 已知但不处理

- 跨行断句 / 断词：一个词被换行切开，标签落在两行之间。
- 页眉页脚混入正文。
- 表格插入段落中间、段落被 HTML 块截断。
- 图注与正文顺序错位。
- 上游已丢失的真上标：PDF 文本层有 `Mem0g`，MD 只剩 `Mem0`。无从判定该不该有上标，补写就是臆造。
- 扫描件：PDF 无文本层，整篇只做屏蔽与报表。
